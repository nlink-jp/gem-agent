# ADR-0120: a directory is opened as a directory, a file as a regular file

| Field | Value |
|-------|-------|
| Status | **Superseded by [ADR-0123](0123-the-line-comes-before-the-fix.md)** (2026-11-18) — accepted 2026-11-17 and implemented; taken out |
| Date | 2026-11-17 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | The fix after v0.104.0 found four project files whose plain open waited on a FIFO, and left every other open unmeasured. Operator: measure the rest, and fix the ones whose name is not the operator's own choice |
| Amends | ADR-0119 (its residual: a directory that is listed no longer has one) |
| Relates to | ADR-0099 (added directories), ADR-0072 §4.8 (the file tools open without waiting) |

## Context

A plain open of a FIFO waits until something opens the other end. ADR-0119 met that for four files whose names a project chooses, and opened them only when they are regular files. The other opens were not measured then. They were measured here, each with a FIFO at the name and on the real code; an open that had not returned in two seconds counted as waiting (macOS 27.2, Go 1.27).

How an open behaves on a FIFO with nobody at the other end:

| Open | Result |
|---|---|
| `os.Open`, `os.ReadFile`, `Root.Open` | waits |
| `os.OpenRoot`, `Root.OpenRoot` | waits — they open plainly and look afterwards |
| an open for writing (`os.WriteFile`) | waits for a reader |
| with `O_DIRECTORY` | answers "not a directory" at once, through a link too |
| with `O_NONBLOCK` | opens at once |
| `Stat`, `os.ReadDir`, a path that leads through the FIFO | answers at once |

What a shell command can do to the roots themselves, run under the real profiles:

| | write lane | operator lane |
|---|---|---|
| make `.claude/skills` or `AGENTS.md` as a FIFO | refused by name | done |
| remove the session's work directory and leave a FIFO under its name | done | done |
| the same for a directory added with write access | done | done |
| move the project directory into another root and leave a FIFO under its name | done | done |

So the name of a root is something the model can choose, not only the names inside it.

What waited:

| The FIFO | What waited | Who can put it there |
|---|---|---|
| `<project>/.claude/skills` | skill discovery, the look before the trust question, the pins (at startup and after a tool writes) | a command the operator approved, or anything outside the runtime |
| the session's work directory | the tidy-up at exit and at `/clear`, the file tools' root, an `@` reference to it | the write lane |
| an added directory | the file tools' root (at startup, at a resume, in the child that runs a read), an `@` reference to it | the write lane |
| the project directory | the instruction files, `.mcp.json`, the pins, the file tools' root | the write lane |
| a memory, a memory directory, a transcript, the sessions directory, the `.project` marker, the two snapshots of the last session, the directory holding the work directories, `policy.toml`, `risk-rules.md`, the project's `rules.md`, the operator's own skills and instruction directories | their loads, most of them at every start; saving a memory over one never came back | the operator, or a process running as the operator outside the lanes |
| the configuration file (`--config`), `headers_file` | its load | the operator, by naming it |

What did not wait: every read the model can ask for (`read_file`, `search_files`, the listings, `view_image`, `show_image`, `edit_file`, the copy source of `write_file`), an `@` reference to a file and `/add-dir` — they open without waiting and look at what they hold (ADR-0072 §4.8) — and the entries of a skills directory and the files of a skill (ADR-0119).

## Decision

1. **A directory that is listed is opened as a directory** (`bounded.OpenDir`, `bounded.OpenDirIn`): with `O_DIRECTORY`, so the kernel refuses anything else at the open, without waiting. Nothing is looked at before the open, so there is nothing to swap in between. It is the flag `os.ReadDir` passes itself, and it changes nothing about how a directory opens.
2. **A root is opened by path only where a look finds a directory** (`bounded.OpenRoot`). `os.OpenRoot` takes no flags, so this is a look and then an open.
3. **A file this runtime reads under a name it fixed is opened only when it is a regular file** (`bounded.OpenRegularPath`, as ADR-0119 did for the project's four): the memories, the transcripts, the marker, the snapshots, `policy.toml`, `risk-rules.md` and the project's `rules.md`. The state directory is included although the lanes cannot write it, for three reasons. One name in it, the work directory, turned out to be the model's to replace. None of these files is ever meant to be a FIFO. And a rule with no exception inside the runtime's own tree can be held by a test, where judging name by name is what left these opens behind.
4. **A file written under a fixed name is written only over a regular file** (`bounded.WriteFile`): a memory, and the temporaries the policy file and the project's rules are saved through.
5. **What the operator names is not changed here.** The configuration file given with `--config`, and the `headers_file` the configuration names, still wait on a FIFO until something writes it: a FIFO or a process substitution there may be what the operator means. Whether to refuse one is the operator's decision, and is left open.
6. **A test holds it** (`TestOpensDoNotWait` in `internal/archtest`): outside `internal/bounded` there is no `os.Open`, `os.OpenFile`, `os.OpenRoot`, `os.Create`, `os.WriteFile` or `toml.DecodeFile`, and no call of an `Open`, `OpenFile`, `OpenRoot`, `Create`, `ReadFile` or `WriteFile` method, except those the test lists with the reason each cannot wait. Its first form left `os.OpenFile` and the `OpenFile` method out; the review of the change found what that hid.
7. **A file is opened without waiting** — decided by the operator after the observation recorded under Consequences. `bounded.OpenRegular` and `bounded.OpenRegularPath` still look first, then open with `O_NONBLOCK`, look again at what they hold, and clear the flag before handing the file back: the way the file tools open. A name swapped for a FIFO between the look and the open is refused instead of waited on. Measured before the change, with the name swapped between a file and a FIFO as fast as the disk allows: the plain open after the look waited in six runs of six, after 10 to 212 opens. After it: some 11,000 opens and 350,000 to 700,000 refusals in each 1.5 s run, and none waited. The flag is cleared before anything is read, so the reads are what they were.
8. **The skill walk opens each level from the one above it, by an open that cannot wait** — the operator asked for the residual this record left for the walk's sub-directories to be closed. The walk held an `os.Root` for each level and got the next one with `Root.OpenRoot`, which takes no flags: a sub-directory whose name was swapped for a FIFO after it had been listed held the walk, and the use of the skill with it. A level is now held as a directory opened for the purpose (`bounded.Dir`), and what it holds is opened from it by one name: a sub-directory with `O_DIRECTORY`, a file with `O_NONBLOCK` and a look at what was opened, neither through a link, and a name that is a path or `..` not at all. Measured before the change, with a sub-directory's name swapped between a directory and a FIFO some 3,400 times in 2.5 s: the walk waited in six runs of six. After it, in none of six. The way first proposed was to name everything by its path from the skill's root, which needs no handle per level. It was measured and not taken: a root resolves a path one component at a time at every open, and a tree at every bound of ADR-0119 took 8.2 s to walk against 0.3 s. As changed it takes 0.3 s. No digest changes, and that took a second look. The first form of the change listed a level by the kind the directory itself records for each name, and its review found a tree that form read differently: one holding a name an ACL denies a look at (`deny readattr`). A listing through a root looks at every name, and stops at one it cannot look at; the pins on disk were taken from that listing, so the names after it are in no pin. `bounded.Dir` lists the same way, and a test holds its listing to a root's, name for name. The same review found that form holding two descriptors for each level where the walk before held one; a level is now listed through a descriptor of its own, closed before the walk goes down. The walk before and the walk after were then compared on trees of every kind a pin distinguishes — links of each sort, names with spaces, newlines and non-ASCII characters, names of 255 bytes 32 levels down, FIFOs, files and directories with permissions taken away mode by mode, ACLs that deny one right on a file or a directory at each of three levels, extended attributes and file flags, a file past the size cap, trees past each bound, a walk with few descriptors left — and on 19 real trees, installed skills and whole repositories up to the cap of 2,000 files: the same entries and the same digest each time. Twelve properties put back one at a time — each plain open, the look at what was opened, the cleared flag, each link, the one name for an open and for a link's target, the listing a root gives, its bound, its own descriptor, close-on-exec — are each seen by a test. The test of 6 also fails on a raw open (`unix.Open`, `unix.Openat`, `syscall.Open`, `syscall.Openat`) outside `internal/bounded`.
9. **Three more opens, found by the review before the release** — a reader who had written none of 1–8 went through the whole change, and found three opens that still waited: two it reproduced, and the third is plain from the code. A result saved under a name that is already taken is compared with the file that is there, and that file was looked at and then opened plainly (`fileSHA256`): the form 7 had measured as beaten, on a name in the work directory, which the session's commands and the MCP servers write. Swapped between a file and a FIFO it waited in three runs of three; swapped for a link to a file that never ends, the comparison would not have ended either. It stood on the list of 6, and the reason given there was the look, which is no reason an open cannot wait. It is opened now without waiting and not through a link (`bounded.OpenRegularPathNoFollow`), the kind and the size are read from what was opened, and no more than that size is read. Removing a session's work directory removes its cache first, and `os.RemoveAll` opens the parent of what it removes, plainly, once the first removal fails: a FIFO where the directory of the caches was — in the state tree, the kind 3 covers — held `workdirs clean` after the operator had confirmed it. The parent is opened as a root and the name removed from it (`bounded.RemoveAll`), which leaves it the residual of 2 and no other. And `bounded.WriteFile` looked and then called `os.WriteFile`: its own comment said a swap in between still waited, while this record named roots as the only residual. It opens without waiting, looks again at what it opened, and empties the file after that look and not by the open. The test of 6 fails on `os.RemoveAll` and `os.OpenInRoot` too. The same review put back, one at a time, what 1–8 had changed, and three of those no test saw: the walk going on past a sub-directory it cannot open, a name that is gone since it was listed being left out, and the look that comes before an open. Each has a test now. The look is kept for a reason of its own: opening a FIFO, even without waiting, lets through whoever waits at its other end. Thirteen properties of this decision put back one at a time are each seen by a test.

## Consequences

- A FIFO at `<project>/.claude/skills` is a project with no skills. A FIFO where a root was is a root that does not open, and what needed it reports an error at once.
- A `policy.toml` that is a FIFO stops the start with an error that names it; it used to stop the start without a word. A `risk-rules.md` that is one is not loaded: the start goes on with the notice any unreadable rulebook gets, and the judge works without it. A link to a regular file is read as before.
- A file under a fixed name that is not a regular file is not written: saving a memory over a FIFO is an error.
- Residual: a root named by path (2) is opened after a look, and a name swapped for a FIFO between the two still waits. The parent a removal opens (9) is such a root. Of the runtime's own opens nothing else is left: not for a directory that is listed, since 7 not for a file that is read, since 8 not for the sub-directories of the skill walk, and since 9 not for a file that is written. That had been written here before 9, and was not so: the review before the release found three. The swap takes a process that keeps rewriting the name while the runtime opens it, in a place it can already write, and all it gains is a wait.
- Closing it took an open that cannot wait (`O_NONBLOCK`) for files; for roots it takes an `os.OpenRoot` that takes flags, which Go does not have. The file tools already open with `O_NONBLOCK` (ADR-0072 §4.8); how such an open and its reads behave on an online-only file of a cloud folder had not been observed on purpose when this was decided.
- It was observed afterwards, on iCloud Drive (macOS 27.2; a 2 MiB file and an 18-byte one, each made online-only with `brctl evict` before every run, two rounds). The open returns at once and downloads nothing, with `O_NONBLOCK` and without it. The first read waits for the download — 0.8 to 1.0 s — and returns the bytes: with the flag still set, with it cleared after the open, and through an `os.Root`. Every byte was read each time, and the file was on disk afterwards. Not observed: a folder that is online-only itself (evicting a folder evicted what it holds and left the folder as it was), a third-party provider's folder, and a download that fails. On this the operator decided 7.
- Observed while 8 was tested, and not changed by it: while a process keeps renaming a directory, opening a file is slow — for the walk, and for every other program that opens a file on that volume. Measured on macOS 27.2 (APFS) with one such loop running: an open waited for a gap in the renames, about 155 ms each time, so 201 files took 30 s to walk against 8 ms, and `cat` of one file took 0.15 s. The directory renamed need not be in the skill: beside it, or elsewhere on the volume, gave the same. Listing a directory, looking at a name, opening a directory and reading a file already open were not slowed; a loop renaming a file had no such effect; a file opened for reading, for writing or for events only waited alike. The walk before 8 and the walk after it are alike. Nothing waits for good, and nothing is read that was not compared. It lasts as long as the loop runs, and takes a process that can rename a directory somewhere on the volume — which a child left running by a command the runtime ran can be, wherever that command may write (reasoned from what the sandbox allows; not measured through it). The opens that wait go through together at the same gap: the same files opened 32 at a time took 1.1 s. An earlier form of this record said the loop had to be inside the skill; that was not measured, and is not so. The operator decided to change nothing for it, and to accept it as a residual: it is the system's and not the walk's — every program that opens a file waits alike, so a faster walk would leave the file tools, the commands the runtime runs and everything else on the machine as slow — and it ends when the loop does. What was weighed against that is under Alternatives. A use by the model does not hold the operator: a cancelled call is given up on after a second, as any tool call is, and the walk ends by itself behind it. `/skill` typed by the operator waits for the walk, and the third interrupt ends the program (both read from the code, not observed in a run).

## Alternatives considered

- **Leave the state directory as it is** — rejected, for the reasons in 3.
- **Open every file with `O_NONBLOCK` now** — not taken: it was unobserved on an online-only file when this was decided, which is why ADR-0119 withdrew it. The observation came afterwards (Consequences), and then it was taken, as 7.
- **Derive a root from an `O_DIRECTORY` descriptor through `/dev/fd`** — rejected: it would close the residual for roots, but it rests on how a device node reopens a directory, and it renames the root in every error.
- **Name everything in a skill by its path from the skill's root** — rejected in 8: no handle per level and so no `Root.OpenRoot`, but 8.2 s for a tree the walk does in 0.3 s.
- **Refuse a FIFO given as `--config`** — left to the operator (5).
- **Open a skill's files several at a time** — not taken: it made 30 s into 1.1 s where it was measured, but it rests on how the system lets waiting opens through, which no document states; it puts concurrency and more open descriptors into the check; and it speeds the walk alone.
- **A bound in time on the skill walk** — not taken: there is nothing to base the number on, and it would refuse a skill that is as it was pinned, on storage that is slow.
- **Let `/skill` typed by the operator come back when it is cancelled** — not taken now: the operator chose to record the slowness and change nothing. It would help whatever makes a walk slow, and is the one to take up if waiting there proves a nuisance.
