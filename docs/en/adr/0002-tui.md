# ADR-0002: Interactive UI — Bubble Tea inline TUI

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-18 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | Operator assessment after Phase 2: the plain line REPL is too austere for daily use, and a backup tool that is unpleasant to use will not be exercised in drills |

## Context

Phases 1–2 shipped a bare line-based REPL. Functionally complete, but:

1. **Waiting is silent** — no indicator during generation, tool runs, or
   MCP calls. The organization has already recorded "a deliberately idle
   state must announce itself in the UI; silent waiting reads as a hang"
   as a lesson.
2. No visual distinction between user input, model output, tool events,
   and approval prompts.
3. No input history or line editing. The RFP listed history navigation;
   Phase 1 deferred it because a hand-rolled raw-mode editor risks IME/CJK
   breakage, and cooked mode was chosen instead.
4. Markdown arrives as raw text.

The tool's reason to exist is being a usable fallback for Claude Code. An
unpleasant fallback rots: it will not be used in monthly drills.

## Decision

Adopt **Bubble Tea** (charmbracelet) with **inline rendering**, plus
bubbles (textarea, spinner), lipgloss (styling), and glamour (Markdown):

- **Inline, never alt-screen.** Completed conversation flushes to the
  terminal's native scrollback (`tea.Println`); only the live region
  (streaming text, status line, input box) is managed. Scrollback,
  search, and copy/paste keep working — the same presentation model
  Claude Code uses.
- **Input**: bordered textarea; Enter submits, pasted newlines insert
  (bracketed paste arrives flagged, so a multi-line paste can never fire
  one LLM call per line); Ctrl+J inserts a manual newline; ArrowUp/Down
  navigate history **only under an explicit navigation-state flag** (the
  recorded org lesson: an unguarded Down handler destroys the draft).
- **Approval gate**: the agent goroutine's `Approve()` sends a request
  into the TUI via `Program.Send` and blocks on a response channel; the
  TUI switches to an approval mode accepting y/n/a. The session allowlist
  stays in the gate, not the TUI.
- **Markdown**: streaming shows plain text in the live region; on turn
  completion the full response is rendered with glamour and flushed to
  scrollback.
- **Non-TTY fallback**: when stdin/stdout is not a terminal, gem-agent
  runs the existing plain REPL (piped smoke tests, scripting), and `-p`
  one-shot mode is unchanged. The "stdout carries model text only"
  contract applies to those non-TTY paths; in TUI mode the terminal is a
  single interactive surface.

## Consequences

- The IME/CJK concern that justified cooked mode in Phase 1 is retired:
  Bubble Tea's textarea handles wide characters (go-runewidth), and IME
  composition happens in the terminal emulator before runes reach the
  app. Should a terminal-specific preedit problem surface, the plain REPL
  remains available as an escape hatch (`< /dev/null` trick or piped use).
- Dependency footprint grows (charmbracelet family). Accepted: these are
  the de facto standard Go TUI libraries, and the alternative — a
  hand-rolled raw-mode editor — is the known IME/CJK trap.
- The agent core (agent/llm/tools/mcp/sandbox) is untouched; the change
  is confined to cmd + a new internal/tui package. Two presentation
  layers (TUI + plain REPL) now exist; the plain one is deliberately kept
  as the non-TTY path, not deprecated.

## Alternatives considered

- **ANSI polish on the line REPL** (colors + spinner only) — cheapest,
  but leaves history navigation and Markdown unaddressed, and the
  presentation layer would be rewritten again when those land. Staged
  implementations that get discarded are a recorded anti-pattern here.
- **Hand-rolled raw-mode line editor** — full control, no dependencies;
  rejected as the known IME/CJK trap that drove the Phase 1 deferral.
- **Alt-screen TUI (full-screen)** — cleaner to implement than inline,
  but destroys native scrollback and copy/paste, which is wrong for a
  conversation tool.
- **Wails/Tauri GUI** — out of scope by RFP; gem-agent is a terminal tool.
