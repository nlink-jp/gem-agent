# 対話インターフェース

TUI・素の REPL・単発実行・キー操作・スラッシュコマンド・補完。各面が
何を表示し、なぜそう振る舞うのか。

## TUI

Bubble Tea の inline 方式 — 素のスクロールバックとコピペがそのまま
使えます。スピナー/ステータス付きストリーミング表示、↑↓ 履歴と複数行
編集付き入力ボックス、色分けされたツールイベント、承認ダイアログ、
glamour による Markdown 整形描画（折り返しは端末幅 — コピーした行が
人工的な幅で切れません）。

入力欄とステータスバーは Claude Code と同様に**ウィンドウ最下部に
固定**され、会話はその上を流れます（素のスクロールバックは維持。
ADR-0003; 起動時に画面を 1 回クリアします）。ステータスバーには自動承認 ON のとき
`⚡auto`・使用モデル・コンテキスト使用量とウィンドウサイズ（モデル
メタデータから自動検出、`[model].context_window` で上書き可）・累計消費
トークン・実効キャッシュ率（`cache NN%`）・プロジェクトディレクトリを
表示します。

パイプ/スクリプト利用時は自動的に素の行 REPL にフォールバックし、
同じスラッシュコマンドに応答します（`/mcp reload`・`/skills reload`・
`/auto`・`/clear`・`/compact` も実際に効きます。読み取り専用なのは
パネルを要する `/settings` だけです）。単発実行モード
（`-p "<prompt>"`）は 1 ターンで終了、回答は stdout、変更系ツールは
拒否します（パイプ向け。承認ポリシーで `"never"` のツールはもともと
聞かないので実行されます — [承認](approval.ja.md)参照）。

**mermaid 図はツールが描きます**（ADR-0042・ADR-0043）: モデルが
`render_diagram` を呼ぶと端末に図が描かれ、モデルには成否だけが返ります。
回答中に書かれた ```` ```mermaid ```` フェンスは**描画されません** —
モデルが書いたとおりに表示するため、ソースのまま出ます。描けるのは
flowchart/graph（全方向・subgraph・ノード形状は矩形で描画）、ASCII
ラベルの sequenceDiagram、erDiagram で、幅の予算と高さ上限 80 行
（高さは端末行数ではなく固定の上限。inline TUI はスクロールする）に
収まる範囲です。現在の予算は `agent_info` が報告するので、モデルは
書く前に収まる形へ設計できます。モデルがファイルに書く図には触れません。
拒否されたときは理由がモデルに戻り（幅超過・ラベル脱落・辺の誤解析）、
モデルは修正して呼び直すので、オペレーターは試行ではなく完成した図を
見ます。図は受け入れ前に幅を測り、ソース中の
全ラベルが図に現れることを確認します — 不完全に描かれるなら、間違って
描くよりソースを見せます。

## ターンの実行を観る（ADR-0033）

ターン実行中のステータス行は固定スピナーではなくライブです:

    ⠸ thinking… 1m07s · 34 chunks · last 0s  (Ctrl+C で中断)

— 経過時間・ストリームから受信したチャンク数・最終受信からの秒数。
かつて同一に見えていた 3 状態が見分けられます: **思考中のモデル**は
チャンクを受信し続けます（thought・メタデータのチャンクも数えます —
問うのは生存性であって可視性ではありません）; **失速した接続**は
90 秒の沈黙で警告表示に変わり、Ctrl+C を名指しします; 一時障害
（429/5xx）後の**バックオフ再試行**は沈黙の代わりに
`リトライ 2/3 (429) — 4 秒待機` を表示します。自動タイムアウトは
ありません: 長い思考は正当であり、判断はオペレーターに残ります。

警告が出るまでは 20 秒ではなく 90 秒です（ADR-0056）: ターン途中の
長い沈黙はたいていモデルがファイルを書いているところであって壊れた
接続ではなく、正常な作業で鳴る警告は無視されるようになるからです。
沈黙の秒数（`last 40s`）はどちらにせよ最初から行に出ています。

Ctrl+C は実行中のターンをキャンセルし、シェルコマンドの**プロセス
グループ全体**を道連れにします — スキルの python（やコマンドが起動
した何であれ）が出力パイプを握って呼び出しをハングさせ続けることは
できません（ADR-0034）。それでもツールがキャンセルを無視する場合、
2 回目の Ctrl+C が警告し、3 回目で gem-agent を終了します —
transcript はイベントごとに書かれているので、詰まった呼び出しまでの
すべては既にディスクにあります。

`[tui].show_thoughts = true`（既定）のときは、モデルの思考サマリも
ライブ領域に dim スタイルで流れ、実回答が始まると置き換わります —
モデルが自分の進捗を実況します。思考は表示専用です: transcript には
書かれず、再送もされません。`false` で静かなスピナーに戻ります。
鼓動とリトライ表示はどちらでも残ります。

**ラウンド上限はギロチンではなく介入です**（ADR-0040）。
`[agent].max_turns` で進捗レビューが走り、続行するかをダイアログで
聞かれます — レビュー所見が判断材料として表示され、ask ダイアログと
同じ操作（数字・Esc）で答えます。auto モードでは高確信の「前進中」
なら可視の通知付きで自動続行。ループの疑い（同一コール 3 連続）は
上限を待たず同じダイアログを即座に上げます。絶対上限は `max_turns`
の 3 倍。それでも停止したときは進捗が保存されており、「続けて」で
続きから再開できます。

## キー操作

Enter 送信、↑/↓ 入力履歴、Ctrl+C 実行中ターンの中断（入力欄では内容を
クリア。空のときは終了）、Ctrl+D 終了。`/help` にも一覧があります。

**ターン実行中も入力できます。** 入力欄は表示されたまま生きており、
Enter は送信ではなく**次のメッセージとして予約**し（実行中の会話は
エージェントループが所有しているため）、そのターンが正常に終わった
時点で送信されます。ターンがエラー・中断で終わった場合、予約した
テキストは**未送信のまま入力欄へ戻ります** — 失敗したターンに向けて
書いたメッセージが、そのまま送りたいメッセージであることは少ない
からです（ADR-0007）。`!` と `/` のコマンドは予約できません —
先に中断してください。

**複数行入力**:

| 方法 | 使用可否 |
|---|---|
| `Ctrl+J` | 常に使える（確実な経路） |
| 行末に `\` を置いて `Enter` | 常に使える（シェルの慣習） |
| `Option`/`Alt` + `Enter` | ターミナルが Option を Meta として送る設定のときのみ |

修飾キー + Enter が効かないのはアプリ側の都合ではなく**ターミナルの
制約**です。エスケープ前置を送る設定になっていない限り、
`Option+Enter` も `Shift+Enter` も通常の改行コードとして届くため送信と
区別できず、**メッセージが送信されます**。`Option+Enter` を使いたい
場合:

- **Terminal.app** — 設定 → プロファイル → キーボード → *Option キーを Meta キーとして使用*
- **iTerm2** — Settings → Profiles → Keys → Left Option key → *Esc+*

複数行のペーストは設定に関係なく常に使えます（ペースト全体が
1 メッセージとして入力ボックスに入り、行ごとに LLM コールが飛ぶことは
ありません）。

## スラッシュコマンド

| コマンド | 内容 |
|---|---|
| `/help` | コマンド・ファイル参照・シェル・キー操作の一覧 |
| `/tools` | 利用可能なツールと、それぞれの現在の承認ゲート |
| `/mcp` | 接続中の MCP サーバー（スコープ付き）。`/mcp reload` で再接続（ADR-0039） |
| `/auto` | auto-approve 切替（shift+tab でも可・実行中も有効） |
| `/compact` | 会話の古い半分をいま要約する |
| `/settings` | 全設定を出所付きで表示・ポリシーとトグルの編集 |
| `/riskbook` | auto モードの評価器が読むリスクルール。`learn` は回答記録から起草（ADR-0050） |
| `/usage` | セッションのトークン明細書（ADR-0019） |
| `/memory` | 永続メモリの一覧（グローバル + このプロジェクト） |
| `/skills` | インストール済みスキルの一覧。`/skills reload` で再探索（ADR-0039） |
| `/skill <name> [args]` | スキルを直接起動（余分なモデル往復なし） |
| `/version` | このビルドのバージョンとプラットフォームを 1 行で |
| `/clear` | 会話履歴をリセット |
| `/quit` | 終了（`/exit` は別名。Ctrl+D でも可） |

対話セッションの終了 — `/quit`・Ctrl+C・Ctrl+D — は必ず 2 行の
サマリで締まります: 再開コマンド付きのセッション ID と、ラウンド/
トークンの合計。スクロールバックの最後の行が「ここへどう戻るか」に
答えます。

`/usage` はセッションの内訳です: メインループのラウンド数と
キャッシュ率、リスク評価・圧縮の側呼び出し、トークンを使ったモデル名
つきのツール別行（要約・Web・ファイル検索エージェント）。

## 補完

**Tab は 3 種類を補完します**。挙動は共通 — 一意なら確定、複数なら
共通プレフィックスまで、進めないときは候補一覧:

- `@<パス>` プロジェクト内ファイル参照（[添付](attachments.ja.md)参照）
- スラッシュコマンド
- `/skill ` の後のスキル名

## シェルエスケープ

`!<コマンド>` でシェルコマンドを直接実行できます — `shell_exec` と
同じ sandbox 下（タイムアウト・出力上限も共通）ですが、自分で打った
コマンドなので承認プロンプトは出ません。コマンドと出力はモデルの
文脈にも追加されるため、`!git status` してから「これを直して」という
流れがそのまま成立します。

## 承認ダイアログ

変更系ツールコールは実行前にダイアログが出ます。回答は**選択式**
（←→ または Tab で移動、Enter で決定）と**ショートカット**
（`y` / `n` / `a` / `p`、Esc = 拒否）のどちらでも可能です。選択式が
あるのは、**日本語 IME が ON のままだと y/n/a が変換に吸われて入力
できない**ためです。

- `y` — この呼び出しを許可
- `n` — 拒否（拒否側に倒れる設計。モデルには「再試行せず利用者に
  聞け」と伝わります）
- `a` — このセッション中はこのツールを常に許可。危険側には届きません:
  Block 判定のコールと "always" ポリシーのツールは以後も必ず確認します
  （ADR-0021）
- `p` — 許可し、以後このツールについては聞かない: ポリシーファイルに
  書き込み、そう表示します。1 セッション限りの `a` とは意図的に別物
  です

初期選択は「許可」ですが、自動承認がエスカレーションしたコールでは
「拒否」から始まり、反射的な Enter で危険な操作を通してしまわないように
しています。長いコール詳細は端末の高さに応じて予算化され、省略行数を
明示します — 見ていないものの承認を求められることはありません。
既存ファイルを上書きする `write_file` には何を置き換えるかの注記
（`replaces existing file: 42KB → 8KB`）が付き、縮む書き換えが同意
の瞬間に見えます（ADR-0051）。
Ctrl+C の後に届いたダイアログは自動で拒否されます: そのターンは既に
死んでいるからです。

## ask ダイアログ（ADR-0036）

モデルがターン途中に `ask_user` を呼ぶと、承認ダイアログの操作文法で
質問ダイアログが開きます: ←→/Tab で移動、Enter で決定、**数字 1〜9 は
選択と決定を 1 打で**、Esc は辞退。辞退はエラーではなく情報です —
モデルには「選ばないことを選んだ。散文で聞き直すか、判断を明示して
進め」と伝わります。ツールは読み取り専用で承認ゲート対象外
（質問へのゲートは「ダイアログを許可するためのダイアログ」）、
Ctrl+C の後に届いたダイアログは承認と同じく自動辞退されます。長い
質問はボックス内で折り返され、高すぎる質問は非表示行数を開示します
— 読めていないものに答えることはありません。素の
REPL では質問は stderr の番号付きプロンプトになり、単発 `-p` モード
ではツールが正直に拒否します — 聞く相手がおらず、パイプラインを
ハングさせてはならないからです。

## `/settings`

`/settings` は全設定を **値の出所付き**で表示するパネルを開きます —
`flag` / `env:VAR` / `config.toml` / `policy.toml` / プロジェクト
ファイル（信頼されず無視された場合は `ignored: untrusted` 付き）/
ワイルドカード規則で一致したツールの `pattern` / `session`（このパネルで
変更）/ `default`。4 層の優先順位を
画面に一切出さない設計は、「利用者が覚えている」ことを前提にして
います。

↑↓ で選択、←→/Enter で値変更、`s` でポリシーの保存先（グローバル /
このプロジェクトのみ）を切替、Esc で閉じます。セッション途中に
変えられない設定（モデル、GCP プロジェクト、sandbox スイッチ、
テーマ、言語）は読み取り専用で、理由を表示します。

永続化先は `~/.config/gem-agent/policy.toml` — gem-agent が所有して
書き換えるファイルです。手書きの `config.toml` には触れないので
コメントが残ります。衝突時は `policy.toml` が勝ち、パネルはどの
ファイルが決めたかを表示します。パイプや素の REPL では同じ行を
読み取り専用で出力します。詳細は ADR-0009。

## 外観と言語

TUI のアクセント色は ANSI 16 色パレット（ターミナルテーマに追従）、
控えめテキストは背景の明暗判定に応じた中間グレーです。
`[tui].theme = "auto"` は起動時に明暗を判定。判定が合わない場合は
`dark`/`light` を明示、どうしても合わないテーマでは `plain` で全装飾を
無効化できます（エラーは `✗` マーカー付きなので色に依存しません）。

`[tui].language` は対話 UI（`/help`・ヒント・プロンプト・承認
ダイアログ）の言語です（ADR-0029）。`auto` は
`LC_ALL`/`LC_MESSAGES`/`LANG` に従い（接頭辞 `ja` なら日本語、それ
以外は英語）、`ja`/`en` で強制できます。起動時に一度だけ解決されます。
ログ体裁の行（バナーラベル・`warning:`）、`--help`、モデル向け
テキストは設計上英語のままです。
