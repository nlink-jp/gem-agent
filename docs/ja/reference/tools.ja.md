# 組み込みツール

モデルが呼べる全ツール、返すもの、その背後の設計判断。ファイル系
ツールはすべてプロジェクトディレクトリに封じ込め（シンボリックリンク
経由の脱出も検査）。`/tools` が現在の承認ゲート付きで一覧します。

承認対象ツール（以下の変更系組み込みツールと、すべての MCP ツール）には
gem-agent がスキーマに追加する引数が 1 つあります: `gem_agent_purpose` —
なぜそのコールが必要かをモデルが一文で述べるもので、承認プロンプトで運用者に
表示されます（ADR-0047）。ツール実行前に取り除かれるため、MCP サーバが
自身のスキーマにない引数を受け取ることはありません。また何の根拠にも
なりません — [承認](approval.ja.md)参照。

名前に接頭辞が付いているのは、サーバ自身の引数名と衝突しないためです。
万一衝突した場合、gem-agent はそのツールには何も足さず、引数も素通しし、プロンプトでは
他の引数と同様に一覧へ表示します — 注記のために引数を落とす承認
プロンプトは作りません。

## 方向づけ: `list_files`・`list_tree`・`search_files`

`list_tree` はプロジェクトをツリー表示、`search_files` は依存ゼロの
高速 grep（regex / literal、バイナリと `.git` はスキップ、上限は報告）
— 方向づけが「ディレクトリごとに 1 ラウンド」から 1 コールになります。

両 walk は ignore を理解します（ADR-0052）: 既知の依存・ビルド
ディレクトリ（`node_modules`・`vendor`・`dist`・`target`・…）と
`.gitignore` 対象 — gitignore 意味論の完全実装をリポジトリ内に持ち、
`git check-ignore` とのクロスチェックで検証 — を列挙時にスキップ
します。実在の 19k ファイル Tauri プロジェクトでの実測では旧 walk の
スキャン量の 99.3% がこれで、しかもそれがノイズの正体でした（依存
README 内のマッチ、`node_modules` に 86% 食われたツリー上限）。
フィルタされるのは発見だけです。ignore されたディレクトリは
`[ignored]` マーク付きで表示され（`list_files` でも）、skip は必ず
脱出ハッチ（`include_ignored=true`）とともに報告され、ignore 領域の
中を明示的に root にした walk は全部を表示してその旨を告げ、明示
パス指定（`read_file` など）はフィルタを一切参照しません。

結果の形は「最初の 200 行」ではなく「どこにあるか」に答えます
（ADR-0052）: `search_files` は 1 ファイルにつき最大 5 マッチ行 +
残りは件数報告、`include`（gitignore 構文のファイルパターン、例
`*.go`・`src/**`）と、ファイルごとの件数だけを返す `mode="files"`
を取ります。`list_tree` は巨大ディレクトリを報告付きのディレクトリ
ごと上限で省略し（1 ディレクトリが残り全部を飢えさせない）、
ファイル数注記付きディレクトリ骨格を返す `dirs_only=true` を取り
ます。

両 walk は Ctrl+C で止まります（ADR-0065）: ディレクトリ・ファイル
の読み取りごと（ファイル内でも 1024 行ごと）にターンの context を
参照するので、遅いファイルシステム上の中断のコストは syscall 1 回分
で、残りのプロジェクト全部ではありません。見つけたものはラベル付き
の結果として残り — `[interrupted after N files scanned — results
above are partial]`・`[interrupted — the tree above is partial]` —
再開のために transcript に保持されます。

## 読む: `read_file`・`summarize_file`（ADR-0014）

`read_file` は `start_line`/`end_line` で全文ではなく窓を読めます
（注記付きで、部分が全体のふりをしない — 行番号プレフィックスは
付けません。`edit_file` の完全一致契約を毒するので）。モデルが読んだ
ものは以後の全ラウンドで再送されるため、窓読みが基本の作業様式です。

`summarize_file` はバイト列の代わりに短い要約を返します — 書くのは
`[model].summary` の軽量モデル（メインモデルとクライアント共有）、
未設定ならメインモデル。ファイル内容は圧縮と同じく nonce ラップ +
ツール無しで要約器に渡り、ブロックされた要約は報告されるエラーで
あって無言の空要約にはなりません。

## 委任検索: `agentic_file_search`（ADR-0037、誘導は ADR-0062）

ADR-0014 の原則を 1 ファイルから 1 質問へ一般化: 子エージェント
ループ（メインモデル）が独立した隔離コンテキストでプロジェクトを
探索し、簡潔な報告だけを返します — 探索は、その外れも含めて、
会話に一切入りません。`search_files` は既に知っている文字列を
見つける道具、こちらは「X はどこで/どう扱われているか」に答える
道具です — そして ADR-0062 以降、システムプロンプトは探索を
**まず**ここへ振ります（自力ナビは既知ターゲット向けの経路）。
プロンプトが手動ループを規定していた間、このツールが一度も自発
発火していなかったことが実測で判明したためです。子には読み取り専用ツールのポジティブ許可リスト
（方向づけ・窓読み・要約 — shell・編集・Web・MCP・自分自身は
決して持たない: 再帰は構造的に不可能）、10 ラウンド、そして
fail-closed 保険としての全拒否承認ゲートが与えられます。報告契約は
否定形の空間を名指しし — 見つからなかったものは明示され —
根拠は `path:行範囲` + 原文引用で、lossy と明記: 報告は回答として
信頼し、読み直すのは呼び出し側が編集・引用する行だけです
（ADR-0062）。子のツールコールは `↳ tool` 行として
ライブ表示され、子の全監査イベントはテレメトリで
`agent="agentic_file_search"` を運びます; トークン消費は `/usage`
に独立カテゴリで載ります。

## 編集: `edit_file`・`write_file`（ADR-0015）

`edit_file` は「一意な文字列の完全一致」契約を守ります — 行番号は
古くなると**黙って**間違った場所に書くが、文字列アンカーは大きな音で
失敗するか正しく動くかのどちらか — その上で安くする装備を持ちます:
順に**アトミック**適用される `edits` 配列（どれかが失敗すれば何も
書かず、何番目がなぜ失敗したかを名指し）、リネーム用 `replace_all`、
**診断つき不一致**（空白違いの近似一致をファイルの実テキスト + 行番号
で引用 — 修正は再読ではなくコピペ）、**成功時の証拠**（変更後領域を
行範囲つきで返すので読み戻し検証が不要）。意図するループは
「窓読み → 一括編集 → 結果で検証」。

`write_file` は新規ファイル用 — そして*意図的な*全面置換用です。
ここが大きな文書の死に場所でした（ADR-0051）: 部分的にしか、あるい
はコンパクション後の状態でしか保持していない大きなファイルを改修
するモデルは、全体を記憶から再生成し、逐語で再現しなかったものは
すべて黙って破壊され、成功として報告されていました。そのため 2KB
以上の既存ファイルを現サイズの 70% 未満の内容で上書きすることは、
`allow_shrink: true` の宣言が無い限り**拒否**されます。拒否は両サ
イズと両方の対処（対象を絞った `edit_file`、または再読してから宣
言）を名指します。宣言は引数なので承認ダイアログに見え、トランス
クリプトに記録されます — 縮む書き換えは可能ですが、無言では決して
できません。ダイアログには上書きが何を置き換えるかの注記
（`replaces existing file: 42KB → 8KB`）も出ます。

## `file_info`（ADR-0016）

ファイルを文脈に読み込まずに「何なのか」を答えます — 内容から判定した
種別（`file` コマンド流: Mach-O/ELF/PE・アーカイブ・スクリプト。
拡張子は表示するが信用しない）、サイズ・モード・更新時刻・**作成
時刻**（macOS 専用設計なので Darwin フィールドは無償）、そして
ハッシュ照合ツールが食べる MD5/SHA1/SHA256 の三点セット — IR の初手が
読み取り専用 1 コールで揃います。`paths` でバッチ、symlink は報告
のみで黙って辿りません。

## `view_image`・`read_document`

`view_image` はプロジェクト内の画像ファイルをループ中のモデル自身が
見るためのツールです（MCP サーバーは画像を生成します: urlscan の
スクリーンショット、pcap 抽出）— `read_file` と同じプロジェクト
封じ込め、MIME はバイト列から判別。`read_document` は PDF をネイティブ
に読み（レイアウト・表・スキャン）、Word/Excel/PowerPoint は標準
ライブラリでローカルにテキスト抽出します。オペレーター側の添付経路は
[添付](attachments.ja.md)へ。

## `shell_exec`

モデルが `access` で宣言したレーンで macOS sandbox-exec にラップした
シェル実行（ADR-0073）: `read`（既定 — 書けるのは専用 scratch だけ・
ネットワークなし・IPC なし・設定書込なし・資格情報と `~/Library` の読取なし。
起動時にレーンが検証された機体では確認なしで走る）、`write`（プロジェクトと
作業ディレクトリに書込可・ネットワーク可、指示/設定ファイルと `.git` 自体・
hooks・config は拒否、資格情報の読取も拒否。承認ゲート付き。起動時に検証され、
拒否を確認できない機体ではセッションが未確認モードになり全コマンドが確認を求める）、`operator`
（ADR-0001 のフルプロファイル。常にあなたが決める）。どのレーンもコマンドを
あなたの端末から切り離す。`ps` と `top` はどの Seatbelt プロファイルでも
走らない。強制は 3 プロファイルに対する実 Seatbelt テストで覆う。タイムアウト
と出力上限、exit status の明示、拒否は求めるべきレーンを添えて返る。
`!コマンド` 入力経路は自分で打ったので operator レーンでプロンプトなし
（[インターフェース](interface.ja.md)参照）。各レーンが拒むものは
[承認](approval.ja.md)を参照。

## `datetime`（ADR-0032）

時計と決定的カレンダー — LLM はまさにこの計算を自信ありげに間違え
ます。操作 5 つ: `now`（ローカル/UTC/unix/曜日/ISO 週）、`info`
（曜日・年内通算日・ISO 週・月の日数・閏年）、`add`（符号付き
カレンダーシフト — Go の月末正規化は発動時に出力で明言）、`diff`
（カレンダー内訳 + 総日数/時間/分）、`convert`（IANA タイムゾーン
変換）。営業日カウントは設計として拒否します: 祝日カレンダーなしの
平日算術は、それが使われる場面でこそ間違います。セッション開始日は
システムプロンプトにも載り（キャッシュ安定）、現在時刻はこのツールへ
誘導されます。

## `ask_user`（ADR-0036）

ターン途中の構造化された選択: モデルが質問と 2〜8 個の選択肢を提示し、
オペレーターが選ぶ（矢印/Tab・選択肢の数字は 1 打で決定・Enter。Esc は
回答しない）。結果は選択を名指しして返る — ターンを終えて聞き直す
往復が不要。読み取り専用・承認ゲート対象外（質問へのゲートは
「ダイアログを許可するためのダイアログ」）。Esc は「辞退」という別個の
結果 — エラーではなく情報。単発 `-p` は「聞く相手がいない」と正直に
拒否し、素の REPL は stderr に番号付きで質問する。自由入力欄は設計
として無し: ターンを終えて聞くことこそが自由入力チャネル。

## `agent_info`（ADR-0030）

モデル自身のランタイム像 — バージョン・プラットフォーム・実行中の
モデル名・思考レベル・コンテキスト占有・累積トークン使用量（`/usage`
と同じ集計元 — 数字は 1 系統）・制限・承認/サンドボックス状態・
プロジェクト信用・接続中 MCP サーバー（最終接続時点 — 起動時または
直近の `/mcp reload`）とスキル。読み取り専用・承認なし。GCP 識別子と
ホスト名は意図的に非開示。

図のツールはありません（ADR-0063）: 回答中の ```` ```mermaid ````
フェンスは、端末が忠実に描ける場合に TUI がその場で描画し、描けない
場合はソースのまま表示します。モデルには図について何も伝えません —
描画は表示層の関心事で、Markdown レンダラが回答に行う他のあらゆる
変換と同じ扱いです。

## Web アクセス: `web_search`・`web_fetch`（ADR-0017）

エグレスツールを 2 つ。どちらも**既定で承認ゲート**付きです —
クエリや URL 自体が、注入された指示がモデルの読めるものを持ち出せる
経路になるため。緩和は[承認ポリシー](approval.ja.md)でツール別に
（`"web_search" = "never"`）— これで `-p` 単発モードでも使えます。

- **`web_search(query)`** — メインモデルの Grounding with Google
  Search。グラウンディングされた回答が**出典つき**（タイトル・
  ドメイン・URI）で返るので、主張を信じるのではなく確認できます。
  first-party で規約もクリーン — 素の検索 API を使わなかった理由その
  ものです
- **`web_fetch(url, focus?)`** — `[model].summary`（未設定ならメインモデル）
  の URL Context
  ツール。ページはプロバイダのインフラが取得し、要約モデル自身の
  コンテキストで読まれます。この会話に入るのは**整理された抽出**
  （正確な名前・数値・日付を保った要点と注意点）だけです。サーバー
  サイド取得は SSRF というクラスを構造的に殺します — localhost や
  LAN には到達不能 — その鏡像コストとしてイントラネット・認証付き
  ページは取得できません（失敗は取得状態つきで報告）

Web コンテンツは非信頼です: 要約は通常どおり nonce ラップされた
ツール結果として返り、ラップできない層にはフェッチプロンプトの防御的
枠書きが当たります。
