# アーキテクチャ

gem-agent の現在の挙動。前提知識を期待せず読めることを目標にしている。判断の
「なぜ」は [ADR](../INDEX.ja.md#adr) 側にあり、本文書は今のコードが何をするかを
記述する。

## 全体の形

1 バイナリ・1 プロセス・1 会話。`main.go` は `cmd.Execute` に渡し、そこで 5 つを
組み立てて配線する:

```
cmd/            フラグ・設定読込・プロジェクト解決・配線・REPL/TUI
  ├── internal/config      strict decode TOML + env/flag 優先順位
  ├── internal/llm         Backend interface + Vertex AI Gemini
  ├── internal/tools       組み込み 5 ツール + MCP 登録
  ├── internal/agent       ターンループ・承認ディスパッチ・圧縮
  └── internal/tui         Bubble Tea inline UI（非 TTY は internal/repl）
```

補助パッケージ: `internal/sandbox`（Seatbelt プロファイル生成）、
`internal/approve`（素 REPL のゲート）、`internal/risk`（自動承認のルール層）、
`internal/mcp`（stdio JSON-RPC クライアント）、`internal/mention`（`@` 参照）、
`internal/instructions`（`AGENTS.md` 探索）、`internal/session`（トランスクリプト:
ロガー + resume ローダ）。

**エージェント中核は UI を知らない。** `Approver` インターフェースと一連の
コールバック（`OnToolCall` / `OnUsage` / `OnNotice` / `OnAutoDecision` /
`OnAttach`）を受け取るだけで、TUI は Bubble Tea メッセージ送信として、素 REPL は
stderr 書き込みとして実装する。同じループが pty・パイプ・`-p` の下で動くのは
これによる。

## プロジェクトディレクトリ

起動時のカレントディレクトリがプロジェクトになる。`sandbox.ResolveWriteDir` を
通すのでシンボリックリンク解決済みの実パスである。他の全てがここから導かれる:
ツールが触れるファイル、sandbox が書き込みを許すパス、読む `.mcp.json`、集める
指示ファイル、`--continue` が候補にするセッション。

**独立した 2 つの境界**が強制しており、失敗の仕方が意図的に異なる:

- **Go レベルのパス封じ込め**（`internal/tools`）。`resolvePath` はプロジェクト
  配下の絶対パスに変換し、clean し、封じ込めを検査し、その後シンボリックリンクを
  解決して**もう一度**検査する。この 2 回目が「プロジェクト内にあってプロジェクト外を
  指すシンボリックリンク」を止める。未作成パスの場合は、存在する最深の祖先で
  リンクを解決してから残りを再結合する。組み込み 5 ツールのうちパスを取る 4 つは
  全てここを通る。
- **プロセスレベルの封じ込め**（`internal/sandbox`）。`shell_exec` はパスを取らず
  コマンドを取るので、生成した SBPL プロファイル（プロジェクト + scratch 以外の
  `file-write*` を deny）で `sandbox-exec` にラップする。`cmd.Dir` はプロジェクト。
  `--no-sandbox` はこの層を外し、バナーにそう出る。

## 1 ターン

```
入力 ──▶ @参照を展開 ──▶ 履歴 append + トランスクリプト記録
           │
           ▼
     ┌──────────────────────────────────────────────┐
     │ ラウンド: 圧縮判定 → リクエスト → ストリーム │
     │   ├── テキスト ──▶ UI（flush でスクロールバック）│
     │   └── ツールコール                            │
     │         ├── 自動承認ラダー（ON なら）        │
     │         ├── 人間ゲート（未承認なら）          │
     │         └── 実行 ──▶ 結果を履歴へ            │
     └───────────────┬──────────────────────────────┘
                     │ ツールコールあり → ループ。テキストのみ → 完了。
```

ラウンドごとの要点:

- **thought signature** は応答の全 Part から捕捉し、次リクエストで
  thoughts → text → function calls の順に再生する。Gemini 3 は signature の無い
  function-call part を拒否するので、最適化ではなく硬い要求である。
- **function response は 1 つの Content にまとめる**: 1 アシスタントターンが
  複数コールを出した場合、その応答は全て 1 つの user Content で送る。
- **非信頼コンテンツは送信時にラップする**（保存時ではない）。ツール結果と
  `@` 添付は生で保存し、リクエストごとに新しい nonce タグ（nlk/guard）で包む。
  タグは呼び出しごとに変わらなければならないためである。システムプロンプトは
  対応する `{{DATA_TAG}}` を持つ。
- **テキストもツールコールも無い応答は保存しない。** 履歴に空 Part が入ると
  以後の全リクエストが 400 になる。コンテンツフィルタのブロックは 1 回だけ
  リトライし、その後は理由を明示して報告する。
- **ラウンド上限**: `[agent].max_turns` が暴走ループを止める。

## 承認

変更系ツール（`write_file` / `edit_file` / `shell_exec` と全 MCP ツール）はゲートを
通る。`y` は 1 回、`a` はそのセッションのそのツール、`n`/Esc は拒否。拒否は
「沈黙」ではなく結果としてモデルに返す。回答は ←→/Tab + Enter で選択できる —
日本語 IME が文字キーを吸うためである。

これはツール単位で上書きできる（ADR-0008）。グローバル設定の
`[approval.tools]` と、プロジェクトの `<project>/.gem-agent.toml` が、ツール名
（または `mcp__server__*` の前方一致）を `always`（全モードでゲート・ラダーは
飛ばす）か `never`（全モードでゲート無し）に対応づける。`never` はルール層の
Block の床を持ち上げないので、block パターンに当たる `shell_exec` は引き続き
聞く。プロジェクトスコープはどこでも締められ、緩められるのは
`[approval].trusted_projects` に載ったディレクトリだけで、無視したエントリは
起動時に名前を出す。

自動承認 ON（opt-in、`shift+tab` で切替。実行中も可）のとき、各変更系コールは
まず純粋なルール分類器を通る: *safe* は実行、*blocked* は必ず確認、*不確実* は
モデル評価へ回り、承認 **かつ** 高確信のときだけ通る。失敗系はすべて確認へ倒れる。
blocked 層はモデルが持ち上げられない床であり、sandbox は全モードで有効である。

`/settings` は全設定を出所付きで表示し、いま効かせられるもの（承認ポリシー・
自動承認・自動圧縮・テーマ）を編集する。永続化するポリシーは
`~/.config/gem-agent/policy.toml`（機械所有）へ書き、手書きの `config.toml`
とは衝突時に前者が勝つ（ADR-0009）。`config.toml` は書き換えないのでコメントが
残る。

## コンテキスト

ステータス行はモデルの入力ウィンドウに対する占有率を出す。値は
`[model].context_window`、無ければモデルメタデータ、それも無ければ `~` 付きの
1M ファミリー推定（Vertex は `inputTokenLimit` を返さない）。**同じ値が自動圧縮の
判定に使われる**ので、`-p` を含む全モードで解決している。

ウィンドウの `[agent].compact_at_pct` に達すると、ラウンド間で会話の古い側が要約に
置き換わり、直近は逐語で残る。切断点はツール結果の上には置かないので、孤立した
function response は生じない。要約器にツールは渡さず、トランスクリプトは nonce
ラップしたデータとして読ませ、要約は添付としてデータ引用で戻る。失敗時は履歴を
一切変更しない。

## 永続化

セッション 1 件 = `~/.local/state/gem-agent/sessions/` の JSONL 1 ファイル、
モード `0600`、タイムスタンプ命名。**診断ログと resume の正本を兼ねる**ので、
会話状態を持つ記録は完全（ツールコール引数・添付・thought signature）であり、
診断記録は要約のままロード時に無視される。圧縮は記録され再生されるので、
圧縮済みセッションは圧縮済みで戻る。

`--continue` は**このプロジェクトの、会話が入っている**最新セッションを選ぶ。
`--resume <id>` は明示指定。resume は別プロジェクトディレクトリ・別モデルを
警告ではなく拒否する。ID は ID として検証し、パスとして解釈しない。

## 設定と drop-in

`~/.config/gem-agent/config.toml`、strict decode（未知キーはエラー）、優先順位は
flags > `GEMAGENT_*` > `GOOGLE_CLOUD_*` > file > defaults。モデル名は常に設定由来で
あり、コードに埋め込まない。

プロジェクト側に必要な設定は無い。`AGENTS.md` / `AGENT.md` / `CLAUDE.md` /
`GEMINI.md` を `~/.config/gem-agent/` → 親ディレクトリを外側から → プロジェクト
自身の順に集める。遡上は `$HOME` で止まる — 指示ファイルは「指示」として従う対象
だからである。MCP サーバーは `~/.config/gem-agent/mcp.json` と
`<project>/.mcp.json`（Claude Code 形式）から読み、名前衝突はプロジェクト側が勝つ。
MCP にキャンセルは無いので、タイムアウトした呼び出しはサーバー子プロセスを kill し、
次回呼び出しで再起動する。

skill（ADR-0010/0011）は MCP と同じ配置に従う: `~/.config/gem-agent/skills`
（gem-agent 自身の置き場。Claude Code との共有はオペレータが張る symlink で、
探索はそれを辿る）+ `<project>/.claude/skills`（共有）を Claude Code の形式で
読む。システムプロンプトには 1 件 1 行、本文は読み取り専用ツール `load_skill`
で必要時に読むか `/skill <name>` で直接注入する。`load_skill` の結果は nonce ラップされない
唯一のツール出力である — skill 本文はオペレータが導入した指示であり、この例外は
「発見済み skill ディレクトリ内に限る読み取り封じ込め」で境界づけられている。

## 失敗時の挙動（一覧）

| 状況 | 挙動 |
|---|---|
| コンテンツフィルタが応答をブロック | 通知して 1 回リトライ、その後は理由名付きで報告 |
| モデルが何も返さない | finish/block reason 付きで報告。保存はしない |
| 要約が失敗 | 履歴不変でターン継続。2 回で自動圧縮を停止 |
| ツールが拒否・エラー | 結果文字列としてモデルへ返す（反応できるように） |
| MCP 呼び出しタイムアウト | サーバーを kill、次回呼び出しで遅延再起動 |
| chunk 消費前の 429 / 5xx | 指数バックオフでリトライ。出力消費後は絶対にしない |
| セッションログが書けない | 警告のみで継続（壊れたログでフォールバックを止めない） |
| resume 対象が読めない | 致命的エラー（利用者はその履歴を求めている） |
| SIGINT | ターンをキャンセル。プロセスは落とさない |
