## Context

レーンは、ランタイムが起動のたびに確かめる主張です（ADR-0073 §5・§7）。レーンが書けないはずの場所にプローブのファイルを作り、失敗しなければならないコマンドをレーンの中で実行します。その失敗をレーンによるものと数えるのは、同じことがサンドボックスの外では成功するときだけです。これが対照です。書き込みの対照は、サンドボックスの外のシェルが、プローブのパスに `echo x >` を実行するものでした。時間の上限は無く、プローブは後でパスによって消していました。

プローブは、レーンが書く場所に置くほかありません。プロジェクト、追加ディレクトリ、作業ディレクトリ、`/private/tmp` です。したがって write レーンのプロセス（操作者が以前に承認したコマンドが残した子プロセスや、別のセッションのコマンド）は、プローブが作られてから使われるまでの間に、それを差し替えられます。ADR-0073 の最終レビュー（R1）は、前からそこにある決まった名前のプローブを閉じました。これは閉じていませんでした。

実物のコードで測りました（macOS 27.2）。本物の write レーンのプロファイルの下で、見つけたプローブをすべて差し替えるシェルのループを動かし、プロジェクトの隣に、どのレーンも書けないディレクトリを置いています。

| プローブを何に差し替えたか | 起きたこと | 回数 |
|---|---|---|
| プローブのディレクトリを、外のディレクトリへのリンクに | 後片づけが、そこにあるプローブと同じ名前のファイルを消した: `AGENTS.md`、`plain`、`.env`、`created` | 7 回中 7 回。確認の 1 巡目で |
| プローブのファイルを、外のファイルへのリンクに | 対照がリンク越しに書いた。そのファイルの中身が `x` になった | 3 回中 3 回。2 巡目までに |
| プローブのファイルを FIFO に | 対照が待ち、起動も待った。テストが許した 60 秒の間、シェルを止めるまで | 置き換え用の FIFO を用意しておくループで 1 回中 1 回。遅いループでは 4 回中 0 回 |

このループ自身が外のディレクトリに書けないことは、先に確かめました。普通のプローブのコマンドはここで 0.01 秒、最も遅いもの（`osascript`）で 0.05 秒です。

開いたまま持っているディレクトリ経由の open がどう動くかは、設計の前に観察しました（`os.Root`、Go 1.27）。ディレクトリの外へ出るリンクは断られますが、中の別の名前へのリンクは、`O_NOFOLLOW` があっても無くても辿られます。ハードリンクは開きます。待たずに書き込み用に開いた FIFO は、その場で断られます。FIFO への `Root.OpenRoot` は待ちます。つまりルートだけでは、書き込みが別のファイルに落ちるのを防げず、プローブのディレクトリを開く手段にもなりません。

ファイルの番号は、どのボリュームでもそのファイルにずっと付いているわけではありません。FAT と exFAT では、空のファイルの番号は仮のもので、最初の書き込みで自分の番号になります。この変更の最初の形は、作ったときの番号を覚えていました。リリース前のレビューがその両方で動かし、そこではどのプローブも差し替えられたものと見なされ、残されることを見つけました。下の変更の後、2 つのディスクイメージで測り直しました。どちらでもすべての確認が通り、何も残りません。1 つ前のコミットは、レビューが言ったとおりに失敗します。

## Decision

1. **プローブを作るディレクトリは開いたまま持ち、プローブはそこから 1 つの名前で、作り、書き、読み、消します。** ディレクトリはディレクトリとして開き（`O_DIRECTORY`）、その中のプローブのディレクトリも、そこから同じように、リンクを辿らずに開きます。ADR-0120 §8 がスキルの歩きのために作った `bounded.Dir` に、プローブに要るもの（`DirAt`、`Mkdir`、`Create`、`OpenWrite`、`Remove`、`RemoveDir`、`ID`）を足して使います。プローブのディレクトリは、作ったときと同じく空であるときだけ使います。何かが入っているなら、それは名前の上に被せられた別のディレクトリで、中のものは確認のものではありません。レーンが差し替えられる名前を通るパスは無くなるので、確認が持っているディレクトリの外では、何も書かれず、消されません。
2. **ファイルのプローブの対照は、ランタイム自身が行い、2 回行います。** 先に作ってあるプローブは、作ったときから開いたまま持ちます。対照では、名前から、待たずに、リンクを辿らずに、書き込み用に開き、作ったファイルであるときだけ書きます。名前の先にあったものと、作ったときから持っている記述子の先にあるものが、その時点で同じデバイスと番号であることを確かめます。レーンのコマンドが作るはずのプローブは、排他的に作ります。読むプローブは、待たずに通常ファイルとして開き、同じように比べます。サンドボックスの外のシェルがプローブのパスに触れることは、もうありません。レーンのコマンドが拒まれた後、対照をもう一度行います。同じファイルが、ここではまだ書ける（または読める）こと、コマンドが作るはずだった名前がまだ空いていること、プローブのディレクトリがまだ自分の名前の下にあること、を確かめます。
3. **拒否とは、成功した 2 回の対照の間で、レーンのコマンドが自分で最後まで走って失敗したことです。** 差し替えられたプローブは、確認の失敗です。シグナルで止められたコマンド（コマンド自身が止められた場合も、シェルが待っていたプログラムが止められた場合も。write レーンのプロセスは、操作者のどのプロセスも止められます）、そもそも起動できなかったコマンド、終わらなかったコマンド（4）も同じです。どれも、どちらの証拠にもならないので、レーンは未確認になります。扱いはほかの確認の失敗と同じです。read レーンが尋ねるようになるか、すべてのシェルコマンドが尋ねるようになるか、追加ディレクトリならエラーです。
4. **プローブのコマンドには、どれも 10 秒の上限があり、止めるときは、それが起動したものごと止めます。** コマンドは専用のプロセスグループで動かし、グループごと止めます。シェルだけを止めると、シェルが待っていたプログラムが残りました。10 秒は、静かな機械で測った最も遅いプローブの 200 倍です。設計レビューは、write レーンのプロセスがディレクトリの名前を変え続けている間のプローブを測りました。それはファイルを開く処理をすべて遅くします（ADR-0120）。そういうループが 1 つで 1 プローブ 0.25〜0.33 秒、16 個で 1.1〜1.4 秒でした。したがってレーンは、プローブに触れずに、確認を上限まで遅らせられます。その代償は、確認の失敗の代償（3）です。
5. **後片づけは、確認が作ったものを、持っているディレクトリから消し、パスでは何も消しません。** ファイルは、その名前がまだ作ったファイルを指している間だけ消し、プローブのディレクトリは、その名前がまだそのディレクトリを指している間だけ消します。レーンのコマンドがプローブのディレクトリの中に作ったかもしれないものは、そこから名前で消します。その間にプローブの名前の下へ置かれたものは残し、取り残し（ADR-0107 §4）にも挙げません。それは確認のものではなく、操作者に消すよう伝えるものでもありません。
6. **ファイルを名指さない対照は、サンドボックスの外のシェルコマンドのままです。** ソケットの接続、シグナル、拒否されたプログラムの起動です。4 の上限は付きます。
7. **ファイル読み取りの確認も、同じ規則に従います。** 2 つのプローブは、開いたまま持つそのディレクトリ経由で作り、消します。そのディレクトリは作業ディレクトリの中にあり、そこは write レーンが書けます。対照は、資格情報の名前を持つプローブをランタイム自身が読むことで、檻の中の読み取りの前と後に行います。檻による拒否と数えるのは、カーネルに読み取りを拒まれたという子プロセス自身の報告だけです。ほかの理由で失敗した子、止められた子、上限までに終わらなかった子は、確認の失敗です。ファイル読み取りの確認が失敗したときの扱いは、これまでと同じです。読み取りはこのプロセスの中で、名前の照合を境界として行います。
8. **read レーンのスクラッチのプローブは、誰にも分からなかった名前にします。** これまではスクラッチのディレクトリの中の決まった名前で、そのディレクトリは作業ディレクトリの中にあります。前もってその名前の下に置かれたリンク越しに `x` が書かれました。狙う瞬間は要りませんでした。
9. **クリップボードの取り込みのファイルは、ランタイム自身の状態ディレクトリに作ります。** 設計レビューは同じ型を確認の外でも探し、ここで見つけました。ファイルは一時ディレクトリに作っていて、そこはどの write レーンも書けます。そして `osascript` は、サンドボックスの外で、渡されたパスへクリップボードを書いていました。本物の write レーンのプロファイルの下で、その名前の下へ動かしたリンク越しに、どのレーンも書けないファイルへクリップボードが書かれました。

## Consequences

- write レーンのプロセスは、確認を失敗させることはまだできます。プローブを差し替える、プローブのコマンドを止める、機械を遅くする、のどれかです。通知はどれであるかを伝え（プローブが差し替えられた、プローブのコマンドがシグナルで止められた、終わらなかった）、そのセッションは、尋ねずに実行していたはずのものを尋ねるようになります。そうしても、レーンの外には何も届きません。
- プローブを差し替える、プローブのコマンドを止める、プローブを誰にも開けなくする、コマンドが作ろうとしている名前を先に取る、のどれによっても、確認を通すことはもうできません。残余: レーンのコマンドを自分の理由で失敗させ、2 回目の対照の前にそれを元へ戻すプロセスは、その失敗をレーンによるものに見せられます。数ミリ秒しか離れていない 2 つの瞬間を、先に見つけなければならないプローブに対して当てることになります。そういうループがどれだけ勝つかは測っていません。これが意味を持つのは、確かめているレーンが拒むべきものを拒まないときだけです。read レーン、追加ディレクトリの資格情報の名前、ファイル読み取りの檻では、write レーンがそのプロセスを閉じ込めたまま、そうなりえます。
- 対照は、シェル自身のリダイレクトがサンドボックスの外で動くことを、もう示しません。「このパスにここで書ける」以外にそれが示していたのは、クォートしたパスがそのファイルを指すことでした。それは `shellQuote` 自身のテストが示すようになり、レーンの中で成功しなければならないプローブは、今もシェルを通ります。
- 残余: プローブを作るディレクトリ（プロジェクト、追加ディレクトリ、作業ディレクトリ、承認済みキャッシュ、`/private/tmp`）は、パスで開きます。確認が始まる前に別のディレクトリへのリンクに差し替えられていると、プローブはそこに作られ、そこから消されます。作られて消されるのは、確認が作ったランダムな名前のファイルだけで（ファイル読み取りの確認では決まった名前が 2 つで、空いているときだけ作ります）、ほかには何も起きません。
- 残余: レーンが実行するコマンドは、今もプローブをパスで名指し、差し替えの後にそのパスがどこへ届くかは、レーン自身のプロファイルが決めます。write レーンのプロセスにとって、これは無ではありません。read レーンは `/private/var/tmp` に書けますが、write レーンは書けません。したがって、対照とレーンのコマンドの間の一瞬に、リンクでそこへ導かれた read レーンのプローブは、そこのファイルに `x` を書きます（設計レビューが測りました）。その確認は、2 回目の対照で失敗します。
- 測っていないこと: ネットワークのボリューム（SMB、NFS）。比較は 2 つの番号を同じ時点で取るので、そこで成り立つ必要があるのはそれだけです。`PROBE_TEST_VOLUME` で、操作者が選んだボリュームの上で確認を走らせられます。
- ここでは決めていないこと: 設計レビューは、同じ種類の場所をコードの中にあと 3 つ読み取りましたが、実行はしていません。どれも、レーンが書けるディレクトリに対して、そのディレクトリ自体が差し替えられたかもしれない後で、パスで操作するものです。ADR-0120 がパスで名指すルートについて記録した残余と同じです。扱う時期は操作者が決めます。

## Tests the design requires

- 本物の write レーンのプロファイルの下のループが、見つけたプローブをすべてリンクに差し替える中で（ファイル、次にディレクトリ）、すべての確認を 15 回、かつ、どれかの確認が差し替えられたプローブに出会うまで実行する。外のディレクトリでは、何も変わらず、消えず、作られず、ディレクトリ自体にも触れられない。
- 同じことを、各プローブのファイルに FIFO を被せて行う。確認はどの巡も戻ってくる。
- 競争なしで: プローブのファイルを 1 つずつ、作られた瞬間と、対照が書いた瞬間に差し替える。確認は毎回、差し替えられたプローブで失敗する。
- 差し替えの種類ごと（外へのリンク、ディレクトリの中の別の名前へのリンク、ハードリンク、読み手のいる FIFO といない FIFO、別のファイル、ディレクトリ、何も無い）に、対照がその場で断る。差し替え先はそのままで、後片づけもそれを残す。
- レーンのコマンドの最中に誰にも開けなくされたプローブと、コマンドが作るはずだった名前を別のものに取られた場合は、確認の失敗になる。
- 開いたときに空でないプローブのディレクトリは使わず、中のものは何も消さない。後からリンクに差し替えられたディレクトリは、通り抜けない。
- 終わらないプローブのコマンドは、起動したものごと上限で止められ、その確認は失敗する。シグナルで止められたコマンド、シェルの下でプログラムを止められたコマンド、起動できなかったコマンドは、拒否ではない。
- 追加ディレクトリの確認も同じように失敗する。名前を取られた場合、資格情報を読んでしまう read レーンの下で資格情報のプローブを開けなくされた場合、コマンドの最中にプローブのディレクトリを差し替えられた場合。読み取り専用の追加ディレクトリでプローブのディレクトリが差し替えられた場合は、通知ではなくエラーになる。
- プロジェクトと追加ディレクトリを FAT と exFAT のボリュームに置いても、すべての確認が通り、何も残らない（`PROBE_TEST_VOLUME`。無ければ一時ディレクトリのボリュームで走る）。
- ファイル読み取りの確認は、子プロセスが拒否を報告したときだけ通り、プローブが消えた、差し替えられた、開けなくなった、のどれでも失敗する。
- スクラッチのプローブは、以前の名前の下で待っているリンク越しに書かない。
- 確認のパッケージには、ファイルをパスで名指す呼び出しが無く、プローブのコマンドを起動する場所は 1 つである。
- 性質を 1 つずつ元に戻すと、どれもテストが検出する。30 個ある。

## Alternatives considered

- **シェルの対照を、プローブ自身のパスへの書き込みだけを許すプロファイルの中で実行する** — 採りません。そのパスの FIFO では、やはり待ちます。別のファイルへのハードリンクがそのパスと見なされるかどうかは、文書にありません。プロファイルの言語自体も、文書にありません。
- **どのレーンも書けない場所にプローブを作る** — できません。プローブが示すのは、レーンが書く場所でレーンが何をするかです。
- **ディレクトリを `os.Root` として持つ** — 採りません。ルートは中の別の名前へのリンクを辿り、ハードリンクを開くので、書き込みがプロジェクトの別のファイルに落ちえます。`Root.OpenRoot` は FIFO で待ちます（Context）。
- **見るだけのシェルの対照（`[ -e path ]`）を残す** — 採りません。それが示すのは、クォートしたパスがそのファイルを指すことで、`shellQuote` のテストが、起動のたびにサンドボックスの外でシェルを動かさずに示します。
- **時間の上限だけを付け、ほかは変えない** — 採りません。リンク越しの書き込みと、ディレクトリ越しの削除が残ります。
- **確認が開くディレクトリを、ファイルツールがすでに持っているルートと比べる** — ここでは行いません。プロジェクトと追加ディレクトリについて 1 つめの残余を閉じますが、確認にそれらのルートを渡す必要があります。
