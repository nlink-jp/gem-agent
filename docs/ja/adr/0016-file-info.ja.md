# ADR-0016: file_info — 種別判定・メタデータ・ハッシュ

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「ファイル種別の判定（file コマンド相当）や、ファイル情報（サイズ・日付・ハッシュ値など）を取るファンクションもあってよいかも」 |

## Context

モデルはファイルを読み・探し・見られるが、「このファイルは**何なのか**」には
読まずに答えられない — そしてバイナリは読むことすらできない（`read_file` は
正しく拒否する）。これで答えられなくなる問いは、まさにオペレータの IR 業務が
始まる問いである: この実行ファイルはどの種類か、いつ変更されたか、そして
**ハッシュは何か** — 組織自身の malware-lookup MCP は MD5/SHA1/SHA256 を
食べるのに、今それを作る手段は承認ゲート付きの `shell_exec shasum` しかない。

## Decision

読み取り専用の組み込み `file_info(path)` を 1 つ — バッチ用に `paths: [...]`
も（edit_file の二形式の前例）— 他のモデル起点ツールと同じくプロジェクト
封じ込め。ファイルごとに報告する:

1. **内容から判定した種別** — `file` コマンドの仕事: MIME 判別に加え、IR が
   実際に出会うもののマジック補正（Mach-O は fat・64bit 変種込み、ELF、PE、
   zip/gzip、PDF、SQLite、shebang スクリプト）、テキスト/バイナリ判定と
   テキストの行数。拡張子は報告するが決して信用しない — 種別判定の眼目は
   不一致を捕まえることにある。
2. **メタデータ** — サイズ、モード（実行ビットは明示）、更新時刻、そして
   **作成時刻（birth time）**: gem-agent は設計として macOS 専用なので、
   Darwin 固有フィールドを使っても約束した移植性は何も失わない
   （ADR-0001 の論法の再演）。
3. **ハッシュ — MD5・SHA1・SHA256** をストリーミング 1 パスで。まさに
   malware-lookup が取る三点セットであり、「ハッシュして照合」がシェル往復
   なしの 1 ループになる。過大ファイル（>512MB）は停滞させず、注記つきで
   ハッシュを省略する。
4. **symlink は報告し、黙って辿らない**: リンク先を表示し、内容の検査は
   解決先がプロジェクト内に留まる場合だけ — 他の全てと同じ封じ込めの話。
5. ディレクトリはエントリ数と浅いサイズ。ハッシュ無し。

## Consequences

- IR の初手 — 識別・日付・ハッシュ・照合 — が 1 つのエージェントループ内で
  回り、ハッシュ三点は MCP ツールへ直結する。
- 組み込みが 10 個。案内はツール説明文が持ち、システムプロンプトは太らない。
- 種別判定は libmagic ではなく有限のマジック表: 知っているものを名指し、
  それ以外は正直に `data` と言う。表の拡張はテスト先行の編集であって、
  依存の追加ではない。

## Alternatives considered

- **`shell_exec` で済ます（`file`・`shasum`・`stat`）** — *答え*としては
  却下（手段としては残る）: 読み取り専用の質問に毎回承認ゲートの儀式が
  つき、出力形式はまちまちで、1 コールで済むものに 3 コマンド要る。
- **libmagic / Go の magic ライブラリ** — 却下。フォールバックツールに
  依存を足して、ループが尋ねもしない数千形式を買うことになる。
- **ハッシュをパラメータで opt-in** — 却下。このオペレータにとって
  ハッシュは機能の中心であり、種別判別と並走するストリーミング 1 パスは
  プロジェクト規模のファイルではほぼ無料。
