## Context

ランタイムは聞かずに走るものを守り、承認や操作者の行為が要るものは残余として記録する。以下の監査の 3 件は後者に当たるか、すでに決まっていたものだが、理由が不十分だったり、操作者の読まない場所に書かれていたりした。

## Decision

1. **`agentic_file_search` の中の読み取りには、フックもツールごとのポリシーもない。** ADR-0072 §3 は、子が読み取り専用で変更を拒むことを理由にフックについて受け入れたが、`always` ポリシーには触れておらず、操作者向けのリファレンスは両方が全モードで効くと書いていた。同じ理由が両方に当てはまる。リファレンスに例外を明記し、すべての読み取りを見る必要があるガードは `agentic_file_search` 自体を対象にするよう書く。資格情報の読み取りは子でも拒否する。
2. **祖先の指示ファイルは信頼の確認の外のままとする。** これを読むことは、ランタイムが守るドロップイン互換の動作である。ADR-0023 の理由（クローンは自分より上にファイルを置けない）は、クローンのサブディレクトリで始めたセッションには当てはまらない。クローンの最上位の `AGENTS.md` は祖先になり、サブディレクトリ自身に何もなければ確認も出ない。そこで始めるのは操作者の行為である。越えるのは指示の文だけで、祖先の MCP サーバーとスキルは読み込まれず、承認ゲートとサンドボックスは残る。リファレンスには、信頼していないリポジトリは最上位で始めるよう書く。移し込まれたディレクトリの経路は ADR-0074 §3 と ADR-0099 §10 の残余で、承認された write レーンのコマンドと、その下で開く後のセッションが要る。
3. **ファイルツールの判定と書き込みは、違うリンクを見ることがある。** ADR-0108 は、`os.Root` が開く先をルートの中に保つことを理由にこの残余を記録した。それは閉じ込めの答えであって、下限の答えではない。`.git` と `.claude` はルートの中にあるので、判定の後でリンクを向け直すと、直接の呼び出しなら拒否される書き込みがそこに届く。成立には、以前に承認された write レーンのコマンド、走り続けるバックグラウンドの子、判定と書き込みの間に合わせた変更が要る。この前提条件と、閉じるには 1 つの狭い競合のために判定から書き込みまでディレクトリハンドルを持ち回る必要があることから、受け入れる。

## Consequences

- 動作は変わらない。
- 読み取りツールに対するガードはファイル検索の子を覆わない。リファレンスにそう書く。

## Alternatives considered

- **子にフックとポリシーを渡す** — 採らない: 子の価値は検索に回答が要らないことにある。読み取りに必ず効かせたいフックは、見えている `agentic_file_search` を名指せばよい。
- **祖先の探索をリポジトリの最上位で止める** — 採らない: モノレポのすべてのセッションで読み込むものが変わり、ドロップイン互換の要件に反する。
