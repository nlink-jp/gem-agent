## Context（背景）

前回の全体レビュー（ADR-0031）から本レビューまでに 10 リリースが
着地し、その多くがターンループの内側に手を入れた: 子検索
エージェント（ADR-0037）、リスク層への指示コンテキスト（ADR-0038）、
セッション中リロード（ADR-0039）、ラウンド上限の介入ラダー
（ADR-0040）。レビューは、保守者によるループ精読と独立レビュワー
3 体（agent/llm・cmd 配線・TUI）、`go vet`、全パッケージの race
detector を組み合わせ、レビュワーの主張は全件コードかプローブで
再検証してから数えた。所見 16 件、うち高 3 件。

## Fixed（修正）

### 1. 子検索エージェントがモデル作成の質問中の `@` 参照を展開していた（高）

`agent.Run` は全入力に `@` 文法を適用し、その文法は「`@` は常に
オペレーターがタイプする」という明示的前提のもとでプロジェクト外の
読み取り — 画像・文書・メディアの絶対/`~` パス — を許可している。
ADR-0037 はその前提を見直さずに質問をモデル作成にした: 毒された
ファイルがメインモデルを `agentic_file_search(question: "… @~/
Documents/contract.pdf …")` へ誘導すれば、子はその PDF をネイティブに
添付し、報告が内容を持ち帰る — 子に `onAttach` が無いので不可視で。
`Options.NoMentions` を子に設定して修正。質問中の `@` トークンは
ただのテキストになった。ナレッジベースに記録する教訓: 「この入力は
人間だけが書く」を根拠にした許可は、モデルがその入力を書けるように
なった瞬間に穴になる — 委任を導入するときは全入力チャネルの信頼
前提を棚卸しせよ。

### 2. live 領域がタブを展開していなかった（高）

`emit()` はスクロールバックの幅クリップ前にタブを展開するが、
`liveView()` は生のストリームテキストを返し、`ansi.Truncate` は
`\t` を 0 セルと数える一方、端末は次のタブ位置まで進む。タブ
インデントのコード行がクリップを通過して管理領域を折り返した —
v0.34.1 で直したレンダラ desync のクラスが、反対側から再侵入して
いた。`liveView` はタブを展開するようになり、差を測ったプローブ
（タブ 3 + 90 文字: 79 セルと数えて 103 セル描画）はテストになった。

### 3. stdin に 2 本目の `bufio.Reader`（高）

ask_user 経路（ADR-0036）— 今はラウンド上限ダイアログも運ぶ — が
`os.Stdin` を独自の reader で包んでいた。素の REPL と承認ゲートは
1 本を共有しており、AGENTS.md が名指しで禁じる構成: typed-ahead は
先に埋まった方のバッファに取り残され、パイプ駆動ではセッションが
ハングしうる。asker は共有 reader を読むようになり、2 本目の
reader が無いことをソースレベルのテストが固定する。

### 4. ask ダイアログが自分の質問を切り詰めていた（中）

質問は 1 行で描画され、200 ルーンで clip された上に端末幅で無告知に
切断されていた（ラウンド上限ダイアログで実測: レビュワーの理由が
単語の途中で消えた）。ボックスは質問と選択肢を内幅で折り返し、
高さを予算化し、非表示行を開示するようになった — 承認ダイアログの
規律をその兄弟に適用した。

### 5. 停滞検知器に 3 つの穴（中）

`toolRunning` はツールコールで立ち、**どんな**ストリームチャンク
でも下りていた — しかしツール実行中に流れるストリームはサイドコール
（リスク評価・進捗レビュー）だけなので、長い自動承認ツールが偽の
停滞警告を出し、評価器の思考がモデルの思考として描画された;
`!command` はハートビートを起動して持っていない接続について警告
した; フラグは中断されたターンを生き延びて次ターンの検知器を無効化
した。今はエージェントが全コール（実行・拒否・スキップ）の後に
`OnToolDone` を発火し、TUI はそれだけで再武装、ツール実行中の
サイドコール思考は無視、ターン境界でフラグをリセット、シェル経路は
コマンドの間フラグを保持する。

### 6. 思考行が最も古い語を見せていた（中）

2 行分のルーンで前方を刈った後に 1 幅で切断 — 最新の思考テキストは
決して見えなかった。折り返して最後の 2 物理行を残すようになった。

### 7. Ctrl+C 後のチェックポイント、監査の穴（中）

`roundIntervention` と `plainAsk` はキャンセル済み context を無視し、
チェックポイント直前に中断された素の REPL ターンがプロンプトで
ブロックした; 両方とも先に確認する。自動コンパクションは監査
ストリームに届いていなかった — `/compact` だけがイベントを出して
いた; 送出を `Agent.Compact` に移し、両経路が記録する。非対話の
延長は無言だった; 自己申告するようになった。

### 8. 小さな修正（低）

子はラウンド上限エラーを文言一致ではなく型付き `RoundLimitError` の
`errors.As` で検出; 報告の切詰めは rune 安全; ループトリガーの証拠は
当該コールを含み、loop-guard でスキップしたコールは `outcome=skipped`
で監査; ダイアログの理由は clip; `/usage` はレビューを正直に
ラベル（"risk & progress reviews"）; 起動ノートの tee はバナー後に
凍結（セッション全体を記録しない）; `releaseTurn` は pending の
承認も ask と同様に drain; 選択肢 0 個の `AskRequest` で UI は panic
しない。

## Deliberately not changed（意図的に変えないもの）

- `…`（U+2026）は East Asian Ambiguous; ambiguous を全角描画する
  端末では width-1 に clip した行が最終列に乗りうる。環境依存で、
  最終列の pending-wrap 状態に限定され、開発端末では再現しない; 記録
  のみ。
- `/mcp reload` はサーバー接続の間その場をブロックする（ADR-0039 が
  受容）; 変になったサーバーは接続タイムアウトまでハングに見える。
  将来の改良: 進捗行付きの非同期化。
- ダイアログの 300 ms typed-ahead 猶予内の Ctrl+C は他のキー同様に
  飲み込まれる（1 打余計）; 猶予は飛行中のキー入力でダイアログに
  答えてしまう事故を防いでおり、その代価に値する。

## Consequences（帰結）

- 子検索エージェントの封じ込めは想定ではなく事実になった。
- inline レンダラの幅不変条件は両側 — 管理領域とスクロールバック —
  で成立し、タブも両側で押さえた。
- ハートビート・ダイアログ・素の REPL のプロンプトは、中断・auto
  モード・サイドコールの下で同じに振る舞う。
- レビューの方法（保守者精読 + 独立レビュワー + race detector、主張
  全件の再検証）は次回の雛形である。
