## 文脈

第 1 回レビュー（ADR-0021）以降に増えた約 4,200 行に対し、5 つの
観点（並行性/FS・TUI 不変条件・セキュリティ境界・LLM データ形状・
config/カタログ整合）で並列レビューを行い、各所見はコード照合 — 
測定可能な主張は実測 — で検証してから受理した。機械検査（`-race`
全走・vet・govulncheck）はすべてクリーンで、以下の欠陥はすべて読解
で見つかり、テストの失敗では 1 件も見つからなかった。それ自体が
第 1 回の教訓の再演である: テストは一度戦ったものを固定するのであり、
一度も配線されなかったものは固定しない。

## 修正した

### 1. 配線と言語（ADR-0029 の後始末）
- **`Msgs` が TUI に渡っていなかった** — カタログは cmd で解決され
  プロンプトと slash 出力には配られたが、`tui.Options` リテラルが
  フィールドを落としており、TUI クローム全体が英語にフォールバック
  していた。修正は 1 行 — 加えて AST レベルの配線テスト: 必須
  フィールドが Options リテラルから消えると失敗する。REPL を起動
  せずにあのリテラルへ届く挙動テストは存在しないからである。
- plain REPL の中断/エラー/bye 行、shift+tab の切替通知、`/mcp`
  出力、「unknown command」は ADR-0029 の対象面なのに英語直書き
  だった — すべてカタログへ。
- `/mcp` は「MCP ツールは常に承認が必要」と主張していたが、auto
  モードのリスク段は日常的な呼び出しを通せるし 'a' はセッション中
  そのツールをカバーする。ゲートの実際を言う文面に改めた。

### 2. 承認の完全性
- **拒否した `view_image`/`read_document` がバイトを添付していた**:
  添付分岐は `error:` 接頭辞だけを見ており、拒否文字列はそれを
  持たない。拒否文字列を名前付き定数にし、両分岐が識別する。
- Ctrl+C でターンを中断した後に届いたツール呼び出しが承認ダイアログ
  を開き得た（'a' 回答は死んだ呼び出しの代理で allowlist に載る）:
  execCall はキャンセル済み context で拒否し、TUI は中断〜TurnDone
  間のゲート要求を自動拒否する。
- 低い端末では承認フレームが溢れ、View クランプが**上から** — 
  まずタイトルから — 無開示で切っていた。詳細バジェットを高さに
  適応させ、タイトルと選択肢は常に描画、省略件数は正直なまま。
  `clipDetail` の件数も 600 ルーン事前クリップ後に数えており過少
  報告だった。

### 3. セッションと状態の整合
- **resume が Reopen の flock 取得前に transcript を読んでいた** — 
  ロックが塞ぐべき隙間そのもの。履歴はロック保持下で、開いた
  Logger 自身のパスから読む。
- `lockSession` は全 flock errno を「使用中」と誤診し、失敗時に
  O_EXCL で作ったばかりのファイルを残していた。errno を区別し、
  正確なパスのファイルを除去する。
- statedir の 2 回目のマーカー読みは「非空 = 自分の所有」と比較
  なしに結論していた — 2 回の読みの間に衝突プロジェクトのマーカー
  が rename され得る。2 回目も照合する。
- policy.toml は各プロセスの起動時スナップショットから全体を書き
  戻しており、stale な並行ライターが直前に拒否した trust を復活
  させ得た。すべての変更は `MutatePolicyFile`（flock・新鮮読込・
  単一変更・保存）を通る。

### 4. メディアストア（ADR-0027 の後始末）
- content-addressed 不変条件に穴が 2 つ: ハッシュ後にパスで開き直す
  （その間の rename 置換で旧ハッシュ名に別バイト）、`io.Copy` 失敗
  後の `Close` が部分バッファを完成オブジェクトとして**確定**する。
  どちらも恒久ストアを無音で汚染した。今は: 両パスとも単一 fd、
  アップロード中に再ハッシュして不一致でストリームを失敗させる
  検証リーダー、中断が何もコミットしないキャンセル可能な writer
  context。
- アップロードがターン context を無視していた（Ctrl+C が数分の
  アップロードに届かない）— コールバックはターンの ctx を取る。
- `sync.Once` が一時的な構築エラーをセッション全体に固定していた —
  成功だけをキャッシュする。
- `GOOGLE_CLOUD_QUOTA_PROJECT` がプロセス env に残り続け、以後の
  すべての `shell_exec` 子に漏れていた — クライアント構築直後に
  復元（実アップロードで検証済み）。

### 5. リソース上限
- docext はメンバー単体の上限だけで合計がなく、上限内のシート/
  スライドが最終クリップ前に無制限に蓄積した — `read_document` は
  承認不要なので、細工ブックはモデルから到達可能なメモリ枯渇
  だった。抽出はテキストバジェットで停止する。mention の Office
  分岐にも PDF 分岐と同じ 32MiB ファイル上限を追加。

### 6. 小さな正直さの修正
- Tab 補完の最長共通接頭辞がバイト単位で削れていた: 資料/説明は
  UTF-8 先頭バイトを共有し、補完が单独の 0xE8 を入力欄に書いた
  （実測）。ルーン単位に。
- ADR-0007 が約束した「実行中も入力が見える」の入力欄が描画されて
  いなかった — 描画するように。
- `emit` は完全充填を仮定していたが、折返し列を跨ぐ全角ルーンは
  丸ごと次行へ折り返す — 数えられなかった行がボトムピンをずらした。
  端末の貪欲折返しをシミュレートして数える。
- 正常終了がターン context を cancel していなかった（ターンごとに
  子 context が 1 つリーク）; 'p' 回答が最後の 2 書き込みイベント
  だった; settings パネルが高さ 8 で 1 行溢れた（最小 9 に）。
- `/settings` に追跡済みなのに非表示だった 2 行（`agent.compact_at_pct`・
  `mcp.enabled`）を追加。theme 行は「適用した」と言って何も適用しない
  編集可能行だった — 再起動注記つき読み取り専用に。language 行は
  `auto` の解決先を表示。パネルでの変更は出所を `session` と表示。
- `agent_info` は MCP 一覧を起動時スナップショットと明示し、trust
  拒否でプロジェクト由来ツールが不在なことも報告する。trust
  プロンプトのスキル数は SKILL.md を持つディレクトリだけを数える。
  `/exit` は補完可能になり別名として文書化。ツールメッセージの
  添付（view_image/read_document の PDF）にもユーザー添付と同じ
  untrusted-data 注記。`estimateTokens` はツール引数とインライン
  バイトを数える。`[model].thinking` 設定時や gs:// 添付履歴での 400 は
  設定キーや回復手順を名指しする。空の `[gcp].location` は config
  読込時に失敗する。

## 実測で反証した

「未応答 FunctionCall で終わる transcript（ツールラウンド中の強制
kill）は resume 後の全ターンが 400」という主張: ちょうどそこで
切った transcript を実 API に resume させたところ正常に応答した — 
第 1 回レビューで「確実」とされた 400 主張 2 件が実測で崩れたのと
同じ構図。サニタイザは追加していない。

## 意図的に変えなかった

- MCP ツールは構造的に Block 段に達しないため、セッション 'a' が
  以後の任意引数をカバーする — ADR-0004 の設計。`/mcp` の文面が
  過大宣伝をやめた。
- `/skill` が注入するスキル本文は @-展開を通る（悪意あるスキルは
  プロジェクト外ファイルを添付し得る）— スキルはオペレーター自身の
  ディレクトリか信用済みプロジェクトからしか読み込まれないことで
  拘束されており、コードでなくここに記録する。
- statedir の write-write 初回起動競合（異なる 2 プロジェクトが
  同時に新規ディレクトリを主張）は後勝ち rename のまま: マーカーは
  best-effort の識別子でありロックではない。
- CreateTemp〜Rename 間のクラッシュが残す `.project.tmp-*` は掃除
  しない: 掃除にはワイルドカード削除が要り、この運用者の削除の
  鉄則が禁じる。残骸は無害。
