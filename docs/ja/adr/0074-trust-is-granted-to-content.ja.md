# ADR-0074: 信頼はパスではなく内容に与える — エージェント向けファイルのピン留め

|-------|-------|

| 日付 | 2026-09-05 |

| 契機 | ADR-0073 §6 の残留: サブディレクトリの永続ファイルは親ディレクトリの rename で置き換えられ、write レーンのパス規則には見えない |

## 背景 — 残留と、それが何のインスタンスか

ADR-0073 は後続セッションが信頼するファイル（`AGENTS.md` 類・`.mcp.json`・
`.gem-agent.toml`・`.claude/`・`.git` とその hooks/config）を**パス**に紐づく Seatbelt
規則で守る。独立検証はその鍵の限界を示した: `mv sub sub.old && mv prepared sub` は
パス `sub` と `sub.old` にしか触れないのに、後には `sub/CLAUDE.md` が別のファイルに
なっている。実測（macOS 26）:

| write レーンのプロファイル | `mv sub sub.old` | `echo > sub/other.txt`・`mkdir sub/deeper` | `mv scratch/prepared brandnew`（`CLAUDE.md` 入りの新ディレクトリ） |
|---|---|---|---|
| 出荷版（永続名の regex） | **許可 → 差し替え成立** | 許可 | 許可 |
| 既存永続ファイルの各親に `(deny file-write* (literal <proj>/sub))` を追加 | **拒否** | 許可 | 許可 |

親ディレクトリ*エントリ*への名指し deny は、プロファイル生成時に存在する永続ファイル
の差し替えを、そのディレクトリ内の通常作業を止めずに閉じる。存在しなかった準備済み
ディレクトリの移し込みは閉じられない — 宛先名は新規の通常名だから。

これは 1 つのクラスのインスタンスで、クラスこそが根本原因: **名前に紐づいた信頼**。
既に 2 つのインスタンスがある:

- **最終レビュー R2**（実パス判定と作成→rename 書込で修正済み）: 通常ファイルの名前の
  リンクが `AGENTS.md` への書込を運んだ。
- **ADR-0023 の信頼そのもの**: 操作者は*ディレクトリ*を一度信頼し、以後 `AGENTS.md`・
  `.mcp.json`・スキルが*何を含もうと*読み込まれる。`AGENTS.md` を変える `git pull`、
  `.mcp.json` を書き換える依存更新、上の差し替え — すべて付与済みの信頼を無確認で通る。
  信頼されたのは名前で、消費されるのは内容。

パス規則は*書込がどこに着地できるか*を縛る。*信頼する読み手が後でその名前の下に何を
見つけるか*は縛れない — 読み手の名前は祖先・リンク・時間を通じて解決されるから。
それを縛れる規則は内容そのものに鍵を持つ規則。

## 決定

### 1. gem-agent が消費する内容をピン留めする

ADR-0023 の信頼プロンプト時 — および信頼を（再）付与するとき — プローブが列挙する
全エージェント向けファイルの SHA-256 **ピン**を記録する: プロジェクトルートの指示
ファイル、`.mcp.json`、`.gem-agent.toml`、各プロジェクトスキル（`SKILL.md` とスキル
ディレクトリのファイル一覧のダイジェスト）。ピンは機械所有の `policy.toml` の信頼記録
の隣に置く（`[projects."…"] pins = { … }`）。

この変更後、既に信頼済みのプロジェクトの初回起動は現在の内容をピンとして記録し、
そう告げる（trust on first use）: 操作者が読み込んできたファイルが今日信頼するもの。

毎回の読み込み — 起動・`/clear`・`/mcp reload`・`/skills reload` — で消費前に照合する:

- 不変 → 従来どおり読み込む
- 変化または新規 → **対話時**: ファイル名と要約を添えた確認 1 行
  （`AGENTS.md changed since you trusted it (1,234 bytes). Trust the new content? [y/N]`）。
  `y` でピン更新、`N` でそのセッションからそのファイルを外す。**非対話（`-p`）**:
  変化ファイルは読み込まず stderr 1 行で告げ、そのファイルについてはセッションを裸で
  走らせる（ADR-0023 §5 の「未決定」規則: 何も拒まず、未確認のものは何も読まない）
- gem-agent 自身が**操作者の承認**で書いたファイル（operator レーンのコマンド、操作者が
  答えた OperatorOnly の `write_file`/`edit_file`）は成功時に再ピン — 操作者はその書込を見た

`gem-agent trust` は信頼状態・ピン・差分のあるファイルを表示し、`gem-agent trust --accept`
は現在の内容を信頼済みとして記録する — 意図した編集の後のスクリプト `-p` フロー向け。

### 2. 既存の入れ子永続ファイルの差し替えを閉じる

write レーンのプロファイルは、プロファイル生成時にプロジェクト配下で見つかった永続
ファイルの親ディレクトリと、プロジェクトルートまでの各祖先に `(deny file-write*
(literal <dir>))` を加える（有界走査、信頼プローブと同じ上限）。`/clear` でプロファイル
とともに再生成。それらのディレクトリ内の通常書込は許されたまま（上で実測）。

### 3. 消せない残留を可視化する

新しい入れ子永続ファイルを運ぶ準備済みディレクトリの移し込みはパス規則で表現できない。
狙われるのは*他の*消費者 — Claude Code の入れ子 `CLAUDE.md`、入れ子リポジトリのフック —
で、gem-agent 自身（ルートと祖先だけを読む）ではない。閉じたと偽らず可視化する:
`/clear` とセッション終了時に、プロジェクト配下の永続ファイル集合をセッション開始時と
比較し、追加と変更を stderr とトランスクリプト（`persistent_changes` 記録）に報告する（`this session added
sub/CLAUDE.md and changed vendor/x/.git/hooks/pre-commit`）。走査は §2 と同じで有界、
打ち切りは告げる。

### 4. 操作者の git が消費するものの助言的ピン

ルートリポジトリの `.git/hooks/*` と `.git/config` もピン留めするが助言的にのみ: 前回
セッションからの変化は起動時に報告（「`.git/hooks/pre-commit` changed since your last
session」）し、決してブロックしない — 走らせるのは gem-agent ではなく git で、操作者が
編集したのかもしれない。

## 検討した代替案

- **Seatbelt の「包含」述語。** 存在しない。SBPL のフィルタは操作対象エントリのパスに
  マッチする。
- **write レーンで全ディレクトリ rename を拒否。** パスで表現できず（ディレクトリと
  ファイルは同じに見える）、`mv src lib` のリファクタを禁じる。
- **永続ファイルの immutable フラグ（`chflags uchg`）。** 所有者が外せる。祖先の rename
  には無関係。操作者のエディタと衝突する。
- **信頼したファイルを state ディレクトリに複製してそこから読む。** ピンと等価だが重く、
  `AGENTS.md` を編集したばかりの操作者を混乱させる。ピンは比較して尋ね、複製は無言で
  食い違う。
- **git index（`HEAD:AGENTS.md`）との照合。** 全プロジェクトがリポジトリではなく、
  悪意あるコミットは両側を変える。
- **記録以上は何もしない。** ADR-0023 自身の穴を開けたまま: `git pull` が無確認で
  再信頼される。

## 影響

- gem-agent 自身の消費について「名前に紐づいた信頼」クラスが閉じる。残るパス規則は
  保証ではなく防御の深さになる。
- **コスト:** gem-agent の外で `AGENTS.md` を編集すると次回起動で `y` が 1 回。その後の
  `-p` パイプラインは `gem-agent trust --accept` まで変化ファイル無しで走る。起動時に
  数個のダイジェストと有界走査 1 回が増える（信頼プローブは既に `.claude/skills` を
  走査している）。
- **挙動変更**（破壊的変更手順）: 既定 ON、オプトアウトは `[approval].pin_trusted_files
  = false`。CHANGELOG は `Breaking:` を付す。
- 他消費者向けの残留（§3）は ADR と approval リファレンスに残留として明記し、閉じたと
  主張しない。

## 決定事項（2026-09-05）

操作者は全点で推奨を採った: ピンは既定 ON でオプトアウトは `[approval].pin_trusted_files
= false`。`-p` は起動拒否ではなく変化ファイルを飛ばす。ピン対象はルートの指示ファイル・
`.mcp.json`・`.gem-agent.toml`・プロジェクトスキルで、`.git/hooks` と `.git/config` は
永続ファイル snapshot による助言。永続ファイル走査は 20,000 エントリで止まりそう告げる。

## 他エージェントの調査（2026-09-05）

主要コーディングエージェントで信頼を内容に紐づけるものは現時点で無い: Claude Code・
Codex CLI・Gemini CLI・Copilot CLI・Cursor は `git pull` 後も続くディレクトリ単位の信頼を
永続化する。Claude Code の `ConfigChange` hook はセッション中の設定変更に反応できるが、
操作者が書くポリシーで既定の再確認ではない。指示の散文（`AGENTS.md` 類）をゲートするのは
Gemini CLI だけで、2025〜26 の複数の事故はまさにそのファイル経由で実行に達した。設定
ディレクトリの自己書換えは Claude Code・Codex・Cursor（ルールディレクトリを除く）が
ゲートする。したがって本 ADR のピンは業界からの意図的な逸脱であり、監視すべきコストは
再信頼プロンプトの頻度。
