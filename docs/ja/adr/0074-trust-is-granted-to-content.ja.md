# ADR-0074: 信頼はパスではなく内容に与える — エージェント向けファイルのピン留め

## 背景 — 残留と、それが何のインスタンスか

ADR-0073 は後続セッションが信頼するファイル（`AGENTS.md` 類・`.mcp.json`・
`.gem-agent.toml`・`.claude/`・`.git` とその hooks/config）を**パス**に紐づく Seatbelt
規則で守る。独立検証はその鍵の限界を示した: `mv sub sub.old && mv prepared sub` は
パス `sub` と `sub.old` にしか触れないのに、後には `sub/CLAUDE.md` が別のファイルに
なっている。実測（macOS 26）:

| write レーンのプロファイル | `mv sub sub.old` | `echo > sub/other.txt`・`mkdir sub/deeper` | `mv scratch/prepared brandnew`（`CLAUDE.md` 入りの新ディレクトリ） |
|---|---|---|---|
| 出荷版（永続名の regex） | **許可 → 差し替え成立** | 許可 | 許可 |
| 既存永続ファイルの各親に `(deny file-write* (literal <proj>/sub))` を追加 | **拒否** | 許可 | 許可 |

親ディレクトリ*エントリ*への名指し deny は、プロファイル生成時に存在する永続ファイル
の差し替えを、そのディレクトリ内の通常作業を止めずに閉じる。存在しなかった準備済み
ディレクトリの移し込みは閉じられない — 宛先名は新規の通常名だから。

これは 1 つのクラスのインスタンスで、クラスこそが根本原因: **名前に紐づいた信頼**。
既に 2 つのインスタンスがある:

- **最終レビュー R2**（実パス判定と作成→rename 書込で修正済み）: 通常ファイルの名前の
  リンクが `AGENTS.md` への書込を運んだ。
- **ADR-0023 の信頼そのもの**: 操作者は*ディレクトリ*を一度信頼し、以後 `AGENTS.md`・
  `.mcp.json`・スキルが*何を含もうと*読み込まれる。`AGENTS.md` を変える `git pull`、
  `.mcp.json` を書き換える依存更新、上の差し替え — すべて付与済みの信頼を無確認で通る。
  信頼されたのは名前で、消費されるのは内容。

パス規則は*書込がどこに着地できるか*を縛る。*信頼する読み手が後でその名前の下に何を
見つけるか*は縛れない — 読み手の名前は祖先・リンク・時間を通じて解決されるから。
それを縛れる規則は内容そのものに鍵を持つ規則。

## 決定

### 1. gem-agent が消費する内容をピン留めする

ADR-0023 の信頼プロンプト時 — および信頼を（再）付与するとき — gem-agent がプロジェクト
ルートから消費する全エージェント向けファイルの SHA-256 **ピン**を記録する: ルートの指示
ファイル（`AGENTS.md`・`AGENT.md`・`CLAUDE.md`・`GEMINI.md`。祖先のファイルは操作者自身の
もので、ADR-0023 同様ゲートの外）、`.mcp.json`、`.gem-agent.toml`、各プロジェクトスキル
（ディレクトリとしてピン留め: 配下の全ファイルの相対パスと内容ダイジェスト、リンクは
ターゲット文字列）。消費ファイルはローダーが読むのと同じ方法で — プロジェクト
ディレクトリの `os.Root` 経由で — ダイジェストする: プロジェクト内のリンクはターゲットと
内容でピン留めされ、外へ出るリンクは双方にとって不在。ピンは機械所有の `policy.toml`
の信頼記録の隣に置く（`[projects."…"]` に `pinned_at`、`[projects."…".pins]` 表に
`name = "sha256:…"`）。`pinned_at` により空集合は「未ピン」ではなく記録済みの答えになる —
エージェント向けファイルの無いプロジェクトは「何も無い」として一度だけピン留めされる。

この変更後、既に信頼済みのプロジェクトの初回**対話**起動は現在の内容をピンとして記録し、
ピン留めしたファイル名を告げる（trust on first use: 操作者が読み込んできたファイルが今日
信頼するもの）。ピン未記録での非対話起動は従来どおり読み込み、まだ何もピン留めされて
いないと告げる。何も記録しない — 誰も確認していない信頼を記録することは ADR-0023 §5 が
拒むことだから。

消費前に照合する — 起動時、そして `/clear`・`/mcp reload`・`/skills reload` でも:

- 不変 → 従来どおり読み込む
- 変化または新規 → **対話起動時**: ファイル名・変化の種類・現在のサイズを添えた確認 1 行
  （`AGENTS.md changed (1234 bytes) since you trusted it. trust the new content? [y/N]`）。
  `y` でそのピンを更新、`N` でそのセッションからそのファイルを外し、ピンは元のまま
  （次回起動でまた尋ねる）。**非対話（`-p`）**とセッション中の再照合（`/clear`・reload —
  そこにはプロンプトに向かう人がいない）: 読み込まず 1 行で告げ、そのファイルについては
  セッションを裸で走らせる（ADR-0023 §5 の「未決定」規則: 何も拒まず、未確認のものは
  何も読まない）
- 削除 → 読み込むものは無い。ピンは残すので、その名前で戻ってきた内容は「変化」であって
  「新規」にはならない
- gem-agent 自身が**操作者の承認**で書いたファイル — 操作者が答えた OperatorOnly の
  `write_file`/`edit_file` — は成功時に**その 1 名**を再ピン。ただし書込開始時点で
  ファイルがピンの記録どおりだった場合のみ: 操作者が見たのはその書込で、その前の
  ドリフトではない（`! git pull` の後に 1 行の編集を承認すると pull 全体がピンされて
  しまう）。集合の他は動かさず、このセッションで外した名前への書込も再ピンしない
  （置き換えられた内容を操作者は見ていない）。operator レーンや `!` のコマンドは文面を
  見せるが、それらファイルへの効果は見せないので何も再ピンしない: ピンと食い違う
  ファイルを注記し、次の対話起動が尋ねる

`gem-agent trust` は信頼状態・ピン・差分のあるファイルを表示し、`gem-agent trust --accept`
は現在の内容を信頼済みとして記録する — 意図した編集の後のスクリプト `-p` フロー向け。
未信頼プロジェクトでの `--accept` はエラー: 記録すべき信頼が無い。

`.gem-agent.toml` も消費対象: その approval 半分がポリシーを緩められるのは、操作者の
config がプロジェクトを名指しし（ADR-0023 §4）*かつ*ピンの下で信頼済みの内容であるとき
のみ。変化したファイルは未信頼プロジェクトのものと同様、締める方向にだけ働く。したがって
信頼判定とピン照合はプロジェクトの何かを読む前に走る。

### 2. 既存の入れ子永続ファイルの差し替えを閉じる

write レーンのプロファイルは、プロファイル生成時にプロジェクト配下で見つかった永続
ファイルの親ディレクトリと、プロジェクトルートまでの各祖先に `(deny file-write*
(literal <dir>))` を加える（20,000 エントリで止まり打ち切りを告げる有界走査）。`/clear` でプロファイル
とともに再生成。それらのディレクトリ内の通常書込は許されたまま（上で実測）。

### 3. 消せない残留を可視化する

新しい入れ子永続ファイルを運ぶ準備済みディレクトリの移し込みはパス規則で表現できない。
狙われるのは*他の*消費者 — Claude Code の入れ子 `CLAUDE.md`、入れ子リポジトリのフック —
で、gem-agent 自身（ルートと祖先だけを読む）ではない。閉じたと偽らず可視化する:
`/clear` とセッション終了時に、プロジェクト配下の永続ファイル集合をセッション開始時と
比較し、追加と変更を stderr とトランスクリプト（`persistent_changes` 記録）に報告する（`this session added
sub/CLAUDE.md and changed vendor/x/.git/hooks/pre-commit`）。走査は §2 と同じで有界、
打ち切りは告げる。

### 4. 操作者の git が消費するものの助言的ピン

ルートリポジトリの `.git/hooks/*` と `.git/config` もピン留めするが助言的にのみ: 前回
セッションからの変化は起動時に報告（「`.git/hooks/pre-commit` changed since your last
session」）し、決してブロックしない — 走らせるのは gem-agent ではなく git で、操作者が
編集したのかもしれない。

## 検討した代替案

- **Seatbelt の「包含」述語。** 存在しない。SBPL のフィルタは操作対象エントリのパスに
  マッチする。
- **write レーンで全ディレクトリ rename を拒否。** パスで表現できず（ディレクトリと
  ファイルは同じに見える）、`mv src lib` のリファクタを禁じる。
- **永続ファイルの immutable フラグ（`chflags uchg`）。** 所有者が外せる。祖先の rename
  には無関係。操作者のエディタと衝突する。
- **信頼したファイルを state ディレクトリに複製してそこから読む。** ピンと等価だが重く、
  `AGENTS.md` を編集したばかりの操作者を混乱させる。ピンは比較して尋ね、複製は無言で
  食い違う。
- **git index（`HEAD:AGENTS.md`）との照合。** 全プロジェクトがリポジトリではなく、
  悪意あるコミットは両側を変える。
- **記録以上は何もしない。** ADR-0023 自身の穴を開けたまま: `git pull` が無確認で
  再信頼される。

## 影響

- gem-agent 自身の消費について「名前に紐づいた信頼」クラスが閉じる。残るパス規則は
  保証ではなく防御の深さになる。
- **コスト:** gem-agent の外で `AGENTS.md` を編集すると次回起動で `y` が 1 回。その後の
  `-p` パイプラインは `gem-agent trust --accept` まで変化ファイル無しで走る。起動時に
  数個のダイジェストと有界走査 1 回が増える（信頼プローブは既に `.claude/skills` を
  走査している）。
- **挙動変更**（破壊的変更手順）: 既定 ON、オプトアウトは `[approval].pin_trusted_files
  = false`。CHANGELOG は `Breaking:` を付す。
- 他消費者向けの残留（§3）は ADR と approval リファレンスに残留として明記し、閉じたと
  主張しない。

## 決定事項（2026-09-05）

操作者は全点で推奨を採った: ピンは既定 ON でオプトアウトは `[approval].pin_trusted_files
= false`。`-p` は起動拒否ではなく変化ファイルを飛ばす。ピン対象はルートの指示ファイル・
`.mcp.json`・`.gem-agent.toml`・プロジェクトスキルで、`.git/hooks` と `.git/config` は
永続ファイル snapshot による助言。永続ファイル走査は 20,000 エントリで止まりそう告げる。

## レビュー（2026-09-05）

実装の独立レビュー 2 本が 31 件の所見を返した。事実を取り、対処はここで決めた
（CONVENTIONS: レビュワーは観察し、コントリビュータが決める）。本 ADR の最終形で修正:
リンクである消費ファイルがピンには不在でローダーには存在した（同じ root 経由でリンク
ターゲット込みでダイジェスト）。空のピン集合が「未ピン」と読まれた（`pinned_at`）。
再ピンが未見のファイルや operator レーンのコマンドを含めて集合全体を書き換えた
（承認された 1 書込に限定、コマンドは報告）。スキルの grant は frontmatter 名で、ピンは
ディレクトリエントリで鍵付けされていた（双方エントリ）。`.gem-agent.toml` はピン対象
なのにピン照合の前に読まれていた（信頼とピンが全プロジェクト読取に先行）。非対話の
初回起動が無言でピン留めした（従来どおり読み込み、何も記録しない）。`/clear` は指示
ファイルを再照合するがスキル一覧は旧のまま持ち越した（再発見）。未信頼プロジェクトの
`--accept` が exit 0 だった（エラー）。却下: 祖先の指示ファイルのピン留め（操作者自身の
ディレクトリで ADR-0023 のゲート外）。プロンプトの行数差分（操作者はファイルを持って
いる。プロンプトは変化とサイズを名指す）。`/clear` と reload での確認（TUI が端末を
持つ — ファイルを外して名指し、次の起動が尋ねる）。本作業の E2E スクリプトがフィクス
チャではなくリポジトリ内で走り `AGENTS.md` を置き換えた。復元し、`make check` は
セクションを欠く `AGENTS.md` を拒むようにした。

第 3 の検証パスが修正を確認（全件確認）し、さらに 7 件を見つけた。すべて採用:
config 経由で信頼したプロジェクトでツールポリシーを既定に戻すとエントリとピンが消えた
（ピンを持つ間はエントリが残る）。承認した編集が、その前にドリフトしていたファイルを
再ピンした（エージェントが書込前に告げ、その時点でピンと比較する）。ピンがポリシー
ファイルのロック外で取ったスナップショットから書き直されていた（ロック内で編集）。
設定パネルがポリシーファイルのポインタを差し替え、セッション側のコピーが古くなった。
指示ファイルとスキルが MCP サーバー起動の後に読まれていた（先に読む）。`/clear` が
ピンの注記を 2 度出した。除外されたプロジェクトスキルが同名の操作者のグローバル
スキルを道連れにした（グローバルが戻る）。記録のまま残す: ダイジェストから読取までの
隙間は今は間に挟まる数呼び出しで、プロジェクト由来のものは何も動いていない — 完全に
閉じるにはローダーが読んだバイトのダイジェストを返す必要があり、この順序の外の読み手が
現れたときのために残す。

v0.70.1 後の外部指摘: 名前照合が大文字小文字を厳密に比較する一方、既定の APFS はケースを
畳み込む — `write_file("agents.md")` は `AGENTS.md` に着地し、作られた
`.git/hooks/PRE-COMMIT` は git が走らせるフックで、`.GIT/config` はルール層の `.git` Block
を通過した。対照付きで実測: カーネル側（Seatbelt の regex・literal フィルタ）はそのボリューム
で既にケースを畳み込み、両レーンで全ケース変種が拒否された。Go 側はしていなかった。
`sandbox.PersistentFile`・ルール層の `.git` 判定・`trustpin.PinName` はケースを畳み込み、
PinName は正規表記（ルートファイルはローダーの名前、スキルは一覧されたディレクトリエントリ）
を返すようにした。対照付きの実 Seatbelt テストと変種の単体テストで固定。ケース区別する
ボリュームでは数個の名前を過剰保護するだけで、コストは無い。

## 他エージェントの調査（2026-09-05）

主要コーディングエージェントで信頼を内容に紐づけるものは現時点で無い: Claude Code・
Codex CLI・Gemini CLI・Copilot CLI・Cursor は `git pull` 後も続くディレクトリ単位の信頼を
永続化する。Claude Code の `ConfigChange` hook はセッション中の設定変更に反応できるが、
操作者が書くポリシーで既定の再確認ではない。指示の散文（`AGENTS.md` 類）をゲートするのは
Gemini CLI だけで、2025〜26 の複数の事故はまさにそのファイル経由で実行に達した。設定
ディレクトリの自己書換えは Claude Code・Codex・Cursor（ルールディレクトリを除く）が
ゲートする。したがって本 ADR のピンは業界からの意図的な逸脱であり、監視すべきコストは
再信頼プロンプトの頻度。
