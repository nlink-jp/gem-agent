# ADR-0079: 通知はクロムであり、エラーは鎖である

| 項目 | 内容 |
|-------|-------|
| ステータス | **採択**（2026-09-08。v0.72.0 で出荷） |
| 日付 | 2026-09-08 |
| 拘束対象 | gem-agent |
| 決定者 | nlink-jp maintainers |
| 契機 | v0.72.0 の 3 回目のリリース前パス: `internal/agent` が書く通知を ADR 無しでカタログへ移した（ADR-0029 §3 が既に覆っているという読みで）。レビュワーの判定「半分は妥当、半分は方針変更」が本 ADR の存在理由である |
| 修正する ADR | ADR-0029 §3（カタログ対象の一覧にエージェントのターン中通知を加え、判定基準を言い直す） |

## 背景

ADR-0029 §3 は閉じた 2 つの一覧として書かれている。カタログ対象（`/help`、
承認ダイアログ、入力クロム、設定パネルの hint、`/auto`・`/clear`・`/compact` の
フィードバック、ADR-0023 の起動時安全プロンプト）と、英語のまま残すもの
（バナーのラベルと `warning:` 行、cobra の `--help`、モデル向けテキスト、
Go のエラー鎖）である。

`internal/agent` がターン中に書くものは、いまカタログの 11 項目が担っている。
「ADR は要らない」として移した。§3 が「`/compact` のフィードバック」を載せており、自動要約は
別のトリガーから来た同じフィードバックだから、という理由で。

その読みは 4 本については成立する。残り —— コンテンツフィルタの再試行、打ち切られた
応答、リモートの反復失敗、記録書き込みの失敗、ラウンドラダーの継続 2 本、そして
プロンプトフックの添付通知 —— はどちらの一覧にも無い。閉じた列挙に対して**新しい面が 5 つ入った**のであり、
同じリリースの `df2ea5e` は同じ規模の移動に対して `Amends` 行つきの ADR を丸ごと
書いている。

さらに悪いことに、移動を正当化するために `internal/uitext` のパッケージ doc に
書いた規則は、自分の適用結果を決められない。

> 操作者の次の一手を運ぶ文はクロムであり、何が書いたかは問わない。包まれた
> エラー鎖はそうでない。

`CompactFailedFmt` は `"context compaction failed: %s"` で、`%s` は
`err.Error()` であり、**次の一手を一切運んでいない**（コマンドは 2 回目の連続失敗、
自動要約が諦める時点で別途届く）。書かれた規則に照らせば英語側に属する。しかしカタログにある。
正当化した当の仕事がその規則に従っていないなら、それは適用された規則ではない。

## 決定

### 1. エージェントのターン中通知はカタログ対象である

§3 のカタログ一覧に「ターン実行中に `internal/agent` が書く通知」を加える。
`Agent.notify` の全呼び出しと、`onNotice` を直接呼ぶ 1 本である。これらは
`/compact` のフィードバックと同じ面である —— 操作者は同じスクロールバックで、
同じセッションで、同じランタイムについて読む —— し、訊いたときは日本語で答え、
訊かないときは英語で答えるセッションこそ ADR-0029 が止めるために存在する drift
そのものである。

### 2. 判定基準は「誰が書いた文か」であって、コマンドの有無ではない

所属を決める規則:

> **gem-agent が文を組み立てる → カタログ。文そのものが返される `error` である
> → 英語。**

カタログ対象の文は、原因をそのまま引用してよい。枠はランタイムのもので翻訳され、
原因は書かれた言語のまま手を触れない。`err.Error()` を `%s` で囲むとは既にその
ことであり、だから `CompactFailedFmt` は結局のところ正しくカタログにある ——
間違っていたのは配置ではなく規則のほうだった。

英語のまま残るのは、スタックを上っていく `error` 値である。その本文は鎖であり、
中身はライブラリ由来で、英語の中身に翻訳された枠を被せることが §3 の消した
混合である。ターン終了時のエラー（ラウンド上限、コンテンツフィルタの遮断、
メディア再生、「使える応答が返らなかった」）が、明白に操作者向けでコマンドも
持っているのにカタログに無いのはこのためである。

次の一手があるかどうかは**文言**についての規則であり（操作者向けの行は全て
持つべきである）、**言語**についての規則では一度も無かった。この 2 つを混同した
結果が、自分の例に否定される正当化だった。

### 3. この規則がまだ覆っていないもの（本 ADR では直さない）

gem-agent が組み立てた文が 3 つ、承認ダイアログの中で描画される —— §3 が
カタログ対象として挙げている面である —— のにハードコード英語のままである:
`EscalationReason`（`internal/agent/autoapprove.go`）、`risk.Verdict.Reason`
の全て（`internal/risk`）、`internal/agent/decision.go` の unknown-tool と
未封じ込めシェルの理由。§2 の規則に照らせばこれらはカタログ対象である。既存の
挙動であり、このリリースでは触れていない。日本語セッションはゲートで英語のリスク
判断を読み続ける。

黙って例外にせず名指しする: これらを違反にしているのは規則そのものであり、
明記されない例外を持つ規則こそ §2 が置き換えるために書かれたものだからである。
カタログ化はリスク段の語彙そのものへの変更であって配線の修正ではないので、
独立した変更として行う。

### 4. 変わらないもの

- バナーのラベルと `warning:` 行は英語のまま（grep 安定な出力）。
- cobra の `--help` は英語のまま。
- モデル向けテキストは英語のまま。加えて `make labels` に専用セクションが
  できたので、通読がそれをクロムと取り違えることはない。

## 検討した代替案

- **5 本をカタログに入れず英語へ戻す** —— 却下: 要約について「1 つの事象に 2 つの
  文字列」という欠陥が復活し、日本語セッションが最も精度を必要とする瞬間に英語の
  復旧手順を読むことになる。
- **ターン終了時エラーもカタログに入れる** —— 却下: `error` は包むことで組み立て
  られ、各層が「中身は英語のままの枠」にカタログキーを必要とすることになる。
  §3 の理由付けは変わっていない。
- **何も書かずパッケージ doc に持たせる** —— これが実際に行われたことであり、
  レビュワーが捕まえた。閉じた列挙が記録無しに 5 つ増えるのは、次の読者が誤った
  規則を学ぶ経路である。

## 影響

- `internal/uitext` のパッケージ doc は、次の一手の規則ではなく著者性の規則を
  述べる。
- ADR-0029 に *Amended by* 行が付く。
- コード変更は無い: 11 項目は既にカタログにあり、本 ADR はそれを置いた決定を記録し、
  理由を訂正する。
