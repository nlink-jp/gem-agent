# ADR-0003: 最下部固定の inline レイアウト

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-18 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 現行 Claude Code とのオペレータ比較: Claude Code は入力欄とステータス行をウィンドウ最下部に固定しているが、gem-agent は会話末尾に追従していた |

## Context

ADR-0002 は素のスクロールバックとコピペを守るため inline 描画を選んだ。その
副作用として、入力ブロックが会話の直下に置かれ、画面が空のうちは上部に浮いて
見える。現行の Claude Code は **alt-screen を使わずに**入力欄を最下部に固定
しており、オペレータが期待するレイアウトはそちらである。

## Decision

inline 描画は維持し、その上に最下部固定を実装する:

- **TUI 起動時に画面をクリア**し、バナーも TUI 経由で出力してカーソル行を
  既知にする（Claude Code も同じ。起動前のビューポート内容はスクロール
  バックにのみ残る）。
- **TUI が print する物理行数をすべて数える**（`emit` が `tea.Println` を
  ラップ。行ごとに `ceil(表示幅 / 端末幅)`、ANSI-aware）。管理領域の行は
  ADR-0002 のリサイズ修正で幅クリップ済みのため View の高さは正確。
- **View の先頭に `height − printed − viewHeight − 1` 行の空行を積む**。
  会話が画面を埋めた後はパディングが 0 に張り付き、従来レイアウトに
  そのまま退化する。
- **リセット**: 縮小時の ClearScreen でカウンタをゼロに（ビューポートは
  空になる）。拡大時はカウンタ維持 — 過去行の再折返しで固定位置が最下部より
  やや上に来ることがあるが、外観上の問題に留まり次のクリアで自己修復する。

## Consequences

- 初回フレームから入力欄とステータス行が最下部に固定され、現行 Claude Code と
  同じ見た目になる。スクロールバック・コピペは引き続き機能する。
- 行数カウントは端末状態の推定である。既知のドリフト経路（自前の折返し=クリップ
  で防止 / glamour=幅以内に事前折返し済み / リサイズ=クリアまたは保守的な
  非パディング）はいずれも「入力欄が最下部よりやや上に来る」に退化するだけで、
  描画破壊には至らない。
- 起動時クリアで起動前のビューポート内容が画面から消える（多くの端末では
  スクロールバックに残る）。Claude Code と同一挙動として受容。

## Alternatives considered

- **alt-screen** — 固定は自動で得られるが、素のスクロールバックとコピペを
  失う。ADR-0002 の却下理由がそのまま生きる。
- **カーソル位置照会（CSI 6n）** — 実行中の端末照会は OSC 漏れと同類のバグ
  （幽霊入力）になるため却下。
- **現状維持**（会話追従型）— ADR-0002 の出荷形。現行 Claude Code を基準と
  するオペレータフィードバックにより却下。
