# ADR-0028: 自己修復する印字行カウンタ

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「/settings で設定開いて ESC で閉じると、フッターが画面下端ではなく画面中央くらいまであがった」 |

## Context

最下部固定（ADR-0003）は各フレームを `printed`（フレーム上端より上の
行数）を基準に配置する。設定パネルは自らを `height−1` 行に予算するが、
既に印字済みの内容の下に実際に残っているのは `height−1−printed` 行 —
パネルの描画は溢れた分だけ端末をスクロールさせ、フレームのアンカーは
上に動くのに `printed` は動かない。次の小さいフレーム（ESC で入力
ビューへ）は、スクロールで消えた行を基準にパディングされ、フッターが
画面中央に落ちる。ADR-0024 の bottom-hold は縮みは覆ったが、腐った
アンカーは覆っていなかった。

## Decision

**`printed` は現実に追従する。** ADR-0024 の hold と同じポインタ描画
状態へ移し、View はパッド計算の前にスクロール会計を適用する: フレーム高が
利用可能行数（`height−1−printed`）を超えるとき、描画に伴い端末は溢れた
分スクロールするので、同じパスで `printed` を `height−1−core`（下限 0）
まで減らす。これで全レジームが一貫する — パッド式・bottom-hold の発動
条件・emit の加算は、すべて「フレームより上の行数」という言葉どおりの
カウンタの上で動く。

テストの ground truth: どの描画の後も `printed + frame ≤ height−1`、
そして高すぎるパネルを閉じた後は `printed + frame = height−1` — フッターの
最下段。

## Consequences

- /settings（および高すぎるあらゆるフレーム: 小さい端末での大きな承認
  ボックス等）を閉じても、フッターは最下段固定に戻る。
- **溢れた後、カウンタの規約は物理的なアンカーより 1 行少ない。これは設計上の
  こと。** 2026-09-10 に 100x30 の tmux ペインで実測: 印字 5 行の下に 29 行の
  フレームを描くと端末は 4 行スクロールする（printed+1 行目から N 行のフレームは
  printed+N-height 行スクロールする）。以後フレームは最下行も占め、印字済み行が
  1 行だけ上に残る — 一方、修復は最下行がまだ空いているかのように printed = 0 と
  読む。相対的に位置決めされるものにはこれで整合する（レンダラーは直前フレーム
  基準で再描画し、pad/hold の算術は最下行を空ける規約を保つ。ADR-0024 のテストが
  固定している）ので、式はそのまま。破綻するのは絶対行が意味を持つ場所だけ:
  画面より 1 行短く予算された設定パネルが、まさにその生き残り 1 行を ESC 後の
  入力欄の上に単独で残した（操作者報告、v0.75.0。操作者の診断はパネルの下詰めで、
  それは会話と題名の間の空白の帯も生んでいた）。
- よって設定パネルは `settingsFrame` が配置する: 会話の下に `settingsFitRows` 行
  以上残っていれば**その残り行の中で上詰め** — 題名は印字済み行の直下、フッターは
  最下段、行ウィンドウはその残り行を予算にする — ので、開いても何もスクロールせず、
  閉じれば画面は元のまま戻る。そうでなければフレームは**端末の全高**、height-1 を
  超えてよい唯一のフレームで、印字済み行は全部スクロールアウトし、修復はゼロに
  着地し、閉じた後は清浄な画面になる。**選択は開いた時に 1 度だけ行い、閉じるまで
  保持する**（`settingsPlan` → `settingsTotal`）: レンダラーはティック毎に最新の
  View しか描かないので、View 毎にカウンタから導き直す選択は、全高フレームが
  カウンタを修復した直後に「収まる」側へ反転し、1 行短いその収まるフレームの方が
  端末に届いた（同じ計測の `script` 生バイト列）。
- ADR-0003 の「printed = クリア以降に印字した行数」の定義は「フレーム
  上端より上の行数（溢れ時に自己修復）」に修正される。ADR-0024 は
  そのまま合成される。
