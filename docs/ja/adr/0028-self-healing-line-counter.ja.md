# ADR-0028: 自己修復する印字行カウンタ

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「/settings で設定開いて ESC で閉じると、フッターが画面下端ではなく画面中央くらいまであがった」 |

## Context

最下部固定（ADR-0003）は各フレームを `printed`（フレーム上端より上の
行数）を基準に配置する。設定パネルは自らを `height−1` 行に予算するが、
既に印字済みの内容の下に実際に残っているのは `height−1−printed` 行 —
パネルの描画は溢れた分だけ端末をスクロールさせ、フレームのアンカーは
上に動くのに `printed` は動かない。次の小さいフレーム（ESC で入力
ビューへ）は、スクロールで消えた行を基準にパディングされ、フッターが
画面中央に落ちる。ADR-0024 の bottom-hold は縮みは覆ったが、腐った
アンカーは覆っていなかった。

## Decision

**`printed` は現実に追従する。** ADR-0024 の hold と同じポインタ描画
状態へ移し、View はパッド計算の前にスクロール会計を適用する: フレーム高が
利用可能行数（`height−1−printed`）を超えるとき、描画に伴い端末は溢れた
分スクロールするので、同じパスで `printed` を `height−1−core`（下限 0）
まで減らす。これで全レジームが一貫する — パッド式・bottom-hold の発動
条件・emit の加算は、すべて「フレームより上の行数」という言葉どおりの
カウンタの上で動く。

テストの ground truth: どの描画の後も `printed + frame ≤ height−1`、
そして高すぎるパネルを閉じた後は `printed + frame = height−1` — フッターの
最下段。

## Consequences

- /settings（および高すぎるあらゆるフレーム: 小さい端末での大きな承認
  ボックス等）を閉じても、フッターは最下段固定に戻る。
- ADR-0003 の「printed = クリア以降に印字した行数」の定義は「フレーム
  上端より上の行数（溢れ時に自己修復）」に修正される。ADR-0024 は
  そのまま合成される。
