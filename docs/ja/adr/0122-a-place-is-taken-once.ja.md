## Context

レーンは、プロジェクト、セッションの作業ディレクトリとその中のスクラッチとキャッシュ、追加ディレクトリ、一時ディレクトリに書けます。レーンは、書けるものを差し替えられます。ディレクトリを消して、その名前の下にリンクを置けます。

ランタイムはこれらの場所を名前で持ち、後からその名前を使い直していました。ADR-0120 と ADR-0121 の修正は、レビューが見つけた使い方を 1 つずつ閉じ、そのたびにレビューが別の使い方を見つけました。そこで、ランタイムの中でファイルをパスで名指す呼び出しと、プロセスを起動する呼び出しを、機械的にすべて挙げ、区分を付けました。159 件です。レーンが書ける場所を名指すのは 18 件で、残りは、ランタイム自身の状態ディレクトリの中か、読むだけか、すでに正しい形でした。18 件の原因は 1 つです。

両方のランタイムで、本物のプロファイルの下で測りました。

| write レーンがしたこと | 次にレーンを組み立てたとき、レーンが得たもの |
|---|---|
| 自分の作業ディレクトリを消し、その名前の下に、プロジェクトの隣のディレクトリへのリンクを置いた | そのディレクトリへの書き込み。そこにファイルを 1 つ書き、1 つを上書きした。起動時の確認は通り、セッションは閉じ込められていると報告された。read レーンは、そこに `scratch` ディレクトリを書いた |
| 同じことをプロジェクトのディレクトリで行った（空にできるプロジェクトで） | 同じ |
| 同じことを、git の設定を含むプロジェクトで行った | 何も得ない。レーンはそのファイルの削除を拒まれ、空でないディレクトリは差し替えられない |

レーンは起動時に組み立てられ、セッションの中でも組み立て直されます。`/clear` と、ディレクトリの付与です。組み立てのたびに、プロジェクトと作業ディレクトリの名前を解決し直し、見つけたものをプロファイルの錨にしていました。リンクになった作業ディレクトリへ保存した結果は、リンクの先に作られました（実測）。リンクになった作業ディレクトリの削除では、リンクだけが消えました（実測）。

追加ディレクトリは、ADR-0099 のレビュー以来、すでに逆の扱いになっていました。1 度開き、開いたものから本当のパスを読み戻し、以後はそのパスを使います。

## Decision

1. **場所は 1 度だけ取ります**（`internal/place`）。取るとは、ディレクトリとして開き、そのときの本当のパスと一緒に、プロセスが終わるまで持ち続けることです。プロジェクトは、起動時にレーンを最初に組み立てるときに取ります。作業ディレクトリ、そのキャッシュ、スクラッチは、ランタイムが作るときに、1 つ上のディレクトリ（状態ツリーの中にあるか、それ自体が取った場所です）から、1 つの名前で、リンクを辿らずに取ります。
2. **場所が要る側は、取ったときの名前で尋ね、持っている場所か、エラーを受け取ります。** 先に名前を見ます。名前は、最後の一歩でリンクを辿らずに、持っているディレクトリへ届かなければなりません。名前の先にいまあるものと、記述子の先にいまあるものが、同じディレクトリであることを確かめます。別のところへ届く名前は `ErrReplaced` です。何も取られていない名前は `ErrNotTaken` で、これはランタイムの誤りです。後から取った場所は、レーンがそこに置いたものになってしまいます。
3. **プロファイルの錨は、取った場所の本当のパスにし、名前は解決し直しません。** これだけで、レーンは元の場所に留まります。場所の名前の下に置かれたリンクは、どの錨の外にも出ていくからです。2 の確認は、セッションに知らせるためのものです。
4. **プロジェクトか作業ディレクトリが差し替えられていると分かった組み立ては、何も組み立てません。** どの場所であるかをセッションに伝え、以後はすべてのシェルコマンドが尋ねるようになり、それまでに組み立てたレーンはそのまま残ります。差し替えられたスクラッチやキャッシュは、レーンに渡しません。read レーンはスクラッチ無しになり、尋ねるようになります。
5. **ランタイム自身が場所の中で作る・書く・消すものは、持っているディレクトリから、1 つの名前で行います。** スクラッチのディレクトリ、確認用のディレクトリ、作業ディレクトリへ保存する結果です。結果は、一時ファイルを排他的に作り、結果の名前の上へ名前を変えます。どちらも、その 1 つのディレクトリの中の名前です。
6. **ファイルツールは、場所を通してそれを開きます。** 受け取るルートは、場所のパスで開いたもので、持っているディレクトリであるときだけ渡されます。ファイル読み取りの子プロセスは独立したプロセスで、何も取りません。渡されたパスを、檻の中で解決します。
7. **一覧をテストにします。** `TestEveryPathCallHasItsClass` は、ファイルをパスで名指す関数と、プロセスを起動する関数のすべてに、6 つの区分のどれかを与えます。入口、読むだけ、操作者の入力、操作者が名指したファイル、システムのもの、ランタイム自身の状態、です。表に無い関数の中の呼び出しがあると失敗します。「レーンが書ける場所で、パスによって、作る・書く・消す」という区分はありません。`TestProfilesAreNotAnchoredOnANameResolvedAgain` は、名前を解決する関数を呼ぶのが、場所を取る関数と判定する関数だけであることを保ちます。

## Consequences

- 差し替えられた場所に出会ったセッションの操作者は、`sandbox unverified: <path> is no longer the directory this session took` を読み、新しいセッションを始めるまで、シェルコマンドのたびに尋ねられます。失われるものはありません。それまでに組み立てたレーンは、実行されるものを今も閉じ込めています。
- 場所は、プロセスが終わるまで開いたままです。1 セッションあたり数個の記述子です。
- 場所の表は、セッションのものではなく、プロセスのものです。プロセスは 1 つのセッションで、ある名前で取った場所は、どこで尋ねられても、その名前に答えます。
- 変えずに、記録すること: 操作者がサンドボックスの外で動くように設定したプログラム（フック、MCP サーバー）には、作業ディレクトリが名前で渡ります。名前をどう使うかは、そのプログラムの側のことです。
- 変えていないこと: 追加ディレクトリは、これまでどおり付与のときに取り、確認はそれをパスで開きます（ADR-0121 の残余が、そのまま当てはまります）。
- セッションが始まる前に差し替えられていたプロジェクトは、別のプロジェクトです。そこから読むものは、どのプロジェクトのものとも同じように照合され、尋ねられます。

## Tests the design requires

- write レーンが、本物のプロファイルの下で、自分の作業ディレクトリをリンクに差し替える。次の組み立ては、差し替えられた場所として断られ、それまでに組み立てたレーンはリンクの先に書けず、そこには何も作られない。空にできるプロジェクトでも、`/clear` と同じ組み立て方で、同じ結果になる。git の設定を含むプロジェクトは、差し替えられない。
- 差し替えられた場所を見つけた `/clear` と付与は、セッションを、シェルコマンドのたびに尋ねる状態にし、どの場所であるかを伝える。
- リンクに差し替えられたスクラッチのディレクトリは、レーンに渡されない。
- 結果は、持っている作業ディレクトリを通して保存される。差し替えられた作業ディレクトリ越しには何も作られず、結果の名前の下にあるリンク、FIFO、別のバイト列は、待たずに結果で置き換えられる。
- ファイルツールと確認は、差し替えられた場所を断る。
- 場所: 名前が別のところへ届くようになる、あらゆる形。リンク越しの下位の場所。取られていない名前。
- 性質を 1 つずつ元に戻すと、どれもテストが検出する。

## Alternatives considered

- **場所を、要る関数すべてに渡す** — 採りません。同じ規則で、すべての関数の引数が変わり、関数に尋ねさせる仕組みは無いままです。答える前に見る入口が 1 つあれば、両方が済みます。
- **最初に尋ねられたときに場所を取る** — 採りません。遅く尋ねられると、そのときまでにレーンが名前の下に置いたものになります。
- **場所が差し替えられていると分かったら、セッションを終える** — 採りません。それまでに組み立てたレーンは今も効いていて、操作者の作業はそのセッションの中にあります。
- **プロファイルの錨だけを直し、ほかは残す** — 採りません。それは 1 つの原因に対する 4 度目の修正で、その前の 3 度が、一覧を作った理由です。
