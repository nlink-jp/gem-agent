# ADR-0005: トランスクリプトログからのセッション再開

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータからの要望「resume を実装しましょう」 |

## Context

RFP はセッション再開を v1 のスコープ外とした。バックアップツールは最小で
あるべき、という理由である。運用は逆の答えを出した。gem-agent が持ち出され
るのはまさに何かが壊れているときであり、そこで行う作業は長い。セッションの
終了 — クラッシュ、`Ctrl+D`、ラップトップを閉じる、フィルタブロックでターンが
死ぬ — はそのまま文脈の終了を意味し、オペレータは記憶を頼りに状況を打ち直す。
`AGENTS.md` を読む判断を支えた論拠（フォールバックに再セットアップの費用を
払わせない）がそのまま当てはまる。

トランスクリプトに近いものは既にある。`~/.local/state/gem-agent/sessions/
<ts>.jsonl` は全てのユーザーメッセージ・アシスタントターン・ツール結果を
記録している。しかし再生はできない。理由は 2 つ: ツール結果は可読性のために
2000 文字で切られており、そして Gemini 3 の **thought signature がそもそも
記録されていない**。これは最適化ではなく API の硬い要求である（signature を
伴わない function-call part を送ると 400 で失敗する）。

## Decision

**セッションログを resume の正本とする** — ログ + 並行するトランスクリプト
という 2 ファイル構成は採らない。同じ会話を 2 箇所に持てば必ず片方がずれ、
ずれるのは常に誰も読まない方である。

1. **履歴を成す記録は完全忠実に記録する。** 会話を再構成する 3 種
   （user / assistant / tool ロールの `message` 記録）は `llm.Message` を
   まるごと記録する。ツールコール引数、添付、thought signature（base64）を
   含む。クリップしない。診断用の種別 — `auto_decision`、`notice`、
   `assistant_empty` — は要約形式のまま残し、ロード時には無視する。
2. **ヘッダ記録**（`session`、1 行目）にスキーマ版、gem-agent 版、モデル名、
   プロジェクトディレクトリを持たせる。一覧表示はヘッダだけを読む。
3. **resume は同じファイルに追記し**、`resumed` マーカーを記録する。
   何プロセスにまたがろうと、1 ファイル = 1 会話。
4. **`compaction` 記録は圧縮として再生する**（ADR-0006）。ローダは実行時の
   エージェントと同じ操作を適用するので、圧縮済みセッションを再開しても、
   意図的に縮めた会話が再び膨らむことはない。
5. **束縛規則。いずれも警告ではなく拒否とする:**
   - **プロジェクト。** 記録されたディレクトリでのみ再開できる。履歴には
     そのプロジェクトのファイル内容とパスが詰まっており、別の場所で再生
     するのは良くて混乱、悪ければ一方のプロジェクトの内容が他方の文脈へ
     漏れることになる。
   - **モデル。** 記録したモデルでのみ再開できる。thought signature は
     モデルに紐づく不透明な継続トークンであり、あるモデルの signature が
     別のモデルへの正当な入力である根拠はない。失敗の出方（再開後の最初の
     リクエストで 400）は、オペレータが作業に戻ったつもりになった後に来る。
     エラーメッセージは記録されたモデル名を出すので、対処はコピペで済む。

設計全体がここに乗っているので、**出荷前に実測した**: あるプロセスが記録した
signature は別プロセスで正しく再生される。ファイルを読ませた one-shot 実行を
別プロセスで再開し、何も読み直さずに復元されたツール結果から回答した
（gemini-3.7-flash、2026-08-19）。これが失敗していたら、逐語再生は諦めて要約
ベースの resume に切り替える必要があった。
6. **ID は検証する。解釈しない。** `--resume <id>` はセッションのベース名
   （`20260819-150102`、必要なら `-2`）のみを受け付け、セッションディレクトリ
   内で解決する。パスは受け付けない。したがってトラバーサルも、攻撃者が
   置いた任意のトランスクリプトの読み込みも起こらない。
7. **操作面**: `--continue` / `-c`（このプロジェクトの最新セッション）、
   `--resume <id>`、一覧用の `gem-agent sessions`。

復元されたツール出力は、既存の送信時ラップ（`wrapToolMessages`）が新しい
ターンの nonce タグで包み直す。トランスクリプトは生の内容を保持し、タグは
呼び出しごとに再生成されるので、ADR-0001 の隔離保証は resume をまたいでも
自動的に維持される。

## Consequences

- セッションファイルは大きくなる。2000 文字の抜粋ではなく完全なツール出力が
  入るためである。個々の出力は tools 層で上限が掛かっており、ファイルは
  `0600`、state ディレクトリはオペレータ自身のものである。ただし明示して
  おく: **トランスクリプトにはエージェントが読んだ全ファイルが入る**。
  従来も半分そうだった。今は完全にそうなる。
- 実質的にセッションはプロジェクト単位になる。これがピッカー無しで
  `--continue` を一意にしている理由でもある。
- モデル束縛は、会話を別モデルへ持って行きたい場面で必ず邪魔になる。
  ただしクロスモデルの signature 再生を実測するまでは、これが誠実な立場で
  ある。ADR-0006 の圧縮は signature を持たない要約を生むので、必要が出た
  ときはそれを土台にしたクロスモデル resume が自然な発展形になる。
- かなり古い gem-agent のトランスクリプトはロードできないことがある。
  ヘッダのスキーマ版により、それは謎ではなく明確なメッセージになる。

## Alternatives considered

- **ログとは別にトランスクリプトファイルを持つ** — 却下。1 つの会話に 2 つの
  記録ができ、resume が通るのは検証の薄い方になる。
- **クリップ済みのログをそのまま使う** — 却下。黙って欠落する。読んだ
  ファイルの後半を忘れた再開セッションは、再開できないより悪い。欠落を
  告げるものが何も無いからである。
- **ロード時に thought signature を捨てる**（resume がモデル非依存になる）
  — 却下。signature 無しの function-call part は Gemini に拒否されるので、
  説明可能な拒否を説明不能な 400 に置き換えるだけになる。
- **起動時に最新セッションを自動再開** — 却下。引数無しできれいに始められ
  ることは必要である。resume は、ここの他のあらゆる文脈持ち越し機能と同様、
  opt-in とする。
