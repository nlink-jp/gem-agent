# ADR-0036: ask_user — モデルがオペレーターに出せる構造化された選択

| 項目 | 値 |
|------|----|
| ステータス | **承認済み** |
| 日付 | 2026-08-21 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレーター: Claude Code の Ask ツールのように、モデルが選択肢を提示して選ばせられる内蔵ツールが欲しい |

## 文脈

ターンの途中でモデルが判断を必要とするとき — 3 案のどれか、本当の
対象ファイルはどれか — 打てる手は「ターンを**終えて**散文で聞く」
だけだった。それは往復 1 回ぶんのコストであり、ターンの勢い（予約
された作業・ロード済みの文脈）を失い、選択肢の列挙をオペレーターの
返信に押し戻す。承認ダイアログが既に機構を証明している: チャネルで
ブロックするツールコール + TUI がキー 1 打を collect する、IME 安全な
UI である。

## 決定

### 1. read-only ツール 1 本: `ask_user(question, options[])`

モデルは質問と 2〜8 個の選択肢ラベルを渡し、オペレーターが 1 つ
選び、ツール結果が選択を名指しする。`Mutating: false` で承認ゲート
対象外 — 質問にゲートを掛けるのは「ダイアログを許可するための
ダイアログ」である。上限: 質問 500 ルーン・選択肢 100 ルーン・
9 個以上は拒否（それほど長いメニューは呼び出し側の設計不良である）。

### 2. ダイアログは承認ダイアログの兄弟

オペレーターが既に知っている操作文法そのまま: ←→/Tab で移動、Enter
で決定、数字 1〜9 は選択と決定を 1 打で、Esc は回答しない。選択式が
存在する理由も承認ダイアログと同じ: 変換中の日本語 IME は文字を
吸うが、矢印と数字は吸われない。Esc は「オペレーターは選択を辞退
した — 散文で聞き直すか、判断を明示して進め」という別個の結果を
返す。辞退はエラーではなく情報である。

Ctrl+C 後に届いたダイアログは承認要求と同じく自動辞退（ADR-0034）:
死んだターンの代理でダイアログは開かない。

### 3. どのモードも正直に答える

- **TUI**: ダイアログ。
- **素の REPL**: stderr に番号付き選択肢、stdin から番号を読む
  （approve.Gate の流儀。EOF は辞退）。
- **単発 `-p`**: 聞く相手がいない — パイプラインをハングさせる
  代わりに「単発モードに対話オペレーターはいない。自分で判断し、
  選んだ内容を回答で明示せよ」を返す。

### 4. 自由入力は意図的に無い

Claude Code の Ask ツールには「その他」テキスト欄があるが、これには
無い。gem-agent には自由入力チャネルが既にある: モデルがターンを
終えて聞けば、入力欄がテキスト欄である。このツールは構造化された
場合のためにあり、非構造の経路をモーダルダイアログ内に複製するのは
「同じことをする 2 つ目の方法」を実 TUI 複雑性で買うことになる。
欠落ではなく判断として読めるよう、ここに記録する。

## 帰結

- ターン途中の判断が、往復 1 回ではなくキー 1 打になる。
- transcript は質問と選択を通常のツールコールとして記録し、
  テレメトリ（ADR-0035)も同様に監査する。
- 聞きすぎるモデルは危険ではなく鬱陶しいだけになる。オペレーターの
  レバーは散文のフィードバック（または Esc）であり、8 個上限が
  メニューの節度を保つ。
