# ADR-0061: 独立エージェントランタイム — 再位置づけと cli-series 昇格

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-01 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 利用者決定:「gem-agent はもう Claude Code のバックアップではない — 独立したエージェントランタイムとして扱い、訓練基準なしで cli-series へ昇格する。実戦投入の実績が根拠である」 |

## Context

gem-agent の当初の存在理由（RFP §1）は継続手段だった: Claude Code が
使えない日に開発作業を止めないこと。この前提は 4 箇所で構造を支えて
いた:

1. **位置づけ** — README の冒頭文と Why 節、RFP の問題設定、org
   profile の行、web サイトのカード、GitHub About、Homebrew tap の
   表 — すべてが Claude Code の不在を参照してこのツールを説明する。
2. **スコープの物差し** — 「バックアップ用途に必要なのは Claude Code
   の日常機能の中核 2 割」（RFP §3）。スコープが他製品の割合で定義
   されていた。
3. **月次訓練** — 「訓練しないバックアップはバックアップではない」
   （[drill](../reference/drill.ja.md)）。訓練は、バックアップ固有の
   リスクが「使われないまま腐ること」だから存在した。
4. **昇格基準** — 訓練 6 回連続合格・モデル廃止サイクルの通過ほか
   （[promotion](../reference/promotion.ja.md)）。どの基準も答える
   問いは 1 つ:「必要な日に、驚きなく、フォールバックは動くか」。

現実が前提の外へ出た。直近の機能軌跡 — ヘッドレス `--auto`
（ADR-0053）・stdin パイプのデータ添付（ADR-0055）・リスク
ルールブック（ADR-0050）・監査テレメトリ（ADR-0035）・オペレーター
pre-tool フック（ADR-0044）・セッション作業ディレクトリ
（ADR-0058）— は最小限の待機要員ではなく日常運用に仕える装備で
ある。そして実際に日常運用されている: 実作業セッション
（ADR-0058 の実地 E2E はそのうち 2 本の上で走った）とヘッドレス
パイプラインは、訓練ではなく実戦投入である。利用者の判断: ツールの
性能・機能はバックアップという役割を超えた。

## Decision

**1. gem-agent は独立したエージェントランタイムである。** その
アイデンティティはもはや Claude Code の可用性を参照して定義され
ない。Vertex AI Gemini 上の CLI エージェントランタイムであり、
macOS 専用、二層防御（sandbox-exec + 承認ゲート）、対話・ヘッド
レスの両用である。

**2. drop-in 互換は最重要要件のまま — 根拠を書き換える。**
プロジェクトの `AGENTS.md` / `CLAUDE.md` / `.mcp.json` / skills を
そのまま読むことの正当化は「障害時の乗り換えに再設定が要らない」
だった。今後の正当化はエコシステム互換である: 1 つのプロジェクト
設定が、その上で動くすべてのランタイムに仕える。要件・機構・
セキュリティ境界（ADR-0010・ADR-0011・ADR-0023）は不変。

**3. スコープ最小主義は自前の憲章で立つ。** shell-agent v1 の教訓
（盛りすぎ → 複雑化 → 作り直し）は引き続き支配するが、物差しは
もう Claude Code の割合ではない。憲章は: 最小限で監査可能な
エージェントループ — read / edit / shell / MCP / 承認 — であり、
分析・GUI サブシステムは持たない。機能追加は従来どおり ADR 経由
のみ。

**4. cli-series へ即時昇格（利用者決定）。** 昇格基準は合格した
のではなく失効した: あの基準群が測っていたのは「必要な日に
バックアップは動くか」であり、その問いはもう役割に合わない。
新しい役割が知る必要があるのは「実際の利用で動くか」で、それには
実戦投入の実績が既に答えている。[promotion](../reference/promotion.ja.md)
は、基準とこの決定の歴史記録として閉じる。以後は cli-series の
契約が効く: インターフェースの安定性は約束であり、破壊的変更は
CHANGELOG の 1 行ではなく組織の破壊的変更プロセス（利用者確認 →
互換案 → 実装）を通る。

**5. 月次訓練は義務としては廃止。** 訓練が提供していた腐敗検出は、
いまは日常利用が提供する。[drill](../reference/drill.ja.md) は
オンデマンドの健全性チェックに再定義する: 長期間使わなかった後、
クリーンマシンへの導入に頼る前、OS やモデル世代の変化の後、
アーキテクチャ文書のコードからの乖離が疑われるとき（step 7 が
その監査を保持する）に推奨。runbook のステップ自体は何も変え
ない — 変わるのは頻度と枠組みだけである。

## Consequences

- 位置づけサーフェスは新しい前提から書き直す（字句の継ぎ接ぎを
  しない）: README（両言語）、RFP §1・§6（本 ADR への参照付き。
  Discussion Log は歴史として不変）、AGENTS.md、CLAUDE.md、INDEX
  の項目、org profile、web サイトカード、GitHub About、tap の表。
- リポジトリは lab-series umbrella から cli-series umbrella へ
  移る。リポジトリ URL は変わらない。
- 安定性の約束が発効する。gem-agent の利用者数（現在 1 名）は
  約束を軽くしない — 契約こそが約束を誰にでも検証可能にする。
- 受容するリスク: 義務としての訓練なしでは、環境の腐敗検出は
  実利用に依存する。利用が長期間途絶えたら、再び頼る前に健全性
  チェックを走らせること — runbook がまさにそう書いている。
- 歴史文書（ADR 群・RFP の Discussion Log・凍結済みの初回訓練
  記録）は当時の言葉のまま残す。記録は自分の時代を語る。
