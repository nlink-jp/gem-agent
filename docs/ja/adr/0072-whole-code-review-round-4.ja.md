## 背景

前回のコード全体レビュー（ADR-0041、v0.36.1）から今回までに 30 リリース: 133
コミット、26,700 行の追加。キャンセルの床（ADR-0065）、データレーン
（ADR-0055）、コンテキストフック（ADR-0069）、skill ディレクトリと共有書込
ルート（ADR-0070）、セッション識別契約（ADR-0071）を含む。方法は ADR-0041 の
もの: 保守者によるエージェントループの精読、独立レビュワー 5 体の並列
（agent/llm、cmd 配線、TUI と図、セキュリティ境界、永続化とインフラ）、
`go vet`、全パッケージの race 検出、`govulncheck`、`gosec`、`golangci-lint` —
そしてレビュワーの主張は全件コードかプローブで再検証してから採用した。機械
検査は全て緑で、以下の所見は全て読解かプローブ由来である。所見 41 件（高 5）、
4 件を除き全て修正。4 件は理由とともに §3 に記録する。

## 1. 修正 — 境界

### 1.1 pre-tool フックの拒否がピクセルを止めなかった（高）

`view_image` と `read_document` は、コールが拒否されなかったときにバイト列を
ツールメッセージへ添付する。第 2 回はこのガードをゲートの拒否フラグに結び
付けた。pre-tool フック（ADR-0044）はゲートの*前*で拒否し、その結果文字列は
フラグも `error:` 接頭辞も持たない — 画像や PDF は拒否文と一緒に運ばれて
いた。`execCall` は `ran` を返すようになった: ツールの `Run` に到達し自力で
戻ったときだけ真で、添付分岐はこれを見る。ゲート・フック・キャンセルの床、
どの層の拒否でもバイト列は入らない。フック拒否の監査結果も `ok` ではなく
`denied` になった。

### 1.2 階梯の途中のキャンセルがゲートに届いた（中）

`execCallInner` は入口で一度だけ context を見ていた。pre-tool フック実行中や
モデル層のリスク評価（ネットワーク往復）中の Ctrl+C はエスカレーションとして
戻り、`gate.Approve` に届いた: TUI の自動 `n` が誰も下していない
`gate_decision` を記録し、plain REPL のプロンプトは次の stdin 行を答えとして
食べた。フック後と階梯後に context を再確認し、`roundIntervention` が既に
そうしているとおり `interrupted` にする。

### 1.3 ルール層のシェル解釈が bash と違っていた（高）

約 160 のコマンド文字列でプローブした結果、ルール層のコマンドラインの
モデルが 5 点で狭すぎた。注記のないものは Review。欠陥の類型は
*変更コマンドを Safe と判定する*こと — auto モードではプロンプトもモデル
コールもなく実行される。

- **改行。** セグメント分割は `|`・`;`・`&&`・`||`・`&` を知っていたが `\n`
  を知らなかった。`ls\ntouch pwned` は Safe: 1 行目の先頭語が全文を決めていた。
  改行は区切りになった。
- **綴り。** Block パターンは素の名前に固定されていた: `/bin/rm -rf`、
  `\rm -rf`、`RM -rf`（既定のファイルシステムは大文字小文字を区別しない）、
  `/usr/bin/sudo`、`curl … | /bin/sh` はどれも Review に落ち、モデル層が承認
  し得た。各セグメントの先頭語をパターン適用前に正規化（パス接頭辞・
  バックスラッシュ・大文字小文字）。`rm` の recursive+force はどの綴りでも
  フラグから読む（`-r -f`、`--recursive --force`、`-Rf`、`xargs`・`env` の
  後ろ）。git はサブコマンド前のグローバルオプションを飛ばし、`checkout … --`、
  `restore`、`stash drop|clear`、`clean --force` が一覧に加わった。
- **実行可能な read-only コマンド。** `xargs`、`env`、`find -delete`/`-exec`、
  `fd -x`、`rg --pre`、`sed -i` と `w` コマンド、`awk system(…)`、`sort -o`、
  `yq -i`、`tee` は全て Safe だった — `find . -name '*.go' | xargs sed -i '' …`
  は組織自身の guard-recursive-write の事例そのもの。`tee` と `xargs` は
  read-only 一覧から外し、残りは素の形のときだけ read-only（`mutatingUse`）。
- **プロセス置換。** `cat <(rm -r x)` は内側のコマンドを bash で実行する。
  `<(` と `>(` は動的構築。
- **走査の起点（ADR-0070 §3）。** `find $HOME`、`find ..`、`find ~user`、
  `ls -R /` は Safe だった。`find /` と同じく Review。資格情報パスに
  `~/.config/gh/`、`~/.docker/config.json`、`.git-credentials`、シェル履歴を
  加え、相対の `.ssh/` などにも一致させる。
- **`/tmp`。** `> /tmp/x` は誤った理由付きの偽 Block だった: Seatbelt が見るのは
  `/private/tmp` で、これは scratch ルートである。`/tmp`・`/var`・`/etc` は
  ルート照合前に別名を解決する — ADR-0070 §2 のずれを字面側で閉じた。

### 1.4 後続セッションが信頼するものへの書込（高）

`write_file .git/hooks/pre-commit`、`.git/config`、`.mcp.json`、
`.gem-agent.toml`、`.claude/skills/*/SKILL.md`、`AGENTS.md` は全て Safe だった:
相対で資格情報でないパス。`.git/` 配下のフックや設定値は操作者の次の git
コマンドで*sandbox の外*で走る。`.mcp.json` は次回起動でサーバーを sandbox
なしに spawn する。`.gem-agent.toml` のポリシーはゲートを外す。指示ファイルは
次のセッションの system prompt になる。ADR-0020 §4 がメモリ書込をモデル層なしの
Review にしたのはまさにこの理由 — 永続化は汚染されたツール結果を誰にも見られ
ずに後続セッション全てへ届ける — であり、これらのパスは同じ永続化を果たす。

決定: `.git/` 配下への書込は **Block**（そこに用のあるファイルツールはない）。
`AGENTS.md`、`AGENT.md`、`CLAUDE.md`、`GEMINI.md`、`.mcp.json`、
`.gem-agent.toml`、`.claude/` 配下への書込は**操作者だけが答える Review** —
`Verdict.OperatorOnly` で、`decideAuto` はメモリ除外と同様に扱う。この規則は
ファイルツールにもシェルのリダイレクト（`echo x > AGENTS.md`）にも同じく
かかる。他のシェル形（`tee`、`cp`、`sed -i`）はもはや Safe ではないので、
従来どおりモデル層に届く。auto モードでは指示ファイル編集 1 回につきプロンプト
1 回のコスト — 評価者が提案者でないことの代価。

## 2. 修正 — 継ぎ目

### 2.1 `/clear` が作業ディレクトリを環境変数にしか伝えていなかった（高）

ADR-0071 は `/clear` に新しいセッション・トランスクリプト・作業ディレクトリを
与え、新ディレクトリを子プロセスに export した — しかしパスの消費者は全て
起動時に固定されていた: sandbox プロファイル（`$GEMAGENT_WORK_DIR` に書けと
言われたシェルが拒否された）、ファイルツールの第 2 ルート、MCP 取込の spill
先、そして旧パスを名指ししたままの system prompt。`rotateWorkDir` が全てを
動かす: `Registry.UseWorkDir`（空はルート除去）、プロファイルを差し替えられる
よう registry が経由する `liveExec`、registry を読む取込、そして
`SetSystem` — クリアされた会話に守るべきキャッシュ接頭辞はない。`/clear` の
欠陥がさらに 2 つ同梱: side-call ツール（`summarize_file`、`web_search`、
`web_fetch`、`agentic_file_search`）が起動時にロガーを値で捕まえ、`usage`
記録を閉じたトランスクリプトへ書いていた（`liveLog` が変数へ転送する）。
state ルート未解決時に `session.Open("")` がプロジェクトサブディレクトリを
作業ディレクトリ相対で解決し、*操作者のプロジェクト内に*トランスクリプトを
書いていた — ルートを先に確認し、新トランスクリプトを何かを終える前に開く
ので、失敗は見つけたセッションをそのまま残す。

### 2.2 セッションフック付きの `/clear` が TUI を固まらせた（高）

`hookNotify` は `Program.Send` を呼んでいた。slash ハンドラは TUI の `Update`
内で走り、Bubble Tea のメッセージチャネルはバッファなしで `Update` が唯一の
消費者 — そこからの `Send` は永遠に戻らない。`session_start` フックを持つ
操作者（agent-board の構成）が TUI で `/clear` を打つとプロセスを殺すしか
なかった。slash コマンド内で上がった注記はその出力に乗って戻る（`uiNotes`）。
TUI 下で stderr に書いていた `/clear` の失敗経路も同じ道を通る。

### 2.3 `Restart` が旧セッションの状態を保っていた（中）

`Agent.Restart` は履歴をリセットしロガーを切り替えるだけだった: 旧セッションの
transcript 死亡マークが新トランスクリプトを丸ごと沈黙させた。`/clear` 前に
キューされた `session_start` 添付が新セッションの初回ターンに新しいものと
並んで乗った。中断されたコールの遅延通知（ADR-0065 §2）はそのコールをした
ことのない会話に告知されるところだった。自動圧縮の停止スイッチも切れたまま。
全て終わったセッションのものである。中断コールの遅延復帰 goroutine が
`/clear` の差し替え中に記録しようとし得るので、ロガーは死亡マークと同じ
mutex 下で読む。

### 2.4 2 回目の圧縮は 1 回目の要約を 1,500 rune しか見なかった（中）

`renderTranscript` はテキスト添付をツール結果の予算で切り詰め、圧縮が残す
要約は添付である。初回以降の圧縮はことごとく末尾 — プロンプトが「未完了」と
「次の一手」を置く場所 — を欠いた要約を要約していた。前回要約は丸ごと渡す。

### 2.5 `/clear` の `session_start` が source `startup` で発火していた（中）

ADR-0071 §4 は `startup` と書いたが、設定テンプレート・リファレンス・Claude
Code 自身の matcher 語彙は `clear` と言う。文書どおりに書かれたフック
（`matcher = "clear"`）は通常経路で一度も発火しなかった。コードが文書に従い、
ADR-0071 §4 を修正する。

### 2.6 永続化と子プロセス（中 / 低）

- 稼働中の**旧フラット配置セッション**が空きに見えた: `session.InUse` は
  プロジェクトサブディレクトリしか見ず、`workdirs clean` がその作業
  ディレクトリを削除し得た。`Reopen` と同じ場所を見る。
- **診断記録の部分書込**（記録途中の ENOSPC）に次のメッセージが接着し、
  1 行の不正行が resume でメッセージ 1 件を丸ごと飲み込んだ。ロガーは次の
  記録の前に裂け目を補修する — `Reopen` がプロセス跨ぎでするのと同じ。
- **自分で stdout を閉じた MCP サーバー**が両パイプを開いたままゾンビに
  なっていた。EOF で世代を回収する。`.mcp.json` の `${VAR:-default}` は
  Claude Code と同じく展開する。
- **フック**: 孫プロセスが stdout を握っても `WaitDelay` が待機を有界にする。
  pre-tool ペイロードは purpose を除いた引数を運ぶ（ADR-0047 §2 は「どこでも」
  と言い、フックが例外だった）。
- `workdirs clean` が `--yes` なしのパイプ `y` を受け付けていた（ADR-0059 は
  拒むと言っていた）。`-p` はテキストを出さなかったターンでも stdout に空行を
  出していた。メモリと指示ファイルの切り詰めが rune の途中で切れていた。

### 2.7 ダイアログと図（高 / 中）

- **承認ボックス**は詳細を折り返さず、`clipLines` が端末端で印なしに切って
  いた。`edit_file` の 1 行詳細は `path=` を 80 桁の外に置いた — 操作者は
  対象を見えないまま編集を承認していた。詳細・目的・理由はボックス幅に折り
  返し、増えた行は詳細の予算から引く。**ask ダイアログ**は選択肢行も予算に
  入れ、切ったものを開示する。
- **設定パネル**の本文はカタログ化された hint 行の周りが英語のハードコード
  だった。カタログから読む。`(no output)` も同様。
- **mermaid**: 引用符付きラベルはリテラル（`A["read_file(path)"]` が
  `read_file[path]` に書き換えられ、忠実性検査は書き換え後と比べていた）。
  `;` は文の区切り（`A-->B; B-->C` は両ガードを通る幻のノードを描いた）。
  `direction` や `subgraph` で始まるノード id はノード。`<-->` は矢頭 2 つ。
  全て ADR-0042 §5 の 3 規則の内側 — いずれも構文上の事実。

## 3. 意図的に変えないもの

- **ターン外のシグナルは closer を飛ばす。** `signal.Notify` は `runTurnWith`
  にあり、plain REPL のプロンプトでの SIGTERM/SIGHUP は既定動作: `session_end`
  フックもテレメトリ flush もない。トランスクリプトはカーネルが閉じ、resume
  できる（末尾補修）。プロセス全体のハンドラは設計変更（REPL は read で
  ブロックする）で、後続 ADR に記録する。
- **ファイル検索の子は pre-tool フックを走らせない。** ツール部分集合は
  read-only（ADR-0037）で `searchDenyGate` が変更を拒む。読取に着目した組織
  ガードは子の読取を見ない。据え置き。フックが走らない唯一の場所として
  AGENTS.md に記す。
- **`--o` / `--x` 辺**はエッジ数にも矢頭数にも寄与せず、欠落しても通る。
  現場報告なし。正しく描かれることは実測済み。
- **テキストのみのターンは thought signature を運ばない**（gemini-3.8-flash で
  `IncludeThoughts` の有無両方を実測。`textsig_live_test.go` がプローブを保つ）。
  モデルが送ってきた場合に備えて parts 経路は再送するようにした。gotcha の
  「every Part」の文言は実測どおりに狭める。

## 4. v0.68.0 のリリース後レビュー（2026-09-05）

外部レビュワーがリリースを読んだ。主張は全件コードかプローブで再検証し、
7 件全てが成立した。v0.68.1 で修正:

- **`awk 'BEGIN { system ("rm -rf .") }'` が Safe** — `mutatingUse` は
  空白区切りトークンごとに `system(` を照合していたが、正しい awk は括弧の前に
  空白を置ける。結合したスクリプト全体で照合する。
- **ファイルツールの symlink TOCTOU** — `resolvePath` は解決先を検査して
  字面のパスを返しており、検査と open の間に差し替えられたリンクは
  sandbox 外の本体プロセスからルートを脱出できた。registry はルートを
  `os.Root` ハンドルとして持ち、`read_file`・`write_file`・`edit_file`・
  `view_image`・`read_document`・`file_info` はそれを通して開く: 検査と open
  が 1 操作になり、外へ向くリンクは間に何が起きても open 時点で拒まれる。
- **読み込みが上限より前にファイル全体を保持** — `read_file` は全体を読んで
  から 200KB に切っており、巨大・sparse ファイルは行範囲指定でもメモリを
  使い尽くし得た。読み込みはストリーム化: 範囲と上限は読みながら適用し、
  1 行も上限を超えて保持せず、画像と文書は読む前にサイズで拒む。
- **`edit_file` が context を一度も見ない** — 遅い読み込み中に床が放棄した
  コールが、操作者が「中断」を見た後に書き込んでいた。読み込み前と書き込み
  前に確認する。
- **`/clear` 後の遅延復帰が新セッションに着地** — 放棄された goroutine は
  完了時点の現行セッションに通知と記録を追加していた。コールはセッション
  epoch とロガーを捕捉し、`/clear` 後は通知を捨て、記録は旧トランスクリプトが
  開いていればそこへ、監査イベントだけが続く。
- **作業ディレクトリ作成失敗で `GEMAGENT_WORK_DIR` が残る** — 直後に
  再接続する MCP サーバーが前セッションのディレクトリを継承した（起動時は
  入れ子起動が親のものを継承した）。セッションに作業ディレクトリが無ければ
  変数を unset する。
- **`/clear` が `session_end` フックより先に `session.end` を送出** —
  ADR-0071 §4a の逆。順序を ADR に合わせ、ソース上で固定した。

### 4.1 再レビュー（2026-09-05、v0.68.2）

レビュワーが v0.68.1 を再読し、残り 3 件を見つけた。全て成立:

- **走査がまだ字面パスを使っていた** — `search_files`・`list_files`・
  `list_tree`・`file_info` は `resolvePath` の後に `os.ReadDir` / `os.ReadFile`
  で列挙・読み込みしており、外へ向くリンクに差し替えられたディレクトリを
  sandbox 外のプロセスから歩いた。tools パッケージの列挙・stat・readlink・
  読み込みは全てルート経由（`readDirIn`・`lstatIn`・`readlinkIn`・
  `readFileCapped`）になり、解決済みパスに対する `os.Open` 系の直接呼び出しは
  残っていない。
- **work root の切替が放棄コールと競合** — `UseWorkDir` は `workDir` /
  `workRoot` を書き換えて旧ルートを閉じており、それを通して解決中の goroutine
  との同期が無かった。ルートはロック下で 1 つのスナップショットとして読み、
  切り替えられた旧ルートは閉じない（`/clear` ごとに記述子 1 つ。スナップ
  ショットを取ったコールは有効なハンドルを保つ）。`Subset` は親のルートを
  読むので、ファイル検索の子も回転に追随する。
- **遅延復帰の監査イベントがまだ新セッションを名乗っていた** — epoch の修正は
  通知とトランスクリプト記録を旧セッションに留めたが、イベントは再構成後の
  sink へ行った。コールは開始時に sink のセッション id を捕捉し、イベントは
  それを `origin_session_id` として運ぶ。

### 4.2 第 3 パス（2026-09-05、v0.68.2）

第 2 パスの差分自体にさらに 3 件、全て成立:

- **`.gitignore` の読込がルートを迂回** — `internal/ignore` は字面パスを
  `Lstat` してから `os.ReadFile` しており、その間に外へ向くリンクへ差し替え
  られた `.gitignore`（またはその上のディレクトリ）は sandbox 外のプロセス
  から読まれ、巨大ファイルへの差し替えは 1 MiB 上限の前に全量読まれた。
  規則は `FileReader` を受け取り、ファイルツールはルート経由で stat・読込
  し上限をストリームに適用する読み手（`gitignoreReader`）を渡す。
- **`search_files` が上限打ち切りの読込を完全な検索として提示** —
  `readFileCapped` の `more` を捨てていたので、列挙と読込の間に 2 MiB
  上限を超えて成長したファイルは上限まで検索され、検索済みに数えられた。
  そうしたファイルはスキップする（`readForSearch`）— 上限超えが常にそう
  だったように。
- **切り替えられた work root を閉じていなかった** — プロセスの寿命の間
  `/clear` ごとに記述子 1 つ。ルートは保持数付きの `rootHandle` になり、
  回転ロック下で取得・open 後に解放・回転時に退役、退役と最後の解放の
  遅い方が閉じる。

## 教訓

- **独立レビュワーは保守者の精読が見なかったものを見つけた** — 4 回連続で。
  フック拒否の添付バイパスは保守者自身の読みで出たが、改行の区切り、`/clear`
  の凍結、作業ディレクトリの継ぎ目は出なかった — そしてそれぞれが出荷済みで
  操作者に届く欠陥だった。方法（ADR-0041）は有効。
- **ある層のフラグに結び付けた許可は、他の全ての層で穴になる。** 第 2 回は
  添付ガードをゲートについて直し、第 4 回は同じバイパスを 1 層上で見つけた。
  「ツールが走った」を意味するガードは、どの拒否者の署名でもなくその事実に
  結び付けること。
- **消費者がコピーを持つなら「変数を追え」では足りない。** ADR-0039 の
  live-variable 規則はクロージャの `sessionLog` には適用され、コンストラクタ
  3 つで漏れた。`/clear` の作業ディレクトリは export されて伝搬しなかった。
  ローテーションには消費者の一覧と、それを歩くテストが要る。
- **境界はツール名ではなく永続化である。** ADR-0020 §4 の論はメモリについて
  だったが、最初からセッションを越えて残り次のセッションが信頼する書込全て
  についての論だった。

## 帰結

- auto モードは指示ファイル・設定ファイルへの編集ごとに 1 回確認し、`.git/`
  配下への書込は決して承認しない。
- ルール層の語彙が広がった。新しい危険な形は引き続き `internal/risk` に
  コーパステスト付きで入れる（`review4_test.go` が今回分を保持する）。
- `/clear` は完全なセッション境界: トランスクリプト、作業ディレクトリ、
  sandbox、ファイルルート、取込、プロンプト、フック、そしてエージェント自身の
  セッション状態。
