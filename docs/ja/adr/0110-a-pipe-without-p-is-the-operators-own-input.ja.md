# ADR-0110: `-p` なしのパイプは操作者自身の入力である

| Amends | ADR-0064 §4（「パイプ stdin はプロンプト文にならない」の文） |

## Context

stdin が端末でなく `-p` もないとき、gem-agent は素の REPL を動かし、パイプを打鍵と同じ経路で読む。`!` は確認なしに operator レーンで走り、`/` はスラッシュコマンドに届き、それ以外のテキストはターンの指示になる。監査は、第三者の内容をパイプして `-p` を忘れた操作者は、その内容の作者にシェルを渡すことになると指摘した。

この動作は仕様である。ADR-0002 はスクリプト用にこのフォールバックを作り、ADR-0055 §3 は「`-p` なしの非 TTY stdin はスクリプト入力の経路で、stdin の行はコマンドでありデータではない」と記録している。監査が矛盾と呼んだものは文の不正確さである。ADR-0064 §4 とインターフェースのリファレンスはパイプ stdin はプロンプト文にならないと書いたが、ADR-0064 §4 は続けて、stdin の行はこれまでどおり続くと書いている。

越えられる境界はない。操作者が自分でパイプを組まない限り何も走らず、`curl … | bash` と同じ形である。ランタイムの規則は、聞かずに走るものを守り、操作者自身の行為が要るものは残余として記録することである。

## Decision

1. **`-p` なしのパイプは操作者自身の入力のままとする。** 権限の境界ではなく、ゲートもしない。ランタイムには誰がテキストを書いたか分からず、判定もしない。
2. **文書は、操作者が読む場所でそう述べる。** README とインターフェースのリファレンスに、このパイプの `!` とスラッシュコマンドは実行されること、第三者のテキストは `-p` に渡すことを書く。「プロンプト文にならない」は `-p` の形の規則である。

## Consequences

- 受け入れる残余: `data | gem-agent "…"` は安全な `data | gem-agent -p "…"` と似ており、フラグ 1 つしか違わない。第三者の内容をパイプするときに `-p` を忘れた操作者は、その内容を自分の入力として実行する。
- 素の REPL のペースト対応の読み取りは、バッファに一緒に入っている行を 1 つの入力にまとめるので、パイプの行は確実に別々の入力になるとは限らない。これは変更せず、文書に記す。

## Alternatives considered

- **`-p` なしのパイプを拒否し、従来の動作は `--script-stdin` フラグにする** — 実装したがリリース前に取り下げた。操作者自身が行う行為を守るために、文書化されたスクリプトの経路を壊すことになり、フラグにも独自の規則（1 行 1 入力、承認の拒否）が要る。
- **パイプのときだけ `!` と `/` を無効にする** — 不採用: 同じ操作者の行為に対する同種のゲートである。
- **stderr への警告** — 不採用: コマンドが走った後に届くので、何も変えない。
