# ADR-0021: 全体コードレビューの修正一括

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「コード全体をチェック — テストは通っているが未知の不具合があるかもしれない」 |

## Context

6 観点の並列レビュー（並行性・封じ込め・LLM 層・セッション/resume・TUI・
配線/ポリシー）+ 静的解析 + 実 API 実測で、確定不具合 9 件とタイミング
依存の TUI 危険群が見つかった。修正の多くは単純な訂正であり、この ADR は
**判断**だったもの — 複数の直し方が成立したもの — を記録する。1 つの
レビューから同時出荷される修正群に 1 本の wide ADR、という既存の前例に
従う。

特筆: 独立した 2 レビュアーが certain と報告した 2 件 —「末尾が dangling
function call のトランスクリプトは resume で 400」「中断されたツール
ラウンドは履歴を汚染」— は**実測で反証**された。現行 API は疑わしい 3 形状を
すべて受理した。この 2 件に修復コードは入れていない。もっともらしい機序より
実測が勝つ。

## Decisions

1. **`/clear` をトランスクリプト記録にし、スキーマ版数を 2 へ。** `Reset`
   は唯一「対応する記録を持たない履歴変更」で、消した会話が resume で
   復活し、clear 後の圧縮の `Replaced` index は誤ったリストに適用されて
   ツール結果の上に切れ目が乗り得た（400 になる形状）。Load は `clear`
   記録を「履歴を空にする」で再生する — ライブと同じに。版数を上げるのは、
   **旧ビルド**が clear 入りファイルを黙って復活させる代わりに拒否する
   ため。新ビルドはスキーマ 1 のファイルを従来どおり読む。
2. **読み込みを行ベース・寛容にし、Reopen が末尾を補修する。** クラッシュの
   torn last line は、Reopen がその直後に追記した時点で 1 本の不正行に
   接着し、旧デコーダは全エラーを EOF 扱いしたため以降の記録を無言で
   全て捨てた（実測: 6 ターン中 1 ターンしか生存しない）。Load は JSONL を
   行単位で読み（無制限リーダー、64KB Scanner 制限なし）、解析不能行を
   スキップして件数を報告する — 「N 行読めなかった」が見え、短くなった
   会話が正常のふりをしない。Reopen はファイルが改行で終わっていなければ
   改行を足し、tear を 1 行に隔離する。
3. **会話を成す記録の書き込み失敗は、大きな音でトランスクリプトを停止する。**
   fire-and-forget はライブ履歴とファイルをずらし、以後の圧縮 index が
   再生を壊し得た。最初の message/compaction 書き込み失敗で logger を dead
   とし、以後何も書かず（ファイルは一貫した接頭辞のまま）、「このセッションは
   もう完全には resume できない」と操作者に告げる。診断のみ劣化させる案は
   却下 — ファイルの第二の役目（ADR-0005: resume の正本）がある以上、
   無言の部分記録は無記録より悪い。
4. **セッションファイルに advisory flock。** 同一セッションへの二重 resume が
   追記を交錯させ、どちらのプロセスも持っていない会話を合成していた。
   Open/Reopen が non-blocking 排他ロックを取り logger の生存中保持する。
   二人目は「session in use」で拒否される。
5. **セッション常時許可 'a' は Block 床と明示 "always" ポリシーの下に置く。**
   実測した穴: 無害な `shell_exec` への一度の 'a' が、以後の Block 判定
   コマンド（sudo・rm -rf・force-push・クレデンシャルパス）を全モードで
   無プロンプト実行にしていた — ゲートが誰よりも先に allowlist を見ていた。
   `Approver` インターフェースに `mustPrompt` を追加: エージェントが Block
   判定と "always" ポリシーのツールで立て、両ゲートは立っていれば allowlist を
   見ない。そのプロンプトで 'a' と答えることは引き続き可能で、将来の
   **非 Block** コールに効く — 床は聞き続ける。これで「後から always に
   締めても allowlist が勝つ」穴も、取り消し API なしで同時に塞がる。
6. **ポリシー解決はスコープ優先、その中で特異性。** 単一のマージ済み
   パターン表がスコープ横断で exact-before-wildcard に解決していたため、
   global の exact がプロジェクトの wildcard **tighten** に勝ち、ADR-0008 の
   「締めるのはどこでも可」を破っていた。プロジェクトスコープを先に
   （近い方が勝つ）、各スコープ内は exact 優先に。
7. **`!` と `/` は実行中にキューできない。** キューされたメッセージは 1 つの
   入力に結合される（ADR-0007 の one-turn-per-instruction）が、結合結果が
   丸ごとプレフィックスでルーティングされていた: キューした `!make test` +
   続けてキューした散文は、散文が shell として実行され、キューした
   `/clear` は後続を無言で捨てた。コマンドはキュー時にヒント付きで拒否し
   （テキストは入力欄に残る）、結合される pending は常に散文になる。
   キューのリスト化は却下 — 動く世界に対する複数の滞留指示は ADR-0007 が
   意図的に避けたもの。
8. **途中打ち切りの非空応答は報告する。黙って受理しない。** 空応答ガードは
   完全な空しか捕まえず、SAFETY/MAX_TOKENS で途中打ち切られた部分テキストは
   正常な回答として保存・返却されていた。ターンは続行する（起きたことは
   起きた）が、回答が切られたことと理由を操作者に告げる。
9. **見送り、記録に残す:** 空の非 thought パートからの signature 捕捉
   （観測されたことのないパターンのために再生形状を変え得る）、memory
   `.project` マーカー欠如（脅威モデル内で到達不能、ADR-0020 に記載済み）、
   プロジェクトパスの大文字小文字正規化（メモリスコープ分裂には意図的に
   奇妙な cd が要る）、幅**拡大**時の画面クリア（拡大リフローで一部端末の
   ピンはずれるが、拡大のたびのクリアはドラッグリサイズ中に可視内容を
   繰り返し消す — 縮小時のみリセット + 優雅なドリフトの方が良いトレードで、
   既存テストが意図的にそう固定している）。

残る修正は判断の重みなしで同乗する: 承認ダイアログの type-ahead 猶予、
キュー送信をまたぐ下書き保全、shell 中断時のハンドバック、ピン描画のタブ
展開、低い端末での view クランプ、起動警告のバナー乗せ、
rune 安全な clip、/tools のライブポリシー、解決済みパスでの trusted_projects
照合、file_info の親解決、MCP stdin の世代ガードと名前衝突の曖昧性解消、
リトライのチャンク計数、web メタデータの nil ガード、復元履歴の圧縮推定、
read_file/edit_file の行数 off-by-one、near-miss 診断の整列、到達可能な
依存脆弱性。

## Consequences

- `/clear` を使ったセッションが正しく resume される。クラッシュした
  セッションの損失は最大で torn line 1 行、しかもそう告げる。二重 resume は
  拒否される。
- 'a' は「定型の確認をやめる」であって「危険なものの確認をやめる」では
  なくなる。明示ポリシーは常に勝つ。
- プロジェクトは global の wildcard/exact 構成が何であれ、本当に締められる。
- トランスクリプトのスキーマは 2。旧ビルドは新ファイルを名指しで拒否する。
