# ADR-0008: ファンクション単位の承認ポリシー（グローバル / プロジェクト）

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ要望: MITL の要否を組み込み・MCP のファンクション単位で、かつグローバル設定とプロジェクト設定の両方で指定したい |

## Context

現在のゲート判定は 1 ビット（`Mutating`）で決まっている。組み込みの書き込みと
`shell_exec` は聞き、`list_files` と `read_file` は聞かない。そして
**MCP ツールは常に全部聞く**。サーバーのツールが何をするのかクライアント側から
知りようがないためである。

摩擦はこの最後の規則にある。読み取り専用の lookup —「この IP は Tor exit か？」—
は、クライアントから見ると本番環境に POST するツールと区別がつかない。だから
毎回聞く。指標のトリアージをしているセッションでは延々と聞き続ける。自動承認
（ADR-0004）が効くのは ON にしている場合だけで、しかも**オペレータが自分の
サーバーについて既に知っていること**を判定するのに LLM ラウンドを 1 回使う。

情報の非対称は実在し、クライアント側では埋められない。だがオペレータは埋められる
— 自分のサーバーのことは知っている。欠けているのは、それを書く場所である。

## Decision

ファンクション単位の承認ポリシーを、2 つのスコープで導入する。

```toml
# ~/.config/gem-agent/config.toml
[approval.tools]
"mcp__tor-exit-lookup__*" = "never"   # 読み取り専用の lookup サーバー
"shell_exec"              = "always"  # auto モードでも必ず聞く
```

```toml
# <project>/.gem-agent.toml
[approval.tools]
"write_file" = "always"
```

1. **値は 2 つ + 未設定。**
   - `"always"` — 全モードで必ず聞く。ADR-0004 のルール層 Block に対応する、
     オペレータが設定する per-tool の床。
   - `"never"` — 全モードで聞かない。**通常モードを含む**。auto モードのときだけ
     効くのでは要望に答えたことにならない（要望は通常時の話でもある）。
   - 未設定 — 現行の挙動（変更系は聞く、auto モードならラダーを通る）。
2. **`never` は Block の床を持ち上げない。** 呼び出しごとに効果が変わるツール —
   とりわけ `shell_exec` — は引き続き純粋なルール分類器を通り、Block 判定
   （`rm -rf`、`sudo`、`curl … | sh`、認証情報パス、プロジェクト外書き込み）は
   聞く。これが無ければ `shell_exec = "never"` は「何でも無人実行」という設定に
   なり、提供する価値が無い。**モデル層は `never` のとき完全に飛ばす**: オペレータが
   既に下した判断に金を払わないことが目的だからである。
3. **マッチング**: 完全一致、または末尾 `*` の前方一致。後者の主目的は MCP の
   サーバー単位ポリシー（`mcp__server__*`）である。完全一致 > 長い wildcard >
   短い wildcard。**単独の `"*"` は設定エラー**とし、近道にはしない。全部を
   無効化するのは `--no-sandbox` 級のオプションの見た目であるべきで、ポリシー
   一覧の 1 文字のタイプミスで到達できてはならない。
4. **スコープと、各スコープが動かせる向き。** プロジェクトファイルは
   **自由に締められる** — 承認を増やす分には誰が書いても構わない。
   **緩められるのは、オペレータがグローバル設定でパスを信頼登録したプロジェクト
   だけ**とする:

   ```toml
   [approval]
   trusted_projects = ["/Users/…/work/my-repo"]
   ```

   信頼されていないプロジェクトでは `"never"` エントリを**無視し、起動時に報告
   する** — 対象ツール名と、望むなら追記すべき行そのものを出す。

   この非対称性が設計の要である。プロジェクトディレクトリの中身は、オペレータが
   書いたものとは限らない。リポジトリを clone して中を見るのは普通の行為であり、
   このツールの想定利用者にとっては**敵性コードに対して**行う普通の行為でもある。
   `shell_exec` の承認を黙って外す `.gem-agent.toml` は、「clone して調べる」を
   コード実行プリミティブに変えてしまう。sandbox は書き込みを封じ込めるが、
   無人で走るシェルはオペレータが読めるものを読んで送れる。

   締める方向に信頼は要らない。敵性リポジトリが「もっと確認してくれ」と言って
   くるのは、防ぐ価値のある攻撃ではない。
5. どちらのファイルも strict decode。ポリシーファイルの未知キーは黙殺ではなく
   エラーとする — 書いてあるとおりに効かないポリシーは、ポリシーが無いより悪い。

## Consequences

- よくある摩擦（常にゲートされる読み取り専用 MCP サーバー）が 1 行で解消する。
  自動承認を ON にする必要も、呼び出しごとの LLM ラウンドも要らない。
- `always` はモデルが持ち上げられない床をオペレータに与える。ADR-0004 の Block
  層と対称であり、`shell_exec = "always"` はグローバル設定に永久に置いておける
  設定である。
- 信頼リストは維持対象が 1 つ増える。プロジェクトの `"never"` が初めて無視される
  ときは多少うっとうしい。ただし起動時の通知が貼り付けるべき行を出すので、コストは
  プロジェクトごとに「1 回のペースト」であり、その対価が「clone したリポジトリが
  ゲートを外せない」ことである。
- ADR-0001 はこれで 2 度目の修正を受ける: MITL は「一次防御・既定モード」
  （ADR-0004）に加えて「ツール単位・オペレータのポリシー」でもある。sandbox は
  変更なく全モードで有効であり、プロジェクトディレクトリ封じ込めも同様。

## Alternatives considered

- **プロジェクトファイルが自由に緩められる** — 却下。`git clone` + `gem-agent` が
  無人シェル実行の手段になる。要望は文字どおりプロジェクトスコープであり、それは
  用意した。用意しなかったのは「オペレータが書いたとは限らないディレクトリに、
  防御を弱める権限を与えること」である。
- **プロジェクトごとに 1 回聞く**（VS Code の workspace trust 方式）— 現時点では
  却下。信頼状態の永続ストアと対話経路が必要になるが、one-shot とパイプ実行には
  対話経路が無い（どちらにせよ fail closed になる）。グローバルの一覧は新しい
  状態ファイル無しで同じ仕事をし、1 箇所で監査できる。一覧の編集自体が摩擦に
  なったら再検討する。
- **グローバル設定のみに per-tool ポリシーを置く** — 却下。要望の半分にしか
  答えていないし、締める方向のプロジェクトポリシーには実用価値がある
  （全書き込みの確認を求めるリポジトリ）。
- **3 つ目の値 `risk` / `ladder`** — 冗長として却下。auto モード下の「未設定」が
  既にそれである。
- **`.mcp.json` に read-only 印を付ける** — 却下。あれは Claude Code の形式であり、
  そのまま読むから drop-in が成立している。他人のスキーマに独自フィールドを
  生やすのは、読む価値そのものを壊す。
