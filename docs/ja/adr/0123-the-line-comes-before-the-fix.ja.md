## 背景

ADR-0122 §1 は線を引いた。サンドボックスが相手にするのは、モデルが間違って、または誘導されて実行したコマンドで、ランタイムと競争するように書かれたプログラムではない。この線は v0.104.0〜v0.106.0 の指摘に当てはめたが、操作者が指示したものは、指示されたという理由で残した。その指示はどれも、直し方は言うが、誰が起こせるのか、どのくらい起きるのか、何を得るのかを言わない提案への答えだった。それらの事実なしに出た指示は、作ったものを残す理由にならない。

v0.100.0 以降の変更をすべて、攻撃がどこから始まるかで読み直した。

| 起点 | 起きやすさ | 守る対象か |
|---|---|---|
| A. 読んだ文章に誘導されたモデル | ふつうの利用で起こり得る | 守る — read レーンは聞かずに走り、write レーンは操作者の承認で走る |
| B. 操作者が信頼する前のリポジトリの中身 | 起こり得る | 守る — 信頼の記録（ADR-0074） |
| C. 操作者自身の操作（`git pull`、別のターミナル、設定） | よくある。悪意はない | 攻撃ではなく、正しさの問題として |
| D. この機械でランタイムと競争するプログラム | 実際の利用で起きた例はない | 守らない（ADR-0122 §1）。それを動かせる者は、プロジェクトのコードを書き換えられる |
| E. 操作者の権限で動くマルウェア | — | 守らない |

**訂正。** ADR-0121 §8 は、scratch のプローブの固定名にリンクを置くと、そのリンク越しに `x` が書かれると書いた。プローブのコマンドは read レーンで走るので、書き込みが届くのは read レーンがもともと書ける場所だけである。誰にも何も与えていなかった。

## 決定

1. **指摘は、何かを作る前に、次の順で判断する: どんな条件で、どのくらい起きるか。誰が起こすか。その者はすでに何を持つか。それで新しく何を得るか。** 修正はこの 4 つの答えを添えて提案し、「直さない」を操作者に示す選択肢の一つに入れる。この 4 つなしの提案に応えた指示は、この 4 つで判断し直す。

2. **プロジェクトのスキルを、使う時点では比べない**（ADR-0119 を置き換える）。起点は C、または pull を通した B。スキルを変える上流の作者は、操作者がビルドして実行するプロジェクトのコードをすでに書いている。変わった文章は次の `/clear` か起動までモデルに届き、そこで ADR-0074 のとおり比べられる。その文章が導くコマンドも、レーンと承認を通る。スキルを書き換えたモデルは、自分のセッションでは何も得ず、次の起動で捕まる。外すもの: 使う時点の比較、問いとその 3 つの結果、無効化の状態、`tools.NeedsOperator` とエージェント側の扱い、問いのダイアログの見出しと初期選択、素のプロンプトでの単語による答え、ターンの一段としての `/skill`（テキストの展開に戻す。ADR-0010 §2）、`skill_trust` / `skill.trust` の記録、断りの文言、名前に制御文字や書式文字を含むスキルのディレクトリを一覧に出さない規則。この規則は問いの文面を守るためのもので、TUI はどのメッセージも入口で無害化している（ADR-0093）。

3. **スキルの digest は、v0.103.1 が出した走査で取る。** ファイル数 2,000 の上限はそのまま。上限に達したとみなすのは、加えようとするファイルが上限を超えるときで、次に来るエントリの種類を問わない判定ではない（v0.105.0 の修正のとおり）。エントリ数と深さの上限、階層ごとのハンドルは外す。これらが抑えていたのは、リポジトリがファイルとして運ぶ木で、それはファイル数の上限がすでに抑えている。上限のない木の代償は起動が遅くなることである。10 の木で比べた — 中と外へのリンク、行き先の無いリンク、リンクであるスキルのディレクトリ、入れ子と ASCII 以外の名前、改行を含む名前、1 MiB を超えるファイル、2,100 ファイル、読めないファイルとフォルダ、FIFO、指示ファイル。ピンと注記は前後ですべて同じだった。例外は 40 段の深さのスキルだけで、v0.104.0〜v0.106.0 は 32 段で打ち切っていたが、今は木全体を digest する。その頃にそれをピンしていれば、次の起動で一度だけ尋ねる。

4. **open は標準ライブラリのものに戻す**（ADR-0120 を置き換える）。v0.103.1 が使っていた場所では `os.Open`、`Root.Open`、`os.OpenRoot`、`os.ReadDir`、`os.WriteFile`、`os.RemoveAll` を使う。外すもの: `bounded.OpenRegular`、`OpenRegularPath`、`OpenRegularPathNoFollow`、`OpenDir`、`OpenDirIn`、`OpenRoot`、`WriteFile`、`RemoveAll`、`ErrNotRegular`、テスト `TestOpensDoNotWait`、そして ADR-0119 の、プロジェクトの 4 つのファイルを開く前に見る処理。名前の場所に FIFO があるとき起きるのは、open が待つことである。git は FIFO を運べないので、置くには操作者が承認したコマンドか、レーンの外のプロセスが要る。待ちは操作者が割り込みで終わらせる。残すもの: ファイルツール自身の待たない open（ADR-0072 §4.8、v0.100.0 より前から）と、読み取りの子プロセスが呼び出しの名指すルートだけを開くこと（ADR-0114 §4、応答しなくなった共有フォルダのため）。

5. **起動時の確認は v0.105.0 の形に戻す**（ADR-0121 を置き換え、ADR-0122 §3 を撤回する）。プローブは乱数名で排他的に作る（ADR-0073 R1）。対照は同じコマンドをサンドボックスの外で走らせる。削除はパスで行う。scratch のプローブは固定名に戻す。プローブのコマンドに時間の上限は置かない。クリップボードの取り込みのファイルは、元の乱数名で一時ディレクトリに作る。外すもの: `internal/sandbox/probe.go` のディレクトリを持ったままにする仕組みと、テスト `TestTheChecksGoThroughHeldDirectories`。どれも起点 D を必要としていた（ADR-0121 自身の測定表）。

6. **ディスク上の信頼の記録が記録である。** v0.103.1 は、ポリシーファイルがそのプロジェクトのピンを失ったとき、セッションのピンを使い続けた。ポリシーファイルはどのレーンからも届かない。ピンを失うのは、操作者かレーンの外のプロセスがそれを消したときである。外すもの: その代替と、セッション自身の書き込みでもピンを保っていた `adoptPolicy`。残すもの: セッションが外したファイルへの書き込みがそう告げること（同じコミットのもう半分）と、ディスク上のファイルとの比較（v0.103.1）。

7. **残すもの。同じ 4 つの答えで判断した:**

   | 変更 | 起点 | 新しく得るもの |
   |---|---|---|
   | ADR-0109、承認済みレーンのキャッシュを read レーンの外へ | A、聞かずに走る | 操作者が承認したビルドへのコードの仕込み |
   | ADR-0111、`!` コマンドの出力はデータ | A | 操作者の声としての文章 |
   | ADR-0112、ダイアログは呼び出し全体を運ぶ | A | 操作者が効果を見られないコマンドの承認 |
   | ADR-0114、追加ディレクトリ | C、`/Volumes` は A | 聞かずに走る read レーンが、マウント中のすべてのボリュームを読むこと |
   | ADR-0122 §2、レーンの基準を一度だけ決める | A、承認されたコマンドを通して | write レーンがプロジェクトの外へ書くこと — サンドボックスが決してしないと言っていること |
   | v0.103.1、ピンをディスク上の記録と比べる | C | —（不具合: 別の場所での `trust --accept` が見えなかった） |
   | ADR-0116〜0118、`golang.org/x/net` | — | セキュリティではない |

## 結果

- 変わったスキルについての問いは出ない。セッション中に変わったスキルは、`/clear` か次の起動までは今の中身で読み込まれ、そこで外されて名前が示される。指示ファイルと同じである。
- ランタイムが開く名前の場所に FIFO があると、割り込むまで待つ。
- 起動時の確認は v0.105.0 と同じに走る。
- 外すものを説明している文書は、同じ変更で直す: README と README.ja（スキルの問い）、両言語のマニュアルと、設定・連携のリファレンス、AGENTS.md、ADR-0074 の改訂。

**受け入れて記録するもの:**

| 起こり得ること | 起点 | 結果 |
|---|---|---|
| セッション中にスキルが変わる | C、または pull を通した B | 新しい文章が `/clear` か起動までモデルに届く |
| ランタイムが開く名前の場所に FIFO がある | 承認されたコマンド、またはレーンの外 | open が割り込みまで待つ |
| 確認の最中にプローブが差し替えられる（ADR-0121 の表） | D | 確認の名前のファイルが書かれる・消される。確認が通る、または待つ |
| 深さやエントリ数でファイル数の上限を超えるスキルの木 | B | 起動が遅い。上限の外はピンされない |
| 2,000 を超えるファイルを持つスキル、または 1 MiB を超える `SKILL.md` | B | v0.104.0 より前と同じく読み込まれる。最初の 2,000 ファイルより後の変更や、大きさを保ったままファイルの最初の 1 MiB より後で起きた変更は、次の起動で見えない |
| ポリシーファイルがプロジェクトのピンを失う | 操作者、またはレーンの外 | プロジェクトのファイルが、ピンのないものとして読み込まれる |

## この設計が要求するテスト

- ピンが区別する種類の木それぞれで、戻した走査の digest が、外した走査の digest と同じである（決定 3 に挙げた木で一度比べた）。
- 外すものを保っていたテストは一緒に外す。v0.103.1 と v0.105.0 が同じコードに持っていたテストは、今もそのコードを説明している限り戻す。
- `make check` が通り、起動時の確認が APFS で通る。

## 検討した代替案

- **スキルの問いは残し、その周りだけ外す。** 不採用: 残る部分も、すでに持っているより少ししか得ない起点に答えている。
- **変わったスキルを、問わずに使う時点で断る。** 同じ理由で不採用: 起動が捕まえないものは何もないのに、モデルを止める。
- **プロジェクトの 4 つのファイルを開く前に見る処理は残す。** 不採用: それが探す FIFO を、git は運べない。
- **先にリリースして、後で外す。** 不採用: v0.106.0 以降の 12 コミットはまだリリースしておらず、これはそれと一緒に出す。
