## Context（背景）

gem-agent はセッションを開始時刻 `YYYYMMDD-HHMMSS` で名付け、同じプロジェクト
ディレクトリ内で衝突すれば数字の接尾辞を付ける（ADR-0005）。セッションは
プロジェクトごとに置かれる（ADR-0022）ので、同じ id が 2 つのプロジェクトに
同時に存在でき、gem-agent の外からは区別できない。id が resume にしか使われて
いない間は無害だった。id が子に export された（`GEMAGENT_SESSION_ID`、ADR-0069
追記 2）時点で無害でなくなった: それを鍵にした消費者が、別プロジェクトで同じ
秒に始まった 2 つのセッションを混同した。

これを表面化させた消費者 — gem-agent と Claude Code のセッションが共有する
マシン内ボード agent-board — は両ランタイムを同一に扱わねばならない。Claude
Code の識別要素は固定で実測済み（2.1.226）: マシン内で一意な UUID v4 の
セッション id、`/clear` で新しい id、ディレクトリとしてのプロジェクト（`cwd`、
子には `CLAUDE_PROJECT_DIR`）、子への `CLAUDE_CODE_SESSION_ID`、`SessionEnd` を
含む 4 つの hook イベント。gem-agent が異なる要素を公開する箇所ごとに全消費者
が特別扱いを要し、オペレーターの指示は下流で補償するのではなく源で差を無くす
ことである。

同じ議論から出た 2 つの制約が設計を縛る: gem-agent の都合でオペレーターの
プロジェクト内に何も書かない。プロジェクトが git 管理下にあることに依存しない。

## Decision（決定）

### 1. セッション id は UUID v4

`session.Open` は UUID v4 を生成する。`ValidID` は新形式とタイムスタンプ形式の
両方を受け付け、既存のトランスクリプトはすべて従来どおり一覧・resume できる。
`--resume` は曖昧でない前方一致を受け付け（一覧は開始時刻の隣に先頭 8 文字を
示す）、オペレーターのタイプ量は従来と変わらない。開始時刻は元からあった場所
— トランスクリプトの `session` ヘッダとファイルの mtime — に残り、一覧はそれで
並ぶ。id は時刻を運ばなくなる。id はマシン内で、実用上はどこでも、一意である。

### 2. `/clear` は新しいセッションを始める

クリアされた会話は新しいセッションである: 新しい id、新しいトランスクリプト、
古いものは閉じられ resume 可能。現在の `/clear` は同じトランスクリプト内で履歴を
空にする（`clear` イベントとして記録、ADR-0021）。Claude Code は `/clear` で
新しいセッションを始める。同じ id が空の履歴で続くのを見た消費者は「クリア」と
「圧縮」を区別できなかった。作業ディレクトリ（ADR-0058）はセッションに従う:
新しいものが作られ、古いものは他と同様に掃除対象になる。

### 3. プロジェクトはディレクトリであり、`GEMAGENT_PROJECT_DIR` として export する

プロジェクトは gem-agent が起動されたディレクトリ（既に `projectDir` である
ルート）。`GEMAGENT_SESSION_ID` と `GEMAGENT_WORK_DIR` の隣で子に export され、
子は Claude Code の子が見るのと同じ 3 つの事実（`CLAUDE_PROJECT_DIR`、
`CLAUDE_CODE_SESSION_ID`、自身の cwd）を見る。プロジェクト識別子を発行したり、
プロジェクト内に保存したり、git から導出したりはしない: 安定した鍵が要る
消費者は、自分の state でディレクトリから導出する。

### 4. `SessionEnd` が hook イベントに加わる

`[[hooks.session_end]]` はセッションの終了時 — 通常終了、`/quit`、EOF、
シグナル、単発実行の終わり — に、Claude Code のペイロード（`session_id`、
`transcript_path`、`cwd`、`reason`: `clear` | `exit` | `other`）で、短い
タイムアウト付き・非ブロッキングで走る（セッション終了は拒否できない。Claude
Code で実測、ADR-0069 の背景）。`/clear` は旧セッションの `SessionEnd`、次いで
新セッションの `SessionStart`（`source` `clear`）を発火する — Claude Code が
生む順序と同じ。

*ADR-0072 §2.5 による修正: この節は当初 source を `startup` と書いていた。
設定テンプレート・リファレンス・Claude Code の matcher 語彙は `clear` と言い、
v0.66.0 はこの節どおりのコードで出荷された — `matcher = "clear"` のフックは
`/clear` で一度も発火しなかった。コードは文書に従う。*

### 5. 変わらないもの

プロジェクト別の state 配置（ADR-0022: エスケープしたパスのディレクトリ、
`.project` マーカー、ファイル移動ゼロ）、トランスクリプト形式（ADR-0005）、
hook ペイロードの形（ADR-0044 / ADR-0069 と追記）、`GEMAGENT_WORK_DIR`
（ADR-0058）。

## Consequences（帰結）

- どちらのランタイムが始めたセッションでも同じ方法で識別される。セッション
  単位の消費者はランタイムごとに 1 行を登録し、特別扱いを持たない。
- オペレーターは id 内の読める時刻を失い、一覧で取り戻す。resume のタイプ量は
  前方一致で短いまま。
- `/clear` は少し重くなり（新しいトランスクリプトと作業ディレクトリ）、少し
  正直になる（旧会話は自身の id で resume 可能なまま）。
- cli-series の安定性契約が適用される: id 形式と `/clear` の意味論は新規
  セッションについてのみ変わり、既存のものは何も止まらない。minor 版で出す。

## Alternatives considered（検討した代替案）

- **タイムスタンプ + ランダム接尾辞**（`20260905-001059-7f3a`）— id 内に読める
  時刻を保つが、gem-agent を全消費者が知るべき特別扱いのままにする。採用要素を
  Claude Code に一致させるというオペレーターの指示により却下。
- **`/clear` をセッション内に留める** — 却下: 消費者がクリアと圧縮を区別
  できず、Claude Code の意味論こそ消費者が既に扱っているもの。
- **gem-agent が発行するプロジェクト識別子**（プロジェクト内、state、git
  由来）— 却下: オペレーターのプロジェクトは gem-agent の帳簿の置き場では
  なく、git は前提条件ではなく、ランタイムごとの識別子は（持たない）Claude
  Code と異なる。ディレクトリは両ランタイムが持つもの。
- **組織横断の ADR** — 却下: これは gem-agent 自身の仕様であり、agent-board の
  仕様はそこから導かれる。
