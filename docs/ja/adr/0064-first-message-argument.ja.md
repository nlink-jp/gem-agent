# ADR-0064: 位置引数は対話セッションの第 1 ターン

| 項目 | 値 |
|-------|-----|
| ステータス | **Accepted** |
| 日付 | 2026-09-02 |
| 拘束範囲 | gem-agent |
| 決定者 | nlink-jp メンテナ |
| 契機 | オペレーター:「初手でやることは決まっているが、その次のターンでは対話で動かしたい」— 地味に繰り返し発生するセッションの形 |

## Context（背景）

既存の 2 つの入口はどちらもこの形を取りこぼす。`-p` は 1 ターン
実行して終了する: スクリプト可能だが、人間が舵を取る前にセッションが
終わっている。対話モードは舵を取れるが、起動前に決まっていた第 1
ターンも手で打たなければならない。「初手を渡して、その後キーボードを
受け取る」方法が無かった。

## Decision（決定）

### 1. 省略可能な位置引数 1 つを、第 1 ターンとして送信する

```
gem-agent "初手の指示"            # TUI 起動、指示が第 1 ターンとして走る
gem-agent -c "続きを頼む"
gem-agent --auto "テストを回して壊れたら直して"
```

メッセージはバナー印字後に送信され、以後は通常の対話 gem-agent。
`--continue` / `--resume` / `--auto` との組合せは**何も特別扱いせずに**
成立する: 引数は、他のフラグが選んだセッションの単なる第 1 ターンで
ある。この面の形は `claude "prompt"` と同型 — エコシステム互換の
要件がここでは追い風になる。

### 2. 引数はタイプした場合と完全に同じ経路を通る

TUI では Enter キーと同じ `submit()` に入る: `!` シェルエスケープ・
スラッシュコマンド・`/skill` 展開・`@` 参照がすべて効き、`> 行` として
エコーされるので、スクロールバックはタイプで始めたセッションと同じに
読める。argv はオペレーター入力 — キーボードと同じ信頼であり、それは
mention 展開が要求する前提そのものである（ADR-0041 §high-1）。

トリガーは 1 回きり: 最初のウィンドウサイズ報告が送信をキューした
時点でクリアされ、後のリサイズが再送信することはない。

### 3. `-p` と引数の併用はエラー

セッションの形が異なる 2 つの第 1 ターンチャネル（答えて終了 vs.
始めて留まる）の併記は曖昧であり、優先順位で黙って解決せず、両方の
意味を名指しした一文で拒否する。

### 4. パイプ stdin の意味は不変。パイプフォールバックでは引数が先に走る

ADR-0055 の境界は立ったまま: パイプ stdin は決してプロンプト文に
ならない。素 REPL のパイプフォールバックでは、引数が最初の stdin
読みの前に走り（`> 行` としてエコー）、stdin の各行は従来どおり
続く。魅力的な組合せ「stdin をデータ添付 + 引数を初手 + /dev/tty で
対話継続」は tty 開き直しの配管が必要で意図的にスコープ外 — やるなら
独立の ADR。

## Consequences（帰結）

- 新モードなし。引数 1 つ、決定 3 行: 最初に走らせる・タイプ経路で・
  `-p` とは併用不可。
- サブコマンド名は第 1 メッセージに勝つ（`gem-agent sessions` は
  セッション一覧）。サブコマンド名と衝突する初手は言い換える —
  エコシステムの先例と同じ受容。
- トランスクリプトには通常の user メッセージとして残るので、
  `--continue` / `--resume` は第 1 ターンの由来を知る必要がない。
