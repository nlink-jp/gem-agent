# ADR-0060: 理由つき拒否 — `N` 回答

| 項目 | 値 |
|------|-----|
| ステータス | **採択** |
| 日付 | 2026-08-31 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | 利用者提案「拒否の際にオプションで理由を入力したい — `n` は即時のまま、`N` で理由欄を開く」 |

*ADR-0075 による修正: `runtime_note` は出所で信頼するツールメッセージの
2 つ目のフィールド — リモートツールの同一失敗の反復についてのランタイム自身の
言葉で、同じ実行器で設定しノンスタグの外側に付ける。内容で認識する案は §3 の
理由で却下のまま。*

## 背景

現在のゲート拒否は固定文 1 つをモデルに返す: *"Tool execution denied
by the user. Do not retry the same call; ask the user how to proceed
instead."* この設計は「拒否には普通、理由がある」ことを認めた上で、
その理由の入手にモデル 1 往復を払っている — モデルは質問でターンを
終え、利用者は `n` を押した瞬間には分かっていた答えを打ち直す。拒否
から質問までの間には、モデルが同種の変種コールを先に試すのを止める
ものがないという窓もある。

自明な模倣先 — Claude Code の「拒否してから入力欄に指示を打つ」— は
ここでは取れない。Gemini は function call ターンの直後のコンテンツが
その function response のみで構成されることを要求し、user パートを
並走させる形は次ラウンドの 400 として実測済み（ADR-0012 §5）。拒否
の瞬間にモデルへ届くスロットは拒否自身の function response ただ一つ
であり、利用者の誘導はそこに乗るか、1 往復待つかの二択になる。

ADR-0036 は `ask_user` に自由入力欄を意図的に与えなかった: 辞退は
「モデルが散文で聞き直す」状態で終わり、そこでは通常の入力欄こそが
自由記述チャネルだからだ。その理路は承認ゲートには移らない。辞退
された `ask_user` は既に「モデルが聞き、利用者が打つ」状態に達して
いるが、拒否されたツールコールはそうではない — ターンはラウンド
途中にあり、通常の入力チャネルはモデル 1 往復先にあり、固定拒否文は
その往復の代金そのものである。二つの設計は別の状況への答えであり、
「ここでは自由記述が正しく、あちらでは正しくないまま」の記録がこの
ADR である。

設計中にもう一つの制約が浮かんだ: **tool ロールのメッセージは送信時
に全て非信頼データとしてノンスラップされる**（ADR-0010 の免除は
`load_skill` のみ）。拒否文の作者は gem-agent と利用者であり、他の
誰も 1 バイトも書き込めないのに、ツール出力と同じ「内容であって指示
ではない」タグに包まれて送られている。固定文だけなら許容できる皺
だったが、利用者が打った誘導に対しては ADR-0010 が述べた通りの自己
矛盾になる: システムプロンプトがデータへの追従を禁じたまま指示を
データとして包めば、その指示は半死する。

## 決定

### 1. ダイアログの 5 つ目の回答: `N`「理由を添えて拒否」

TUI 承認ダイアログの拒否と常時許可の間に回答を 1 つ足す:
**理由を添えて拒否 (N)**。選択（矢印/Tab + Enter、または IME オフ時
の大文字 `N` 直接指定）で選択肢の行が 1 行のテキスト欄に置き換わる。
Enter で理由つき拒否を送信、空 Enter は素の拒否、Esc は何も決めずに
選択肢へ戻る。

`n`・Esc・Ctrl+C は現在の意味を完全に保つ: 1 打・理由なしの拒否。
「`n` を押してから任意の理由欄を却下する」形は利用者が明示的に退け
た — 速い経路は 1 操作のままでなければならない。素の stdin ゲートも
同じ回答を得る（回答行で `N`、続けて理由 1 行）。ワンショットの拒否
ゲート（`-p`・agent search）と中断ターンの自動拒否は従来どおり理由
なしで答える。

### 2. 理由は拒否の function response に乗る

理由つき拒否はツール結果として次を返す:

> Tool execution denied by the user, who gave this reason:
> «理由»
> Do not retry the same call; follow the reason, or ask the user how
> to proceed.

これはラウンド途中で API が開けている唯一のスロットであり（背景を
参照）、常設の「どう進めるか利用者に聞け」往復を、決定の瞬間に届く
誘導へ変換する。

### 3. 拒否結果はノンスラップを免除する — 出所で判定し、内容では決して判定しない

`llm.Message` に tool ロールのフィールド `denial` を足す（永続化・
追加のみ — スキーマ版数は不変）。設定箇所はただ一つ、実行器のゲート
拒否経路である。`wrapToolMessages` はこれを運ぶメッセージの非信頼
ラップを飛ばす。理路は ADR-0010 のそれを、システムが既に非ラップで
信頼しているもう一方の当事者へ適用したものだ: 拒否文の作者は
gem-agent（固定文）と利用者（コンソールで打った理由）— システム
プロンプトや利用者自身のメッセージと同じ信頼段にある。

拒否を**文字列比較で認識する案は棄却**する: 従来の前方一致・完全
一致検査（view_image / read_document の添付ガード、監査 outcome）は
「拒否の形をした文字列を返す MCP サーバー」1 つで誤分類する距離に
既にあり、内容起因のアンラップは本物のインジェクション扉になる —
レビュー第 2 回が閉じたまさにその欠陥クラスである。3 検査すべてを
出所 bool へ移し、定数は文面としてのみ残す。

旧ビルドが新トランスクリプトを resume した場合はフィールドを無視し
て従来どおりラップする — 文言が弱まるだけで、安全性は損なわれない。

### 4. 記録は理由を保持し、テレメトリは保持しない

トランスクリプトの `gate_decision` 記録に `deny_reason` を足す。
これは利用者が自分の決定について自分の言葉で残したもの — ADR-0045
が保存し ADR-0048 の学習器が重み付けする証拠そのものであり、理由の
明示された拒否は素の `n` より遥かに強い証拠である。OpenTelemetry
エクスポート（ADR-0035）には**載せない**: 承認プロンプトで打たれる
自由記述はパスやホスト名、あるいはより強いものを含みがちな種類の
内容であり、エクスポートの属性集合は列挙可能なまま保つ。

## 帰結

- リダイレクト型の拒否 1 回につきモデル 1 往復の節約。拒否と誘導の
  間の変種再試行の窓も消える。
- 学習器の原料が、学習器側の変更ゼロで濃くなる（本 ADR に学習器の
  変更は含まれない）。
- `Approver` インターフェースの戻り値が 3 つになる（`denyReason`）。
  全ゲートとテストフェイクが更新される。struct ではなく素の多値の
  まま — 共有パッケージの import 循環に関する ADR-0035 の理路は
  引き続き成立する。
- ダイアログの IME 規則（ADR-0002 系譜)は理由欄にも及ぶ: 変換済みの
  日本語を受け付け、Enter は変換確定後にのみアプリへ届く — メインの
  入力欄と同じ契約である。
