# ADR-0029: 完全二面カタログによる UI 言語モード

| 項目 | 値 |
|------|----|
| ステータス | **承認済み** |
| 日付 | 2026-08-20 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレーター: ヘルプやヒントのメッセージが英語と日本語で恣意的に混在している — 日本語モード/英語モードのような概念で統一すべき |

## 文脈

対話クロームの文字列は 19 リリースにわたって 1 本ずつ増え、その
時々の言語で出荷されてきた: `/help` はコマンドを英語で列挙しキーは
日本語で説明する、承認ダイアログの選択肢は日本語なのに判定結果は
英語で印字される、trust プロンプトは英語で予約拒否の警告は日本語。
個々の文字列に誤りはないが、集合として支離滅裂であり、しかも一貫
させる仕組みが存在しない — 新機能はその場の言語で文字列を足し、
ドリフトは複利で積み上がる。

## 決定

### 1. `[tui].language = "auto" | "ja" | "en"`、既定 `auto`

`auto` は POSIX のメッセージカタログ慣行に従う: `LC_ALL`、
`LC_MESSAGES`、`LANG` のうち最初の非空値が決定し、接頭辞 `ja` なら
日本語、それ以外（`C`/`POSIX` を含む）は英語。言語は起動時に一度だけ
解決し、`/settings` では再起動注記つきの読み取り専用行として表示
する。セッション中の切替はスクロールバックを二分し、印字済みの
ものは何も再描画しない — 一貫性のための機能が自ら不一貫を持ち込む
ことになる。

### 2. カタログ構造体は 1 つ、完全なリテラルは 2 面

`internal/uitext` は `Messages` 構造体 — オペレーター向け文字列
1 本につき 1 フィールド — と、ちょうど 2 つのパッケージレベル
カタログ `en`・`ja` を定義する。リフレクションテストが両カタログの
全フィールドを走査し、空文字列があれば失敗する。このテストこそが
本当の修正である: 元の問題は誤訳ではなく、2 言語に同じ面を覆わせる
強制力の不在だった。新しいクローム文字列は両カタログに入るか、
`make check` に落ちるかのどちらかになる。

### 3. 範囲: 対話クローム。4 つの面は英語のまま

カタログ対象: `/help`、承認ダイアログ（選択肢・ヒント・判定・
省略行警告）、入力クローム（プレースホルダ・予約通知・中断/エラー
マーカー）、settings パネルのヒント、`/auto`・`/clear`・`/compact`
の応答、ADR-0023 の起動時安全プロンプト。

どちらのモードでも意図的に対象外とするもの:

- **バナーラベルと `warning:` 行** — オペレーターが grep し issue に
  貼るログ体裁の出力であり、英語トークンが安定していることが機能;
- **cobra の `--help` / CLI フラグ** — CLI 慣行であり、cobra 自身の
  雛形テキストも英語;
- **モデル向けテキスト** — システムプロンプトとツール説明はモデルの
  ために書かれておりオペレーター向けではない。モデルの応答言語は
  会話に従い、この設定には従わない;
- **Go のエラー連鎖** — ラップされた原因はライブラリから英語で来る。
  英語の連鎖に翻訳された接頭辞を付けるのは、本 ADR が取り除こうと
  している混在そのものである。

## 帰結

- オペレーター向けクロームはどちらのモードでも単一言語になり、
  完全性テストによって機械的にそれが保たれる。
- カタログへ移した文字列はすべて一段の間接参照になる。かつて本文が
  直接書かれていた場所は `m.msgs.QueueRefused` と読むことになる。
  受容する: リテラル直書きのスタイルこそがドリフトを生んだ当のもの
  である。
- `auto` により `ja_JP` 端末はアップグレードで見た目が変わる。従来の
  混在表示は保存に値する状態ではない。`language = "en"` で完全な
  英語に戻せる。
