# ADR-0067: パイプ stdin を待つ単発実行は、待っていると言う

| 項目 | 値 |
|------|----|
| ステータス | **Accepted** |
| 日付 | 2026-09-04 |
| 対象 | gem-agent |
| 意思決定者 | nlink-jp メンテナ |
| きっかけ | ツールハーネスから起動したスクリプト経由の `gem-agent -p …` が、どちらのストリームにも何も出さないまま 10 分ハングした。ハーネスは開いたまま何も流れない pipe を stdin として渡していた |
| 修正対象 | ADR-0055 §2（「ハングしない」条項はターミナル stdin しか扱っていなかった） |

## 背景

ADR-0055 は `データ | gem-agent -p "…"` において、非ターミナルの stdin を
EOF まで読んでデータとして添付するようにした。対話時の穴 — ターミナル
stdin は決して読まない — は塞いだが、そこで止まっていた。もう一つの
「何も来ない stdin」の形、すなわち開いているが誰も書かず閉じもしない
pipe は未対応のままだった。タスクスケジューラ、launchd ジョブ、CI ステップ、
エージェントのツールハーネスは、そのような pipe を継承させて子プロセスを
起動するのが常である。ADR-0055 のもとでは、その子プロセスは `io.ReadAll`
で永久にブロックし、しかも無言でブロックする。待機を名指しするバナー行が
無いので、オペレーターには何も出さないプロセスがハングしているように
見える。

EOF まで読むこと自体は正しい契約である。`claude -p` がそうしているし、
あらゆるフィルタがそうしているし、単に遅いだけの生産者
（`curl … | gem-agent -p`）を打ち切ってはならない。欠陥は沈黙にある。
ADR-0033 §2 は既にこのランタイムの規則を述べている: 意図的な待機は
ハングに見えてはならない。stdin 待ちはステータス機構が見ていない原因で
ある。ターンが始まる前に起きるうえ、ハートビートは TUI 専用で `-p` では
決して動かないからだ。

## 決定

### 1. 待機は短い猶予の後に 1 回だけ告知する

`-p` は引き続き非ターミナルの stdin を EOF まで読む。読み始めてから
**2 秒**経っても EOF が来なければ、stderr に 1 行出す:

    [stdin: waiting for piped input to end (no EOF after 2s) — close the pipe, or run with < /dev/null if nothing should be attached]

猶予があるので、よくある形は静かなままである。`< /dev/null`、
ヒアストリング、`echo … |` は即座に EOF を届け、何も表示しない。
実際に遅い pipe か実際に何も来ない pipe だけがこの行を得る — それが
まさにこの行を必要とする集合である。行は両方の対処を名指しする。
読んでいるオペレーターは自分がどちらの場合にいるか分からないからだ。

### 2. 待機には終わりの行がつく

通知を出した場合、読みの結果を同じチャンネルで報告する。内容が届けば
既存の `[stdin: N bytes attached as data]`、データ無しで pipe が閉じれば
新設の `[stdin: ended empty — nothing attached]`。告知した待機は終わりも
見えなければならない（ADR-0033 §2）。無言の解決では、通知が最後の
出来事だったのかどうかオペレーターが推測するしかなくなる。

### 3. それ以外は変えない

読みは上限付きのまま、バイナリ stdin は警告付きでスキップのまま、空の
stdin は何も添付しないまま、ターミナル stdin は決して読まないまま、
stdout はモデルのテキストのみのまま。通知は他のステータス行と同じく
stderr である。

## 検討した代替案

- **明示的な `--stdin` フラグ** — 却下: ADR-0055 が支えるために存在する
  正規の形 `データ | gem-agent -p` を壊すし、`claude -p` との drop-in
  互換が第一要件である。
- **pipe に即座にデータが無ければ読みをスキップ** — 却下: 取得に 3 秒
  かかる生産者が黙って無視される。それは ADR-0055 が直した当の失敗で
  ある。データの有無では「遅い」と「来ない」を区別できない。区別できる
  のは EOF だけである。
- **非ターミナル読みの開始時に毎回通知** — 却下: `< /dev/null` は
  ヘッドレス起動の推奨イディオムであり、そのすべての実行に stdin 行を
  刻印するとイディオムが騒がしくなる。猶予は高速経路で何も費やさず、
  人が待っているかもしれない場所にだけ行を置く。

## 結果

- 報告されたハングは、2 秒の待機とそれに続く「何をすべきか」を述べる
  1 行になる。本当に遅い生産者も同じ行を見るだけで、何も失わない。
- 健全性チェック手順書やパイプラインの文書は、「データを渡す意図が
  無い」のイディオムとして `< /dev/null` を、ランタイム自身がそれを
  指し示す形で書ける。
- 猶予（2 秒）は定数であり調整項目ではない。`-p` で働く待機通知はこれ
  だけである。接続ハートビート（ADR-0033 §1、しきい値は ADR-0056 で
  改定）は TUI のものであり、単発実行では動かない。
