# ADR-0024: Bottom-hold — 画面が埋まった後のフレーム安定化

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「画面下端まで履歴が伸びてくると、フッターの表示位置が上下移動をすることがある。mcp コールや MITL が介入した時に発生するように見える」 |

## Context

ADR-0003 は `pad = height − printed − core − 1` のパディングで入力ブロックを
ウィンドウ下端に固定する。画面が埋まるまでは pad がビュー自身の高さ変動を
すべて吸収し、フッターは最下段に張り付く。埋まった後は pad が 0 に張り付き、
設計は「素の inline に退化」としていた — つまりフレームの下端がフレームの
高さと一緒に動く。フレーム高は常に変わる: ライブ末尾はストリーミング中
0→12 行へ育ち、**flush のたび（= ツールコール境界、なかんずく MCP コール）に
0 へリセット**され、承認ダイアログは 8〜14 行の箱を出し入れする。結果、
ツールコールや承認が介入した瞬間に、フッターが十数行単位で上下する。

## Decision

**満杯レジームではフレームの合計高を保持する。** モデルは小さな描画状態
（`lastTotal`。Bubble Tea のモデルコピーを生き延びるようポインタ越し）を持つ:

1. pad が正（画面未満杯）の間は挙動不変、`lastTotal` は解除状態 —
   吸収役は pad。
2. pad が 0 に達したら、各フレームを
   `total = clamp(max(lastTotal, core), core, height−1)` 行で描画し、
   差分 `total − core` を先頭の空行にする。縮み（flush リセット・
   ダイアログのクローズ）はフレーム下端 = フッターをその場に残し、
   空いた行はフレーム内の空白になる。
3. scrollback へ 1 行印字するごとに `lastTotal` を 1 減らす: 印字は履歴を
   1 行分上へ送るので、その 1 行を返上して空白域を 1 行縮める — 穴が
   ライブ領域の上に残り続けるのではなく、履歴が隙間へ滑らかに流れ込む。
4. 既存の不変量はその上に重なる: 全行の幅クリップ、フレームは
   `height − 1` を超えない（ADR-0021 のクランプ）、リサイズは既存の
   クリア+再計数経路で全会計をリセット。

テストの ground truth はフレーム高の不変量: 満杯レジームでの一連の操作 —
ストリーム・flush・承認オープン・クローズ — を通じ、描画フレームの行数は
「その間に scrollback へ印字した行数」ちょうどの分以外では減ってはならない。

## Consequences

- フッターは最下段に達したら動かなくなる。MCP コールの flush と MITL
  ダイアログはもう弾まない。
- 一時的に空いた行は履歴とライブ領域の間の空白として見え、以後の
  scrollback 1 行につき 1 行ずつ消費される — 安定したフッターの視覚コスト
  であり、動いているターンでは短命。
- ADR-0003 の「素の inline に退化」条項は本 bottom-hold で置き換え。
  ADR-0003 の他の部分は存続。

## Alternatives considered

- **ライブ末尾の固定高**（ストリーム領域を 12 行に固定パディング）—
  flush の弾みしか消えず、ダイアログの弾みは残り、待機中も行を浪費する。
- **常時フル高フレーム**（常に height−1 行描画）— 弾みは消えるが、履歴と
  ライブ領域が画面サイズの空白で恒久に分断される。
- **縮み補償の scrollback 詰め物**（縮んだ分の空行を印字）— 描画の都合で
  scrollback の記録を汚す。
