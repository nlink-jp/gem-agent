# ADR-0020: セッションをまたぐエージェントメモリ

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「グローバルメモリとプロジェクトメモリを搭載する必要があるかもしれない」 |

## Context

gem-agent が現在の会話の外から知れることは 2 つしかない: オペレータの
指示ファイル（AGENTS.md ほか、起動時注入）と、resume したトランスクリプトに
たまたま入っていたもの。作業の**途中で**学んだ事実 — ビルドの癖、オペレータの
好み、ステージングホストの名前 — は、オペレータが手で指示ファイルに書き写さない
限りセッションと共に死ぬ。Claude Code はエージェント自身が維持するメモリで
これを解いており、フォールバックツールは一番必要な場面でちょうどこの連続性を
失っている。

## Decision

1. **エージェントが書くメモリを 2 スコープで。** グローバル（オペレータと
   このマシンに関する事実、どこでもロード）とプロジェクト（1 プロジェクトの
   事実、そこでのみロード）。1 メモリ = slug 名の小さな markdown ファイル
   1 つ。同名で保存すると更新。
2. **機械所有・リポジトリ外。** メモリはエージェント生成物なので、他の
   エージェント生成物と同じ場所に住む:
   `~/.local/state/gem-agent/memory/global/` と
   `memory/projects/<エスケープ済パス>/`。プロジェクトツリーには何も書かない
   — ADR-0009 の論法（キー 1 打の副作用でリポにファイルが現れるのは驚き）は
   書き手がモデルならなお強く効くし、リポ持ち運びのメモリは clone と一緒に
   作者不明のまま届いてしまう。パスエスケープ（`/`→`-`）は非可逆なので、各
   プロジェクトディレクトリは実パスを書いた `.project` マーカーを持つ。
   不一致 = 衝突であり、そのプロジェクトのメモリは誤帰属せず注記付きで
   スキップする。`~/.claude` は読まない（ADR-0011 の原則）。Claude Code の
   メモリは形式も別物（索引 + frontmatter）なので symlink 共有の筋書きも
   ここには無い。
3. **予算付きの全文注入。** 全メモリがシステムプロンプトに乗る — グローバル
   が先、プロジェクトが後、スコープ内はアルファベット順（決定的な順序は
   ADR-0018 の implicit caching のプレフィックス安定にも効く）。指示ファイル
   と同じ予算機構で抑える: メモリ単位の上限（マーカー付き切り詰め — save が
   上限を強制するので手編集でしか到達しない）と総量上限（超過分は注記付き
   スキップ）。skills 型の「索引 + オンデマンドロード」は不採用 — メモリは
   短い事実で、説明行が本文そのものになり、間接化は往復を倍にして何も
   節約しない。実メモリが予算を超えて育ったら再訪。
4. **書き込みが信頼境界。** `save_memory` と `delete_memory` は Mutating で
   既定承認ゲート。ルール層は Review に分類し、Safe には決してしない —
   メモリは prompt injection の**永続化経路**である（汚染されたツール結果が
   モデルを説得して指示を「記憶」させると、以後の全セッションで信頼済み
   らしき文脈に化ける）。防御は書き込み時の MITL であり、ADR-0008 ポリシーが
   オペレータの意図的な緩和。注入されるセクションはあるがままに枠書きする:
   過去セッションでエージェントが記録したもの、指示ではなく背景知識、古く
   なっているかもしれない。ノンスラップはしない — 「従うな」とラップされた
   メモリは自己矛盾（load_skill の論法）— が、AGENTS.md のオペレータ authored
   の地位も与えない。枠書きの一行がその差を明言する。
5. **プロンプトは「何を保存してよいか」だけでなく「いつ保存するか」を
   述べる**（v0.39.0）。元の文面で 39 セッションを実測したところ、モデルが
   自発的にメモリを提案したことは**一度もなかった** — 保存された全件が
   利用者の明示指示に続いており、書込ゲートは一度も自発発火していない。
   したがってこの機能の「適合率」は利用者の判断を測っていたのであって、
   エージェントの判断ではない。文面は能力を与え（"you can persist…"）、
   具体的な文をすべて 3 つの禁止に費やしていた — **曖昧な推奨と具体的な
   禁止が並ぶと「めったにやるな」と読める**。プロンプトは今、利用者が手で
   供給していたチェックポイント（「ふり返りからメモリしたほうがよいことは
   ありませんでしたか？」）を持つ: 作業が一段落したら、開始時に知っていれば
   手間が省けたことを学ばなかったかを問い、あれば**指示を待たずに**保存する。
   推奨の具体性を禁止と同等にし、テストで両方（および推奨が禁止より長いこと）
   を固定した。
6. **モデル層はメモリ書込を決して承認しない**（v0.39.0）。§4 は書込時 MITL を
   防御線とし、ツールポリシーを利用者の**意図的な**緩和と位置づけている。
   モデル評価者はその意図的判断ではない — 書込を提案したのと同一の当事者で
   あり、§4 が記述する汚染ツール結果の攻撃は両段階を自力で通過してしまう。
   保存が実際に発火するようになった結果、auto がひとつを承認する様子が
   実測された（"saving a project-scoped memory note is safe and low-risk"）
   — 利用者はそれを見ていない。`save_memory`/`delete_memory` は自動承認から
   除外し、階層評価の結果によらず常にエスカレートする。**エージェントが何を
   記憶するかは利用者が決める**。意図的な緩和手段としてのツールポリシーは
   従来どおり残る。
7. **起動時スナップショット。** メモリはセッション開始時に一度読む。保存は
   「次セッションから効く」と応答で明言する（保存したその会話では、モデルは
   既にその事実を知っている）。これによりシステムプロンプトはセッション中
   不変になり、ADR-0018 のキャッシュプレフィックスが依存する性質が保たれる。
   `/memory` はいまディスクにあるものを一覧し、「ロードは起動時」の但し書きを
   添える。

## Consequences

- 契機は仮定ではなく実機で検証した: 踏んで初めて分かる quirk（キャッシュを
  暖めるまで失敗するビルドターゲット）だけを持つタスクで、エージェントは作業を
  終えたのち `make check` の前に `make warm` が要る旨をプロジェクトメモリとして
  **指示なしに提案**した。§6 の変更後は、同じ実行で保存が自己承認ではなく
  利用者へエスカレートすることも確認した。
- 指示ファイルの手作業維持なしにセッション間の連続性が得られる。代わりに
  オペレータは書き込み 1 件ごとにレビューする。
- ゲート付きツール 2 つ、スラッシュコマンド 1 つ、バナー 1 行の追加。設定
  ノブは無し — 上限は固定既定値、ゲートの調整は既存の ADR-0008 ポリシー。
- 単発 `-p` モードはメモリを思い出せるが保存はできない（変更系ツールは
  拒否される）。ポリシーで `"never"` なら別。
- メモリファイルは既知ディレクトリの素の markdown: 手で監査・編集・削除
  できる。

## Alternatives considered

- **リポジトリ内のプロジェクトメモリ**（`.gem-agent/memory/`）— 却下:
  リポ汚染、gitignore 管理、clone 持ち込みの作者不明メモリ（§2）。
- **索引 + オンデマンドロード**（skills パターン）— 短い事実に対する往復
  コストで却下（§3）。
- **注入セクションのノンスラップ** — 自己矛盾として却下。境界は書き込み時の
  MITL ゲート（§4）。
- **Claude Code のメモリディレクトリを読む** — ADR-0011 の原則と形式不一致で
  却下（§2）。
