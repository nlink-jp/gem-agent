# ADR-0103: 画像は画面が許すだけ大きく、それ自身より大きくはしない

| Field | Value |
|-------|-------|
| Status | **Accepted**（2026-11-02） |
| Date | 2026-11-02 |
| Binds | gem-agent |
| Decision makers | nlink-jp メンテナ |
| Triggered by | 利用者: インラインで描く画像（`show_image`・`/show`）がターミナルの窓に対して小さすぎ、よく見えない |
| Amends | ADR-0090 §3（画像のボックスを選ぶときの上限と幅） |
| Relates to | ADR-0089（宣言するボックス）、ADR-0092 §4（`TIOCGWINSZ` で読むセル） |

## Context（背景）

`termimg.BoxFor` は画像のボックスを 2 つの固定の上限に対して選んでいた。端末の幅に
かかわらず**最大 40 桁**、高さは**画面の 3 分の 1 まで**（`maxImageRows`）。行数は
セルの縦横比を定数 2.25 として求めていた。200×50 の窓では正方形の写真が 16 行×36 桁
— 窓の幅の 5 分の 1 — で描かれる。40 桁のボックスは図については既に「読めない」と
測定されており（mermaid-render RFP 段 0、ADR-0092 B5）、利用者は写真やスクリーン
ショットでも小さすぎると判断した。

ADR-0092 のために測った 2 つの事実が置き換えに関わる:

- 端末はセルの大きさを画素で `TIOCGWINSZ` から報告する。問い合わせではなく ioctl
  なので Bubble Tea が stdin を持っている間も安全である。利用者の Retina 画面で
  iTerm2 は 8×18、kitty は 7×13 を返した — 画面の point であって実画素ではない（段 0）。
- セルの縦横比は端末ごとに違う（2.25 と 1.86）。段 0 の記録は、kitty が宣言した
  ボックスいっぱいに画像を引き伸ばすなら、定数 2.25 では写真が縦に約 17% つぶれると
  書き留めた。写真では測っていない。kitty がどちらの振る舞いでも、定数ではなく読んだ
  セルでボックスの形を決める理由になる。

## Decision（決定）

### 1. ボックスは画面が許すだけ大きくする

幅の上限は 40 桁ではなく端末の幅から 1 桁引いたもの（ADR-0089 §2 の余白、`Fit` が
かける）。高さの上限は枠より上の画面: 端末の高さから、画像を描くその時点で枠が
占める行数と、pad が空けておく 1 行を引いたもの。描かれた画像は丸ごと画面に収まり、
それより前の会話は上へ流れる — 画面の半分ではなくこちらを利用者が選んだ。枠の高さは
view が並べるとおり（`viewContent` を切り詰めたもの）で測り、hold の会計に書き込む
`view` は呼ばない。

画像は両方の上限に収まるよう形を保って縮める。端末の幅が分からなければ従来の 40 桁、
高さが分からなければ従来の 10 行のまま。推測は控えめな数より悪い。

### 2. 画像そのものより大きくはしない

画像の原寸をセル単位で表すと、画像の画素数を端末が報告するセルの画素数で割ったもの
— 画像の 1 画素を端末が報告する 1 画素に対応させる。ボックスはそれより大きくしない
ので、アイコンが画面いっぱいに引き伸ばされることはない。iTerm2 と kitty は Retina
画面で point を報告するので、画像はブラウザが 100% で表示する大きさを上限に描かれる。
実画素を報告する端末ならそれより小さく描かれ、大きくはならない。ボックスはセル単位に
丸めるので、原寸を超えるのは半セル未満に限られる。

画素を報告しない端末には iTerm2 の実測値 8×18 を仮定する。その縦横比は従来ボックスの
形を決めていた 2.25 である。報告されたセルの縦横比が 1〜4 の外なら同じく扱う
（`DiagramBox` が既にそうしている）。

### 3. セルは大きさの報告ごとに 1 回読む

`Options.CellAspect` を `Options.CellSize` に替える。同じ ioctl で、セルの幅と高さを
返す。図のボックスが使う縦横比（ADR-0092 §4）はそこから導くので、1 回の読み取りで
両方のレーンに足り、画素の無い報告は従来どおり最後の読み取りを残す。

## Consequences（結果）

- 大きな画像は窓の幅か枠より上の画面のどちらか先に効く方いっぱいに描かれる。画像の
  属する返答は上に流れることがあるが、長い返答の冒頭と同じく scrollback にある。
- `maxImageRows` は枠の高さに依存し、枠はターンの実行中に伸びる（ライブ表示・思考
  表示）。ターン中に出る画像は、待機中の `/show` で出す同じ画像より小さい。画面に
  丸ごと収めることの代償である。
- kitty は PNG 以外の画像をボックスに合わせて縮めて PNG にし直す（`kittyPNG`）。
  ボックスが大きくなったので、JPEG の写真は大きめの PNG になる。`MaxBytes` が引き続き
  上限で、超えたら縮め直さず描かない。
- ADR-0089 A2 はセルの画素数からボックスを導く案を、応答の無いことがある `ESC[16t`
  照会が要るとして却下した。今は ADR-0092 が持ち込んだ ioctl で読むので応答は要らず、
  A2 の異議はこれには当たらない。

## Alternatives considered（検討した代替案）

**A1. 図の帯と同じく画面の半分まで。** 上の返答が見えたままになるが、どの端末でも
画像が半分になる。利用者は画面全体を選んだ。

**A2. 上限を `[tui]` の設定にする。** 妥当な値が 1 つしかないつまみは誰も要らない。
根拠が出てから足せる。

**A3. 小さい画像も上限まで拡大する。** 従来のボックスはそうしていた（どの画像も
40 桁）。利用者が却下: 画面いっぱいに描いたアイコンはアイコン以上のものを見せない。
