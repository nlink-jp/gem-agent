# ADR-0042: mermaid 図を端末に描く — 忠実に描ける種別だけを、それだけを

| 項目 | 内容 |
|------|------|
| Status | **Accepted** |
| Date | 2026-08-22 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレーター: チャット中の mermaid はレンダラに貼らないと読めない、だが「図を使うな」は本末転倒で、チャット内容をブラウザで見るのも変 — 端末が描ける種別をモデルに教え、それを端末に描き、残りはそのまま出し、ファイル出力は制限しない |

## Context（背景）

glamour は ```` ```mermaid ```` フェンスをただのコードブロックとして描画
するので、オペレーターが見るのは図のソースである。flowchart を
ソースから読むには、会話を離れてどこかに貼って描かせる必要がある —
これは道具のループ（結果を読んで次の一手を決める）を断ち切る。図を
禁じれば構造を説明する良い手段を捨てることになり、チャット内容を
ブラウザへ飛ばす案（最初に検討した）は 1 つの会話に 2 つ目の面を
作る。

純 Go の端末レンダラは存在する。2 つを実際の図 — ここでの実用性を
決める日本語ラベルを含む — で実測した:

- 片方（22 種を標榜）は flowchart ラベルの UTF-8 を文字化けさせ、
  sequence 図の CJK を揃えられず、state 図の**辺を黙って落とした** —
  グラフの一部を隠す描画はソースより悪い。
- 本家（`AlexanderGrooff/mermaid-ascii`、MIT）は日本語 flowchart を
  セル幅を正しく揃えて描き（subgraph 含む）、日本語エンティティ名の
  ER 図も揃い、sequence 図は ASCII ラベルなら揃うが CJK では揃わず、
  `[box]` 以外のノード*形状*は解釈しなかった（`B{判定}` が文字通りの
  ラベル + 迷子の `B` ノードになる）。他の種別は明確にエラーになり、
  6 ノードの横並びは詰めた padding で 91 セルに収まった。

## Decision（決定）

### 1. 描けるものを正確に宣言し、それだけを描く

システムプロンプトは TUI でのみ、端末が描ける mermaid の種別を
モデルに伝える: **flowchart/graph**（全方向・subgraph）、**ASCII
ラベルの sequenceDiagram**、**erDiagram**。それ以外 — 他の種別・
全角ラベルの sequence 図・端末に対して広すぎる/高すぎる図・レンダラが
拒否したもの — はソースのまま無変更で現れ、プロンプトはそうした種別を
チャットで使うときは 1 行のキャプションを添えるよう求める。ファイルは
対象外: モデルがファイルに書くものには触れず、プロンプトもそう言う。
宣言するリストとレンダラの能力は**1 つのパッケージの 1 つのリスト**で
あり、テストで固定される — プロンプトがレンダラのできないことを約束
することは起こり得ない。

### 2. flush 時に描き、同じスクロールバック規律に乗せる

書き換えは Markdown が描画される場所（ストリーム区間の flush）で走る:
対象の ```` ```mermaid ```` ブロックはボックスアートを収めたプレーンな
コードブロックに置き換わり、live 領域はストリーム中ソースを見せる —
他の全 Markdown とまったく同じ。アートは受け入れ前に測る: 端末幅
（glamour のマージン分を引いた）より広い → 詰めた padding で再試行 →
それでも広い、あるいは 80 行より高い → ソース。`emit()` に折り返しを
要するものは決して届かない。

### 3. 形状を正規化し、忠実性を検証する

レンダラが解釈しないノード形状 — `{判定}`・`((円))`・`([スタジアム])`・
`[/平行四辺形/]`・`[[サブルーチン]]`・`[(DB)]`・`{{六角}}`・`(丸角)` — は
描画前に `[box]` へ書き換える: 形状は表現であり、グラフが内容である。
自信満々に描かれた間違ったグラフこそ恐れるべき失敗形だ。描画後、
ソースから抽出した全ラベル（ノードと辺のラベル・参加者とメッセージ
本文・エンティティ名と関係ラベル）がアート中に現れなければソースへ
後退する: レンダラには書かれたより少なく描くことを決して許さない。
表現用の文（`classDef`・`style`・`linkStyle`・`click`）は描画前に
落とす。

### 4. 素の REPL と単発はそのまま

stdout はモデルのテキストのみ（単発の契約）であり、素の REPL は
流れるまま出力する。どちらも今日 Markdown を描画せず、図の処理も
受けない — プロンプト節もそこでは省かれるので、モデルはその面に無い
能力を告げられない。

## Consequences（帰結）

- チャット中の flowchart は会話の起きている場所で読める — 日本語
  ラベル込みで — そのために端末を離れることはない。モデルが出す
  典型（flow/sequence/ER）は覆われ、ロングテールはキャプション付きで
  正直にソースとして見える。
- 依存は MIT・純 Go で、1 つのパッケージ（`internal/diagram`）の
  1 つの関数の後ろに住む — より良いレンダラへの差し替えは交換で済む。
  グラフレンダラは上流の `cmd` パッケージにあり、同パッケージは Web
  サーバーの依存も抱えるためバイナリが約 5MB 太る。受容: レンダラを
  フォークして切り出す価値は drift に見合わない。
- ノード形状は矩形に平坦化される: 判定の菱形は判定テキストと yes/no
  の辺を持つ矩形として読める。意図的である — 字形の忠実性よりグラフの
  忠実性。
- トランスクリプトとモデルの履歴は元の mermaid ソースを保つ; 書き
  換わるのは表示だけである。
- 忠実性はラベル存在だけでなく構造でも担保する（v0.37.2）: flowchart
  のソース辺数 = 描画矢印頭数、`-- text -->` 辺ラベルは解釈形へ正規化、
  subgraph id への辺（幻ノード）はソースへ後退。
- 密な ER 図の複雑さ上限（v0.37.3）は試みたのち**リバート**した
  （v0.37.4、オペレーターの方針）: 画面に収まる図は線が交差していても
  提示する — 可読性はオペレーターの判断であり、「複雑すぎる、簡単に」
  はモデルへのメッセージであって閾値ではない。残るガードは「間違い」
  についてであり、「醜さ」については決してない。subgraph の
  `direction` ヒント除去（レンダラがノード化し隣接タイトルを融合）は
  維持; CJK ロケールで罫線が千切れないよう幅モデルは 1 つに固定
  （v0.37.1）。
