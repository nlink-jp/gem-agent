## Context

ルート — プロジェクト、セッション作業ディレクトリ、追加したディレクトリ — は
実パスで持っている。ファイルツールは `Registry.resolvePath` でパスを閉じ込める:
打ったパスを絶対パスにして整えたものが、**字面の上で**ルートの中になければ
ならない。そのあとで初めて解決し、実パスもルートの中になければならない。
判定の地点は、ルールの段が判定する前に同じ関数（`Registry.RealPath`）でパスを
解決するので、段はそのファイルが何かを見る（R2）。入力欄の `@` 参照も
`mention.resolve` で同じ 2 段の確認をする。

そのため、どのルートの**外**にもあるリンクを経由して打ったパスは、2 段目に
届かない。macOS とクラウドのプロバイダは、そういうリンクをホームに置く:
`~/Dropbox` → `~/Library/CloudStorage/Dropbox`、`~/OneDrive` や `~/Google Drive`
も同様。運用者が `~/work` → 別の場所のチェックアウト、を置くこともある。
ADR-0107 はそれらのフォルダを書き込みのルートにでき、運用者とモデルが知って
いる名前はそのリンクである。

このマシンで測った（2026-11-06）。プロジェクト、書き込みのルート、読み取りの
ルートを持つレジストリと、そのどれの外にもあるディレクトリに置いたリンクで:

| 打ったパス | `RealPath` | ルールの段 | `write_file` | `read_file` |
|---|---|---|---|---|
| リンク → 書き込みのルート、新しいファイル | 断る | Block、「outside the project and added directories」 | 断る、「path escapes the project directory」 | 断る |
| リンク → 書き込みのルート、既存のファイル | 断る | Block | 断る | 断る |
| リンク → 読み取りのルート | 断る | Block | 断る | 断る |
| リンク → プロジェクト | 断る | Block | 断る | 断る |
| リンク → どのルートの外へも | 断る | Block | 断る | 断る |

つまり、欠けているのは段だけではない: Block の確認で書き込みを承認した運用者は、
ツール自身から「path escapes the project directory」を受け取り、読み取りさえ
断られる。シェルのレーンは影響を受けない — カーネルがリンクを解決し、ADR-0107 の
測定では write レーンで `~/Dropbox` を通して書き込めた。

ルールの段は、設計として I/O をしない（`internal/risk` の `pathAliases`）: 渡された
文字列を判定する。段はすでに判定の地点から実パスを受け取っている。打ったパスを
受け取ったのは、`RealPath` が断ったからにすぎない。

## Decision

### 1. 呼び出しは、入ってきたところで一度だけ書き換える

モデルからのツール呼び出しが入ってきたとき — 表示し、判定し、実行し、記録する
前に — 組み込みのファイルツールのパス引数（`path`、`from`、`paths` の各要素。
`shell_exec`、`request_directory`、MCP ツールは対象外）を一度だけ見る。引数が

- 絶対パスで、
- 字面の上でどのルートの外にもあり、
- 綴りの上で資格情報ではなく（`sandbox.CredentialPath`）、
- `/Volumes`・`/Network`・`/net` の下でもない

なら、その**親ディレクトリ**を解決する。解決した親と、打ったとおりの最後の
要素をつないだものがルートの中にあれば、引数をそれに置き換える。そうでなければ
引数は打ったとおりのままで、ファイルツールがあとで今とまったく同じに、今の
文言で断る。

書き換えた呼び出しが、それ以降の呼び出しである: 承認の確認はそれを示し、
判定の地点はそれを判定し、ツールはそれを実行し、トランスクリプト・監査・
テレメトリはそれを記録する。履歴にあるモデル自身のメッセージは、モデルが
送ったままにしておく。

条件にはそれぞれ理由がある:

- **入口で一度だけ** — 今は判定の地点とツールが同じ文字列をそれぞれ解決する
  ので、判定と実行の間にリンクを差し替えると、別のファイルについて下した判定で
  書き込まれる。その隙間はルートの中のリンクについてはすでにある。解決を
  ルートの外のリンクへ広げると、write レーンのコマンドが書ける共有の一時
  ディレクトリにまで隙間が広がるところだった（この ADR の設計レビュー）。
  書き換えた後は、ルートの外のリンクを二度と見ない。
- **親だけ** — 最後の要素は打ったとおりに残す。そこにあるリンクは、ルートの
  中のどのリンクとも同じ扱いになる: 実名で判定し、通してではなく置き換えで
  書く（R2）。
- **資格情報の綴りは残す** — パスを綴りで判定する床（`classifyPath`、
  `ReadCopySource` の 2 つの綴りの確認）は、引き続きそれを見る。ルートへの
  リンクを通して届く資格情報の名前は、operator 以外のどのレーンでもカーネルが
  拒否する。
- **マウントには触れない** — モデルが名指した `/Volumes`、`/Network`、
  自動マウントの `/net` の下のパスを解決すると、誰も何も承認しないうちに
  共有に触れたり、止まった共有を待ったりする。
- **失敗しても新しいことは言わない** — 親が解決しない、またはどのルートの
  外へ解決するなら、引数は打ったとおりのままなので、拒否は今のもので、そこに
  リンクがあるか、どこへ行くかを明かさない（ADR-0021）。

### 2. `@` 参照も同じ規則に従う

入力欄の絶対パスの `@` 参照は、`mention.resolve` が閉じ込める前に、同じ関数で
書き換える。`~` で始まる参照と相対の参照は変えない。

### 3. 閉じ込めとルールの段は変えない

`Registry.resolvePath` は順序を変えない — 字面での包含、次に実パス — §1 の
後に届くのはすでに実の親だからである。ルールの段は I/O をせず、これからも
しない。ADR-0072 §4 の `os.Root` を通す開き方も変えない。

### 4. テスト

- 書き換えの関数: 測った表の各行（プロジェクト・書き込みのルート・読み取りの
  ルートは実パスで受け入れる。外へ行くリンクは打ったとおりのまま）。最後の
  要素がリンクならリンクのまま。資格情報の綴り、`/Volumes` の下のパス、相対
  パス、字面の上で中にあるパスは打ったとおりのまま。
- 偽のモデルでエージェントのループを通す端から端まで: 外のリンクを通して
  書き込みのルートへ向けた `write_file` は、追加したディレクトリの中の編集として
  承認されて書き込まれる。リンクを通したプロジェクトの `AGENTS.md` は運用者
  だけのもの。承認の詳細と記録された呼び出しは実パスを持つ。外へ行くリンクの
  拒否は行き先を挙げない。
- 書き換えた後に外のリンクを差し替えても、書き込み先は変わらない。
- 外のリンクを通した絶対パスの `@` 参照は、ファイルを添付する。

## Consequences

- `write_file`、`edit_file`、`read_file` とほかのファイルツールが、運用者や
  モデルが知っているリンクの名前でルートに届き、承認・判定・実行・記録されるのは
  1 つのパス、実パスになる。
- 新しい到達範囲は無い: 書き換えが作るのはいつもルートの中のパスで、ファイル
  ツールはそれを、打たれた実パスと同じに閉じ込める。
- **受け入れる残余: 承認前のメタデータの読み取り。** 親を解決するために、
  モデルが選んだ、ルートの外のパスのメタデータ — リンクとその親 — を承認前に
  読む。これまでは何も読んでいなかった。マウントは除く（§1）。保護された
  フォルダ（たとえば `~/Documents`）では、macOS がターミナルにアクセスを許すかを
  尋ねることがある。それは、モデルが名指したパスについての OS の問いである。
- **変わらない残余:** ルートの*中*のディレクトリは、判定と開く間に write
  レーンのコマンドがリンクへ差し替えうる。ADR-0072 §4 の `os.Root` が、今と
  同じく開く先をルートの中に保つ。
- **範囲外:** `@` で `openConfined` を通して開く文書とメディアの添付は、
  プロジェクトだけに閉じ込められ、追加したルートは含まない — この ADR が触れない
  既存の欠け。

## Alternatives considered

- **`resolvePath` で、使うたびに解決する。** 最初の案。設計レビューで却下:
  判定と実行がそれぞれリンクを解決し、その間の差し替えで別のファイルについての
  判定で書き込まれ、最後の要素を解決すると、R2 が置き換えるリンクを通して
  書き込む。
- **ルールの段で解決する。** 却下: 段は設計として I/O をしない。
- **起動時に各ルートのリンクを別名として記録する。** 却下: リンクは起動後にも
  作れる。綴りの一覧は、ADR-0101 がディレクトリでの 1 つの比較に置き換えたもの
  である。
- **そのままにして、モデルに実パスを伝える。** 却下: システムプロンプトはすでに
  実パスを挙げており、運用者はリンクを打つ。結果は、事実と逆のことを言う拒否
  だった。
