## Context（背景）

ADR-0073 はシェルのコマンド文字列から Safe を導出する設計を撤回した。その
理由は領域の議論であり、ナレッジベースもそう記録している: コマンド文字列は
無限の領域、カーネルは有限の領域であるから、判定をカーネルへ移し、文字列規則は
判定を上げることしかできない床として残す。その後もシェルレーンに残っている
13 個の `blockPatterns` が許容できるのは、見逃しのコストが「檻がいずれ捕まえる
確認 1 回」であって穴ではないからである。

file ツールはその移動をしていない。Seatbelt を通らないからである。`os.Root`
経由でファイルを開くインプロセスの Go コードであり、`read_file .env` とモデルの
間に立つ唯一のものは Go で書かれた照合器 `sandbox.CredentialPath` である。ここでの
見逃しは確認の欠落ではない。ファイルの内容が transcript に載ることである。

利用者の観察は履歴が示すとおりである。ADR-0073 以降、資格情報規則に触れた
コミットを数えると:

| 変更 | 回数 |
|---|---|
| 一覧への項目追加 | 1 |
| 照合規則の変更 | 6 |

項目は `.config/mcp-bridge` の 1 件。規則の 6 件は、ケース畳み込み、write を実パスで
判定、環境変数の scrub、scrub の接頭辞免除を名前一覧へ、末尾一致をセグメント一致へ、
walk が根を解決、である。うち 4 件は 1 回のリリースに集中し、いずれも独立レビューの
所見由来で、いずれも直前の規則が想定していなかった綴りだった: シンボリックリンク、
ケース、末尾、語の境界。

これは撤回した設計の兆候そのものであり、理由も同じである。**既知のファイルへの
パスの綴り方の集合は無限である。** ファイルの一覧は有限であり、そこは問題では
ない。比較の前に正規形へ到達することが問題であり、これまでの修正はどれも
「正規形へ一歩近づく」であって「導出をやめる」という決定ではなかった。

環境変数の scrub はさらに悪く、撤回した設計そのものである。無限の名前空間に
対する拒否リストの正規表現だからである。出荷中の正規表現で実測すると、次は
素通りする:

```
OPENAI_KEY  GH_PAT  STRIPE_SK  ANTHROPIC_KEY  GPG_PASSPHRASE
SESSION_COOKIE  BEARER  LICENSE_KEY  PAT
```

`NPM_TOKEN` は捕まり `OPENAI_KEY` は捕まらない。語をいくら足しても収束しない。
その半分には移る先のカーネルが無く、ADR-0087 で別に決める。この ADR は
file ツールの話である。

### カーネルが実際に何をするか

2026-09-13 に実機で計測。プロファイルは `(allow default)`・`(deny file-write*)`・
`(deny network*)` と資格情報 deny・テンプレート再許可だけを持つ:

| `.env` への操作 | 結果 |
|---|---|
| `cat .env` | `Operation not permitted` |
| `stat .env` | 許可 — deny は `file-read-data`。下記参照 |
| `cat .env.example` | 許可 — テンプレート再許可が効く |
| ディレクトリ全体の `grep -r` | その 1 ファイルだけ拒否して続行 |
| `ls -a` | **`.env` の名前は一覧に出る** |

つまりカーネルは内容に対しては完全な境界であり、メタデータと名前に対しては
境界ではない。演算子の選択が効く: `file-read*` はメタデータも拒むが、Go の
`os.Root` の一覧は各エントリを stat するので、拒まれた名前が 1 つあるだけで
ディレクトリ読取全体が失敗し、プロジェクト内のあらゆる walk が
"no matches (0 files scanned)" を返した（独立レビュー、実測。この ADR の初版は
その状態で出荷された）。`file-read-data` は内容を拒み stat を残す。それが walk に
必要なものであり、かつ秘密ではない。

起動コスト、同じ機体、各 10〜20 回:

| 対象 | 1 回あたり |
|---|---|
| 素の `/usr/bin/true` | 1.8 ms |
| `sandbox-exec` + `/usr/bin/true` | 7.8 ms |
| `sandbox-exec` + このバイナリ | 27.4 ms |

file ツールのコールは既にモデル 1 往復を伴う。1 回 27 ms は設計を曲げる予算では
ない。

## Decision（決定）

### 1. モデルが求めた読取はサンドボックス下の子で起きる

レジストリの読取プリミティブは、専用プロファイルの `sandbox-exec` で包んだ子
プロセスで走る。ツールコール 1 回につき 1 回の起動、このバイナリを内部サブ
コマンドで再実行する。要求は stdin に乗り（argv は `ps` で誰にでも見える）、
バイトは stdout に乗る。どちらも上限付きである。

プロファイルは基本部に `(deny network*)` を足し、`sandbox.CredentialFilters(home)`
を `(deny file-read* …)` として置き、その後に `.env.example` 系を再許可する。
他のすべての強制者と同じ `internal/sandbox` の一覧から作る。第 2 の一覧は作らず、
1 つ目の一覧に 4 人目の読み手が付くだけである。

プロジェクトの封じ込めは Go に残す。カーネルはプロジェクトの場所を知らず、
`os.Root` は既に syscall で脱出を拒み（ADR-0072 §4）、その機構は綴りのバグの
出所になったことがない。カーネルにはここで 1 つの仕事だけを与える。
**このプロセスでは資格情報を開けない。**

対象: `read_file`・`file_info`・`summarize_file`（`read_file` 経由）、および
`search_files` の walk 全体。walk は子の中で走らせ、そこで行う全ての open が
カーネルの裁定を受けるようにする。`view_image` と `read_document` は**コール**が
対象である — ツール自体が子で走るので資格情報パスはそこで拒まれる — 一方、
モデルが最終的に受け取るバイトは添付経路がインプロセスで読み直す。添付は
コール自体が走ったときだけ走る（`ran`、gem-agent ADR-0072 §1.1）。檻はそれが
起きるかどうかを決めるのであって、画素を運ぶのではない。

### 2. 拒否が操作者への問いになり、照合器は境界であることをやめる

拒否された open は型付きのエラーを返す。`Agent.execCall` がそのエラーを
ADR-0085 §1 が定めた操作者専用の確認に変え、承認されたら読取を**インプロセスで**
再発行する。これは operator レーンの権限を file ツールに適用したものである:
資格情報を読めるのは操作者だけであり、その操作者がいま読めと言った。

拒否された open はバイトを生まないので、ゲートの前にモデルへ届くものは無い。

したがって `risk.credentialRead` は正しさのためには不要になる。残す理由は 1 つ、
よくある場合に子プロセス 1 回を使わずに確認を出すためと、承認の記録を同じ形に
保つためである。そこでの見逃しのコストは、子プロセス 1 回と回りくどい確認で
あって、漏洩ではない。これは ADR-0073 がシェルレーンに与えた性質であり、
それを file ツールにも与えるということである。

### 3. 名前は伏せない — ADR-0085 §2 を撤回する

カーネルは名前を出し、内容を拒む。ファイル名は秘密ではない。秘密は内容である。
ADR-0085 §2 は「`.env` を名指す一覧は、毎ラウンド差し出される『確認を要する
読取』である」という理由で名前を伏せた。しかし件数も同じ推測を誘い、モデルは
どちらでも `.env` に手を伸ばし、操作者はまさにその読取を確認したい。一方で
名前を伏せる仕組みは、同じ無限の綴り領域に対する第 2 の規則であり、6 件の規則
変更のうち 2 件はそこで起きた。

よって `list_files` と `list_tree` は資格情報名のエントリを他と同じく列挙し、
資格情報のコードを一切持たない。`search_files` は読めなかったファイルを名指して
続行する。`grep -r` が既に持つ形であり、ADR-0052 が求める形である。
`credentialSkipNote` と件数の計上は削除する。

これは 2 つのランタイム間の矛盾も解消する。lagent の ADR-0015 §2 は名前を報告し、
gem-agent の ADR-0085 §2 は件数を報告していた。どちらも残らない。両ランタイムが
名前を出し、内容を拒む。

### 4. 天井は追いかけず、書き留める

この設計がしないことを 3 つ、ここに明記する。将来のレビューがこれらを
「もう 1 つパターンを足して塞ぐ穴」ではなく既知として報告するためである:

- **通常の名前を持つ資格情報ファイルへのハードリンク。** 正規化すべき実パスが
  存在しない。リンク自体が実名である。いかなるパス規則でも塞げない。
- **通常の名前でのコピー。** 同じ。
- **一覧が名指さないファイルの中の秘密。** 内容検査は、この ADR 全体が避けようと
  している無限の領域である。

3 つとも、対処はシステムリスクレビュー 10 章が既に勧告し、先行する両 ADR が既に
記録しているもの、すなわち「実秘密をエージェントが読む作業コピーに置かない」で
ある。

### 5. 劣化はレーンと同じく計測する

起動時に、read レーンと同じ形で子を検証する（ADR-0073 §7）: プロファイルが必ず
拒むプローブファイルと、必ず読める通常ファイル。失敗したら file ツールは
`risk.credentialRead` を境界とするインプロセス読取へ退避し、起動時の警告がそれを
名指す。カーネルが見張っていると
主張する劣化状態は、照合器より悪い。

### 6. これが残す判定基準

**項目は安く、規則が兆候である。** `internal/sandbox` にパスを 1 つ足すのは、
機構が設計どおりに働いていることである。パスの比較方法に規則を 1 つ足すのは、
判定が誤った領域に居ることの signal である。規則変更が 3 回続いたら、それは
4 回目の修正を要する照合器ではない。境界の場所が誤っている。

## Consequences（帰結）

- 資格情報の照合器は読取について荷重を担うことをやめる。残る仕事はプロファイル
  の生成、シェルの Block 床（見逃しのコストは確認 1 回）、write ツールの Block
  （§対象外）である。
- 削除されるもの: walk の差し止め機構、`credentialSkipNote`、`list_files` と
  `list_tree` の資格情報分岐、そして ADR-0085 §2 とそれを巡るレビュー行。
- 追加されるもの: プロファイル関数 1 つ、内部サブコマンド 1 つ、型付きエラー
  1 つ、再試行分岐 1 つ、起動プローブ 1 つ。
- 対象ツールのコール 1 回あたり約 27 ms 増える。コールは既にモデル 1 往復を伴う。
- `search_files` は弱くならず強くなる。読めなかったファイルを「無かったこと」に
  せず報告するからである。
- **対象外: 書込。** 資格情報パスへの `write_file` は Go 側の Block のままである。
  書込は秘密を公開するのではなく破壊するものであり、書込経路は既に毎回ゲートを
  通る。対称な手 — 同じ一覧に対して `file-write*` を拒むプロファイル下の書込用の
  子 — は取れるが、ここでは取らない。取るなら独自の計測を伴う独自の ADR に
  すべきである。
- lagent は ADR-0073 の設計がそうされたように、同じ決定を自身の番号の ADR として
  取る。

## Alternatives considered（検討した代替案）

- **常駐ヘルパープロセス。** 却下: 1 コールあたり 27 ms を買う代わりに、プロトコル、
  ライフサイクル、`/clear` の作業ディレクトリ回転と結合した再起動経路、そして
  セッション途中でヘルパーが死ぬという新しい障害クラスを払う。コールごとの起動には
  そのどれも無く、計測は起動が問題でないと言っている。
- **エージェントプロセス自身をサンドボックス化する。** 不可能: プロファイルは
  エージェントが正当に行うこと全部、つまり transcript の読み書きとネットワーク
  到達を許さねばならず、`sandbox_init` は不可逆かつ非推奨である。
- **プロジェクト封じ込めもカーネルで** — `(deny file-read*)` に根を再許可する形。
  却下: 子は自身の実行ファイルとシステムライブラリを読む必要があるので、全体
  read deny はシステム再許可の一覧に化ける。それは新しい無限の一覧である。
  `os.Root` は封じ込めを既に正しく行っている。
- **照合器を境界のまま残し、カーネルを第 2 層として足す。** 却下: 1 つの規則に
  2 つの境界は「一覧は 1 つ、強制者は N 人」が避けるためにある形であり、照合器が
  荷重を担い続ける。それこそが今回の指摘そのものである。
- **内容検査。** 却下、無限、ADR-0085 と同じ。

## 独立レビュー（2026-09-13、リリース前）

変更を書いていない読み手 2 名がランタイムごとにリリース diff をレビューし、
Critical で一致した。最初にコミットした形は壊れていた。**資格情報名のファイルが
1 つあるだけで `search_files` が "no matches (0 files scanned)" を返した** —
自信のある偽陰性であり、置き換えようとした漏洩より悪い。所見と結果:
