# ADR-0007: ターン実行中に打たれた入力

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 初回月次訓練: 実行中の入力が無反応で捨てられる |

## Context

ターン実行中、TUI がキーイベントを渡す先は 2 つしか無い: Ctrl+C（中断）と
shift+tab（自動承認トグル）。それ以外は床に落とされる。オペレータは続きを打ち、
文字が出ないのを見て、プロンプトが戻ってから打ち直すことになる。

これは珍しい状態ではない。ツールラウンドが数回あるエージェントターンは数十秒
動くが、**次の指示を思いつくのはまさにそのとき**である — 流れていく出力を見て
思いつくことも多い（「いや、そのファイルじゃない」）。Claude Code は打った内容を
キューに積む。そこから持ち越した筋肉記憶がここではテキストの消失を生むし、
drop-in の親しみやすさはこのツールの明示的な目標である（RFP §1）。

そして**黙って捨てる**のが悪い方の半分である。目に見える拒否なら、少なくとも
オペレータが認識できる判断になる。

## Decision

ターン実行中も入力欄は生きたままにし、**Enter は送信ではなく 1 件のキュー投入**
とする。

1. **実行中もタイピングは効く。** 文字・バックスペース・Ctrl+J の改行・ペースト、
   すべてプロンプト時と同じように textarea に届く。書いている内容が見える。
2. **Enter でキューに積む。** テキストは入力欄から消え、キュー行としてスクロール
   バックに出て、待機する。ターン途中では送らない: 実行中の会話履歴はエージェント
   ループが所有しており、未完了のツールラウンドに user メッセージを差し込めば、
   Gemini が要求する call/response の対応が壊れるか、ループが書いている履歴と競合
   する。
3. **キューではなく 1 件。** 既にキューがある状態の 2 回目の Enter は、何も置き換
   えず何も捨てず、保留中メッセージへ改行付きで**追記**する。独立した複数ターンを
   キューするにはエージェントループが無人でターンを連鎖する必要があり、問題の
   大きさに対して変更が大きすぎる。このツールのスコープは意図的に中核 2 割である。
4. **自動送信は正常終了のときだけ。** ターンが正常に終わったら、キューされた
   メッセージを次のターンとして送信する。エラーや中断で終わった場合は、テキストを
   **未送信のまま入力欄へ戻す**（通知付き）。この非対称性が肝である: 失敗した
   ターンの最中に書いたメッセージは、もう存在しない世界に対して書かれたもので
   あり、壊れた状態へ発射するのは「キューは信用できない」と思わせるまさにその
   驚きである。
5. **Ctrl+C は常に中断。クリアには使わない。** 実行中は脱出ハッチであり、下書きの
   クリアを兼ねさせると脱出ハッチが「入力欄が空なら」という条件付きになる。
6. **承認ダイアログには影響しない。** 開いている間、キーはダイアログへの回答で
   ある。ここでキーを積むのは、誰も意図していない承認になりうる。

## Consequences

- よくある場面 — ターン中に訂正を思いついて打つ — でテキストが残る。まれな場面 —
  キューした後にターンが失敗する — では送らずに返す。
- 自動送信は「2 回目の Enter なしにメッセージが出ていく」ことを意味する。それが
  狙いだ（それが無ければキューする価値が無い）が、だからこそ正常終了という条件は
  親切心ではなく硬い規則にしてある。
- ステータス行に新しい表示は増やさない。スクロールバックのキュー行と空になった
  入力欄がフィードバックである。一過性の状態のために常設ウィジェットを 1 つ増やす
  のは割に合わない。

## Alternatives considered

- **現状維持 + ヒント行を出す** — 却下。消失を可視化するだけで止められない。
  テキストは相変わらず消える。
- **キューしたメッセージを実行中のターンに流し込む** — 却下。実行中の履歴は
  ループが所有しており、Gemini は function call と応答の同一リクエスト内対応を
  要求する。ツールラウンドの途中に user メッセージを差し込める安全な位置は無い。
- **複数メッセージをキューしてターンを連鎖する** — 現時点では却下。エージェントが
  「指示 1 つにつき 1 ターン」から「無人のキュー実行機」に変わり、中断の意味も
  自動承認の適用範囲も変わる。保留 1 件では足りないと分かったら再検討する。
- **無条件に自動送信** — 却下（決定 4 参照）。失敗したターンへ送られるキューは、
  返されるキューより悪い。
