## 背景

v0.104.0、v0.105.0、v0.106.0 は、どれも独立した検証役が本物のサンドボックスプロファイルの下で再現した手口を塞いだ。実際の利用で起きたものは一つもない。検証役には、攻める側が誰なのかの線を引かないまま、レーンの中から攻めるよう頼んでいた。そして、再現できた指摘を、塞がなければならない指摘として扱った。その結果できたのは次のコードである。スキルを読んで返したバイト列を、比較したバイト列ともう一度照合する処理と、大文字小文字や Unicode の形の違いを吸収する自前の名前照合。システムコールの上にじかに書いたディレクトリ型（`bounded.Dir`、369 行）。そして、差し替えられたプローブを自分の作ったものと見分け、外から止められた命令を拒まれた命令と見分け、対照を二度取る起動時の確認。

「どんな条件がそろえば、どのくらい起き得るか」を最初の問いにして読み直すと、指摘は二つに分かれる。

| 塞いだもの | 起きるためにそろう必要があること | 起きること |
|---|---|---|
| 確かめてから開くまでの間に、名前を FIFO に差し替える | この機械で、名前を差し替え続けるプログラムが動いている | open が待つ |
| 起動時の確認の最中に、プローブを差し替える | 書き込みレーンに残って動き続け、数ミリ秒だけ存在する乱数名のファイルを見張るプログラム | 1 つのファイルに `x` が書かれる。または 4 つの名前のファイルが消える |
| 比較してから読むまでの間に、スキルを差し替える | 同じ種類のプログラム | 差し替えた文面が 1 回モデルに届く |
| 確認の命令を外から終わらせ、拒否に見せる | 同じプログラムに加えて、レーンが実際に壊れていること | 通るべきでない確認が通る |
| 信用済みのスキルが、セッションの途中で書き換わる | `git pull`、またはスキルがリンクしているディレクトリへ書くコマンド | 新しい文面が、尋ねられずにモデルに届く |
| レーンの作業ディレクトリをリンクに置き換え、そのあとレーンが作り直される | 書き込みレーンの普通のコマンド 2 つと、操作者によるディレクトリの追加 | 書き込みレーンが、リンク先へ書けるようになる |

上の 4 つには、ランタイムと競争するように書かれたプログラムが要る。書き込みレーンでそれを動かせる相手は、プロジェクト自身のコードを書き換えられる。操作者はそのコードを、あとでサンドボックスの外で実行する。4 つのどれが与えるものよりも、そちらの方が大きい。下の 2 つには競争が要らない。5 つ目は ADR-0119 の「比べて、違えば尋ねる」が塞いでいる。6 つ目は公開したすべての版で開いていた。レーンは起動時、`/clear`、権限の追加のたびに作り直され、そのたびにプロジェクトと作業ディレクトリの名前を解決し直していた。そのため、リンクになった名前は、プロファイルの基準をリンク先に置いた（v0.106.0 で、`rm -rf "$GEMAGENT_WORK_DIR" && ln -s <dir> "$GEMAGENT_WORK_DIR"` のあとにレーンの組み立てを呼んで実測した。書き込みレーンのプロファイルは `<dir>` を許した。保護対象の名前を持たないプロジェクトも、同じやり方で置き換えられる）。ランタイム自身も、大きな MCP の結果を保存するときに、サンドボックスの外から作業ディレクトリの名前の下へ書く。同じ 2 つのコマンドのあとでは、結果のファイルがリンク先にできた（実測）。

## 決定

1. **サンドボックスが相手にするのは、モデルが間違って、または誘導されて実行したコマンドである。ランタイムと競争するように書かれたプログラムは相手にしない。** 指摘は次の順で判断する。どんな条件で、どのくらい起き得るか。誰がするのか。その相手はすでに何を持っているか。それで新しく何を得るか。この線の外にある指摘は記録し、備えは作らない。手口がどこかに書かれているかどうかは判断に入れない。塞ぐコード、あるいは塞ぐコードを外す変更の量の大小も入れない。

2. **レーンの基準にするディレクトリは、一度だけ解決する。** プロジェクト、作業ディレクトリ、一時ディレクトリの実パスは、このプロセスでその名前を最初に解決したときの答えである（`sandbox.ResolveKept`）。あとの組み立てが名前を解決し直すのは、比べるためだけである。プロジェクトか作業ディレクトリが、覚えた答えに解決されなくなっていたら、レーンは作らない。以後のシェルコマンドはすべて操作者に尋ね、どのディレクトリが置き換えられたか、今どこへ通じているか、そのディレクトリを元に戻してから再起動すればサンドボックスが戻ることを通知する。操作者への通知は、作り直しを求めたのが誰であっても出す。モデルが求めた権限の追加でも同じである。それまでに作ったレーンは、そのまま間に入り続ける。名前が無くなっただけなら、覚えた答えを使う。レーンの基準はディレクトリがあった場所のままで、コマンドはそこに作り直せる。一時ディレクトリは覚えた答えを使い続け、何も止めない。元の場所を基準にしたプロファイルは、リンクに何も与えない。

   レーンが置き換えられたあとで、ランタイムがその名前をもう一度使う場所でも、同じ比較をする。作業ディレクトリの下へ MCP の結果を保存する前（置き換えられていたら何も保存せず、呼び出しがそう伝える）と、作り直しのときに追加ディレクトリの中へプローブを作る前（置き換えられていたら確認に落ち、無くなったディレクトリと同じく外される。ADR-0114 §2）である。

   このために開いたまま持つものはなく、ファイルを装置番号と通し番号で比べることもしない。比較と使用の間に置き換えるのは、競争である。

3. **起動時の確認は、プローブを持ち続けることで自分のプローブだけに触れる。確認の判定そのものは、もう守らない。** プローブファイルは、それを置くディレクトリを `os.Root` として開いたまま、その中に乱数の名前で作り、開いたままにする。対照は、開いているファイルへ書く。名前を開くことはない。片づけは、確認が作った名前を、その root を通して消す。パスでは何も消さない。プローブの命令 1 つにつき 10 秒の上限と、始めたものごと終わらせる扱い（ADR-0121 §4）、スクラッチのプローブの乱数名（§8）は残す。

   ADR-0121 から撤回するもの: レーンが拒んだあとの二度目の対照。差し替えられたプローブを自分の作ったものと見分ける比較。プローブディレクトリが空であること、元の名前の下にあることの確認。`Denial` が見分けていた、成功と失敗以外の 3 つの終わり方（§2、§3 と、§1・§5・§7 のうちこれらに当たる部分）。ファイル読み取りの確認が、子プロセス自身の終了コードを読む扱い。確認が誤って通ってもレーンは弱くならないので、誤って通させたプロセスは何も得ていない。装置番号と通し番号による比較は、ネットワーク上のボリュームで測ったことがなかった。

4. **スキルの走査は、ふたたびスキルの root を通して読む。`bounded.Dir` は削除する**（ADR-0120 §8 を撤回）。走査は v0.105.0 のものに戻し、3 つの上限はそのままにする。下位のディレクトリは、親から `Root.OpenRoot` で開く。一覧のあとに FIFO へ差し替えられると待つ。木のダイジェストは前後で変わらないので、信用の記録は一つも変わらない。

5. **スキルは読むたびに先に比較し、読んだものをもう一度は比較しない**（ADR-0119 §1 を改める）。撤回するもの: 返したバイト列を、比較した木の一覧（マニフェスト）と照合する処理。マニフェスト自身がリンクをたどり、大文字小文字と形の違う名前を突き合わせる処理。ダイジェストが見ていない項目を省くディレクトリ一覧。名前の突き合わせは、ボリュームが別の綴りで見つけたファイルを、バイト列の照合が拒まないようにするためのものだった。その最初の形は、そういうスキルをいつまでも拒んだ。

6. **変えないもの。** 変わったスキルについての質問と、その答え方のすべて（ADR-0119 §2〜§13）。ディレクトリだけ、通常ファイルだけを開く open と、待たない open（ADR-0120 §1〜§7、§9）。スキルの走査の上限。クリップボードの取り込み先のファイル（ADR-0121 §9）。名前に制御文字や書式用の文字を持つスキルのディレクトリを一覧に載せない扱いも残す。名前はリポジトリで運ばれるもので、プログラムを要しない。

## 帰結

- 通知「… was replaced while the sandbox was being checked」と「… showed nothing: the command was ended by a signal」は出なくなる。「… did not finish within 10s」は残る。
- プロジェクトスキルの中のディレクトリの一覧は、ふたたびすべての項目を示す。「[not listed: N that are not part of the trusted skill]」の行は出なくなる。
- 別の綴りでファイルを求めたために、スキルが「まだ変わり続けている」として拒まれることは、なくなる。この通知が残るのは、質問に答えている間に 2 度変わったスキルに対してだけである。
- プロジェクトか作業ディレクトリをリンクに置き換えられたセッションは、再起動するまで、シェルコマンドのたびに尋ねる。

**受け入れて、書き残すもの。** どれも、この機械でランタイムと競争するプログラムが要る。

| 起き得ること | 結果 |
|---|---|
| 一覧から open までの間に、名前を FIFO に差し替える | スキルの比較、または起動が、中断されるまで待つ |
| 確認の最中に、プローブディレクトリを、同じ root の中の別のディレクトリへのリンクに差し替える | そこにある、確認の 4 つの名前のファイルが消える |
| 確認の命令を外から終わらせる | レーンが実際に壊れている場合に、確認が通る |
| 比較から読み取りまでの間に、スキルを差し替える | 差し替えた文面が 1 回モデルに届く。次に使うときは比較する |
| 2 の比較から使用までの間に、ディレクトリを置き換える | レーンの基準は、それでも覚えた答えである。ランタイムがその名前の下にパスで作るもの（スクラッチのディレクトリ、保存する MCP の結果、確認のプローブ）は、リンク先に置かれる |

競争を要しない残余が 1 つある。信用済みのスキルに空のディレクトリを足しても、ダイジェストは変わらない。その名前は、これからは、それが置かれたディレクトリの一覧に出る。255 バイトまでの名前である。git は空のディレクトリを運ばず、書き込みレーンはプロジェクトの `.claude` を拒まれる（実測）。したがって、それを作れるのは、操作者が操作者レーンで実行したコマンドか、スキルのディレクトリが書き込みレーンの書ける場所へのリンクである場合である。

## 設計が求めるテスト

- 作業ディレクトリをリンクに置き換えると、作り直しは何も作らず、すべてのコマンドが尋ねる。プロジェクトも同じ。一時ディレクトリを置き換えても、プロファイルは変わらない。作業ディレクトリが無くなっただけなら、置き換えとは扱わず、レーンを作り直す。リンクになった作業ディレクトリ越しには、MCP の結果を保存しない。組み立てのたびの素の解決に戻すと、はじめの 2 つが落ちる。
- 対照は、名前がリンクになっていても、作ったファイルへ書き、リンク先は変わらない。片づけは、プローブディレクトリの名前の下に root の外のディレクトリを置かれても、そこから何も消さない。
- 確認は、APFS と、テストに指定したボリュームで通る。
- スキルの木のダイジェストは、これまでと同じである（走査の上限とダイジェストのテストは、そのまま残す）。

## 検討した代替案

- **公開したものを、そのままにする。** そのコードは、起動のたび、プロジェクトスキルを使うたびに走る。3 分の 1 は、標準ライブラリがすでに包んでいるシステムコールの上に書かれている。備えている相手は、競争するプログラムである。不採用。
- **基準にするディレクトリをすべて開いたまま持ち、名前の下にあるものを装置番号と通し番号で比べる。** v0.106.0 のあとに、持っているディレクトリの台帳と、パスを取る呼び出しをすべて分類するテストとともに作り、公開しなかった。決定 2 が残す競争を塞ぐが、コードは 15 倍になる。決定 1 により不採用。
- **スキルを使うたびに木全体のダイジェストを取るのをやめ、読むファイルごとに比べる。** そうしていれば、走査の上限は要らなかった。ここでは採らない。信用の記録の意味が変わるうえ、実際の利用がそれを求めていない。
