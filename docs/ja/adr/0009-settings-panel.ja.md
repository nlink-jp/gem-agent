# ADR-0009: 設定パネルと、機械が所有するポリシーファイル

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「そろそろ `/` コマンドで設定を視覚的にできる機能が必要かもしれない」 |

## Context

設定は 4 層（フラグ・`GEMAGENT_*`・`GOOGLE_CLOUD_*`・ファイル・組み込み既定）で
解決されるが、**セッションの中からはそのどれも見えない**。バナーは数個の値を
出すだけで、それがどこ由来かは示さない。「なぜこのモデルを使っているのか」に
答えるには、いま設定ファイルを読み、優先順位を記憶から唱えるしかない。

編集には別の問題がある。運用で実際に変わる設定は承認ポリシー（ADR-0008）で
あり、**「このツールは今後聞かなくていい」と判断する瞬間はダイアログが出た
瞬間**である。ところが今それを反映する唯一の方法は、終了して TOML を編集し、
起動し直すことである。

書き込みにも制約がある。使用中の TOML ライブラリは**コメントを保持しない**。
同梱テンプレートはそのコメントが 71 行あり、各キーが何をするか・既定値がなぜ
その値かを説明している。設定 UI が `config.toml` に書き戻す実装にすると、
値を変えた最初の 1 回で、まさに編集中の人が頼っている説明文を黙って消す。

## Decision

**`/settings` は「全部見せて、少しだけ編集する」パネルとする。**

1. **全項目を出所付きで表示する。** 各行が「有効な値」と「どこから来たか」を
   持つ: `flag` / `env` / `config.toml` / `policy.toml` / プロジェクトファイル /
   `default`。この半分だけで機能は元が取れる。セッション途中で変えられない設定
   （GCP プロジェクト、モデル — 変更はバックエンドクライアントの作り直しを
   意味する）は読み取り専用で出す。
2. **編集できるのは「今すぐ効かせられるもの」だけ**: ツール単位の承認ポリシー、
   自動承認、自動圧縮、テーマ。テーマ切替が安全なのは、端末に問い合わせるのは
   `auto` だけで、その検出は Bubble Tea がキーボードを取る前に既に済んでいる
   ためである（ADR-0002）。`dark`/`light`/`plain` 間の移動は、端末に何も聞かずに
   スタイルを組み直すだけで済む。
3. **永続化先は機械が所有するファイル** `~/.config/gem-agent/policy.toml` とし、
   1 行目に「gem-agent が書き換える」と明記する。`config.toml` は手書きのまま
   一切触らないので、コメントが生き残る。両者はマージし、**衝突時は
   `policy.toml` が勝つ** — UI で行った変更が「手書きファイルに同じツールの
   記述がある」というだけで黙って無効になってはならない。パネルは各エントリの
   出所を出すので、隠された方も不可視ではなく可視である。
4. **UI はプロジェクトに書き込まずに、プロジェクト限定のポリシーを設定できる。**
   `policy.toml` は `[tools]` と `[projects."<path>".tools]` の両方を持ち、
   パネルには書き込み先を切り替えるキーがある。設定パネルから
   `<project>/.gem-agent.toml` を書く案は却下した: キーを 1 つ押した副作用として
   他人のリポジトリにファイルが増えるのは驚きが大きく、そこに緩める指定を書いても
   信頼登録が無ければどうせ無効である（ADR-0008 §4）。手書きのプロジェクト
   ファイルは引き続き読み、読み取り専用で表示する。
5. **承認ダイアログに 4 つ目の回答「今後聞かない」を足す。** そのツールに
   `never` を `policy.toml` のグローバルスコープへ書き、専用の行でそう告げる。
   この機能が存在する理由がこの導線である。既定選択には**しない**し、既存の
   `a`（このセッションでは常に許可）とは**意図的に別物**にする。片方はセッション
   内の利便であり、もう片方はディスク上のファイルを編集する行為である。
6. **非 TTY では表を読み取り専用で出す。** 素の REPL とパイプでは、エディタ
   無しで同じ行を表示する。素の REPL が存在する理由と同じ理由である。

## Consequences

- 優先順位が口伝でなくなる。表示の無い 4 層は「オペレータが覚えている」ことを
  前提にした設計であり、行ごとの出所表示はその前提を外す。
- グローバルスコープの承認ポリシーを記述するファイルが 2 つになる。これは実際に
  コストであり — ADR-0005 ではトランスクリプトについてまさにこの形を却下した —
  ここで受け入れるのは**両者の作者が違う**からである。一方は手書きでコメント付き、
  もう一方は生成物。マージは明示的で、勝者は明記され、パネルが各エントリの出所を
  出す。
- 「今後聞かない」は、一次防御の永続的な弱体化をキー 1 つの距離に置く。これは
  オペレータ自身が、目の前のツールについて下す判断であり、実行時に告知され
  `/settings` で後から見える — ただし既定選択にしてはならず、許可した内容にも
  ルール層の Block の床は効き続ける（ADR-0008 §2）。
- パネルは新しい TUI フェーズである。中のキーはパネルのもので、承認ダイアログと
  実行中ターンは自分のキーを保つ（ADR-0007）。

## Alternatives considered

- **閲覧のみ** — 却下。肝心の瞬間（ダイアログが出ていて、答えは分かっている）に
  再起動のコストが残り続ける。
- **全設定を編集可能に** — 現時点では却下。モデルと GCP プロジェクトは
  バックエンドクライアントの作り直しを要し、`[sandbox].enabled` はセッション途中に
  メニューから切り替えるものではない。これらは「見せる」対象であり「編集する」
  対象ではない。
- **`config.toml` に書き戻す** — 却下。コメントを破壊する。しかもそのコメントは、
  誰かが編集しているまさにその瞬間における、そのファイルの唯一の説明書である。
  テンプレートから再生成する案は、手書きファイルの所有権を生成器に渡すことになる。
- **`<project>/.gem-agent.toml` を書く** — 却下（決定 4 参照）。
- **`gem-agent config set` サブコマンド** — 後で足すのは妥当だが、今回のきっかけ
  である「セッション途中、ダイアログが出ている状態で判断が起きる」ケースは
  解決しない。
