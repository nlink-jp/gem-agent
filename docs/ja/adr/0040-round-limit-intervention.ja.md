# ADR-0040: ラウンド上限をギロチンから介入ラダーへ

| 項目 | 内容 |
|------|------|
| Status | **Accepted** |
| Date | 2026-08-22 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレーター（セッションログから）: 健全に前進していた 50 ラウンドの調査ターンが max_turns にパイプライン途中で殺され、エラーの助言（/clear）は回復可能な仕事を破壊する内容だった。素のカウンタは有能なエージェンティックモデルをスポイルする — ループ検出と第三者の進捗評価を組み合わせよ |

*ADR-0075 による修正: ループガードの隣に姉妹検出器 — 1 つの MCP ツールが
異なる引数に同じエラー文を返す反復で、同一コール署名では見えないもの。
function response で語り、ターンを止めることはない。ラウンド梯子が天井のまま。*

## Context（背景）

`[agent].max_turns` はギロチンだった: 50 ラウンド目が来たら、何を
していようとターンは死ぬ。本 ADR の発端となったログは完璧な標本で
ある: incident-research スキルの実行 — 検索 15・取得 12、その後
レポート各節を 1 つずつ書いてはスキーマ検証 — が、**単調に前進して
いる最中に**、レポート 6 節目を書いた地点のラウンド 50 で殺された。
同一コールの反復はゼロ。オペレーターが「続けて」相当を打つと 10
ラウンドで完走した。損害は往復 1 回と、エラーの助言 — 回復を可能に
している当のものを破壊する `/clear` を勧め、続行が可能なことには
一言も触れない — だけだった。

一方、本物の暴走ループは逆のコストを払う: 何かが介入するまでに、
上限までの全ラウンドを浪費する。

コードベースはこの答えの**型**を既に持っている: 自動承認ラダー
（ADR-0004）— 決定論的ルール層・判断のためのモデル層・人間の床・
そしてその下の何ものも持ち上げられない Block の天井。

## Decision（決定）

### 1. ルール層: ループ検出器 — 常時・即時

ターンは連続する同一コール（ツール名 + 正規化引数 JSON）を追跡する。
3 連続で下記の介入が**その場で**発火する — 本物のループはもう 40
ラウンドをタダ取りできない。正当な反復は実在する（非同期 MCP ジョブ
のポーリングは設計上同一コールの連続）ので、検出それ自体は決して
殺さない: エスカレーションし、「続行」の裁定は**そのコール署名を
ターンの残りに対してホワイトリスト**する — ポーリングが 3 回ごとに
聞かれることはない。

### 2. 上限到達時: 進捗レビュー、そして裁定

ラウンド上限（と以後の各延長境界）でサイドコールを 1 回走らせる:
レビュワーはオペレーターの指示とターンの直近ツールコールトレースを
— リスク評価（ADR-0038）とまったく同じ証拠ラップ・ツール無しで —
読み、`{progressing, confidence, reason}` で答える。別々の対象を
単調に進むのは前進、状態が変わらない同一コールは停滞、ポーリングは
正当な待機かもしれないと明記する。

裁定はモードに従う:

| モード | 裁定 |
|---|---|
| 対話 + auto ON | 前進 + 高確信 → **自動続行**（可視の通知付き — auto は中断回数の低減のために入れたのだから）。それ未満 → ダイアログ |
| 対話 + auto OFF | 常にダイアログ（レビュー所見を判断材料として表示） |
| 非対話（`-p`） | 前進 + 高確信 → 続行。それ未満 → 停止（fail-closed） |

ダイアログは ask 機構（ADR-0036）に相乗りする: 2 択・数字 1 打・
Esc・Ctrl+C 後の自動辞退。延長 1 回は `max_turns` の半分。

### 3. どんな裁定も持ち上げられない天井

絶対上限は **3 × max_turns**。ここでは裁定にも回答にも関わらず停止
する — 騙されたレビュワーの被害は既知の支出で有界になる。Block の
床の原理をラウンドに適用したものである。（`agentic_file_search` の
子は素の 10 ラウンド上限のまま: 使い切る子に必要なのは狭い質問で
あって大きな予算ではない（ADR-0037）— 延長機構はメインループ専用。）

### 4. 停止メッセージは真実を言う

それでも停止するとき、メッセージはログが証明したことを言う:
進捗は会話に保存済みであり、「続けて」で続きから再開でき、恒久的に
は `[agent].max_turns` で上限を上げられる。回復を成立させている
当のものを破壊せよという `/clear` の推奨は消えた。

## Consequences（帰結）

- 長い正当な仕事をする有能なモデルはもうスポイルされない: auto
  モードでは可視の通知 1 つでチェックポイントを通過し、最悪でも
  `max_turns/2` ラウンドごとにキー 1 打である。
- 本物の暴走は 50 ラウンドではなく約 3 ラウンドで捕まり、支出は
  3 × max_turns を決して超えない。
- コストはチェックポイントごとにサイドコール 1 回 — 長いターンでも
  高々数回、上限に達しないターンではゼロ。
- 介入はトランスクリプトに記録され（`round_intervention`: trigger・
  rounds・verdict・decision）、延長は監査ストリームの `turn.end` の
  rounds が `max_turns` を超えることで可視である。
- レビューの消費は `/usage` でリスクレビューのカウンタに合流する —
  どちらも「エージェント自身の挙動へのモデル層レビュー」である。
