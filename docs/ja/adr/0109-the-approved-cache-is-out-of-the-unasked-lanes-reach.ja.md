## Context

ADR-0084 §1 は、read レーンのキャッシュと承認済みレーンのキャッシュを分け、「読んだ内容に操られた read レーンのコマンドが、承認済みの `make build` がリンクするオブジェクトを仕込めない」ようにした。2 つのディレクトリは `<scratch>/<name>` と `<scratch>/<name>-approved` だった。違いは環境変数の値にしかない。read レーンのプロファイルは scratch の subpath 全体に `file-write*` を許すので、`-approved` のパスを名指すコマンドはそこに書ける。Go は読み出し時にキャッシュの中身を検証しないため、ADR-0084 の Alternatives で退けた経路（「全レーンで 1 つのキャッシュ」）は開いたままだった。

監査は、キャッシュを作業ディレクトリ内の scratch の隣へ移す案を出した。シェルの経路はこれで閉じるが、別の経路が残る。作業ディレクトリはファイルツールのルートで、`risk.Classify` はその中への `write_file` を Safe と判定する。自動承認のもとでは、読んだ内容に操られたモデルが、聞かれずに隣のディレクトリへ書ける。クラスは「承認済みビルドが信頼するディレクトリは、聞かずに走るものすべての手の届かない所に置く」である。聞かずに書けるものは read レーンとファイルツールの 2 つあり、さらに、他のセッションのレーンが書ける場所にあってもいけない。

## Decision

1. **承認済みレーンのキャッシュは、作業ディレクトリの隣の、セッション専用のディレクトリに置く。** `<state>/<project>/approved-cache/<session id>` で、`<state>/<project>/work/<session id>` の兄弟である（`workdir.ApprovedCachePath`）。モードは 0700。`[sandbox].scratch_caches` の各行は、表の名前のままその子になる。`-approved` の接尾辞はなくなり、場所そのものが分離になる。このディレクトリはファイルツールのルートではなく、これを名指すのはこのセッションのプロファイルだけである。
2. **プロファイルがそれを言う。** `Spec.ApprovedCacheRoot` を write レーンと operator レーンの書き込み可能な集合に足す。read レーンのプロファイルは、最後の書き込み許可の後でこのディレクトリへの `file-write*` を拒否する。既定の state ルートでは、このセッション自身の write レーンと operator レーン以外の許可はこのディレクトリに届かず、名指しの拒否は第 2 線である。リンクになったセッションのディレクトリは、次に作るときにたどらず拒否する。write レーンは差し替えられるので、そうしないと再開で書ける範囲が広がる。
3. **主張は起動時に測る。** `VerifyReadLane` に、失敗しなければならないプローブ（承認済みルートへの書き込み）を足す。成功してしまう環境では、他のプローブと同じく read レーンを無効にする。
4. **保持は作業ディレクトリに従う。** キャッシュはセッション ID で引くので、`--continue` では温まったまま見つかる。`gem-agent workdirs` はこれを数え、`workdirs clean` が作業ディレクトリと一緒に消す（ADR-0059）。勝手に消すものはない。
5. **そのディレクトリがないときは、承認済みレーンのキャッシュは振り向けない。** 作業ディレクトリのないセッション（状態を作れなかった）や、ディレクトリを作れないセッションでは、これらのレーンのキャッシュ変数を設定しない（操作者が export したものはそのまま通る）。read レーンには影響せず、ビルドもできる。write レーンと operator レーンの Go ビルドは、どちらのレーンも書けない既定のキャッシュで失敗し、その旨を告げる。

## Consequences

- 古い `<scratch>/<name>-approved` に仕込まれたエントリは消費されない。そのパスを読むものはもうない。
- 受け入れる残余: 以上の保証は既定の state ルートでのものである。操作者が state ルートをプロジェクトの中、一時ルート（`/private/tmp`、`$TMPDIR`）、`/private/var/tmp` の下に置くと、このディレクトリかその祖先にレーンやファイルツールの手が届く。read レーンは書ける祖先をリネームして名指しの拒否の下からずらせ、他のセッションのレーンも書ける。プロジェクトが state ルートを含む場合（広いルートの確認を経たホームディレクトリなど）は、ファイルツールについて同じことが起きる。これは、そのようなルートの下の作業ディレクトリやトランスクリプトと同じ既存のクラスである。
- 受け入れる残余: 列挙するのは `work/` だけなので、作業ディレクトリを手で消したキャッシュは操作者が消すことになり、`gem-agent workdirs` には出ない。

## Alternatives considered

- **作業ディレクトリ内の scratch の隣**（監査の案）— 不採用: ファイルツールが Safe で書ける（Context を参照）。
- **一時ディレクトリの中の、プロセスごとのディレクトリ** — 最初の実装。独立レビューが実際のプロファイルで測り、不採用にした。`TMPDIR` が `/private/var/tmp` の下にあると、read レーンは祖先をリネームしてエントリを仕込め、並行するプロセスのルートにも書けた（拒否が名指すのは自分のルートだけ）。既定の `TMPDIR` では、どのセッションの write レーンも他のセッションの使用中のキャッシュに書けて、セッションをまたぐ辺が新たにできた。正常に終了しなかったプロセスは数百 MB を残し、それを引き取るものがなかった。
- **規則層でパスを保護扱いにする** — 不採用: ディレクトリの意味を表す一覧がもう 1 つ増えるうえ、シェルの経路はどのみちカーネルのプロファイルに任せることになる。どのルートの外にも置けば、規則は要らない。
- **`GODEBUG=gocacheverify=1`** — 不採用: Go 専用だが、表はどのツールチェーンの行も持てる。
