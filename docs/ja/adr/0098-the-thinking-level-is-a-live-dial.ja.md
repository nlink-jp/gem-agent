# ADR-0098: 思考レベルはセッション中に回せるダイヤルにする

| 項目 | 内容 |
|-------|-------|
| ステータス | **採択**（2026-10-23） |
| 日付 | 2026-10-23 |
| 拘束対象 | gem-agent |
| 決定者 | nlink-jp maintainers |
| 契機 | 運用者: セッション中に思考レベルを切り替えたい |
| 修正する ADR | ADR-0025 §3（/settings では読み取り専用・ライブ編集は保留） |
| 関連 | ADR-0082（モデル層の専用枠）、ADR-0083（司書の専用枠）、ADR-0009（設定パネル）、ADR-0005（再開） |

## 背景

ADR-0025 は `[model].thinking` を起動時の設定とし、ライブ編集を保留した。
理由は「めったに変えない設定のために、共有の Vertex クライアントへ初めての
可変フィールドを足すことになる」だった。`--thinking`（2026-08-21）で実行
ごとに選べるようになったが、変えるにはまだセッションを終える必要がある。
そして変えたくなる理由はセッションの中で生じる — 長いリファクタの後の軽い
調べもの、日常作業の途中の難しい質問。再起動するとライブの状態（スクロール
バック、セッション中の承認、`/auto`、読み取り専用の上限）を失う。`--resume`
が戻すのは会話だけである。

レベルはリクエストごとのフィールド（`GenerateContentConfig.ThinkingConfig`）
であって、クライアントや会話の性質ではないので、作り直すものは無い。壊し得る
前提は 1 つだけ、思考署名の再送（ADR-0009）である: あるレベルで作られた前の
ラウンドが、別のレベルの下で署名ごと送り返される。**決める前に実測した**
（`internal/llm/levelswitch_live_test.go`、運用者が設定しているモデル）:
`high` で行ったツール呼び出しを、その署名ごと `low` で再送 — 受理。その会話を
`high` とモデル既定で再送 — 受理。`minimal` はレベルを名指しする 400 で拒否
された。ADR-0025 §4 が別のモデルで記録したのと同じで、対応はモデルごとで
あり、切り替えごとではない。

## 決定

1. **`/thinking [minimal|low|medium|high|default]`。** 引数なしでは、効いて
   いるレベルとその出所を示す。レベルを付けると設定する。`default` はモデル
   自身の既定に戻す — 同じことに `--thinking` が既に使っている語である。それ
   以外（余分な語を含む）は使い方のエラーで、何も変えない（`/auto` と
   `/readonly` の文法）。TUI とプレーン REPL の両方で受け付ける。
2. **/settings の `model.thinking` 行を編集可能にする**。`default, minimal,
   low, medium, high` を巡回する。行とコマンドは同じ値を変える。行の出所は、
   値がセッション開始時と異なる間 `session` と読む。
3. **セッション限り。** どのファイルにも書かない。新しいプロセスは config と
   フラグから始め直し、`--resume` は会話を設定済みのレベルで戻す — `/auto` と
   同じ足場である。`/clear` はレベルを保つ: 始めるのは新しい会話であって、
   新しいプロセスではない。
4. **次のモデルリクエストから効く。** レベルはリクエストを組み立てるときに
   1 回だけ読み、リクエストとその 400 のヒントはその 1 回の読みを使う。運用者
   はターンの途中では変えられない — TUI はターン実行中のスラッシュコマンドを
   拒否し、/settings はプロンプトでしか開かない — が、Ctrl+C の後もまだ走って
   いるツールはリクエストの途中であり得て、そのリクエストは送ったときの
   レベルのままである。
5. **効く範囲は、メインのバックエンドそのものを持つすべての呼び出し**であり、
   今日すでに `[model].thinking` で走っている経路である:
   - 会話、圧縮、`agentic_file_search` の子。
   - 自前の枠を持たない間のモデル層（リスク評価、進捗レビュー、読み取り専用の
     見張り）と司書 — /settings の「(follows …)」表示が既に言っているとおり。
   - `[model].summary` が未設定のときの `summarize_file` と `/riskbook learn`。
     このときはメインのバックエンドに乗る。

   名前のある枠（`[model].risk`、`risk_thinking`、`librarian`、
   `librarian_thinking`）と名前のある要約モデルには届かず、自分のレベルを
   保つ（ADR-0025 §2、ADR-0082 §3）: `WithModel` と `WithThinking` は、写しに
   共有ではなく自前のダイヤルを持たせる。グラウンディング検索と URL 取得は
   思考の設定を送らないので影響しない。（ADR-0025 §2 の「要約モデルは自身の
   既定のまま」は、名前のある要約モデルにだけ成り立つ。これは以前からそうだった。）
6. **値は 1 つ、メインのバックエンドが持ち、どのゴルーチンから読み書きしても
   安全。** パネル、`/thinking`、`agent_info`、すべてのリクエストがそこを読む
   ので、ずれる第 2 の写しは無い。副呼び出しは UI と並行して走るので、値は
   アトミックにする。`cfg` は起動時の値を保ち、出所の列はそれと比べる。
7. **`/thinking` で設定した後の 400 のヒントは `/thinking` を名指しする。**
   未対応のレベルは引き続き API が決める（ADR-0025 §4）: 次のリクエストが
   レベルと戻り方を名指しして目に見える形で失敗し、運用者は再起動なしに次の
   `/thinking` で直せる。

## 採らないもの

- **変更ごとの transcript 記録。** `mode_change` 記録は承認モードと読み取り
  専用の上限 — ゲートが何をしたか、なぜか — のためにある。思考レベルは費用の
  ダイヤルで、その効果は費用が記録される場所に既に残る: 各 usage 記録が
  そのラウンドの思考トークンを持つ。
- **選んだ値を config に書き戻す。** ひとまとまりの作業のために回した
  ダイヤルが、黙って以後すべてのセッションの既定になってしまう。ファイルは
  運用者が手で書いた既定の表明であり続ける。
- **受け付ける前にレベルをモデルに照らして検証する。** 対応レベルを示す
  メタデータの項目は無く、確かめるためのリクエストは、次の本物のリクエストが
  無料で答える問いに、切り替えのたびにお金を払うことになる。
- **モデルのライブ切り替え（`/model`）。** 範囲が違う: コンテキストウィンドウ、
  使用量の単価、再送する署名はすべてモデルに依存するが、ここでは何も依存しない。
- **フッターにレベルを表示する。** `/thinking` と /settings が尋ねられたとき
  に答える。費用のダイヤルは、承認モードのように常に画面に出ている必要は無い。

## 結果

- Vertex バックエンドに初めての可変フィールドができる（ADR-0025 §3 の懸念）:
  アトミックな値 1 つで、枠ごとに共有ではなく写す。
- 運用者はセッションを失わずに、軽い作業ではレベルを下げ、難しい作業では
  上げられる。
