## 背景

### 何が起きたか

read レーンが読んだ 2 ファイルは、設計上資格情報を持つ。
`~/.config/mcp-bridge/config.json` は事前登録 OAuth クライアントの資格情報を
保持するために存在し、`~/.config/gem-agent/mcp.json` は各サーバーのコマンドと
`env` を持ち、慣習上 API キーはそこに置かれる。どちらも資格情報一覧
（ADR-0073 §3、ディレクトリ 12・ファイル 9）に無い。操作者の機体でファイル名
のみを数えると、`~/.config` にはツールのディレクトリが 52 あり、その
`config.toml` / `config.json` のうち 13 本がちょうど `token`・`api_key`・`secret`
という名前のキーを持つ（緩い照合では 16 本）。

### 初稿と、そのレビューが見つけたもの

初稿は ADR-0073 の規則 — インスタンスでなくクラスを閉じる — を適用し、
設定ホーム全体（`~/.config`・`$XDG_CONFIG_HOME`）を read/write レーンで
`file-read*` 拒否とし、有限の再許可（skills ディレクトリ・git の設定・
ビルドツール向けの操作者キー）を添えた。その草案に対するコードと Seatbelt
のレビュー（独立検証者、全プローブに対照実行つき）は、1 パスで次を見つけた:

- skills の再許可は解決後の実パスに書かねばならない。Seatbelt は symlink
  解決後のパスで照合し、リンクのパスに書いた allow も deny も何もしない（実測）
- 名前ベースの拒否（`.env`・`id_rsa`・`credentials.json`）は subpath 再許可の
  たびに再度出さねばならない。さもなければ再許可した skills ツリー内の `.env`
  が読める（実測）
- git のディレクトリは丸ごと再許可できない。`~/.config/git/credentials` は
  git が文書化する平文トークンファイル
- ランタイムは `$XDG_CONFIG_HOME` をどこでも読まない。檻だけがプログラムの
  他の部分にない「設定ホーム」の観念を持つことになる
- 起動プローブが 2 つ増え、うち 1 つは `~/.config` に書き込む
- 操作者キーは、設定をそこに置く全ての読取専用ツールの動作を担うことになり、
  機体のツールと共に増える

1 つの deny が、再許可規則 4 つ・規則の順序に関する規則 2 つ・操作者が
維持する一覧 1 つ・プローブ 2 つを生んだ。これは ADR-0073 が終わらせる
ために書かれた形そのもの — 次の項目を求め続ける設計 — であり、今回は
資格情報一覧の代わりにその補集合を求めていた。

### なぜカーネルにはこの線が引けないか

ADR-0073 が read レーンをカーネルに委ねられたのは、読取専用コマンドに
ネットワークソケット・Mach ポート・設定書込の正当な用途がないからだ。
ケイパビリティ族の拒否はコストゼロで、族は有限かつ文書化されている。
設定ホームは種類が違う。秘密と通常の設定が同居し、read レーンの存在理由
であるツールがそこの設定を読む — git は `config` と `ignore`、`fd` は
ignore ファイル、`tshark` は preferences。`~/.config/x` への `file-read*`
が、トークンを取りに行くモデルなのか起動中の git なのかは syscall には
無く、コマンドにある。したがってディレクトリに対するカーネル規則は正当な
読み手を列挙せざるを得ず、その集合は ADR-0073 の拒否族が空だったのと
対照的に無限である。

### symlink

レビューは ADR-0011 §3 が Claude Code との skill 共有に勧める機構 —
`ln -s ~/.claude/skills ~/.config/gem-agent/skills` — も実測した。
`~/.claude` は ADR-0073 以来資格情報一覧にあり（skills の隣に Claude Code
のトークンを持つ）、Seatbelt は解決後のパスで照合する。リンクした skill は
探索され本文も読み込まれる（ランタイムは檻の外で読む）が、そのスクリプトは
read/write レーンで `Operation not permitted` で失敗する。v0.69.0 以来そう
なっていた。

## 決定

### 1. 設定ホームは拒否しない

資格情報一覧は ADR-0073 §3 が定めたままにする: よく知られた資格情報の
置き場と秘密のファイル名の一覧 1 つを、プロファイル・file ツール・リスク床が
読む。`~/.config` は加えず、事象の 2 ファイルも加えない。ツールの設定
ディレクトリに置かれた平文トークンは read/write レーンで読める。承認
リファレンスは既にそう述べており、その境界にこの例を添える。

### 2. 挙動はその契機で扱う

セッションで起きたのは、サーバーが誤動作したときにモデルがランタイムを
調査したことだ。欠けていた契機は ADR-0075 が供給する — ランタイムが
サーバーの同一応答の反復を名指しし、モデルに報告を求める。途中で読んだ
ファイルは症状である。

### 3. skill はリンクせずコピーする（ADR-0011 §3 撤回）

Claude Code 向けにインストール済みの skill はグローバルディレクトリへ
コピーする:

```sh
cp -R ~/.claude/skills/<name> ~/.config/gem-agent/skills/<name>
```

`/skills` の空状態はこのコマンドを 2 行の `ln -s` の代わりに表示し、
統合リファレンスも同じことを言う。探索は従来どおり symlink を辿る —
レーンが読めるディレクトリへのリンクはこれまでどおり動く — が、ランタイムは
`~/.claude` へのリンクを勧めない。ADR-0011 が棄却した代替案「copy-on-install
ツーリング」は棄却のまま: コピーコマンド 1 行はツーリングではなく、Claude
Code 側と分岐するコピーは ADR-0011 が望んだとおり操作者の選択である。

## 採らなかったもの — 次の読者のための記録

- **カーネルで `~/.config` を拒否** — 上記の初稿。
- **read レーンだけで拒否** — 巻き添えは半分になる（ビルドツールは write
  レーンで走る）が、再許可規則 3 つと symlink 解決は残り、設定を読む
  読取専用ツールはすべて write レーンとその確認に落ちる。無確認の read
  レーンの存在意義を削る。
- **`~/.config` 配下のパスを名指しするコマンドの Block 床** — 安価で
  巻き添えがなく（ツールはコマンドラインにそのパスを書かない）、セッション
  の 2 コマンド — どちらも `~/.config/…` を字面で名指しした — を捕えていた。
  本 ADR では採らない: 文字列規則は檻ではなく床（ADR-0073 §2）であり、
  契機の修正（ADR-0075）を先に測る。**論点:** いま足すか、ADR-0075 出荷後に
  調査パターンが再発したときに足すか。
- **ランタイム自身の配線ファイルを literal で追加**（`mcp.json`・mcp-bridge
  の `config.json`）— フリートのものと違い、構成上閉じた集合。床と同じ理由で
  本 ADR では採らない。**論点:** 同上。

## 帰結

- `cmd/skills.go`: 空状態の文言はコピーコマンドを表示。`internal/skills`・
  `internal/trustpin` のコメントは symlink を共有機構として記述しない。
  探索は不変。
- ドキュメント: 統合リファレンス（skills 節）、承認リファレンス（資格情報
  一覧の段落に設定ホームの例）、ADR-0011 の *修正* 行、AGENTS.md の gotcha、
  CHANGELOG。
- `~/.claude/skills` をリンクしていた操作者はリンクをコピーに置き換える。
  それまでリンクした skill のスクリプトは read/write レーンで失敗し続け、
  拒否に既に添えられるレーン注記が付く。
