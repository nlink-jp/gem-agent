# ADR-0022: セッションのプロジェクト別配置と state dir override

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「フラットに置くよりも、メモリの配置のようにプロジェクトごとにサブディレクトリを作るとよいかも」 |

## Context

セッション transcript は `~/.local/state/gem-agent/sessions/` にフラットに
置かれ、全プロジェクトのファイルが同居し、所属プロジェクトは各ファイルの
ヘッダの中にしか記録されていなかった。代償は 3 つで、うち 1 つはたった今
血で支払った: テストセッションを狙った掃除の glob がオペレータの実
transcript にも一致した（id は全て日付始まり — フラットな共有ディレクトリは
glob に選別能力を与えない）。`--continue` と一覧は全プロジェクトの全ファイルを
開いてヘッダで選別する。resume が強制するプロジェクト束縛はファイルシステム
上からは見えない。メモリ（ADR-0020）は `projects/<エスケープ済パス>/` で
この 3 つに既に答えている。

## Decision

1. **新規セッションは
   `~/.local/state/gem-agent/sessions/projects/<エスケープ済パス>/` に置く。**
   エスケープ（`/`→`-`、非可逆）と `.project` マーカーはメモリと同一の
   規約（不一致 = エスケープ衝突。そのディレクトリは注記付きスキップ、
   誤帰属はしない）。テストプロジェクトのセッション掃除は「そのプロジェクト
   自身のディレクトリの中」の操作になり、一覧は 1 ディレクトリを読むだけに
   なり、束縛は目に見える。
2. **エスケープとマーカーの実装は共有パッケージ（`internal/statedir`）へ
   抽出**し、メモリとセッションの両方が使う — 規約 1 つ、実装 1 つ、
   テスト 1 組。リファクタ前後でメモリのパスはバイト同一。
3. **旧フラットファイルはその場で読み取り継続、永久に。** 一覧はプロジェクト
   サブディレクトリとヘッダ選別した旧フラットをマージし、resume はどちらの
   場所でも見つけてその場所に追記する。何も動かさない — 削除事故の数時間後に、
   オペレータが自動移行・コマンド移行より「ファイル移動ゼロ」を選んだ。
   旧セッションは自然に古びていく。
4. **`GEMAGENT_STATE_DIR` が state ルート**（`sessions/` と `memory/` の親）
   **を差し替える。** 主目的はテストと訓練を実 state から隔離すること —
   事故の構造的対策そのもの（実 transcript が見えない E2E はそれを消せない）。
   GEMAGENT_* env 規約に従う。config キーにはしない（config での state
   移設は永続パス drift 問題を招くし、テストはどのみち env が要る）。

## Consequences

- 掃除・一覧・束縛が「ヘッダ選別の慣習」から「プロジェクト別の構造的事実」
  になる。
- `session.Open/Reopen/Find` が projectDir を取る。ヘッダの Project は
  多層防御と旧ファイルのために残る。
- 別プロジェクトの 2 セッションが同じ id を持ち得るが、resume は現
  プロジェクト（+ 旧フラット）内で解決するので見えない。
- E2E は `GEMAGENT_STATE_DIR` を scratch に向けて走る。訓練 runbook も同様に
  できる。

## Alternatives considered

- **起動時自動移行（rename）**と**明示移行コマンド** — 提示の上、オペレータが
  読み取り継続を選択（§3）。
- **state ルートの config キー** — 却下。env のみ（§4）。
