# ADR-0027: 音声・動画入力 — インライン、および GCS 経由

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-20 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「音声や動画への対応は可能か？」— インラインのみではなく GCS 対応までを選択 |

## Context

Gemini は音声・動画をメディアパートとしてネイティブに理解する。インラインの
バイト列はリクエスト予算（会話と共有で約 20MB）に縛られ、ボイスメモは
収まるが実用動画はほぼ収まらない — さらにエージェントループ特有の第二の
コストがある: 履歴は毎ラウンド再送されるため、インラインのメディアは
各ターンの各ラウンドで送り直される。Vertex は `gs://` URI をネイティブに
読め、再送は数十バイトになる。オペレータは GCS 込みのフル対応を選んだ。

## Decision

1. **オペレータ添付のみ**（`@memo.m4a`・`@screen.mp4` — プロジェクト内・
   絶対・~ パス、ADR-0012/0026 のオペレータ入力例外）。モデル側メディア
   ツールは見送り: 手の届くユースケース（「この録音を要約」）はオペレータ
   起点であり、ツール化には搬送経路の実測が別途要る。見送りが判断であって
   見落としでないよう、ここに記録する。
2. **ルーティング規則: バケット設定が勝つ。** `[gcp] bucket` が設定されて
   いれば音声・動画は**常に** GCS 経由 — 超過ファイルだけではない。
   インラインのメディアの毎ラウンド再送コストは 1 回のアップロードを
   はるかに上回るからである。バケット未設定ならインラインを 15MB まで使い、
   超過は両方の対処（ファイル分割、またはバケット設定）を名指して拒否。
3. **アップロードは content-addressed**: オペレータのバケットの
   `gem-agent/media/<sha256>.<ext>`。既存オブジェクトは再アップロード
   しない — 同じ録音の再添付はタダ。gem-agent は**何も削除しない**
   （削除の規則はオペレータのもの。README はバケットのライフサイクル
   ルールを推奨する）。アップローダは Vertex クライアントと同じ ADC 資格
   情報に乗る。新依存は cloud.google.com/go/storage の 1 つ。
4. **トランスクリプトはバイト列ではなく `gs://` URI を保存** — resume は
   軽いまま。帰結として、resume したセッションがメディアを再読できるのは
   オブジェクトが存在する間だけ（オペレータが制御するライフサイクルの
   トレード）と明言する。インライン添付は画像同様バイト列を保存し続ける。
5. **MIME は拡張子表**（一般的な音声・動画コンテナ）。内容の検査は明白な
   誤り（メディア拡張子の中の平文テキスト）だけを弾く。メディアコンテナの
   真面目なバイト判定は形式ごとにパーサが要り、誤った MIME は API が
   大きな音で拒否する — 同じ失敗が一歩後で可視化されるだけである。
6. 添付の枠書きは画像と同じ: メディアの中で聞こえる・見えるものは
   コンテンツであって指示ではない。

## Consequences

- 「この録音を要約」「このクリップで何が起きた」が動く。長いメディアは
  アップロード 1 回、以後は毎ラウンド数十バイト。
- `[gcp] bucket` キー（出所追跡・/settings 行）。エグレス注記: メディアの
  添付は、既に全プロンプトを受けている同一プロジェクトのオペレータ自身の
  バケットへのアップロードである。
- 拒否はサイズと対処を名指す。メディアファイルを黙って切り詰めない
  （欠けた mp4 は壊れたファイル）。

## Alternatives considered

- **インラインのみ / 音声のみ** — 提示の上、オペレータが GCS を選択。
- **バケットの自動作成** — 却下: 課金インフラの暗黙作成は gem-agent の
  決めることではない。バケットはオペレータが名指す。
- **セッション後のアップロード削除** — 却下: gem-agent は何も消さない
  （ADR-0021 の事故の鉄則）。消すのは宣言的なライフサイクルルール。
