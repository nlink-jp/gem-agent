# ADR-0117: モデル呼び出し 1 回はリクエスト 1 回 — SDK の自動継続は切る

| Relates to | ADR-0057（モデル呼び出しごとの usage レコード）、ADR-0116（再試行を記録する）、ADR-0006（圧縮はプロンプトの大きさで発火する）、ADR-0100（接続のヘルスチェックはこのランタイムのもの） |

## Context

gem-agent は `google.golang.org/genai` v1.71.0 を使っていた。現行は v1.77.0 である。
移行で変わるのは `go.mod` の 1 行で、コードはそのままコンパイルでき、テスト一式も
そのまま通る。

その間の v1.74.0 で、`GenerateContent` と `GenerateContentStream` に**自動継続**が
入った。リクエストが切らない限り有効である。応答が継続トークンつきで終わると —
終了理由が `CONTINUATION` のとき、またはチェックポイントのトークンの後で
ストリームが切れたとき — SDK は同じリクエストをトークンつきで必要な回数だけ送り直し、
呼び出し側には 1 本のストリームとして渡す。そこから何が起きるかは SDK 自身の文書が
述べている。タイムアウト・再試行・課金はリクエストごとに掛かり、報告される usage は
それらの合算になる。

エンドポイントがいつ継続を持ちかけるかは、プロバイダーのガイドにある。1 回の応答が
運べる量（ストリームで 65,536 トークン、それ以外で 32,768 トークン）を超える出力を
リクエストが求めたとき、そしてストリームでは出力 32,768 トークン以降の
チェックポイントである。gem-agent は出力の上限を指定しておらず、操作者の記録に残る
最長の応答は 2 万トークン未満なので、既定のままでも今日は何も変わらない。変わるのは
最初の長い応答のときで、それは黙って起きる。

このランタイムには、呼び出しがリクエスト 1 回であることを前提にしたものが 3 つある。

- **usage レコード**（ADR-0057）は呼び出しごとに 1 件で、そのプロンプト数は会話の
  大きさとして読まれる。文脈の表示がそれを出し、圧縮がそれで発火する（ADR-0006）。
  複数のリクエストを合算した数は、そのどちらでもない。プロバイダーのガイドは、
  ハーネスの作者にまさにこの点を警告している。
- **再試行のレコード**（ADR-0116）は、送り直したリクエストを書き残すためにある。
  SDK の中での送り直しは、このランタイムからは見えない。
- **再試行の方針**は、出力を少しでも消費した後は再試行しない。2 回目の試行が出力を
  重複させるからである。SDK の継続は、既に出力を届けたストリームを再開する。

## Decision

1. **SDK を v1.77.0 に更新する。** プロバイダー自身のモジュール（サプライチェーンの
   規則でいう一次のもの）であり、古い版に留まって得るものは無い。
2. **すべてのリクエストで自動継続を切る**（`AutomaticContinuation: false`）。
   モデル呼び出しはリクエストちょうど 1 回のままになる。継続つきで終わった応答は、
   それ自身の終了理由と usage を持ったまま返り、ターンのループは `STOP` で終わら
   なかったほかの応答と同じに扱う。
3. **テストで固定する。** 継続を持ちかけるローカルのエンドポイントに対して、
   呼び出しはリクエストを 1 回だけ送る。対照として、SDK の既定では 2 回送ることも
   確かめるので、SDK が変わったときにテストが黙ることはない。ソースの検査が、
   このパッケージのすべてのリクエスト設定にこの指定を求める。
4. **1 回の応答に収まらない長い応答には、これまでどおり対応しない。** 必要になった
   ときは、継続はこのランタイム自身のループに置き、リクエストごとの usage レコードと
   送り直しごとの記録を持たせる — それは別の判断である。

## Consequences

- このリリースで目に見える変化は無い。SDK は新しくなり、挙動を変えるはずだった
  新しい既定は 1 つだけで、それは採らない。
- 会計の約束（usage レコード 1 件にリクエスト 1 回）と、再試行のレコードの約束
  （送り直しはすべて書かれる）は、応答の長さに依らずに成り立ち続ける。
- 継続が必要になる応答は、最初の応答が終わるところで終わる。v1.71.0 でも同じ
  だった。
- プロバイダーの文書が最新のモデルについて述べている 2 つのもの — 会話の過去の
  ターンを編集したときの扱いを決める設定と、あるモデルの最も高い思考レベル — は、
  この版の SDK には無く、SDK を更新しても使えるようにはならない。

## Alternatives considered

- **既定のままにする。** 採らない。理由は Context の 3 点で、最初の長い応答までは
  動き、そこで数え違え、跡を残さずに送り直す。
- **v1.71.0 に留まる。** 採らない。差は開く一方で、次に更新するときには同じ既定が、
  もっと多くの変更と一緒に来る。
- **継続を、記録つきで今採り入れる。** 採らない。記録に残るどのセッションも
  必要としておらず、これは依存の更新ではなく、会計上の問いを伴う 1 つの機能である。
