# ADR-0030: モデル向け read-only 自己情報ツール

| 項目 | 値 |
|------|----|
| ステータス | **承認済み** |
| 日付 | 2026-08-21 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレーター: システム情報やセッション情報（モデル名・トークン消費状況など）をモデルが把握できる内蔵ツールがあってもよいのでは |

## 文脈

オペレーターはランタイムをどこでも見られる — フッター、`/usage`、
`/settings`。だがモデルは何も見えない。「あなたはどのモデル？」と
聞かれれば推測する（モデルは自分のデプロイ名を確実には知らないし、
このエージェントは config でモデルを差し替える）。残りコンテキスト
を見込んだ作業計画を頼まれても、フッターが表示している占有率を見る
術がない。ホストについて聞かれれば、`uname` が印字する程度のことに
`shell_exec` の承認ラウンドを消費する。モデルに必要なものはすべて
プロセス内に既にある — 手渡すツールがないだけである。

## 決定

### 1. read-only ツール 1 本: `agent_info`

引数なしのツール 1 本が、エージェント自身のランタイムを報告する:
バージョン、プラットフォーム（OS/arch/CPU 数/macOS 版数）、メイン・
要約モデル、思考レベル、コンテキストウィンドウ占有、累積トークン
使用量、制限（max turns・shell timeout）、承認/サンドボックス状態、
プロジェクトディレクトリ、セッション id、接続中 MCP サーバー、
スキル数、メモリと media バケットの有無。system/session の 2 本に
分けない: 想定されるどの呼び出しも同じ 1 ページを求めるし、
レジストリは小さいままにする。

`Mutating: false` — `file_info` と同じく承認なしの read-only 段で
動く。オペレーター自身の画面が既に表示していないものは何も開示
しない。

### 2. 数字は `/usage` の数字

ツールは `/usage` が読むのと同じ `agent.UsageStats` を描画する —
集計元は 1 つ、ビューが 2 つ。合計は完了済みラウンドを反映するので、
ターン途中の呼び出しは直前ラウンド時点の状態を報告する。それが
集計の持つ最新の真実である。

### 3. 意図的に出さないもの

- **GCP プロジェクト id とバケット名** — モデルの挙動に影響しない
  環境識別子。バケットは `configured`/`none` のみ（大きなメディアを
  添付できるか否かは挙動に影響する）。
- **ホスト名 / ユーザー名** — 同じ理由。transcript は移動するもの。

除外が従う規則: フィールドは「取得できるから」ではなく「モデルの
行動を変えるから」載る資格を得る。

### 4. 出力は英語

ツール結果はモデル向けテキスト — まさに ADR-0029 §3 が言語カタログ
の対象外とした面である。

## 帰結

- 「あなたはどのモデル？」「コンテキストの残りは？」「このプラット
  フォームは？」が、推測や承認ラウンドではなく安価なツール呼び出し
  1 回になる。
- スナップショットは `cmd`（config・agent・tally・session・MCP の
  状態を同時に見られる唯一の層）でプロバイダクロージャとして組み、
  描画は純関数としてテストする。
- 将来のフィールド追加は §3 の規則を通過してから。
