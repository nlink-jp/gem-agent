# ADR-0111: `!` コマンドの出力はデータである

## Context

`!` コマンドの出力は、「I ran this shell command myself:」で始まる 1 つのユーザーメッセージとして履歴に入っていた。送信時の包みはツールの結果と添付を対象とするので、プログラムの出力が印なしで、操作者の声で、以後のラウンドと再開の後もモデルに届く唯一の場所になっていた。このプロジェクトの規則は、信頼できないデータを包むことである。

これは ADR-0110 の場合とは違う。あちらは操作者が入力の流れを組み立て、仕様がそれを操作者の入力と定めている。こちらで操作者が頼んでいるのはプログラムの出力を見ることで、出力された文を操作者の言葉とするとは誰も決めていない。

## Decision

コマンドは操作者の声のテキストのままとする。出力は同じメッセージのテキスト添付（`kind "shell output"`、`ref "!"`）にし、包み、トランスクリプト、再開、圧縮は添付の経路をそのまま使う。承認ゲートとリスク評価器は変えない。評価器が読むのはターンの入力だけである。

## Consequences

- `!git status` の後に「それを直して」と続ける使い方はそのまま動く。モデルは包みを通して出力を読む。
- セッションの一覧には引き続きコマンドが出る。メッセージは接頭辞と `$ ` の行を保つ。
- これ以前に記録されたセッションは、再開しても古いメッセージのまま（包まれない）である。
- 圧縮は添付をユーザーの行より小さい枠で要約するので、長い出力が要約に残る量はこれまでより少ない。

## Alternatives considered

- **操作者自身の行為としてそのままにする** — 操作者が不採用とした: コマンドを実行することは、その出力を保証することではない。
- **メッセージ全体を包む** — 不採用: コマンドは操作者の言葉であり、従わないテキストとして印を付けることになる。
