# ADR-0054: リスク評価器は全ラウンドでオペレータ指示を見る

| 項目 | 内容 |
|-------|-------|
| ステータス | **承認済み** — [ADR-0038](0038-risk-eval-instruction-context.ja.md) §3 を修正（ラウンドカットオフを撤廃） |
| 日付 | 2026-08-29 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | 利用者: ヘッドレスパイプラインの終端送信が指示の見えない状態で評価されていた。拒否自体は正しい（egress ルーブリック）が、「`< 3` は現実に合っているのか」は再検討に値した |

## 背景

ADR-0038 は auto-approve のモデル層に、オペレータがタイプした依頼を
整合性の証拠として渡した — ただし**ターンの先頭 3 ラウンドのみ**。
カットオフは当時の利用者指示で、直感で置かれ、数字に実測の裏付けは
なかった: ターン深部のコールは依頼が名指ししないサブゴールに仕える
はずで、判定者に「間接的関連の許容」を促すのは難問への soft
engineering に見えた。

state ディレクトリの全実トランスクリプトで実測した
（55 ファイル・モデル評価 171 件・35 ターン、2026-08-18 → 08-29）:

- **モデル層評価の 70% はウィンドウ外で起きている**（119/171）。
  round 8–48 だけで 49%。ウィンドウは、知らせるために設計された
  判定の少数派しか覆っていない。
- **63% のターンは*最後の*ゲート対象コールをウィンドウ外に置く**
  （22/35）— 終端アクション、つまり整合が最も重要なコールほど、
  指示の見えない側で評価されている。
- **ウィンドウ外エスカレーション 26 件は全件ネットワーク系**
  （web_fetch ×19・読み取り専用 lookup MCP ×5・web_search・Slack
  送信 1）。gate 記録が存在する範囲（v0.46 以降）ではオペレータが
  事後に 3/3 を手承認 — ADR-0048 §1 は同じ形を大規模に記録している
  （25 回エスカレート・全部承認）。ウィンドウ外エスカレーションは
  実態として、読み取り専用の調査コールへの誤警報である。
- **指示が見えていてもネットワーク系は確実には救われない**:
  whois-lookup は指示が目の前にあって承認 2 / エスカレート 7、
  doh-lookup は 1 / 4。ルーブリックの「reach the network」行が
  支配し、判定は揺れる。従って本修正が直すのは*届く範囲*であり、
  lookup 摩擦ではない — そちらは ADR-0008 の常設 `"never"` か
  ADR-0050 のルールブックの領分で、ADR-0053 の egress 姿勢も不変。

ADR-0038 §1 が拠って立つ構造的事実にラウンド依存はない:
**タイプされた入力は、注入攻撃者が書けない唯一のコンテキスト
チャネル** — round 0 でも round 40 でも。round 20 で汚染ツール出力に
操られたコールは、指示が見えている方が矛盾が可視になり*検出しやすく*
なる。

## 決定

### 1. 指示は全モデル層評価に同乗する

`riskContextRounds` を撤廃する。ターンにタイプされた指示がある限り
（`Run` は空入力を拒否するので常にある）、リスク評価ペイロードは
従来どおりクリップ付きでそれを運ぶ。ADR-0038 の他の部分はすべて
不変: §1 の厳格なスコープ（タイプ入力のみ — 履歴・ツール結果・意図
の弁明・添付バイトは決して含めない）、§2 のノンスラップ内の証拠
フレーミング、2000 ルーンのクリップ、addendum の文面 — その末尾の
一文（「多段タスクでの間接的関連は正常で、それ自体はエスカレート
理由にならない」）が、カットオフの担っていた負荷を引き継ぐ。

### 2. フォールバックから均一性へ

ADR-0038 §3 はバイト同一のフォールバックを価値とした: コンテキスト
が適用されない場所に回帰なし。カットオフが消えた今、均一なのは
*コンテキストあり*の評価 — 1 ターンに 1 つのプロンプト形で、同じ
コールがラウンド番号で違って判定されることはなくなる。指示なしの
分岐はコード上ガードとして残るが、モードではない。

### 3. 意図的に変えないもの

- **egress ルーブリック行**: 送信は指示が見えていてもエスカレート
  する（ウィンドウ内実測: 承認 0/2）。egress を開くのは引き続き
  オペレータの明示的行為 — ADR-0008 ポリシーか `--allow`
  （ADR-0053）。
- Safe/Block 層・confidence 基準・全不確実経路の fail-closed。
- ラウンド上限レビュー（ADR-0040）のラウンドカウンタ利用は独立。

## 検討した代替案

- **定数の引き上げ**（5? 8?）— どの定数も実測の裾野と合わない:
  round 8–48 が量の半分を持つ。「現実に合う数字」はカットオフなし
  である。
- **単発モード限定**（`-p` はカットオフなし・対話は 3 のまま）—
  実測された摩擦（web_fetch 連鎖・lookup エスカレーション）は
  対話側だった。モード分割は測っていない側を直し、測った側を残す。
- **意味的ドリフト検出**（「まだ関連する」間だけ同梱）— 判定者が
  自分のコンテキスト適格性を判定するのは、ADR-0038 §3 が拒んだ
  soft engineering の二乗。

## 帰結

- 終端アクションとターン深部の調査コールが、整合性の証拠を見た
  上で評価される。矛盾検出の便益（ADR-0038 の実測ケース）が全
  ラウンドに適用される。
- 従来素で走っていたリスクコールにペイロード数百トークンの追加 —
  side call 会計のみ（ADR-0019）。
- 上記の lookup 摩擦の数字は、後続（ポリシーかルールブック）を
  別途判断するための基準線になる。
