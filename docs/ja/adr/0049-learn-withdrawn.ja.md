# ADR-0049: `/learn` を撤収する — 確認は緩和の恒久的な境界にならなかった

| 項目 | 値 |
|------|----|
| Status | **Accepted** |
| 日付 | 2026-08-26 |
| 適用対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレータ、v0.47.0 のフィールドテスト後: 「思った以上に許可されてしまうので、これは危険と判断しました。折角実装しましたが、`/learn` は一度、根本から検討し直したほうが良さそうです」 |

## Context

`/learn` は 2 回フィールドテストされ、正反対の向きに 2 回失敗した。
v0.46.0 では 25 回承認したセッションが提案ゼロを生み（原因は
ADR-0048 が診断した）、両方の修正を入れた v0.47.0 では「許可され
すぎる」がオペレータの評決だった。2 回の間に閾値は一度ずつ両方向へ
調整されている — **1 回の調整の両側で失敗する制御面は、較正を誤った
面ではなく、間違った面である**。

### なぜ許可しすぎたか

この設計の安全性を支えた論拠は ADR-0048 §3 —
「オペレータが覆うツールの全一覧を目の前にして 1 件ずつ確認する」—
だった。現場でその確認は、載せられた重みを支えられなかった。理由は
4 つあり、複合する:

1. **同意は 1 打鍵で、最悪の瞬間に差し出された。** 提案は物事を承認
   し続けたセッションの直後に届く — オペレータは yes と答え続ける
   構えのままであり、`1` は恒久的な許可を、`y` が単発コールを承認
   したのと同じ安さで受理する。ゲート自身の教訓（1 回の `a` が多数の
   判断の代わりになってはならない）は確認ステップ自体にも当てはまる
   のに、設計はそこに適用しなかった。
2. **束がリスク水準を混ぜていた。** サーバワイルドカードは読み取り
   専用の lookup と変更系ツールを 1 つの yes/no で覆う。開示は
   それらを列挙した — 正直に — が、束ねられた問いは束ねられた回答を
   招き、長いセッションの後に 8 個のツール説明を読み直す者はいない。
3. **一時的な証拠が、恒久で文脈のない付与を買った。** ある午後の
   調査中の 5 回の承認は**その調査についての**判断である。それが
   なったルールはグローバルで永続する。付与を証拠と同じ幅 — 時間に
   おいても範囲においても — に狭める仕組みは何もなかった。
4. **受理されたルールに管理面がなかった。** `/settings` は学習された
   コマンドルールをライブポリシーに合成していたが、一度も表示して
   いなかった。参照文書は逆を主張していた。同意の瞬間の後に不可視に
   なる恒久的許可は再考できず、構えたままの 1 打鍵が誰も見直さない
   ポリシーに変わる。この欠陥は修正ではなくここに記録する — 属する
   機能ごと撤収するからである。

より深い誤り: ADR-0008 の非対称は「緩和はオペレータの明示的行為で
なければならない」と言い、**そのコストは設計の一部だった**。ポリシー
行を手で書くことが熟慮であるのは、それが手作業だからである。
`/learn` はまさにその摩擦を取り除こうとして、成功した: 緩和を安く
した。オペレータはいま、その均衡を危険と判断した。機能は設計どおり
動き、設計が、コスト構造が支えていた境界を動かしてしまった。

## Decision

### 1. コマンドと提案エンジンを削除する

`/learn`・`internal/learn`・提案 UI のすべてを取り除く — 無効化では
なく削除であり、再設計のためのコードは git 履歴が保持する。
「存在するが牙を抜かれた」半死の機能は、文書と文字列と曖昧さを
残し続ける。

### 2. 記録は残す

`gate_decision` と `auto_decision` の記録 — 集計キーと `source` の
区別（ADR-0048 §1）— は引き続き書かれ、`Approver.Approve` の 2 値
返しも維持する。データは機能より長生きする: 将来のどんな設計も
まさにこの記録を必要とし、診断専用であり、コストはゼロである。
コマンド単位のポリシー語彙（`policy.CommandKey`・`ForCall`・
ポリシーファイルの `commands` テーブル）もコードに残す: 既存の
ポリシーファイルはパースされ続けなければならず、ゲート側の機構は
健全である — 失敗したのは付与のパイプラインであって語彙ではない。

### 3. 学習されたコマンドルールの適用を止める

`[projects."…".commands]` テーブルは `/learn` だけが書いたもので、
どの管理面からも不可視である。機能を再考している間それを黙って有効
なままにするのは最悪の状態なので、ポリシーに供給しない。起動時の
note が見つかったエントリ数と場所を報告し、オペレータは削除するか
将来の版のために残す。記録されたポリシーを無視することがここで
許されるのは、向きが締める側だからであり — 無視されたルールは常に
「より多く聞く」ことを意味する — かつ、それを確認した本人が結果を
危険と判断したオペレータだからである。

`/learn` が書いたグローバル `[tools]` エントリ（`mcp__<server>__*`）
は手書きの ADR-0008 ポリシーとバイト同一で区別できないため、有効な
まま残る。オペレータにはレビューを勧め、リリースノートに探すべき
行を明記する。

## 再設計への未決の問い

決定ではなく、問いとして記録する:

- **付与ではなく可観測性か？** 摩擦レポート — 何を繰り返し承認した
  か・モデル層がどこでブレるか — はリスクゼロで価値がある。後継は
  証拠を見せて止まり、ルールを書くことは手作業のままにできる:
  書くコストこそが熟慮である。
- **恒久ポリシーではなくセッション限定の緩和か？** 報告された摩擦は
  少数サーバの多数ツールを横断する調査チェーンだった。サーバ単位の
  セッション allowlist（終了まで有効な、サーバを覆う `a`）はまさに
  それを和らげ、何も永続させない。
- **付与が戻るなら: 列挙であってワイルドカードではない。** 証拠の
  あるツールだけを列挙するルールは未使用のものを何も覆わず、新しい
  ツールは自分のエントリを自分で稼ぐ。
- **そもそもまだ必要か。** ADR-0046 が既にモデル層のブレを根源で
  減らした。何かを作る前に、残っている摩擦を測る。

## Consequences

- `/learn` が解消しようとした摩擦は、後継が設計されるまで全量戻る。
  オペレータが危険と判断した緩和機構を撤収するための、受け入れた
  コストである。
- ADR-0045 と ADR-0048 は設計とそのフィールド失敗の記録として残り、
  INDEX の行に撤収を注記する。
- 恒久的許可を付与するあらゆるものへの教訓として記録する: 完全な
  開示付きの 1 件ずつの確認は、必要条件であって十分条件では
  **ない**。付与は証拠と同じ幅であるべきで、同意の瞬間の後も可視で
  あるべきで、それが退役させるリスクより安く受理できてはならない —
  そして正反対の方向へ 2 回調整された閾値は、つまみが違う機械に
  付いていると告げている。
