# ADR-0097: ランタイムが示す日付はセッションごとに 1 回だけ取り込み、再開したセッションは会話がいつ始まったかを言う

| 項目 | 内容 |
|-------|-------|
| ステータス | **採択**（2026-10-06）— 実装済み。同日、事実を言う位置を測って改訂した（§4） |
| 日付 | 2026-10-06 |
| 拘束対象 | gem-agent |
| 決定者 | nlink-jp maintainers |
| 契機 | ADR-0096 の運用者が、10/2 の本番セッションを 10/5 に再開して新しい作業を頼んだところ、4 回中 2 回、モデルが案件フォルダに元のセッションの日付を付けた（ADR-0096 §6.2） |
| 修正する ADR | ADR-0032 §2（システムプロンプトのセッション開始日） |
| 関連 | ADR-0084（プロンプトは事実を言う）、ADR-0005（再開）、ADR-0071 §2（`/clear` は新しいセッションを始める）、ADR-0018（安定した接頭辞） |

## 背景

モデルに日付を伝えるのは、システムプロンプトの 1 行だけである（ADR-0032 §2）:
`Session started: 2026-10-05 (Monday, JST)`。今の時刻については `datetime`
ツールを指す。コードと照合すると、この行には欠陥が 2 つある。

- **再開時に事実と違うことを言う。** この行はプロセスの起動時に計算されるので、
  10/5 に再開したセッションは 10/5 に「開始した」と言う。一方、モデルが読んで
  いる会話は 10/2 に始まり、10/2 の日付であふれている — フォルダ名、ツール結果の
  時刻。ランタイム自身の言葉が、モデルの前にある記録と食い違っており、運用者の
  4 回中 2 回で、モデルはその食い違いを会話の側に解決した。
- **1 回だけ取り込まれていない。** `composeSystem` は、skill の再読み込み、MCP の
  構成の変化、`/clear` のたびにプロンプトを作り直し、そのたびに `time.Now()` を
  呼び直す。日付をまたいだ後の再読み込みで、「セッション開始日」が翌日に動く。

日付を**どこで**言うかで振る舞いが変わるか — システムプロンプトではなく、作業の
近く、再開した地点の注記で言う — は、振る舞いについての別の主張であり、ADR-0096
が決める前に測った種類のものである。同じ日に測った（§4）。

## 決定

1. **日付はセッションごとに 1 回だけ取り込む。** セッションが始まるとき — 新規でも
   再開でもプロセスの起動時、そして `/clear` が新しいセッションを始めたとき — に
   取り込み、システムプロンプトの作り直しはすべてそれを使う。作り直しで日付は
   動かない。
2. **再開したセッションは、2 つの事実をどちらも正しく言う。** 行は
   `Resumed: 2026-10-05 (Monday, JST); the conversation above began on
   2026-10-02.` になる。再開日は「今日」ではなく再開日と呼ぶ。日付をまたいで
   続くセッションでは「今日」が事実でなくなり、続く `datetime` への案内が今の
   時刻を受け持つからである。元の日付は、トランスクリプトの最初の記録
   （セッション一覧の「started」）である。新規のセッションは `Session started:`
   のままで、`/clear` もそれに戻る。
3. **行はシステムプロンプトに置いたまま**にし、`datetime` への案内も変えない。
4. **同じ事実を再開地点でも言う。** 再開時、ランタイムは復元した履歴の後に自分の
   メッセージを足す: `gem-agent: this session was resumed on 2026-10-06 (Tuesday,
   JST); the conversation above began on 2026-09-04.` 他のメッセージと同じく
   トランスクリプトに記録されるので、後で再開したときは、以前の注記を履歴として
   読み、新しい注記を足す。

   *測定（2026-10-06）。* 実際の 2026-09-04 の調査セッション（128 メッセージ、約
   12.8 万トークン、会話の中に 2026-09-04 が 16 回出てくる）を隔離した HOME に
   複製し、2026-10-06 に再開して、追加で確認すべき点を 3 つ「日付つきのファイル名の
   メモに」保存するよう頼んだ — 運用者の事例と同じく、日付は指定しない。各ビルド
   5 回、`gemini-3.8-flash`、`thinking = "high"`:

   | ビルド | メモの日付が 2026-10-06 | `datetime` を呼んだ |
   |---|---|---|
   | v0.91.0（「Session started: 2026-10-06」） | 0/5 — 全回 2026-09-04 | 0/5 |
   | §1〜§3 のみ（事実どおりの行） | 0/5 — 全回 2026-09-04 | 0/5 |
   | §1〜§4（再開地点の注記を加える） | **5/5** | 4/5 |

   システムプロンプトの行を正しくしても、モデルはまったく動かなかった。同じ事実を
   再開地点に置くと、すべての回が動いた（下 2 行で Fisher p = 0.008）。日付の
   情報源が 2 つ食い違うとき、モデルは作業の近くにある方を採った。測定の費用は
   合計 $2.61。

システムプロンプトは、もともと再開のたびに作り直されていたので、接頭辞キャッシュ
（ADR-0018）が失うものは無い。

## 結果

- 再開時、モデルは会話と食い違わない 1 つの文を読む: 会話は 10/2 に始まり、10/5 に
  再開された。
- プロンプトの日付は、再読み込みで動かなくなる。
- 日付を付けた再開後の作業は、5 回中 5 回が今日の日付を使った（§4）。行だけでは、
  5 回中 5 回が会話の日付を使った。
- 再開したセッションの履歴には、再開ごとにランタイムの注記が 1 件残る。
- lagent はセッション事実のメッセージで同じ事実を言っており、再開時に同じ欠陥を
  持つ（元の行の隣に、今日の日付の「session started」がもう 1 行並ぶ）。lagent は
  これを自分の記録として移植する。

## 検討した代替案

- **再開時に「Today:」と書く。** 採らない: 日付をまたぐまでしか正しくない。
- **毎ターン日付を言い直す。** ADR-0018 の理由で採らない: システムプロンプトが
  毎リクエスト変わる。
- **システムプロンプトの行だけを直す。** 測定で 5 回中 0 回（§4）。行は、足りるから
  ではなく、事実だから残す。
