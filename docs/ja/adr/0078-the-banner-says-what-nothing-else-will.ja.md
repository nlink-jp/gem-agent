# ADR-0078: バナーは、他の何も言わないことだけを言う

| 項目 | 内容 |
|-------|-------|
| ステータス | **提案** |
| 日付 | 2026-09-08 |
| 拘束対象 | gem-agent |
| 決定者 | nlink-jp maintainers |
| 契機 | v0.72.0 のリリース前ラベル通読: 操作者が何も打つ前に折返し 28 行あり、うち 11 行がカンマ連結の一覧 1 本だと実測された |
| 修正する ADR | ADR-0002（インライン TUI の起動出力）、ADR-0039 §banner、ADR-0050 §banner line —— それぞれが 1 行ずつ足し、誰も建てると決めていない壁になった |
| 関連 | ADR-0077 §4（同じ論法を、まだ存在しない報告に向けたもの）、ADR-0029 §3（バナーのラベルは英語のまま —— 変更しない） |

## 背景

操作者自身の環境・MCP サーバー 24 個・80 桁での実測:

| 行 | 文字数 | 行数 |
|---|---|---|
| project trust 警告 | 106 | 2 |
| `gem-agent <version> — <model> @ <project>/<location>` | 82 | 2 |
| `project: <絶対パス>` | 120 | 2 |
| `sandbox: enabled (shell lanes: …)` | 73 | 1 |
| `session log: <絶対パス>` | 301 | 4 |
| `mcp: <全サーバーをカンマ連結>` | 809 | 11 |
| `skills: …` | 88 | 2 |
| `approval policy: …, … N rules total (/tools shows each tool's effective gate)` | 150 | 2 |
| `risk rulebook: base + project (/riskbook shows it)` | 40 | 1 |
| `/help for commands, Ctrl+D to quit` | 34 | 1 |
| **合計** | | **28** |

**28 行を出すと決めた者はいない。** バナーは起動中の stderr 書き込みを丸ごと
ティーして組み立てられており（`cmd/root.go`）、機能を足した ADR がそれぞれ 1 行
ずつ足してきた。著者のいない壁はこうして積み上がる。

そのうち 2 行は、**自分を置き換えるコマンドの名前で終わっている** ——
`(/tools shows each tool's effective gate)`、`(/riskbook shows it)`。「実際に見る
にはこっちを実行しろ」と自分で言う行は、自分が操作者の必要とした事実ではないと
認めている。

そして原則はすでにここに記録されている。ADR-0077 §4 は drift 報告をこのバナーに
足すことを拒んだ —— **報告は制御ではない。** 誰も問いを持っていない時点で印字
される行は状態表示であり、毎起動出る状態表示はどの起動でも読まれない。印字は
ランタイムに「開示した」という感覚を買い与えるだけで、操作者には何も買わない。
あの ADR が落としたのは、まだ存在しない 1 行だった。本 ADR は同じ論法を、既に
存在する 28 行に向ける。

## 決定

**起動時に席を得られるのは、他の何もそれを言わない行だけである。**

規則はこれだけである。帰結は 3 つあり、以下はその展開である —— 常時表示の
クロムが既に見せているものはバナーに入らない。`/` コマンドが求めに応じて見せる
ものもバナーに入らない。そして**異常は常に入る**、操作者にはそれを探しに行く
理由が無いからである。

### 1. 残すもの

- **`gem-agent <version> — <model>`。** どのビルドで、このセッションが何を
  費やしているか。**`@ <project>/<location>` は落とす** —— GCP プロジェクト ID が
  全スクリーンショットと貼り付けられたバグ報告の 1 行目に載るのは、共有物に
  環境固有値を入れることであり、このワークスペースの規約はそれを避ける。
  `/settings` が求めに応じて見せる。
- **`instructions: …`。** ディスク上で発見され、エージェントの振る舞いを変え、
  操作者が打ったのではなく、どのコマンドも一覧しないファイル。バナーの中で最も
  明快な事例であり、誰も疑わなかった唯一の行である。
- **`resumed: session <id> (<n> messages restored)`。** 他に現れる場所の無い、
  このセッションについての事実。
- **異常はすべて**そのまま: sandbox の無効化・未検証、`read_lane_prompts`、
  未信頼プロジェクト、起動しなかった MCP サーバー、無視されたポリシ項目、
  陳腐化した `[mcp] exclude` の名前。これらは状態ではなく変化であり、それぞれが
  次の一手を持っている。
- **`/help for commands, Ctrl+D to quit`。** 1 行で、下で落とすものすべての
  行き先である。

### 2. 1 行に畳むもの

MCP サーバー・skills・memory は、それを展開するコマンドと共に個数になる。

```
mcp: 24 servers, 251 tools · skills: 5 · memory: 3 (/mcp /skills /memory)
```

15 行が 1 行になる。個数を落とさず残すのは、「自分の道具立ては期待どおり上がって
いるか」が操作者が**打つ前に**持つ問いだからである —— 起動に失敗したサーバーは
警告するが、設定から漏れているサーバーは誰にも警告されない。落とすのは列挙の
ほうで、`/mcp` が既に 1 サーバー 1 行でよりよく出している。

### 3. 落とすもの

- **`project: <絶対パス>`** —— TUI のフッタがプロジェクトディレクトリを、モデル名
  とコンテキスト計と並べて常時出している。
- 通常時の **`sandbox: enabled (shell lanes: …)`** —— 毎起動同一の 3 レーン方針の
  要約はマニュアルの抜粋である。異常時の 3 変種は残す（§1）。
- **`session log: <絶対パス>`** —— そのパスを消費するコマンドが無い。再開が取るのは
  `--continue` と `--resume <id>` で、`gem-agent sessions` が一覧し、終了時サマリが
  既に id と再開コマンドを出している。
- **`approval policy: …`** と **`risk rulebook: …`** —— どちらも自分を置き換える
  ものを自分で名指している。

### 4. work directory の注記はサイズで判定する

`cmd/root.go` は残ったディレクトリの**個数**で判定しているので、空のものが 2 つ
あるだけで起動時に `note: 2 earlier session work dir(s), 0B — …` が出る。何も
溜まっておらず、やることも無い。バイト数で判定するようにし、末尾の「nothing is
deleted automatically」は落とす —— `gem-agent workdirs` が自分の help で言って
いるし、設計上の保証は次の一手ではない。

### 5. やらないこと、とその理由

- **モードで変わるバナーにしない。** plain REPL にはフッタが無いので、`project:`
  を落とすとそこでは失われる。クロムの有無でバナーを分岐させると、次の読者は
  2 つのコード経路から規則を再構成する羽目になる。`/settings` はどちらのモードでも
  プロジェクトを見せるし、操作者は自分が起動したディレクトリに立っている。
- **設定可能なバナーにしない**（`[tui].banner = "full" | "minimal"`）。設定した人の
  ために壁が保存され、以後すべての行の設計に設定項目が 1 つ増える。印字する価値が
  ある行なら全員に印字する価値があり、無いならオプションは決めないための方便である。
- **本 ADR では何も翻訳しない。** ADR-0029 §3 はバナーのラベルを grep 安定な出力
  として英語のままにしており、そこは触らない。
- **終了時サマリは触らない。** あれは既にこの規則を通っている —— セッション id と、
  それを再開するコマンド。

## 検討した代替案

- **`skillBannerLine` と同じく MCP 一覧を打ち切る**（8 個で `… +N more`）——
  答えの小さい半分として却下。11 行が 3 行になるだけで、「そもそもなぜ列挙が
  バナーにあるのか」には答えていない。
- **プロジェクトでの初回起動時だけバナーを出す** —— 却下: 異常行こそ、季節ものに
  してはならないものである。
- **全部残して操作者のスクロールに任せる** —— これが現状であり、それを計測した通読
  パスは `tools/labels` を直すまでバナーを見ることすらできなかった。誰も通しで
  読めない壁は、説明的バナーを 4 リリース連続で出荷させた当のものである。

## 影響

- `cmd/root.go` は、stderr に何が書かれたかではなく規則からバナーを組む: 個数行が
  `mcpSummary` の連結・`skillBannerLine`・`memory.BannerLine` を置き換え、policy と
  rulebook の行は消え、sandbox 行は異常変種だけを出す。
- 識別行から `@ <project>/<location>` が消える。
- `workdirs` 注記はバイト数で判定。
- テスト: 通常起動は識別・instructions・個数・hint だけを出すこと、各異常条件が
  依然として自分の行を出すこと、resume 行、個数行がコマンドを名指すこと。
- ドキュメント: interface リファレンスの起動節、README と README.ja のバナー掲載
  箇所、CHANGELOG、両 INDEX。
- `make labels` がバナーを見せるようになったので、出荷前に通しで読める —— これらの
  行が積み上がった当時に存在しなかった検査である。
