## Context（背景）

### この画面の文字列を誰が書くか

モデルの文字列は信頼できない。プロンプトインジェクションを含む Web ページ・ファイル・
ツール結果はモデルの書く内容を誘導でき、モデルは読んだツール出力を引用する。モデルが
**引数として書くもの**も同じである — ツール呼び出しの詳細と宣言された目的はモデルの
言葉で、イベント行と承認ダイアログに表示される。端末は文字列を読むのではなく、送られた
バイトの一部を実行する。OSC はウィンドウのタイトルを変え、クリップボードに書き込み
（許可している端末では OSC 52）、ハイパーリンクを開く。CSI はカーソルを動かし画面を
消す。APC `_G`（kitty）と OSC 1337（iTerm2）は画像を描く — ADR-0089 が宣言した行数の
会計を作ったまさにそのレーンであり、宣言の無い画像はその会計を壊す。

### 実測: 描画器を何が通り抜けるか

本番の描画器（`newGlamourRenderer`）と、モデル自身のライブ経路・フラッシュ経路に、
18 種の敵対的な文字列を流した — OSC 0・2・8・52・1337、APC `_G`、DCS、CSI の消去 /
カーソル位置 / SGR、C1 の CSI と OSC（UTF-8 と生の 8 ビットバイトの両方）、CR、BS、
BEL、DEL、U+202E。それぞれを段落・コードブロック・mermaid フェンスの中に置き、両
スタイルで描いた。すべての文字列のすべての制御文字が出力に残った。2 つのスタイルの
違いはシーケンスの**周り**でしていることだけである。`dark` は `ESC` と引数の間の文字列に
スタイルを付けるので、段落では偶然 CSI が壊れる。どちらも生の 8 ビットバイトは U+FFFD に
変える。どちらも防御ではない — ライブ領域は、どちらかが動く前に生のバイトを出す。

### 実測: 実機の端末がそれをどう扱うか

`make escprobe`（tools/escprobe）は、本番の Model を本番のインラインプログラムで、
`set-clipboard on` の専用 tmux 3.7c サーバの中で走らせ、各文字列を、文字列が TUI に届く
経路のうち 5 つで届け、端末の状態を読み返す。v0.85.0 に対して **80 回の配送のうち 58 回が作用した**:

| ケース | 返答（ライブ） | 返答（フラッシュ後） | 思考 | ツールイベント | 承認ダイアログ |
|---|---|---|---|---|---|
| OSC 0 / OSC 2（タイトル） | 変更 | 変更 | 変更 | 変更 | 変更 |
| OSC 52（クリップボード） | 書込 | 書込 | 書込 | 書込 | 書込 |
| CSI 2J（画面消去） | 消去 | 消去 | 消去 | 消去 | 消去 |
| CSI 3;60H（カーソル） | 移動 | — ¹ | 移動 | 移動 | 移動 |
| CR | 行頭を隠した | 隠した | 隠した | 隠した | 隠した |
| BS | 上書き | 上書き | 上書き | 上書き | 上書き |
| 終端されない OSC | 以降を隠した | 隠した | 隠した | 隠した | 隠した |
| OSC 8・OSC 1337・DCS | 解釈 | 解釈 | 解釈 | 解釈 | 解釈 |
| APC `_G` | 解釈 | — ¹ | 解釈 | 解釈 | 解釈 |
| C1 の CSI / OSC（UTF-8・8 ビット） | — ² | — ² | — ² | — ² | — ² |
| `&#27;]0;…&#7;`・`&#x1b;]52;…`・`abcdef&#13;XY` ³ | — | 変更 / 書込 / 隠した | — | — | — |

¹ glamour の `dark` スタイルがシーケンスを分断した — 上に書いた偶然であって、防御ではない。
² tmux は UTF-8 モードで C1 に作用しない。これは tmux のパーサの性質でありこのランタイムの
ものではなく、8 ビット制御を受け付ける端末なら作用する。
³ 文字参照で、制御文字は含まない。Markdown を描くのはフラッシュ後の返答だけで、goldmark が
そこで復号する。最初の実装へのレビューが見つけ、その実装で測った — 入口だけ（§2 の前半）
ではちょうどこの 3 つが作用し、95 回中 3 回だった。v0.85.0 も同じ経路を持つ（モデルと
glamour の間でこれに触れるものは何も無かった）が、これを含めた再測定はしていない。

装飾を超えて重要な行が 2 つある。**承認ダイアログは今日、偽装できる**: `shell_exec` の
コマンド中の CR はそれより前をすべて隠し、終端されない OSC はそれより後をすべて隠す。
操作者が読むコマンドは、実行されるコマンドではない。そして文字列の中の画像エスケープは、
宣言されたボックスを経ずに画面に届く。ADR-0089 §6 は「view 層だけが画像エスケープを
出す」と述べたが、そのテストが固定しているのは payload を組み立てる**コード**であり、
文字列は一度もコードではなかった。

「解釈」は端末がそのバイトを制御として消費したことを意味する（tmux は kitty・iTerm2・
sixel の画像を描かない。描く端末なら描く）。

### ほかの入口

素の REPL と `-p` は、モデルの差分を `fmt.Fprint` で stdout に書き（ADR-0042 §4:
「stdout はモデルの文字列だけ」）、ツールイベント・承認プロンプト・質問ダイアログを
stderr に書く。どちらかのストリームが端末なら、同じバイトが何も挟まずに届く。

## Decision（決定）

### 1. 取り除くもの: 制御文字、それ以外は何も取り除かない

次のルーンを取り除く:

- タブと改行を除く C0 制御文字（U+0000–U+001F）— ESC・CR・BS・BEL を含む
- DEL（U+007F）と C1 制御文字（U+0080–U+009F）
- 双方向テキストの埋め込み・上書き・隔離（U+202A–U+202E、U+2066–U+2069）。bidi を
  実装した端末では、操作者が読むもの — 承認ダイアログではコマンド — の並びを入れ替える

不正な UTF-8 は U+FFFD にする。生の 8 ビット C1 バイトがバイトのまま残ることはない。
集合は有限で、1 つのパッケージ（`internal/inert`）の 1 つの述語である。

**取り除くのは文字であって、シーケンスの本体ではない。** 端末の制御はすべて ESC か C1 の
導入子で始まるので、それが無くなれば文字列の中の何もシーケンスを始められず、
シーケンスの本体だったものはただの文字列になる。`\x1b]0;T\a` は `]0;T` と表示される。
シーケンス全体を取り除くのは指摘の文面の素直な読みだが、採らない（A1）。OSC・DCS・APC は
終端子まで続き、終端されないものは文字列の終わりまで続く。それを取り除けば、上の表で
端末がしていることをランタイムが再現する — 承認コマンドの残りを隠すことになる。文字を
取り除いても、操作者が読めたはずのものは何も隠れない。残る文字列は何かが試みられた
証拠であり、transcript はバイトをそのまま保持する。

目に見える印への置き換えはしない（A2）。操作者は取り除くことを求めており、文字ごとの
印は報告であって制御ではない — 取り除くことが制御である。

### 2. どこで: 1 回だけ、TUI の入口で

`internal/tui` で宣言された型のメッセージは、`Update` の先頭で、どの分岐も読む前に、
運ぶ文字列をすべて書き換える — フィールド、文字列のスライス、入れ子の構造体、エラーの
文言（エラーは包むので、`errors.Is` は元のエラーを見続ける）。リフレクションで行うので、
後から足されたフィールドは足された日から対象になる。バイト列は文字列ではない —
`tui.Image` のバイト列は view 層が符号化する絵である — ので触らない。

`Options` のうち文字列を返すコールバックはすべて `New` で 1 回だけ包む: スラッシュ
コマンドのハンドラ（`/memory` は `save_memory` が保存したものを一覧する）、スキル展開の
エラー、補完候補（モデルやプロジェクトが作り得るファイルとスキル）、設定パネルの内容と
編集が出す 1 行（MCP サーバの再接続エラーを引用し得る）、バナーの行（起動時の注記は
MCP サーバの出力やパスを引用する）。フッタが再描画のたびに出す `Options` の文字列 —
モデル名と、名前をディレクトリの作り手が決めるプロジェクトディレクトリ — も同様である。
設定の行の `Tool`・`Exclude`・`Group` は表示されず、行が返す編集のキーなのでバイトを保つ:
書き換えると、除外は存在しない関数を名指し、黙って効かなかった。テストは `Options` の関数フィールドを列挙し、包まれても
おらず、理由を書いた除外にも入っていないものがある間は失敗する。

書き換えないメッセージが 1 つある: 操作者の argv の最初のメッセージ（`initialSubmit`、
ADR-0064）。キーボードと同じ信頼で、ターンの文字列そのものであり、書き換えればモデルに
送るものが変わる（A6）。

**変換は、制御文字を含まない文字列から制御文字を作り得る。** glamour の下の goldmark は
文字参照を復号する: `&#27;]0;T&#7;` は害の無い ASCII として入口に届き、本物の OSC として
描画器から出る。本番の Model と実機の端末で測ると（下の `ENT-` の行）、タイトルを変え、
クリップボードのバッファに書き込み、CR の後ろに文字列を隠した。そこで TUI が外から来た
文字列にかけるすべての変換の出力を、その変換自身が書くエスケープだけに抑える — 測定では、
glamour の `dark`・`light` スタイルは SGR（`CSI … m`）だけを書き、`notty` は何も書かず、
罫線アートの描画器も何も書かない。`inert.Styled` は SGR を残し、それ以外の制御を §1 と
同じく取り除き、SGR を含む出力はリセットで閉じるので、スタイルはそれが来た返答より長く
生き残らない。plain テーマと罫線アートには §1 をそのまま適用する。リセットは飾りではない:
glamour の plain スタイルは HTML ブロックの復号済みの文字列をリセット無しで出し、そうして
開いたままになった復号済みの SGR 8（conceal）は、後に続くイベント行と承認ダイアログを、
コマンドごと隠した（2 本目のレビューパスが再現）。抑えは描画器を組み立てる場所
（`New` が保持するファクトリ）で 1 回だけかけるので、リサイズ時の描画も、拒否された絵の
注記も、表示箇所で呼ぶことなく覆われる。図の注記は抑えた描画器を通って描かれるので、
`noteSafe` は今のまま — Markdown のためのガード — である。描画器を抑える基準はランタイムが
書くものであって、文字列が含んでいたものではない: 復号された SGR にできるのは、描かれた
返答に色を付けることだけである（§4）。

表示箇所は誰もこの関数を呼ばない。lipgloss の色、Bubble Tea のカーソル制御、`termimg` の
payload は入口の後でランタイムが書くもので、そのまま通る。表示箇所も無害化するなら第 2 の
機構になり、その代償はナレッジベースに記録されている: 一方が他方の欠落を隠す。

### 3. 素の REPL と `-p`: 端末には無害化して、それ以外にはそのまま

`runREPL` は冒頭で 1 回だけ、コマンドの stdout と stderr を、**そのストリームが端末で
あるとき**に限って無害化する writer に置き換え、それ以外では触らない。これはホスト自身の
慣習である: `ls` は非図形文字を「出力が端末のときは既定で」`?` として表示し、そうで
なければ生で出す（macOS `ls(1)` の `-q` / `-w`）。

ADR-0042 §4 の約束 — stdout はモデルの文字列だけ — は、それが書かれた相手に対して
意味を保つ。パイプやファイルを読むプログラムはすべてのバイトを受け取る。端末はバイトの
消費者ではなく、その一部を実行する装置であり、プロンプトで打つ `-p` は普通の手での
使い方である。常に無害化すれば、守る相手のいないところで約束を破る。決して無害化
しなければ、stderr 上の承認プロンプトは TUI のものとまったく同じように偽装できる。

writer は 1 回の書き込みの末尾にある不完全な UTF-8 シーケンスを次の書き込みまで保持する。
書き込みの境目で分かれたルーンが 2 つの U+FFFD にならないためである。これは状態なので
ロックを持つ: 素の REPL の割り込みハンドラとターンは同時に stderr に書き、以前の書き先の
`*os.File` はそれに対して安全だった。

### 4. 外に残るもの、およびそれを受け入れる理由

- **`gem-agent -p … | cat`、`| less -R`。** パイプを選んだ操作者が端末に生のバイトを
  渡している。`ls | cat` と同じである。
- **描かれた返答の色。** `&#27;[…m` から復号された SGR は dark・light の描画器の抑え（§2）を
  通り抜け、モデル自身の返答の文字列に色を付けたり隠したりでき、返答の終わりのリセットが
  そこで止める。カーソルを動かすこと、消すこと、
  タイトルを変えること、クリップボードに書くこと、絵を描くことはできず、コマンドを見せる
  ダイアログは Markdown として描かれない。
- **`GEMAGENT_MCP_STDERR=1`。** オプトインのデバッグ用スイッチで、MCP サーバの stderr を
  プロセス自身のものとして端末に渡す。サーバのデバッグのためのものである。
- **テレメトリのエクスポータのエラー**は stderr へ直接書かれる — コレクタの応答文を含む
  可能性がある（確認していない）。
- **操作者が打つもの**: 入力欄と argv の最初のメッセージ。
- **MCP サーバが自分で端末に書くこと。** サーバは操作者が動かすプログラムで、新しい
  セッション無しで起動されるので `/dev/tty` を開き得る。それはコードの実行であって、この
  ランタイムが表示する文字列ではなく、本記録の範囲外である。
- **transcript。** 設計どおり逐語である: 記録であり、証拠である。
- **ほかのサブコマンド**（`sessions`・`workdirs`・`trust`）は操作者自身の状態を表示する。
- **`!` の出力は対象になる**。メッセージとして届くからである。パイプ越しに色付けを強制
  されたプログラムは色を失い、`[32m` のような残りが出る。多くのプログラムはパイプに色を
  付けない。

### 5. どう保つか

- 振る舞いのテストは `go/ast` で `msgs.go` からメッセージ型を読み、ケースの無い型がある
  間は失敗し、全ケースの全文字列をリフレクションで敵対的な文字列で満たし、`Update`・
  フラッシュ・`View` を通して、2 つを確かめる: 敵対的な文字列の制御文字が出力に無いこと、
  そしてその文字列**自体は**出力にあること。後者が無ければ、何も表示しないメッセージは
  空虚に合格する。
- ウォーカーは文字列・構造体・スライスを書き換え、数値・バイト列・チャネルを通す。
  ポインタ・マップ・配列・インターフェースのフィールドは読み飛ばされる。テストは全メッセージ
  型をフィールドごとにこの種類に縛るので、そういうフィールドは素通りせずビルドを落とす。
- 除去対象の各クラスの文字参照を、本番の描画器で 3 つのテーマすべてについて描き、制御文字が
  画面に届かないことを確かめるテスト。
- `Options` の関数フィールドと文字列フィールドを列挙するテスト（§2）。
- 復号済みの conceal を含む HTML ブロックを 3 つのテーマで描き、plain テーマはエスケープを
  出さず、イベント行が出る時点で開いたスタイルが無いことを確かめるテスト。もう 1 つは
  スタイルを開いたままにする描画器をファクトリに渡し、glamour 自身がリセットする癖とは別に
  リセットを確かめる。
- アーキテクチャテストは `internal/inert` を import するファイルを — import パスで照合するので
  別名では通らない — 2 つの入口のファイルに固定する。自分で無害化を始めた表示箇所は、隙間を
  隠す代わりにビルドを落とす。
- writer のロックは並行書き込みでテストするが、落ちるのは `-race` の下だけである。
  `make check` は競合検出器を走らせない。
- `make escprobe` は端末の表を取り直す。

### 6. lagent

lagent の `internal/tui` は同じ経路（`case TextDelta` が生のチャンクを追記する）を持ち、
したがって同じ欠陥を持つ。AGENTS.md の規則は「共有する機構の欠陥は両方で直す」で
ある。今回の作業は操作者が gem-agent に範囲を絞っており、移植は次の作業である。それが
入るまで、この行が分岐の記録である。

## Consequences（結果）

- 実測の表はゼロになる: 探ったすべての経路・すべてのケースで、文字参照も含めて 95 回中 0 回。
- ADR-0089 が乗る行数の会計は、文字列について再び正確になる: モデルの文字列の 1 行が、
  カーソルを動かす幅ゼロのエスケープを運ぶことはもう無い。
- モデルは文字列を通じてハイパーリンクと絵を出せなくなり、色は描かれた返答の中の文字参照を
  通じてだけ出せる（§4）。どれもモデルに提供したことは無い。
- CR を含む正当な文字列（CRLF の行末）は CR を失う。タブと改行は残る。
- **ADR-0042 §4 を修正する**: 素の REPL と one-shot の出力は、パイプやファイルには逐語、
  端末には無害化して出す。
- **ADR-0089 §6 の既存の面を TUI について修復する** — `!` のシェル出力はメッセージとして
  画面に届き、今は無害化される。

## Alternatives considered（検討した代替案）

- **A1. エスケープシーケンス全体を取り除く**（指摘の文面）。却下: 終端されない文字列型の
  シーケンスは文字列の終わりまで続くので、取り除けば承認ダイアログのコマンドの残りを
  隠す — 実測した偽装を、防御が再現する。CSI の終端バイトは英字なので、取り除くと後ろの
  文字列の 1 文字も食う。
- **A2. 制御文字ごとに目に見える記号（␛・␍）へ置き換える。** 忠実で、文字ごとの報告に
  なる。操作者は取り除くことを求めており、transcript はバイトを保持する。
- **A3. 表示箇所ごとに無害化する** — ライブ表示、フラッシュ、注記、ダイアログ、イベント行。
  却下: ナレッジベースには、独立レビューが呼び出しの書き忘れを 5 箇所見つけた CLI が
  記録されている。どれも誰も疑わない短いフィールドだった。ここで実測した経路は 1 つでは
  なく 5 つである。
- **A4. Bubble Tea の出力ストリームを許可リストで濾す。** 却下: 描画の後では、ランタイム
  自身のカーソル制御・消去・画像 payload は、攻撃者が必要とするのと同じバイトであり、
  そこでは書き手を区別できない。
- **A5. x/ansi の `ansi.Strip`。** 却下: シーケンス全体を取り除き（A1）、しかもこれほど
  小さな決定のために他のプロジェクトが選んだパーサに頼る。
- **A6. エージェントの中核で、transcript の前に無害化する。** 却下: 記録と、モデルが
  受け取るデータを変える。表示のために文字列を無害化するのは表示の仕事である。
- **A7. 素の REPL と `-p` を常に逐語、または常に無害化。** §3 で却下。
- **A8. 文字参照を入口で無力化する。** 却下: 上限の無い領域 — 10 進と 16 進の形、先頭の
  ゼロ、そのほか復号器が受け付けるもの — に対する、1 つの復号器に向けて書いた文字列規則で
  あり、入口は文字列がコードブロック（文字参照は復号されず、エスケープがそのまま見える）に
  入るかどうかを知り得ない。描画器の出力は有限の語彙であり、測ってある。
