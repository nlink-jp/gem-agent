## 背景

ADR-0010 は、スキルのディレクトリを Claude Code の書式のまま読む。スキルは読み込まれるまで、システムプロンプトに説明 1 行ぶんの費用しかかからない。説明は「段階的な開示の、荷を負う半分」であり、それだけでスキルを読み込むかどうかが決まる。ADR-0010 はこの行の長さを定めていない。

コード（`4848c71` で確認）には、Claude Code より書式を少なく読む箇所が二つある。

1. **説明を 400 ルーンで切り、そのことを何も言わない**（`internal/skills/skills.go` の `DefaultLimits().MaxDescription`）。Claude Code と org のスキル検証は 1,024 文字まで受け付ける。skills-series の 9 個のスキルを測ると、6 個が 400 を超える:

   | スキル | 文字数 | 400 の位置 |
   |---|---|---|
   | mcp-tactics | 1,020 | 「Splunk logs;」の直後。BigQuery・データ分析・ブラウザ・音声・文字起こし・セカンドオピニオンと日本語のトリガーがすべて落ちる |
   | news-digest | 644 | — |
   | compliance-review | 594 | 日本語のトリガーの途中 |
   | weather-forecast | 580 | 週末の天気・雨が降るか・傘が要るか・気温が落ちる |
   | incident-review | 578 | 日本語のトリガーの直前 |
   | incident-research | 509 | 日本語のトリガーの直前 |

2. **複数行の説明を 1 行目として読む。** frontmatter の読み取りは最小限で、1 行に `key: value` が一つ、字下げした行は読み飛ばす。YAML のブロックスカラー（`description: >` や `|` の後に字下げした行が続く形）や、字下げした行に続くプレーンスカラーは、Claude Code の書式として正しい。測ると、`description: >` の後に字下げした 2 行が続く説明は、`>` の 1 文字として読まれた。そのスキルのトリガーはすべて失われ、それでもスキルは一覧に載る。org が配布するスキルで、いまこの形を使うものは無い。

## 決定

### 1. 説明は 1,024 文字まで示す

`MaxDescription` を 1,024 にする。Claude Code と org の検証がスキルに課す上限である。それより長い説明はこれまでどおり切るが、切ったことを発見時の注記として操作者に伝える: `skill "<name>": description is <n> characters; only the first 1024 are listed`。トリガーが隠れたスキルが見えるようになる。欠けていたのはそこである。

待機時の費用は、400 を超えるスキル 1 つにつき最大で約 624 文字増える。行数は `MaxSkills`（100）がすでに抑えている。skills-series の 9 個では、一覧は約 1,700 文字増える。

### 2. 複数行の YAML の値を読む

`parseFrontmatter` は、後続の行に深く字下げして続く値を読む:

- **ブロックスカラー。** `>` は行を空白でつないで 1 行に折りたたみ、空行は改行になる。`|` は改行を保つ。チョンピングの指示（`-`・`+`）と、明示の字下げの数字も受け付ける。その後で値をトリムする。説明はすでにすべてそうしている。
- **字下げした行に続くプレーンスカラー**は、YAML と同じく空白でつないで折りたたむ。

共通の字下げは取り除く。ブロックは、字下げも空行でもない最初の行で終わる。これはまだ YAML のパーサではない。行をまたぐ引用符つきの値、アンカー、フローの集まりは読まない。スキルの frontmatter では使われず、そのための完全なパーサは、org が採らない依存である（サプライチェーンの規則）。

## 結果

- プラットフォームの上限まで書いたスキルが、gem-agent でも宣言したすべてのことで起動する。
- 長い説明の分だけシステムプロンプトが大きくなる。増え方には上の上限がある。
- 1,024 文字を超える説明は、黙ってではなく注記つきで切られる。
- lagent にも同じ 400 ルーンの上限と同じ読み取りがある。lagent は自分で決める。

## 検討した代替案

- **400 のまま注記を足す。** org が配る 9 個のうち 6 個で注記が出て、そのトリガーは見えないままになる。400 には記録された理由が無い。ADR-0010 は Claude Code の書式を約束として名指しており、ここは gem-agent がそれを少なく読んでいた唯一の箇所である。
- **上限なし。** 説明は操作者が入れたテキストだが、すべてのプロンプトに上限の無い行が入るのは、ADR-0010 が抑えようとした費用である。スキルの作者はすでにプラットフォームの上限に合わせて書いている。
- **YAML のライブラリ。** 上に挙げた形もそれ以上も読めるが、一つの欄のために外部の依存を抱えることになる。
