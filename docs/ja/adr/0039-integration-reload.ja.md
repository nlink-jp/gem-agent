# ADR-0039: セッション中の skills / MCP リロードと --mcp フラグ

| 項目 | 内容 |
|------|------|
| Status | **Accepted** |
| Date | 2026-08-22 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレーター: セッション途中で skill を追加したり MCP サーバーを直すにはセッションごと再起動が必要で不便。合わせて単発 `-p` 向けにコマンドラインで MCP の有効/無効を選びたい |

## Context（背景）

skills と MCP サーバーは起動時に一度だけロードされる。セッション
途中で skill を導入する、`mcp.json` にサーバーを足す、変になった
サーバーを回復する — どれも会話に何も触れない操作なのに、セッション
を終了して文脈を失う必要があった。（タイムアウトした MCP コールは
既にサーバーを kill して遅延再起動するが、癒えるのはクラッシュの
場合だけ: 設定変更と新しいツールリストは決して届かない。）

別件として、`-p` 単発実行は毎回 MCP の起動コスト — 設定された全
サーバーの子プロセス起動 — を払う。MCP ツールは承認ゲート付きで
単発モードはゲートに答えられないため、一般的な構成ではその子
プロセスは何にも仕えない。

## Decision（決定）

### 1. `/skills reload` と `/mcp reload` — 新コマンドではなくサブコマンド

リロードは、その統合を既に表示しているコマンドの上に住む。
`/mcp reload` は registry から全 `mcp__*` ツールを除去し、旧
クライアントを閉じ、**起動時と同一の接続経路を再実行**する —
グローバル設定・プロジェクト設定・マージ規則・警告まで。コード
経路は 1 本であり、並行の亜種を作らない。`/skills reload` は skill
探索を再実行する。接続警告はコマンド自身の出力に載る: リロードは
TUI の下で走り、stderr への書き込みは表示を壊すからである。

### 2. trust の判断は起動時のもの — リロードは広げられない

リロードは起動時に決まった trust 判定（ADR-0023）を再利用する:
非信頼プロジェクトの `.mcp.json` と skills は、起動時とまったく
同様にロードされないまま。trust ゲートは「何かがロードされる前に
一度だけ」走る — 再質問できる（あるいは黙って広げる）リロードは、
表示コマンドを trust 面に変えてしまう。trust の答えを変えるには
今も再起動が要る。

### 3. 宣言とシステムプロンプトが追随する

MCP リロード後、エージェントはツール宣言を再キャッシュする。skills
リロードはシステムプロンプトの skill 節を再構築する。どちらも
バイト同一のリクエストプレフィックスを無効化するので、implicit
cache（ADR-0018）は次ラウンドで再ウォームする — オペレーターが
起動した意図的なコストであり、再起動でも同じものを払う。
`load_skill` は skill が 0 個でも最初から登録される（生きたリストを
getter 経由で読む）ので、空で始まったセッションもリロードで
埋められる。

ロックは追加していない: スラッシュコマンドはターン実行中に構造的に
走れない（ADR-0007 は入力をキューし、`/` はキューできない）ので、
リロードはターン goroutine の single-writer 規律を共有する。

### 4. リロードを意図的に生き延びるもの

セッション承認 allowlist（`a` 回答）はツール名がキーであり生き残る:
オペレーターが承認したのは*ツール*であって、同じ名前で再接続した
サーバーは同じ判断である。ツール別ポリシー・自動承認状態・会話は
無傷 — それこそが再起動ではなくリロードする意味である。

### 5. `--mcp on|off`

`[mcp].enabled` の CLI 上書き。優先順位の最上位に座り、`/settings`
の出所表示で `flag` と出る。`off` がパイプラインの場合: `-p` 実行が
全サーバー起動をスキップする。`on` はその鏡像: 無効化した設定に
対して 1 回だけ MCP を強制する。

### 6. 監査される

リロードはセッションにできることを変える — MCP リロードは子
プロセスを起動する — ので、トランスクリプト記録に加えて
`integration.reload` 監査イベント（kind・servers・tools）を出す。
途中でツール面が育ったセッションが、監査ログの上で最初からそう
だったセッションに見えてはならない。

## Consequences（帰結）

- skill の追加やサーバーの修理が、会話を保ったままキー数回の操作に
  なる。
- 変になった MCP サーバーに、遅延再起動より強い回復経路（完全再接続
  + 新しいツールリスト）が文脈を失わずに手に入る。
- `/mcp reload` はサーバー接続の間その場をブロックする（起動時と
  同じタイムアウト）— 起動と同じく、意図して呼ぶ操作である。
- `--mcp off` の単発パイプラインは実行ごとの N 子プロセス起動を
  省く。
- 除去されたサーバーのツールは `/tools` と宣言から消える; 古い文脈
  からモデルがそれを呼べば、通常の unknown tool 経路で伝わる。
