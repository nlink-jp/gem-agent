# ADR-0115: Linux 版は出さない — write レーンの名前による拒否を持ち込めない

| Date | 2026-11-11 |

| Decision makers | nlink-jp maintainers |

| Relates to | ADR-0001（機構。「macOS 専用」は設計上の制約）、ADR-0073（レーン。シェルコマンドを判定するのはカーネルで、文面ではない）、ADR-0072 と ADR-0074（永続ファイル）、ADR-0086（カーネルがファイルを読む） |

## Context

ADR-0001 は、隔離が `sandbox-exec` の上に作られているという理由で gem-agent を macOS 専用とした。これは選んだ機構についての記述であり、別のカーネルが同じ保証を担えるかは測られていなかった。この記録はそれを測り、決める。

持ち込む必要があるのは「サンドボックス」一般ではなく ADR-0073 のレーンであり、とくに write レーンの次の性質である。

- 永続ファイル（`AGENTS.md`、`CLAUDE.md`、`.mcp.json`、`.gem-agent.toml`、`.claude/`、`.git/hooks`、`.git/config` ほか `sandbox.PersistentFiles` の一覧）への `write_file` / `edit_file` による書き込みは、必ず操作者に尋ねる。モデル層は答えられない。
- write レーンの `shell_exec` は、文面ではまったく判定されない（ADR-0073: 文面は無限の領域である）。それらのファイルを書かせないのはカーネルで、write レーンのプロファイルが**名前で、どの深さでも、そのファイルがまだ無くても**拒否する。write レーンのコマンドを承認した者（操作者、自動承認のもとではモデル層）は、新しい指示ファイルを承認したことにはならない。それには operator レーンが要り、答えられるのは操作者だけで、その承認画面はそう書いてある。

`write_file` で断られたモデルは、次に `shell_exec` を試す。macOS ではその試みは、コマンドの綴りがどうであれカーネルで失敗する。製品が立っているのはこの性質である。「プロジェクトを変えてよい」と「後のセッションが信頼するものを変えてよい」の違いが、操作者がコマンド行を読み解けるかどうかより下の層で強制されている。

## Measurement

Linux の 2 台で、非特権ユーザーとして、それぞれ 1 回測った（2026-11-11）。

- Fedora CoreOS 44 の仮想マシン、カーネル 7.1、arm64 — Landlock ABI 9、SELinux。
- Proxmox VE ホスト上の Ubuntu 24.04 コンテナ、カーネル 7.0-pve、amd64 — このカーネルでは Landlock が有効でない（`landlock_create_ruleset` が `EOPNOTSUPP` を返す）。

試した機構は 2 つ。Landlock 単独（3 つのシステムコールで規則を足してから `exec`）と、名前空間（`unshare` でユーザー名前空間とマウント名前空間を作り、保護を bind マウントで用意し、その内側に操作者自身の uid のユーザー名前空間を重ねて、コマンドが capability を持たないようにする）である。拒否されるべきプローブは、まず機構なしで走らせ、そこで成功することを確かめた。外でも起きる失敗は何も証明しない（ADR-0073 §5）。問い、結果の読み方、1 台 1 回という止めどきは、最初の実行より前にスクリプトへ書いた。第 1 回のプローブのうち 1 つは不成立で（対照が、何もマウントされていない場所をアンマウントしていた）、それだけを `umount2` の直接呼び出しで測り直した。

| macOS のレーンが保証すること | Landlock 単独 | 名前空間 |
|---|---|---|
| プロジェクトの外へ書けない | 拒否された | 単独では未測定。Landlock との併用で拒否された |
| 既にある `AGENTS.md` を書けず、消せず、改名できない | **許された** | 拒否された |
| 新しい `AGENTS.md` を作れない | **許された** | **許された** |
| `AGENTS.md` を含むディレクトリを改名できない | 未測定 | **許された** |
| 既にある `.env` を読めない | **許された** | 拒否された（`/dev/null` を上に bind） |
| 資格情報のディレクトリを読めない | 読み取りを木の許可リストにすれば拒否された | 拒否された（空のファイルシステムを上にマウント） |
| TCP で接続できない | 拒否された | 拒否された |
| 親へシグナルを送れない | 拒否された | 拒否された |
| 抽象 UNIX ソケットへ接続できない | 拒否された | 拒否された |
| パス上の UNIX ソケットへ接続できない | **許された** | **許された** |
| コマンドが保護を外せない | — | 拒否された（`EPERM`） |
| `ls`、`cat`、パイプ、`git init` と `git status` が動く | 動いた | 動いた |

名前空間の列は 2 台で同じだった。Landlock のカーネル文書（2026-11-11 に読んだ）は 1 列目と一致する。規則が名指すのはファイルの階層と、そこで許すアクセスであり、拒否の規則も名前のパターンも無い。

つまり、既にあるものは守れ、まだ無いものは守れない。コマンドがほかは書いてよい木の中で、名前を理由にファイルの作成を断ることは、どちらの機構にもできない。

## Decision

1. **Linux 版は出さない。** gem-agent は macOS 専用のままとする。ADR-0001 の帰結はそのままで、その理由が機構からの継承ではなく実測になった。Linux では write レーンのコマンドが、新しい `.mcp.json`、サブディレクトリの新しい `AGENTS.md`、無かった `.claude/` を作れる。モデルとそのファイルの間にあるのは、コマンド行の読み解きだけになる。読むのは操作者で、自動承認のもとではモデル層である。これは ADR-0001 が「頼らない」と決めた境界である。
2. **Windows の経路として WSL2 を案内しない。** 理由は同じで、それは Linux 版である。
3. **サンドボックスの制御を抽象化しない。** 実装が 1 つしかなく、2 つ目は作らないと決めたインターフェースは、呼び手のない費用である。`internal/sandbox` は今のままとする。
4. **再検討のきっかけは需要ではなく機構である。** 条件は、書き込める木の中で名前のパターンによって作成と改名を断れる、非特権で使えるカーネルの機能が、人が実際に使うディストリビューションにあり、上のプローブ（それぞれ対照つき）で新しい永続ファイルを断ると示されること。ある基盤でだけ弱い保証は、この製品の一つの版ではない。

## Consequences

- Makefile のターゲットは 1 つのままで、`AGENTS.md` と `CLAUDE.md` の「linux / windows のビルドターゲットを足さない」も残り、この記録を指す。
- Linux の利用者には提供できない。これが費用であり、そこでは守れない保証に製品の名前を付けて出すことと比べて選んだ。
- lagent は `internal/sandbox` とレーンを共有している。この実測に gem-agent 固有の点は無い。

## Alternatives considered

- **Linux では閉じ込めなしを既定にする**（`--no-sandbox` と同じく、すべてのシェル呼び出しが操作者のもの）— 最も安い移植で、偽りもない。ランタイムは確かめられなかったことを既にそう述べる。採らない: 通常の使い方で、操作者の承認が唯一の境界になる。`--no-sandbox` はデバッグ用（ADR-0001）であって、製品ではない。
- **read レーンは再現し、write レーンのコマンドは毎回尋ねる** — read レーンの保証は実測で持ち込めた。採らない: write レーンのコマンドの承認が、それが作る新しい永続ファイルの承認も兼ねることになる。新しい名前については write レーンと operator レーンが 1 つのレーンになり、承認画面はそうでないと正直には書けない。
- **防ぐ代わりに検知する** — write レーンのコマンドのたびに永続ファイルのスナップショットを比べ、現れたものを操作者に知らせる。安く、仕組みも既にある（ADR-0074、ADR-0099 §10）。基盤の土台としては採らない: 知らせるのは書かれた後で、同じファイルを読む別のツールが先に読みうる。
- **重ねがけ（overlay）に書かせ、結果を厳密な名前の判定を通してプロジェクトへ反映する** — コマンドの文面ではなく、実際にできたファイルを判定するので、保証を保てるかもしれない唯一の道である。未測定で、採らない: 反映（削除、改名、ディレクトリ）、大量に書くビルドでの費用、コマンドが終わるまでほかのプロセスに書き込みが見えないこと — 要望 1 件のために保守するファイルシステムの層がもう 1 つ増える。
- **監視プロセスがシステムコールに割り込む** — 調べていない。

## Not measured

- Ubuntu の実機。AppArmor が非特権のユーザー名前空間を制限している可能性がある。測ったコンテナはホストのカーネルで動いており、これについては何も言えない。
- WSL2 そのもの。Microsoft が公開しているカーネル設定（6.6.107.1、x86 と arm64）を読んだだけである。そこでは Landlock と、ユーザー・PID・ネットワークの各名前空間が有効になっている。
- 制御端末、UDP、パス上の UNIX ソケットに対する Landlock のアクセス権。

これらはどれも決定を変えない。どれも「ほかにどれだけ持ち込めるか」に関わるもので、名前による作成の拒否には関わらない。
