# ADR-0014: コンテキスト経済 — summarize_file と部分読み

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-19 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | オペレータ:「推論用メインモデルとは別の軽量モデルでファイル要約を取得するツール」「ファイルの部分参照 — 現在の read_file は全部読み込んでしまう」 |

## Context

2 つの要望は同じコストを両端から攻めている。`read_file` は全か無かであり、
2000 行のファイルについて 1 つ質問に答えるために、モデルは 2000 行全部を
履歴へ引き込む — その履歴は**以後の全ラウンドで再送される**。ADR-0013 で
「探す」は安くなった。残った高価な手が「読む」である。

無駄の形は 2 つ:
- モデルが必要なのは 560〜575 行なのに、ファイル全体の代金を払う — しかも
  以後のラウンドでも払い続ける。
- モデルが必要なのは文書の要旨であって本文ではない — そしてその要旨は、
  推論している モデルの何分の一かのコストのモデルで作れる。

## Decision

### 部分読み: `read_file` に `start_line` / `end_line` を追加

1. 任意・1 始まり・両端含む。省略時は現行どおり。切り出しには既存の
   truncation 様式で末尾注記 `[showing lines A–B of N]` を付ける — 部分が
   全体のふりをすることは決してできない。ファイル末尾を超える `start_line`
   は、実際の行数を名指しするエラー。
2. 内容は生のまま — **行番号プレフィックスは付けない**。行番号付き出力は
   読みやすいが編集ループを毒する: 読んだものを `edit_file` の old_string に
   写すモデルは番号ごと埋め込み、すべての編集が外れる。組み合わせは逆向きに
   機能する: `search_files` が `path:line` を報告し、モデルがその前後の窓を
   要求する。

### `summarize_file(path, focus?)` — バイト列の代わりに要約を

3. ファイルを要約器に送り短い要約を返す読み取り専用ツール。`focus` で
   観点を絞れる。メインループの履歴が持つのはファイルではなく要約になり —
   全文読みと違って、この節約は会話の残り全ラウンドで繰り返し効く。
4. **要約器のモデルは設定** `[model].summary`。未設定はメインモデル。
   オペレータの要望 —「軽量モデル」— がこのノブの眼目だが、ノブ無しでも
   ツールには価値がある（メインモデル価格でも「履歴に要約」は「履歴に
   ファイル」に勝る）ので、未設定でツールを無効化はしない。第 2 モデルは
   メインモデルの Vertex クライアントを共有する（同じプロジェクト・
   ロケーション・認証）— モデル選択は呼び出し単位であり、これは名前で
   あって第 2 の接続ではない。モデル名は設定駆動、コードに埋め込まない
   （組織規則）。
5. **要約器は「圧縮パターンの単一ファイル適用」である**（ADR-0006）:
   ファイル内容は非信頼なので、防御的枠書きを先頭にした nonce ラップで
   渡し、呼び出しにツールは一切与えず、ブロック・空応答は報告されるエラー
   であって無言の空要約にはしない。要約自体は通常のツール結果として返り、
   通常のツール結果ラップを受ける — 非信頼由来は非信頼のまま。例外は
   与えない（内容の作者がオペレータである ADR-0010 との対比）。
6. 発明より再利用: ツールは `read_file` 自身の経路でファイルを読む —
   同じ封じ込め、同じ画像拒否、同じサイズ上限と truncation 注記
   （切り詰め読みの要約はそう名乗る）。
7. 要約器のトークンはフッターのカウンタにまだ入れない: フッターの
   コンテキスト計はメイン会話を測るものであり、側呼び出しのプロンプト
   トークンを混ぜると占有率が嘘になる。セッションログには記録する。
   累積の別カウンタは、支出が問題になったときの改良とする。

## Consequences

- 「全部読む税」が opt-in になる: 精密には窓、要旨には要約、全文は全文が
  論点のときだけ。システムプロンプトの指針もそう誘導する。
- `[model].summary` は、ADR-0004 が「安い第 2 モデル」としてほのめかして
  作らなかった枠をようやく実体化する。軽量モデルがここで実績を作れば、
  リスク評価層を同じモデルへ向けるのは自然な次の一手 — 別判断であり、
  今回は取らない。
- 要約は不可逆に情報を落とし、モデルはそうでないかのように振る舞いうる。
  結果テキストは自身を要約と名乗り、書いたモデル名を名乗る。荷重のかかる
  用途の指針は変わらず「実際の行を読め」。
- ノブ 1 つ・ツール 1 つ増（組み込み 9 個）。どちらも待機コストはゼロ
  （ノブの既定はメインモデル、ツールはプロンプト 1 行）。

## Alternatives considered

- **read_file 出力に行番号** — 却下。edit_file の完全一致契約を毒する（§2）。
- **別ツール `read_lines`** — 却下。同じ操作に 2 つ目の名前。モデルは名前で
  ツールを選ぶので、使い分けの学習を強いる。既存動詞へのパラメータ追加の
  ほうが表面積が小さい。
- **`[model].summary` 設定時のみ summarize_file を登録** — 却下。コンテキスト
  節約はモデルが安いことに依存しないし、設定で現れたり消えたりするツールは
  習慣を築きにくい。
- **行範囲ではなくバイトオフセット** — 却下。周辺はすべて行で語る
  （`search_files` の出力、コンパイラエラー、スタックトレース）。
- **埋め込みベースの検索** — ADR-0013 でオペレータ自身が引いた上限
  （「RAG までは要らない」）によりスコープ外。
