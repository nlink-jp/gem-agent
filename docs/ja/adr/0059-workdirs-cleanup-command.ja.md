# ADR-0059: `workdirs` — 作業ディレクトリ報告の「掃除側」

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-08-31 |
| Binds | gem-agent |
| Decision makers | nlink-jp maintainers |
| Triggered by | 利用者「起動時の note は蓄積を警告するのに掃除ツールが無い — 片手落ちではないか」 |
| Amends | ADR-0058 §5（自動削除はしない） |

## Context

ADR-0058 は意図して何も削除しない。作業ディレクトリのファイルこそが成果物で
あり、保持は利用者の判断だからだ。それが黙った蓄積にならないよう、起動時に
以前のセッションの作業ディレクトリの件数と容量を報告する。

承認済みプランには「削除は明示コマンドのみ」とあった。報告は出荷されたが、
コマンドは出荷されなかった。つまり note は、ツールが対処手段を提供しない
問題を利用者に告げている — 対処なき報告であり、報告を無視する訓練にしか
ならない。

## Decision

`sessions` と対をなす CLI サブコマンド `workdirs`:

- **`gem-agent workdirs`** は現在のプロジェクトのセッション作業ディレクトリを
  一覧する — id・最終更新からの経過・ファイル数・容量・合計。`--all` で
  全プロジェクト分。一覧こそが dry run であり、別途 `--dry-run` は設けない。
- **`gem-agent workdirs clean`** が削除する。形は 2 つ:
  id 明示（`clean 20260831-022743 …`）、または引数なしの `clean` で
  現在プロジェクトの非稼働ディレクトリ全部。プロジェクト横断の掃除は
  意図して無い: note が出た場所で実行する。
- **人間の確認が既定。** 削除対象（id・容量・合計）を正確に印字して問う。
  EOF や `y` 以外は中止 — 承認ゲートと同じ deny-on-EOF の構え。
  スクリプト用に `--yes` があり、非 TTY で `--yes` なしは黙って同意せず拒否する。
- **稼働中セッションのディレクトリは決して消さない。** 稼働セッションは
  logger の生存期間中 transcript に排他 flock を保持する（ADR-0021）ので、
  生存判定は transcript への共有 flock 試行で行う: `EWOULDBLOCK` なら稼働中で、
  そのディレクトリは注記付きでスキップ。transcript を持たない作業ディレクトリ
  （隔離 state での実行・削除済みログ）は非稼働として扱う。
- **slash コマンドではなく CLI。** ディスクを空けるのにモデルセッションを
  要してはならない — これはバックアップツールであり、保守面は他の何も
  動かないときに動く必要がある。起動時 note はここを指すようになる:
  `review with 'gem-agent workdirs'`。

削除自体は、検証済み単一セグメントの session id からツールが組み立てたパスへの
`os.RemoveAll` — 利用者入力のパスは受け取らないため traversal の余地がない。
組織の手動削除規則（フルパス・再帰禁止）はエージェントの場当たりシェル操作を
律するもので、明示確認の下で自身の state を消す製品コマンドはその規則が指す
形そのものである（data-toolbox の `delete_workspace`、lookup 系の
`cache --clear` と同型）。

## Consequences

- 起動時 note が対処手段を得て、単数形の文法も直る
  （`1 … directory holds`、`hold` ではなく）。
- note とこのコマンドは他の起動診断・CLI サブコマンドと同じく stderr/stdout の
  英語 — ja/en の uitext カタログ（ADR-0029）の**意図的な対象外**とする。
  カタログが覆うのは対話セッションの chrome である。見落としと誤読されない
  よう判断として記録する。
- `internal/workdir` に `List` と `Remove` を追加。`Sweep` は `List` 上の
  集計になり、note と一覧が食い違えなくなる。
- `internal/session` に flock プローブ `InUse` を追加。プローブ対象のロックと
  同じく advisory であり、flock 非対応ファイルシステム上の state root では
  非稼働と報告される — それは黙った削除ではなく、利用者が読む確認プロンプト側へ
  倒れる失敗である（確認は常に全 id を列挙する）。

## Alternatives considered

- **経過時間・容量ベースの自動掃除。** 却下: ADR-0058 が引いた線を再び越える。
  利用者が見ていない出力をエージェントが消すことが失敗モードそのものであり、
  閾値の問題ではない。
- **slash コマンド `/workdirs` を主面にする。** 却下: 稼働セッションが必要に
  なるが、掃除はまさにセッションに**いない**ときの作業である。後日の
  便宜ビューとしての追加は妨げない。
- **`--keep` / `--older-than` セレクタ。** 見送り（スコープ最小主義）:
  id 明示と全非稼働で観測された需要は覆える。実セッションの利用パターンが
  要求したときに足す。
