## Context

`CallDetail` は 1 行のイベント表示のために書かれたもので、シェルコマンドは 300 文字、それ以外の引数は 120 文字、行全体は 300 文字で切る。承認ゲートが受け取るのはこの文字列だけだった。さらにダイアログはそのうち最大 8 行しか出さない。そのため、長いコマンドは効果の部分を操作者の見える範囲の外に置けたし、編集は文字列が約 270 桁を占めてパスがほとんど見えず、省略行の案内は「拒否して別の方法で確かめる」だった。

ダイアログの役割は、内容を理解したうえでの同意である。隠れた行数を数えても、問題を正直に示すだけで解決にはならない。

## Decision

1. **呼び出しの描画を 2 つにする。** `Describe` / `CallDetail` は、イベント、テレメトリ、記録のための切り詰めた要約のままとする。ゲートには `approvalDetail` / `FullCallDetail` を渡す。シェルコマンドは全文、それ以外は全引数で、`path`、他の短い値、長い値の順にする。長い本文が短い引数を最初の画面から押し出すことはない。文字列でない値は JSON で表示し、リストの境界や数値の形を保つ。長い値や複数行の値は名前の下に字下げする。ツールの注記（「既存ファイルを置き換える」など）は長い本文の下に埋もれないよう先頭に置く。
2. **上限は明示する。** 切り詰めるのは名前と値の合計が 64 KiB を超える呼び出しだけで、それも名前と値ごとに上限の取り分（最低 64 バイト）を超えた分だけなので、短い引数には影響しない。省略の印などの分だけ、表示される文字列は上限を超えることがある。切り詰めた値は先頭と末尾を残す。コマンドの効果は末尾にありうるからである。省略は本文の該当箇所に示す。省いた量は詳細の先頭行にも示す。下のほうの印は、そこまでスクロールしない人には警告にならないからである。モデルはどんな大きさの `write_file` でも渡せ、ダイアログは描画のたびに折り返し直す。
3. **ダイアログはスクロールする。** 窓は最大 20 行で、短い端末ではそれより少ない。↑↓ で 1 行、PgUp と PgDn で 1 ページ、Home と End で端まで動く。収まらないときは、位置と隠れた行数を示す行を出す。レイアウトに行の余地がないときは行数を示し、承認しないよう伝える。新しい問いは先頭から開く。タブは折り返しの前に展開する。折り返しはタブを 0 桁、描画は複数桁と数えるので、そのままでは行が枠を超えて末尾が黙って失われる。呼び出しの各行は `┊` で始まるので、呼び出しの始まりと終わりを目で追える。macOS のターミナルの既定のプロファイルでは、Shift を押さない限りページキーと Home、End が端末自身のスクロールに使われることがある。↑↓ はどこでも使える。
4. **↑↓ は回答の選択を動かさない。** これまでは文書化されないまま選択を動かしていた。←→ と Tab はそのまま動く。日本語 IME が有効でも使えるのは矢印キーなので、スクロールを英字キーにはできない。
5. **報告は短いままにする。** `denyGate` は呼び出しを 1 行で報告する（`ClipDetail` が行をまとめて切り詰める）。素の REPL のプロンプトは全文を表示する。端末のスクロールバックがその役割を果たすからである。

## Consequences

- レイアウトは読むためのもので、何も証明しない。文字はモデルのものであり、折り返された行、申告された目的、複数行のコマンドは、別の引数やダイアログ自身の行に見せかけることができる。そうではないと約束した草案は、レビューを受けて取り下げた。約束するのは有限のことだけである。すべての引数があり、短いものが先に来て、タブで行末が失われず、省略した分は明示する。
- 読むことは強制しない。操作者はスクロールせずに答えてよく、まだ見ていない分は位置の行が示す。
- トランスクリプトの `gate_decision` はこれまでどおり切り詰めた要約を持つ。全文はトランスクリプトのツール呼び出しの記録にある。

## Alternatives considered

- **最後までスクロールしないと `y` を受け付けない** — 不採用: 許可するつもりの長い `write_file` に、儀式のようなキー操作を強いる。
- **別の全画面ページャ** — 不採用: 箱の中の窓で足りることに、別の画面とキーが増える。
- **切り詰めの上限を上げる** — 不採用: 切る位置が動くだけで、その先を見る手段にならない。
