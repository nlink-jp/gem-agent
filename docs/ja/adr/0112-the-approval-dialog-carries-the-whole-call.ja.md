## Context

`CallDetail` は 1 行のイベント表示のために書かれたもので、シェルコマンドは 300 文字、それ以外の引数は 120 文字、行全体は 300 文字で切る。承認ゲートが受け取るのはこの文字列だけだった。さらにダイアログはそのうち最大 8 行しか出さない。そのため、長いコマンドは効果の部分を操作者の見える範囲の外に置けたし、編集は文字列が約 270 桁を占めてパスがほとんど見えず、省略行の案内は「拒否して別の方法で確かめる」だった。

ダイアログの役割は、内容を理解したうえでの同意である。隠れた行数を数えても、問題を正直に示すだけで解決にはならない。

## Decision

1. **呼び出しの描画を 2 つにする。** `Describe` / `CallDetail` は、イベント、テレメトリ、記録のための切り詰めた要約のままとする。ゲートには `approvalDetail` / `FullCallDetail` を渡す。シェルコマンドは全文、それ以外は全引数で、`path` を先頭に、長い値や複数行の値は独立した行にする。ツールの注記（「既存ファイルを置き換える」など）は長い本文の下に埋もれないよう先頭に置く。
2. **上限は明示する。** 1 回の呼び出しで運ぶのは 64 KiB までとし、それを超えたら省いたバイト数を文中に示す。モデルはどんな大きさの `write_file` でも渡せ、ダイアログは描画のたびに折り返し直すからである。
3. **ダイアログはスクロールする。** 窓は最大 20 行で、短い端末ではそれより少ない。↑↓ で 1 行、PgUp と PgDn で 1 ページ、Home と End で端まで動く。収まらないときは、位置と隠れた行数を示す行を出す。新しい問いは先頭から開く。
4. **↑↓ は回答の選択を動かさない。** これまでは文書化されないまま選択を動かしていた。←→ と Tab はそのまま動く。日本語 IME が有効でも使えるのは矢印キーなので、スクロールを英字キーにはできない。
5. **報告は短いままにする。** `denyGate` は呼び出しを 1 行で報告する（`ClipDetail`）。素の REPL のプロンプトは全文を表示する。端末のスクロールバックがその役割を果たすからである。

## Consequences

- 読むことは強制しない。操作者はスクロールせずに答えてよく、まだ見ていない分は位置の行が示す。
- トランスクリプトの `gate_decision` はこれまでどおり切り詰めた要約を持つ。全文はトランスクリプトのツール呼び出しの記録にある。

## Alternatives considered

- **最後までスクロールしないと `y` を受け付けない** — 不採用: 許可するつもりの長い `write_file` に、儀式のようなキー操作を強いる。
- **別の全画面ページャ** — 不採用: 箱の中の窓で足りることに、別の画面とキーが増える。
- **切り詰めの上限を上げる** — 不採用: 切る位置が動くだけで、その先を見る手段にならない。
