# ADR-0033: ターン可観測性 — 鼓動・リトライ・思考

| 項目 | 値 |
|------|----|
| ステータス | **承認済み** |
| 日付 | 2026-08-21 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレーター: thinking のまま応答が延々と返ってこないことがあり、何が起こっているのか画面から分からない |

## 文脈

ターン中のステータス行はスピナーと固定文言「thinking…」だけだった。
その裏で 3 つの状況が同一に見えていた:

1. モデルが健全に思考中（thought チャンクは**届いている** — 高い
   思考レベルは最初の可視トークンまで数分使うことがある）;
2. 接続が失速して何も届いていない;
3. ストリームが失敗し、無言の指数バックオフ再試行中（最大 3 回・
   バックオフ上限 15 秒 — 意図的な沈黙が 30 秒を超え得るのに表示
   ゼロ）。

オペレーターは「待つべき」と「中断して仕切り直すべき」を区別できず、
「何をしているのか?」には画面上の答えが存在しなかった。

## 決定

### 1. ストリーム鼓動、常時表示

バックエンドは受信した全チャンクをオブザーバーに報告し、TUI の実行中
ステータスがライブになる:

    thinking… 1m07s · 34 chunks · last 0s

— ターン開始からの経過、受信チャンク数、最終受信からの秒数。
thought のみ・メタデータのみのチャンクも数える: 問うているのは
生存性であって可視性ではない。20 秒無受信で警告スタイルに切り替わり
その旨を表示する — 失速した接続が思考中のモデルと**違って見える**
ようになり、Ctrl+C が選択肢だと分かる。自動タイムアウトは追加しない:
長い思考は正当であり、表示 + オペレーターの判断は、本物の仕事を殺す
タイマーに勝る。

### 2. リトライは見える

バックオフループは各再試行の予定を報告し、ステータス行は沈黙の
代わりに `retry 2/3 (429) — waiting 4s` を表示する。意図的な待機が
ハングと見分けられてはならない（「無言の意図的状態」の教訓）。

### 3. 思考サマリはライブ表示・揮発性

`[tui].show_thoughts = true`（既定）のとき、リクエストは thought
summary（`IncludeThoughts`）を要求し、TUI はそれをライブ領域に dim
スタイルで流す。実回答が始まると置き換わる。これが「何が起こって
いるのか」への直接の答えである: モデルが自分の進捗を実況する。

正直さと経済性の境界を 2 つ:

- **設計として揮発。** 思考テキストは表示して捨てる — transcript には
  書かず、履歴でも再送しない。保存形は ADR-0018/0021 が実測した形の
  まま: thought パートは署名だけを運ぶ。（実測済み: サマリ要求 ON +
  テキストを剥いだ再送で、複数ラウンドのツールターンも resume も
  クリーンに通る。）
- **メインループのみ。** 側呼び出し（リスク評価・圧縮・要約・Web
  ダイジェスト）と要約モデルは thought を要求しない — 誰も見ていない
  ストリームである。

`show_thoughts = false` で静かなスピナーに戻る。鼓動とリトライ表示は
残る — あれは装飾ではなく正しさの可観測性である。素の REPL と単発
実行は対象外: 出力先はパイプである。

### 4. ステータス文字列がカタログに入る

実行中状態の文字列（「thinking…」「waiting for the tool…」「圧縮
中…」「中断中…」、鼓動とリトライの書式）は ADR-0029 のカタログに
入っていなかった。今回両言語で入れる — まさにカタログが存在する
理由であるオペレーター向けクロームだからである。

## 帰結

- 「考えているのか、詰まっているのか」が一目で分かり、答えは毎秒
  更新される。
- thought summary の要求はリクエスト設定を変えるが、応答の保存経路は
  不変と実測済み（署名のみの再送が受理される）。サマリは思考レベルが
  既に支払っている thought トークン予算に乗る。
- 本当に死んだ TCP 接続も「last Ns」が育つ形でしか現れない — 中断の
  判断はオペレーターに残る。受容: どんな自動遮断も正当な長考を同時に
  遮断する。
