# ADR-0032: 決定的な日付/時刻ツール

| 項目 | 値 |
|------|----|
| ステータス | **承認済み** |
| 日付 | 2026-08-21 |
| 拘束対象 | gem-agent |
| 意思決定者 | nlink-jp maintainers |
| 契機 | オペレーター: 現在日時を取得する内蔵ツールと、日付計算をする内蔵ツール — LLM は日付計算が苦手と聞く |

## 文脈

モデルには時計がない: システムプロンプトにもツール群にも今日の日付は
なく、「今日は何日?」は訓練カットオフに引きずられた推測になり、
オペレーターの相対表現（「先週の火曜から」「来月末までに」）は全部
間違った「今」に対して静かに解決される。カレンダー算術は「無い」より
悪く「自信を持って間違う」: 月の長さ・閏年・ISO 週・タイムゾーン
オフセットは、言語モデルが確信ありげにしくじる桁上がりだらけの記号
操作そのものである。次善策の `shell_exec date` は、リスクゼロの計算に
承認（または auto-approve のリスク評価）を 1 回浪費する。

## 決定

### 1. read-only ツール 1 本 `datetime`、操作 5 つ

`now`（既定）・`info`・`add`・`diff`・`convert` を `op` 引数で選ぶ。
2 本ではなく 1 本: 「現在時刻」は算術ツールをゼロで評価しただけの
ものであり、レジストリは小さいまま、モデルが覚える名前は 1 つ。
`Mutating: false` — `agent_info`（ADR-0030）同様に承認なし。開示する
のは時計である。

- **now**: ローカル時刻（RFC3339）・タイムゾーン名とオフセット・
  UTC・unix 秒・曜日・ISO 週。
- **info**（`date`）: 曜日・年内通算日・ISO 週・その月の日数・閏年。
- **add**（`base` + 符号付き `years/months/days/hours/minutes`）:
  移動後の時刻と曜日。Go の `AddDate` 正規化はそのまま保ち、発動時は
  **出力で明言**する（1/31 + 1 ヶ月 = 3/3）: 黙って正規化された日付は
  「一ヶ月後」バグの出荷経路である。
- **diff**（`a`, `b`）: 符号付きカレンダー内訳（年/月/日）・総日数/
  時間/分・両端の曜日。**営業日カウントは載せない**: 祝日カレンダー
  なしの平日算術は、それが使われる場面（日本の祝日）でこそ間違う。
  権威ある形をした誤数値は無いより悪い。
- **convert**（`time`, `to`, 任意 `from`）: IANA ゾーン変換。入力に
  明示オフセットがあれば `from` より優先。

日付の受理形式は RFC3339・`2006-01-02`・ナイーブな
`2006-01-02[T ]15:04[:05]`（操作の `tz` 引数、既定はローカルで解釈）。
エラーは受理形式を名指しする。

### 2. セッション開始日はシステムプロンプトに載る

日付・曜日・タイムゾーンの 1 行。受動的な参照はツールラウンドなしで
解決される。意図的に**セッション開始時**の日付である: リクエスト毎の
タイムスタンプはプレフィックスキャッシュを毎ターン壊す（ADR-0018）。
ドリフトには正直で、行自体が「現在時刻は `datetime` を呼べ」と言う。

### 3. 実装の形

`internal/tools/datetime.go`、他の built-in と同じ場所で登録。注入
可能な時計（パッケージ変数 `timeNow`）上の純計算なのでテストは厳密な
値を固定できる。出力はコンパクトな key: value の英語（モデル向け =
ADR-0029 §3）。タイムゾーン DB はホストの `/usr/share/zoneinfo` — 
このプロジェクトが拘束される macOS には常にある。

## 帰結

- 「今日は何曜日?」「この 2 つの日付の間は何日?」・タイムゾーン変換・
  締切計算が、確信ありげな推測や承認付き `date` ではなく決定的な
  1 コールになる。
- モデルが見る時計はホストの時計: システムクロックが狂っていれば
  そのまま伝播する。受容 — どの代替案も同じ時計に立脚する。
- 月末の正規化セマンティクスは隠さず表面化する。営業日は近似せず
  拒否する。
