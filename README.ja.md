# gem-agent

Vertex AI Gemini 3.x をバックエンドとする CLI 対話型エージェント — Claude Code が
利用できない状況での開発作業継続手段。

> **リリース済。** `brew install nlink-jp/tap/gem-agent` または
> [リリースページ](https://github.com/nlink-jp/gem-agent/releases)から
> 導入できます（Developer ID 署名 + Apple notarize 済み、macOS arm64）。
> 現在の版はリリースページが正であり、ここには書きません（腐るため）。
> 実験的ツール（lab-series）であり、リリース間でインターフェースが変わる
> ことがあります。完全な仕様は [RFP](docs/ja/gem-agent-rfp.ja.md) を参照。

[English README](README.md)

## Why

Claude Code が使えない状況（プロバイダ側障害・契約やネットワークの制約）でも
開発作業を止めないためのツールです。独立したバックエンド（Vertex AI）上の
意図的に最小限なフォールバックエージェントで、**drop-in** を最重要要件と
します: 既存プロジェクトの `AGENTS.md` / `CLAUDE.md` / `.mcp.json` をそのまま
解釈するため、乗り換えにプロジェクト単位の再設定は不要です。

## 機能（実装済み）

- **対話 TUI**（Bubble Tea、inline 方式 — 素のスクロールバックとコピペが
  そのまま使える）: スピナー/ステータス付きストリーミング表示、↑↓ 履歴と
  複数行編集（Ctrl+J）付き入力ボックス、色分けされたツールイベント、承認
  ダイアログ、glamour による Markdown 整形描画。パイプ/スクリプト利用時は
  自動的に素の行 REPL にフォールバック
- Gemini エージェントループ — Gemini 3 thought signature の capture/replay
  （実機検証済み）
- 組み込みツール: `list_files` / `list_tree` / `search_files` / `read_file` /
  `summarize_file` / `view_image` / `read_document` / `write_file` /
  `edit_file` / `shell_exec`
  （すべてプロジェクトディレクトリに封じ込め。シンボリックリンク経由の脱出も検査）。
  `list_tree` はプロジェクトをツリー表示、`search_files` は依存ゼロの高速 grep
  （regex / literal、バイナリと `.git` はスキップ、上限は報告）— 方向づけが
  「ディレクトリごとに 1 ラウンド」から 1 コールになります
- **`file_info`**（ADR-0016）: ファイルを文脈に読み込まずに「何なのか」を
  答えます — 内容から判定した種別（`file` コマンド流: Mach-O/ELF/PE・
  アーカイブ・スクリプト。拡張子は表示するが信用しない）、サイズ・モード・
  更新時刻・**作成時刻**（macOS 専用設計なので Darwin フィールドは無償）、
  そしてハッシュ照合ツールが食べる MD5/SHA1/SHA256 の三点セット — IR の
  初手が読み取り専用 1 コールで揃います。`paths` でバッチ、symlink は
  報告のみで黙って辿りません
- **往復しない編集**（ADR-0015）: `edit_file` は「一意な文字列の完全一致」
  契約を維持しつつ — 行番号は古くなると**黙って**間違った場所に書き、文字列
  アンカーは大きな音で失敗するか正しく動くかのどちらか — 安くする装備を
  得ました: 順に**アトミック**適用される `edits` 配列（どれかが失敗すれば
  何も書かず、何番目がなぜ失敗したかを名指し）、リネーム用 `replace_all`、
  **診断つき不一致**（空白違いの近似一致をファイルの実テキスト + 行番号で
  引用 — 修正は再読ではなくコピペ）、**成功時の証拠**（変更後領域を行範囲
  つきで返すので読み戻し検証が不要）。意図するループは
  「窓読み → 一括編集 → 結果で検証」です
- **コンテキスト経済**（ADR-0014）: `read_file` は `start_line`/`end_line` で
  全文ではなく窓を読めます（注記付きで、部分が全体のふりをしない — 行番号
  プレフィックスは付けません。`edit_file` の完全一致契約を毒するので）。
  `summarize_file` はバイト列の代わりに短い要約を返します — 書くのは
  `[model].summary` の軽量モデル（メインモデルとクライアント共有）、未設定なら
  メインモデル。ファイル内容は圧縮と同じく nonce ラップ + ツール無しで要約器に
  渡り、ブロックされた要約は報告されるエラーであって無言の空要約にはなりません
- 変更系ツールの都度承認ゲート（MITL）+ セッション内 allowlist
  （`y` = 1回、`a` = このセッションでは常に許可。拒否側に倒れる設計）。
  `a` は危険側には届きません: Block 判定のコール（sudo・再帰削除・
  クレデンシャルパス等）と、ポリシーで "always" 指定のツールは
  以後も必ず確認します（ADR-0021）
- **自動承認モード**（opt-in、shift+tab または `/auto`）: 変更系コールごとに
  二層レビュー — まずルールベース分類器、不確実なものだけモデルによるリスク
  評価。安全なものは無人実行、破壊的・プロジェクト外・認証情報関連・不確実な
  ものは従来どおり確認。詳細は [ADR-0004](docs/ja/adr/0004-auto-approve.ja.md)
- `shell_exec` の macOS sandbox-exec ラップ — ファイル書き込みをプロジェクト
  ディレクトリ + scratch に制限（実 Seatbelt での強制テスト付き）
- ペースト安全な入力: 複数行ペーストは 1 つの入力になる（行ごとに LLM コールが
  飛ぶことはない）
- **セッション再開**: `--continue` でこのプロジェクトの最新セッション、
  `--resume <id>` で特定のセッションを再開。`gem-agent sessions` で一覧。
  `~/.local/state/gem-agent/sessions/` の JSONL トランスクリプトはログで
  あると同時に resume の正本であり、完全忠実に記録されます（API が再生時に
  要求する Gemini の推論トークンを含む）。詳細は
  [ADR-0005](docs/ja/adr/0005-session-resume.ja.md)
- **コンテキスト圧縮**: 会話がモデルのウィンドウに近づくと、ターンを失敗させる
  代わりに要約します — 古い側は 1 件の要約になり、直近はそのまま残ります。
  既定は 80%（`[agent].compact_at_pct`）で自動、`/compact` で任意のタイミングに
  手動実行。詳細は [ADR-0006](docs/ja/adr/0006-context-compaction.ja.md)
- **文書の読解**（ADR-0026）: PDF はそのままモデルへ — レイアウト・表・
  スキャンをネイティブに読みます（実測: オペレータ添付とツール応答内の
  両方で受理、後続ラウンドもクリーン）。Word/Excel/PowerPoint
  （.docx/.xlsx/.pptx）は標準ライブラリだけでローカルにテキスト抽出:
  段落、タブ区切りのシート行、番号付きスライド。経路は ADR-0012 の
  分割どおり 2 つ — ファイルを選ぶのがあなたなら `@report.pdf` /
  `@data.xlsx`（絶対・~ パス可 — 打ったのはあなた自身）、モデルなら
  `read_document` ツール（プロジェクト封じ込め）。レガシー
  .doc/.xls/.ppt は対象外と明言します
- **エージェントメモリ**: `save_memory` / `delete_memory` で短い事実を
  セッションを跨いで永続化 — グローバルスコープ（利用者やこのマシンの
  こと、どこでも想起）とプロジェクトスコープ（そのプロジェクトのみ）。
  実体は `~/.local/state/gem-agent/memory/` 配下の素の markdown で、
  リポジトリ内には決して書きません。セッション開始時にシステムプロンプトへ
  ロードされ、書き込みは承認ゲート付き。詳細は [メモリ](#メモリ) と
  [ADR-0020](docs/ja/adr/0020-agent-memory.ja.md)
- スラッシュコマンド: `/help` `/tools` `/mcp` `/usage` `/memory` `/compact`
  `/clear` `/quit` — `/usage` はセッションのトークン明細書（ADR-0019）: メイン
  ループのラウンド数とキャッシュ率、リスク評価・圧縮の側呼び出し、
  トークンを使ったモデル名つきのツール別行（summarize/web）
- **drop-in プロジェクト互換**: プロジェクトが既に持つエージェント指示ファイル
  （`AGENTS.md` / `AGENT.md` / `CLAUDE.md` / `GEMINI.md`）を、他のエージェントと
  同様に**親ディレクトリまで遡って**探索しシステムプロンプトへ注入。ワーク
  スペース共通ルールが配下の全リポジトリに効きます。`.mcp.json`（Claude Code
  形式、stdio サーバー）もそのまま接続 — プロジェクト単位の追加設定ゼロ
- MCP クライアント: ツールは `mcp__<server>__<tool>` として常に承認ゲート付き。
  タイムアウトした呼び出しはサーバー子プロセスを kill（MCP にキャンセルは無い）、
  次回呼び出しで遅延再起動
- ツール出力はノンス XML タグ（nlk/guard。メインループはセッションスコープ、
  側呼び出しは per-call — ADR-0018）で隔離 — ツールが返す
  内容は常にデータであり指示ではない、という枠付けを強制
- 単発実行モード `-p "<prompt>"`: 1 ターンで終了、回答は stdout、変更系ツールは
  拒否（パイプ向け）
- Vertex の一時障害（429/5xx）は指数バックオフでリトライ
- **implicit コンテキストキャッシュ**（ADR-0018）: 隔離タグをセッション
  スコープにしたことでリクエストのプレフィックスがラウンド・ターンを跨いで
  バイト同一になり、再送される履歴が Vertex の implicit caching で
  キャッシュ価格になります。同一 4 ラウンドタスクの実測: 旧 per-call タグは
  **0%**、セッションタグは **81〜95% キャッシュ**。フッターに実効率
  （`cache NN%`）を表示。nlk/guard がタグ名を含むコンテンツを拒否するため
  健全 — 漏れたタグは運び手を差し止めさせられるだけで、ラッパーからの脱出
  には使えません

設計上のスコープ外: RAG・ベクトルメモリ、データ分析、GUI、macOS 以外の
プラットフォーム。

## 使い方

```sh
cd /path/to/your/project
gem-agent                                  # 対話 REPL
gem-agent -c                               # ここでの最新セッションを再開
gem-agent sessions                         # 再開可能なセッション一覧
gem-agent -p "このリポジトリを要約して"      # 単発実行、パイプ向け
```

カレントディレクトリがプロジェクトになります: ファイルツールはそこから出られず、
サンドボックス化されたシェルコマンドは外側に書き込めません。変更系ツールは実行前に
承認ダイアログが出ます。回答は**選択式**（←→ または Tab で移動、Enter で決定）と
**ショートカット**（`y` = 1回 / `n` = 拒否 / `a` = このセッションでは常に許可、
Esc = 拒否）のどちらでも可能です。選択式があるのは、**日本語 IME が ON のままだと
y/n/a が変換に吸われて入力できない**ためです。初期選択は「許可」ですが、自動承認が
エスカレーションしたコールでは「拒否」から始まり、反射的な Enter で危険な操作を
通してしまわないようにしています。`--no-sandbox` は Seatbelt ラップの無効化
（デバッグ専用）、`--model` はモデルの上書きです。

TUI キー操作（`/help` にも一覧あり）: Enter 送信、↑/↓ 入力履歴、Ctrl+C
実行中ターンの中断（入力中はクリア）、Ctrl+D 終了。

**ターン実行中も入力できます。** Enter は送信ではなく**次のメッセージとして
予約**し（実行中の会話はエージェントループが所有しているため）、そのターンが
正常に終わった時点で送信されます。ターンがエラー・中断で終わった場合は、
予約したテキストは**未送信のまま入力欄へ戻ります** — 失敗したターンに向けて
書いたメッセージが、そのまま送りたいメッセージであることは少ないからです
（[ADR-0007](docs/ja/adr/0007-input-during-a-turn.ja.md)）。

**複数行入力**:

| 方法 | 使用可否 |
|---|---|
| `Ctrl+J` | 常に使える（確実な経路） |
| 行末に `\` を置いて `Enter` | 常に使える（シェルの慣習） |
| `Option`/`Alt` + `Enter` | ターミナルが Option を Meta として送る設定のときのみ |

修飾キー + Enter が効かないのはアプリ側の都合ではなく**ターミナルの制約**です。
エスケープ前置を送る設定になっていない限り、`Option+Enter` も `Shift+Enter` も
通常の改行コードとして届くため送信と区別できず、**メッセージが送信されます**。
`Option+Enter` を使いたい場合は以下を設定してください:

- **Terminal.app** — 設定 → プロファイル → キーボード → *Option キーを Meta キーとして使用*
- **iTerm2** — Settings → Profiles → Keys → Left Option key → *Esc+*

複数行のペーストは設定に関係なく常に使えます（ペースト全体が 1 メッセージとして
入力ボックスに入り、行ごとに LLM コールが飛ぶことはありません）。

### 自動承認モード

既定は OFF。shift+tab（または `/auto`）で切り替え、ON の間はステータスバーに
`⚡auto` が出ます。**shift+tab は実行中のターンでも効きます** — 手動モードで
始めた長いエージェントループを、終わるのを待たずに自動承認へ切り替えられます
（次のツールコールから反映。既にダイアログで待っているコールには回答が必要）。ON のとき変更系ツールコールは次を通ります:

1. **ルール層**（モデル呼び出しなし）: *safe* → 実行、*block* → 必ず確認
   （`rm -rf`・`sudo`・`git push`・ダウンロードのシェル直パイプ・ディスク
   書き込み・認証情報パス・プロジェクト外など）、*不確実* → 第 2 層へ
2. **モデル層**: 別の評価ラウンドが対象コールを判定（コールはノンス隔離した
   非信頼データとして渡し、この評価ラウンドにはツールを一切与えない）。
   承認 **かつ** 高確信のときだけ自動実行、それ以外は確認へ

失敗系（モデルエラー・壊れた verdict・未知ツール）はすべて確認へ倒れます。
block 層はモデルが覆せない硬い床で、sandbox はどのモードでも有効です。

**どちらの結果も理由が表示されます**: 自動承認されたコールは理由付きで表示され、
確認に回されたコールは承認ダイアログに `⚠` 行が付き、**どの層が止めたのか**まで
分かります — 決定論的な床なら `blocked by rule (always asks): …`、モデルの
判断なら `escalated by risk review: …`。

`@<パス>` でプロジェクト内のファイル/ディレクトリをメッセージに添付できます。
`@src/main.go これ直して` のように書くとファイル本体が指示と一緒に送られ、
`@docs/` ならディレクトリ一覧が送られます。**Tab で補完**できます（まず共通
プレフィックスまで、それ以上進めないときは候補一覧を表示）。参照はシンボリック
リンク経由も含めプロジェクト内に限定され、添付できなかった参照は黙って捨てずに
理由付きで報告します。添付内容はツール出力と同様に**非信頼データとして隔離**して
モデルに渡されます。

`!<コマンド>` でシェルコマンドを直接実行できます — `shell_exec` と同じ
sandbox 下（タイムアウト・出力上限も共通）ですが、自分で打ったコマンドなので
承認プロンプトは出ません。コマンドと出力はモデルの文脈にも追加されるため、
`!git status` してから「これを直して」という流れがそのまま成立します。

入力欄とステータスバーは Claude Code と同様に**ウィンドウ最下部に固定**され、
会話はその上を流れます（素のスクロールバックは維持。ADR-0003; 起動時に画面を
1 回クリアします）。ステータスバーには使用モデル・コンテキスト使用量と
ウィンドウサイズ（モデルメタデータから自動検出、`[model].context_window` で
上書き可）・累計消費トークン・プロジェクトディレクトリを表示します。

### セッションの再開

```sh
gem-agent sessions        # id・経過時間・モデル・最初の質問
gem-agent -c              # このディレクトリの最新セッション
gem-agent --resume 20260819-150102
```

再開したセッションは自分自身のトランスクリプトに追記されます — 何プロセスに
またがろうと 1 ファイル = 1 会話 — そしてツール結果まで含めて元のとおりに
戻ります。2 つの拒否は意図的なものです: セッションは記録されたディレクトリで
のみ、そして記録したモデルでのみ再開できます（再生する推論トークンがモデルに
紐づくため）。それぞれのメッセージが代わりの手を示します。圧縮済みの
セッションは圧縮された状態で戻ります（縮めた元のサイズに膨らみ直しません）。

したがってトランスクリプトには、エージェントが読んだ全ファイルの本文が
入ります。置き場所は
`~/.local/state/gem-agent/sessions/projects/<エスケープ済パス>/`、モードは
`0600` — メモリと同じ規約の**プロジェクト別サブディレクトリ**です
（ADR-0022）。一覧は 1 ディレクトリを読むだけになり、あるプロジェクトの
ディレクトリ内での掃除が別プロジェクトの transcript に触れることは
構造的にできません。旧バージョンがフラットな `sessions/` 直下に記録した
transcript はその場で読み取り継続されます（一覧・resume とも可、移動は
しません）。環境変数 `GEMAGENT_STATE_DIR` は state ルート全体（sessions と
memory）を差し替えます — テストと訓練の隔離用です。

### 会話の圧縮

モデルのウィンドウの `[agent].compact_at_pct`（既定 80%）に達すると、会話の
古い部分がその要約に置き換わり、直近はそのまま残ります。`/compact` で任意の
タイミングに同じことができます。通知には何件を要約したかを出します — その後
その半分の詳細は二次情報になるので、忘れたモデルが最初から知らなかった
モデルのように見えてはならないからです。

要約呼び出しが失敗した場合（エラー、コンテンツフィルタ）は、履歴を一切変更
せずターンを続行します。`auto_compact = false` で自動側を止められます
（`/compact` は動きます）。

### `/settings`

`/settings` は全設定を **値の出所付き**で表示するパネルを開きます —
`flag` / `env:VAR` / `config.toml` / `policy.toml` / プロジェクトファイル /
`default`。4 層の優先順位を画面に一切出さない設計は、「利用者が覚えている」
ことを前提にしています。

↑↓ で選択、←→/Enter で値変更、`s` でポリシーの保存先（グローバル / このプロジェクト
のみ）を切替、Esc で閉じます。セッション途中に変えられない設定（モデル、GCP
プロジェクト、sandbox スイッチ）は読み取り専用で、理由を表示します。

永続化先は `~/.config/gem-agent/policy.toml` — gem-agent が所有して書き換える
ファイルです。手書きの `config.toml` には触れないのでコメントが残ります。衝突時は
`policy.toml` が勝ち、パネルはどのファイルが決めたかを表示します。パイプや素の
REPL では同じ行を読み取り専用で出力します。詳細は
[ADR-0009](docs/ja/adr/0009-settings-panel.ja.md)。

承認ダイアログには 4 つ目の回答 **今後聞かない (`p`)** が増えました — この呼び出しを
許可し、以後そのツールについては聞きません。ポリシーに書き込み、そう表示します。
1 セッション限りの `a` とは意図的に別物です。

### ファンクション単位の承認ポリシー

MCP ツールは呼び出しのたびに承認を求めます。サーバーのツールが何をするのか
gem-agent 側から知りようがないからです。あなたは知っているので、それを書けます:

```toml
# ~/.config/gem-agent/config.toml
[approval.tools]
"mcp__tor-exit-lookup__*" = "never"   # 読み取り専用の lookup サーバー
"shell_exec"              = "always"  # 自動承認モードでも必ず聞く
```

`"never"` は全モードでゲートを飛ばし、`"always"` は全モードでゲートします
（自動承認でもセッション内 `a` でも持ち上げられません）。未設定のツールは
現行どおりです。末尾 `*` は MCP サーバー全体にマッチします。解決は
**スコープ優先、次に特異性**（ADR-0021）: プロジェクトのルールはマッチする
ツールについて global のどのルールにも勝ち、同一スコープ内では完全一致が
wildcard より優先されます。単独の `"*"` は拒否します — 全ゲートの無効化が
1 文字で到達できてはいけません。

**`"never"` は「何でも実行」ではありません。** 呼び出しごとに効果が変わるツール
（`shell_exec`）では、ルール層の block パターン（`rm -rf`・`sudo`・
`curl … | sh`・認証情報パス・プロジェクト外への書き込み）は引き続き聞きます。

プロジェクト側は `<project>/.gem-agent.toml` に独自ポリシーを持てます
（`gem-agent.example.project.toml` 参照）。**向きが重要**です:

| プロジェクトファイルからの指定 | 有効になる条件 |
|---|---|
| `"always"`（承認を増やす） | 常に |
| `"never"`（承認を減らす） | **自分の**設定の `[approval].trusted_projects` にそのプロジェクトが載っているときだけ |

チェックアウトしたリポジトリは自分が書いたものとは限らず、clone しただけで
ゲートを外せてはいけません。無視したエントリは起動時に名前を出し、望むなら
追記すべき行も示します。詳細は
[ADR-0008](docs/ja/adr/0008-per-tool-approval-policy.ja.md)。

知っておくと便利な副作用: `-p` 単発モードは「答える人がいない」ので変更系ツールを
拒否しますが、`"never"` のツールはもともと聞かないので実行されます。読み取り専用の
MCP lookup に `"never"` を付ければ、パイプラインで使えます。

## Web アクセス

エグレスツールを 2 つ（ADR-0017）。どちらも**既定で承認ゲート**付きです —
クエリや URL 自体が、注入された指示がモデルの読めるものを持ち出せる経路に
なるため。緩和は[承認ポリシー](#ファンクション単位の承認ポリシー)でツール別に
（`"web_search" = "never"`）— これで `-p` 単発モードでも使えます:

- **`web_search(query)`** — メインモデルの Grounding with Google Search。
  グラウンディングされた回答が**出典つき**（タイトル・ドメイン・URI）で返る
  ので、主張を信じるのではなく確認できます。first-party で規約もクリーン —
  素の検索 API を使わなかった理由そのものです
- **`web_fetch(url, focus?)`** — 軽量要約モデルの URL Context ツール。
  ページはプロバイダのインフラが取得し、要約モデル自身のコンテキストで
  読まれます。この会話に入るのは**整理された抽出**（正確な名前・数値・日付を
  保った要点と注意点）だけです。サーバーサイド取得は SSRF というクラスを
  構造的に殺します — localhost や LAN には到達不能 — その鏡像コストとして
  イントラネット・認証付きページは取得できません（失敗は取得状態つきで報告）

Web コンテンツは非信頼です: 要約は通常どおり nonce ラップされたツール結果
として返り、ラップできない層（サーバーサイドのページ）にはフェッチプロンプトの
防御的枠書きが当たります。

## 画像

スクリーンショットは第一級の入力です（ADR-0012）。入り口は 3 つ + モデル用に 1 つ:

| 経路 | 例 |
|---|---|
| プロジェクト内ファイル | `@docs/mock.png これを再現して` |
| どこからでも（画像のみ） | `@~/Desktop/スクリーンショット.png` |
| クリップボード | Cmd+Ctrl+Shift+4 のあと `@clipboard ここがおかしい` |
| モデル起点 | `view_image` ツール（`read_file` と同じくプロジェクト封じ込め） |

プロジェクト外経路は画像限定で、安全なのは `@` が**あなたの打った入力**からしか
解析されないためです — モデル出力やツール結果からは決して解析されません。
`view_image` は逆方向です: MCP サーバーは画像ファイルを生成します
（urlscan の `get_screenshot`、pcap 抽出）— それをループ中のモデル自身が
見るための経路で、こちらはプロジェクト封じ込めのままです。MIME はバイト列から
判別し（拡張子を偽ったバイナリは拒否）、画像は 1 枚 8MB・1 メッセージ 4 枚まで。
超過は丸ごと拒否します — 切り詰めた PNG は小さい絵ではなく壊れたファイルです。

画像は nonce ラップできないため、隔離の立場は枠書きで示します — 画像内に
見えるテキストはデータであり指示ではない。これはタグ隔離より弱く、ドキュメントは
そう明言します。トランスクリプトはバイト列を保存するので、resume したセッションは
見ていたスクリーンショットごと復元されます。

## Skills

gem-agent は **Claude Code の skill 形式をそのまま読みます** — ただし
自前の設置場所から。MCP とまったく同じ配置です（形式互換は drop-in、
場所の共有は結合 — [ADR-0011](docs/ja/adr/0011-skill-scope-separation.ja.md)）:

| スコープ | パス | |
|---|---|---|
| グローバル | `~/.config/gem-agent/skills/<name>/SKILL.md` | gem-agent 自身の置き場 |
| プロジェクト | `<project>/.claude/skills/<name>/SKILL.md` | Claude Code と共有 |

`~/.claude/` は読みません — あれは Claude Code の生きた環境であり、暗黙に
相続すると主系の環境が変わるたびに副系の挙動が変わります。**共有は自分で張る
symlink** で、skill 単位でも丸ごとでも可能です（探索はリンクを辿ります）:

```sh
ln -s ~/.claude/skills/meeting-notes ~/.config/gem-agent/skills/meeting-notes
ln -s ~/.claude/skills ~/.config/gem-agent/skills   # 全部共有
```

frontmatter は最小限（`name` / `description` / `argument-hint`）だけ読み、
`allowed-tools` は無視します — gem-agent には自前の承認モデルがあり、他所の
権限付与を黙って尊重するとそれをバイパスするからです。名前衝突は MCP と同じく
プロジェクト側が勝ち、そう告げます。

skill は progressive disclosure です: 各 skill はシステムプロンプトに説明 1 行を
載せるだけで、本文は使うときに読み込まれます —

- **モデル**がタスクと説明の合致を見て `load_skill(name)` を呼ぶ。skill 自身の
  `references/`・`scripts/` は `load_skill(name, file)` で読める
- **利用者**は `/skill <name> [args]` で直接起動（本文はターンに直接注入 —
  余分なモデル往復なし）。`/skills` が一覧

skill の内容は非信頼データとしてラップせず、**指示として**扱います —
利用者自身が導入したファイルであり、`AGENTS.md` と同じ信頼階層だからです。
この例外には境界があります: `load_skill` は発見済み skill のディレクトリ内
しか読めません（シンボリックリンクも解決して検査）。`scripts/` を
`shell_exec` で走らせる場合も sandbox と承認ゲートは他と同様に掛かります。
詳細は [ADR-0010](docs/ja/adr/0010-skills.ja.md)。

## メモリ

エージェントは短い事実をセッションを跨いで永続化できます（ADR-0020）:
決定事項、好み、環境の癖 — プロジェクトのファイルには書かれていないが
次回も知っていてほしいこと。

| スコープ | 想起される場所 | 保存先 |
|---|---|---|
| `global` | 全プロジェクト | `~/.local/state/gem-agent/memory/global/<name>.md` |
| `project` | そのプロジェクトのみ | `~/.local/state/gem-agent/memory/projects/<エスケープ済パス>/<name>.md` |

- 1 メモリ = 1 つの小さな markdown ファイル。同名で保存すると更新。
  セッション開始時に全件がシステムプロンプトへロードされ（グローバルが
  先、プロジェクトが後）、固定予算で抑えられます。切り詰めは無言ではなく
  必ず報告されます。
- **書き込みは承認ゲート付き**（`save_memory` / `delete_memory`）:
  永続化されたメモリは以後の全セッションのプロンプトに現れるため、
  メモリは注入された指示の永続化経路になり得ます — だから人間が書き込み
  1 件ごとにレビューします。そのトレードを受け入れるなら
  [ファンクション単位の承認ポリシー](#ファンクション単位の承認ポリシー)
  でツール単位に緩和できます。
- 注入されるセクションは「エージェントが記録した背景知識」として枠書き
  されます — 利用者自身の指示ファイルより明示的に一段低い地位で、古く
  なっている可能性も明記されます。
- リポジトリ内には決して書き込まず、`~/.claude` も読みません。ファイルは
  素の markdown なので、いつでも手で監査・編集・削除できます。
- `/memory` がいま保存されているものを一覧します。新しい保存が効くのは
  次のセッションからです。

詳細は [ADR-0020](docs/ja/adr/0020-agent-memory.ja.md)。

## 起動時の安全機構

何かがロードされる前に 2 つのゲートが走ります（ADR-0023）:

- **広すぎるルートは先に確認。** `/`・ホームディレクトリ・その祖先で起動
  すると、file ツールと sandbox 下のシェル書き込みがそのツリー全域に及ぶ
  ことを説明した上で確認します（既定は No）。非対話実行（`-p`・パイプ）は
  その場でエラー拒否します。
- **初見のプロジェクトは 1 回だけ信用確認。** エージェント向けファイルを
  提供するプロジェクトでの初回起動は、その提供物 — 指示ファイル
  （**あなたの**指示として注入）、`.mcp.json`（サーバーエントリごとに
  子プロセスを起動）、`.claude/skills` — を列挙して信用するか尋ねます
  （既定は No）。回答は機械所有の `policy.toml` にプロジェクト単位で永続化
  されます（`trust = "granted" | "declined"`。キーを消せば再確認）。拒否
  してもセッションは起動します — そのプロジェクト自身のファイルをロード
  しないだけで、バナーがその旨を表示します。祖先の指示ファイルと
  グローバル設定はゲートの外です（clone はあなたが所有する上位
  ディレクトリにファイルを置けません）。`[approval].trusted_projects` に
  載せたプロジェクトは質問なしで信用されます。未決プロジェクトでの
  非対話実行は素で走ります（プロジェクト由来を何もロードせず、stderr に
  注記、記録もしない）— checkout したてのリポジトリへの読み取り専用 `-p`
  パイプラインは止まりません。

## プロジェクト指示ファイル

リポジトリが既に持っている指示ファイルを、各ディレクトリで次の順に読みます:

| ファイル | 慣例 |
|---|---|
| `AGENTS.md` | ベンダー横断の標準 |
| `AGENT.md` | その単数形 |
| `CLAUDE.md` | Claude Code |
| `GEMINI.md` | Gemini CLI |

収集順は `~/.config/gem-agent/`（全プロジェクト共通の自分用ルール）→ 親
ディレクトリを外側から → プロジェクト自身。これにより**ワークスペース共通
ルールが配下の兄弟リポジトリすべてに効き**、最も近いファイルが最後に読まれる
（＝最も具体的なものとして扱われる）形になります。内容が同一のファイルは 1 回
だけ注入されます。読み込んだファイルは起動バナーに一覧表示されます。

親ディレクトリの遡上は**ホームディレクトリで停止**します。指示ファイルは
「データ」ではなく「指示」として従う対象なので、`/tmp` のような自分の管理外の
場所から拾わないためです。

## MCP サーバー

サーバー定義は 2 つのスコープから読み込みます。どちらも Claude Code の
`.mcp.json` 形式（stdio トランスポート、`${VAR}` 展開対応）なので、エントリを
そのまま移動できます:

| スコープ | パス | 用途 |
|---|---|---|
| グローバル | `~/.config/gem-agent/mcp.json` | 全プロジェクトで使うサーバー |
| プロジェクト | `<project>/.mcp.json` | そのリポジトリ固有のサーバー |

どちらも任意です。両者はマージされ、**名前が衝突した場合はプロジェクト側が
優先**されます。`/mcp` で接続中のサーバーがスコープ付きで一覧表示されます。

```json
{
  "mcpServers": {
    "tor-exit": { "command": "tor-exit-lookup", "args": ["mcp"] }
  }
}
```

ガバナンスと監査証跡を付けたい場合は
[mcp-guardian](https://github.com/nlink-jp/mcp-guardian) を経由させます —
guardian 自体が stdio MCP サーバーなので、opt-in は `.mcp.json` のエントリ
1 つで済みます:

```json
{
  "mcpServers": {
    "guarded": { "command": "mcp-guardian", "args": ["--profile", "myserver"] }
  }
}
```

## 設定

リポジトリ同梱のテンプレートから始められます:

```sh
mkdir -p ~/.config/gem-agent
cp config.example.toml ~/.config/gem-agent/config.toml
cp mcp.example.json    ~/.config/gem-agent/mcp.json   # 任意: MCP サーバー
```

`~/.config/gem-agent/config.toml`:

```toml
[gcp]
project  = "your-project-id"
location = "global"        # デフォルト; Gemini 3 系は global エンドポイント専用

[model]
name = "<gemini model id>"
# context_window = 1048576  # 任意; フッター表示と圧縮判定に使う厳密値
# thinking = "high"         # 任意; Gemini 3 の思考レベル: minimal|low|medium|high
#                           # (未設定 = モデル既定。対応レベルはモデル依存。
#                           #  要約モデルには効かない — ADR-0025)

[sandbox]
enabled = true             # デフォルト

[agent]
max_turns = 50             # デフォルト
shell_timeout_sec = 120    # デフォルト
auto_approve = false       # デフォルト; 起動時から自動承認モードにする
auto_compact = true        # デフォルト; ウィンドウ接近時に古い履歴を要約
compact_at_pct = 80        # デフォルト; 発動するウィンドウ占有率

[tui]
theme = "auto"             # auto | dark | light | plain
```

TUI のアクセント色は ANSI 16 色パレット（ターミナルテーマに追従）、フッターや
ヒントなどの控えめテキストは背景の明暗判定に応じた中間グレーを使い、どの
テーマでも背景との輝度差を確保します。`theme = "auto"` は起動時に明暗を判定。
判定が合わない場合は `dark`/`light` を明示、どうしても合わないテーマでは
`plain` で全装飾を無効化できます（エラーは `✗` マーカー付きなので色に
依存しません）。

優先順位: フラグ（`--model`）> `GEMAGENT_*` > `GOOGLE_CLOUD_*` > config file
> defaults。設定ファイル内の未知キーはエラーになります（strict decode）。

### コンテンツフィルタ

Vertex はリクエストとレスポンスの両方にコンテンツフィルタを適用します。
フィルタが作動した場合、gem-agent は**空の応答を見せるのではなく、API が
返した理由を明示して「ブロックされた」と報告**し、**1 回だけ自動リトライ**
します。判定対象はその試行で生成されたテキストなので**フィルタは確定的では
なく**、同じ要求でも次の試行では通ることが多いためです。実測: インシデント
対応手順書を文脈に含む同一要求で、**`[model].safety` の設定に関係なく**
ブロックされる試行と通る試行がありました。

リトライも弾かれた場合はその旨を報告します。要求を狭める、`/clear` で
大きな文書を文脈から外す、といった対処が有効です。

`[model].safety` は調整可能な 4 カテゴリの閾値を変更します（`SAFETY` 由来の
ブロックには有効ですが、**`PROHIBITED_CONTENT` はこの設定が及ばない別系統の
フィルタ**である点に注意）:

| 値 | 効果 |
|---|---|
| `default` | プロバイダ既定の閾値 |
| `relaxed` | 確信度が高いものだけブロック |
| `off` | 該当カテゴリではブロックしない |

緩めるかどうかは意図的な判断であるべきなので、既定値は変更していません。

注: 2026-08 時点で Gemini 3 系（gemini-3.7-flash / gemini-3-flash-preview で
実測）は global エンドポイントからのみ提供されており、リージョナル指定は 404 に
なります。Gemini 2.5 系は `us-central1` 等のリージョナルで動作するので、使う
場合は `location` をそちらに設定してください。
